系统级实时音频处理引擎

整条音频链路， 拆成 23 个单元

AuraDSP 接管系统音频输出，把它拆成 23 个可以单独调节的单元。噪声门、滤波、动态、限幅，中间夹着 12 级可以自己排顺序的经典算法。装好之后所有单元都在旁路状态，你打开哪个，它才开始处理。

01 定位

设计出发点

大部分音效软件卖的是预设：装好，挑一个「流行」或「人声」，声音就变了。AuraDSP 不做这种一键结果。它给的是一条完整通路：四段，二十三个单元，段与段之间还留着插件的插入点。

改动可以只发生在某一个单元上：只开噪声门和限幅，中间全部旁路；也可以把某一段整个换成人家的插件。同一个播放器，开哪几个单元，出来的声音就不一样。

如果你知道自己房间低频多、耳机中频凹、某首歌齿音重，这些都能对应到链路上的某一段。改完再听一遍，有没有用当场就能判断。

刚装好时，23 个单元都是旁路状态。默认状态

    03 形态

    平台与接法

    Desktop
    Windows 10 / 11
    引擎以 DLL 跑在进程内。输出侧可选系统 APO、AuraVAIO 虚拟声卡、Voicemeeter 回调，或直接用 ASIO（2 / 4 / 6 / 8 声道）。
    主力形态
    Linux
    Ubuntu · PulseAudio / PipeWire
    同一份 C ABI 的原生库，三种接法都能用：系统输出、虚拟设备、回环驱动。也可以直接挂 ALSA。
    功能对等
    Root
    Android · KSU / Magisk
    效果注入系统音频 HAL，全局生效。重启之后依然在位。
    端到端打通
    Rootless
    Android · APK
    以会话级 AudioEffect 前台服务运行，不需要 root。作用范围限于当前会话。
    蓝本阶段

    界面和引擎之间只隔一层 C ABI。界面拿到的只是函数调用，不区分引擎跑在哪个进程、哪个平台上，同一份二进制在四个平台都能加载。

    04 工程

    实时回调的约束

    第一

    音频回调里不分配内存、不加锁、不做 IO。调参数时不直接改引擎正在读的那份，先写一份副本，等一个块处理完再整体换过去。

    第二

    界面和引擎之间只有一份头文件。两边的函数签名对不上，构建脚本会直接拦下来，不靠谁去记。

    第三

    参数、预设、效果表都不写死在代码里。它们放在引擎的参数表和 JSON 文件里，界面读同一份，改一处两边都跟着变。

    05 开始

    安装与首次运行

    第一步

    安装

    Windows 是单文件向导；Linux 有 deb、AppImage 与 tar.gz。装完不到一分钟，不用重启系统。

    第二步

    挂上输出

    默认接管系统音频。想只处理某个播放器，就把它挂到虚拟声卡上。所有单元默认旁路，不会突然改变你的声音。

    第三步

    逐段调

    从第一段开始往下开。每个单元都能单独旁路，改错了关掉就行，不牵连其他段。预设随时保存。
