01定位

为什么不做「一键音效预设」

多数音效软件通过固定预设粗暴拉升特定频段，声音变大的同时容易带来数字削波与相位失真。AuraDSP 提供完全摊开的透明通路。

黑盒预设

粗暴拉升增益与不可控削波

在原音频流上盲目施加大幅度静态增益，波形顶峰被直接切平，引入严重的非线性奇次谐波失真与听觉疲劳。

  • 固定 EQ 叠加，峰值电平突破 0 dBFS 产生硬削波
  • 缺乏针对不同阻抗耳机与音箱单元的频响矫正机制
  • 处理过程全黑盒，无法观察信号在各环节的真实变化
AuraDSP 白盒设计

高精度浮点处理与物理旁路

每个单元均可独立旁路或重排，全链路 64 位浮点留足动态净空，搭配真峰值超前预测，彻底杜绝输出失真。

  • 23 个单元默认全部处于 0 开销物理旁路状态
  • 全程 64 位双精度浮点运算，完整保留音频动态与微弱泛音
  • 覆盖系统全局接管、虚拟声卡定向路由与低延迟硬件直通

滤波

15 段双四阶参量均衡

染色

非线性双曲正切特性，平缓限制瞬态并引入偶次谐波，消除数字音频冷硬感。

动态

可调阈值与软拐点（Soft Knee），在保持声音瞬态自然的同时平抑大动态跳跃。

第三方插件宿主 VST3 / CLAP / VST2 · 四插槽 × 五级插入点 · 64 位插件进程内极速加载；32 位插件经由独立进程桥（Bitbridge）隔离运行，即便第三方插件崩溃亦不中断主系统音频输出 · 原生界面在各平台均可直接调出

03形态

跨平台驱动与系统运行形态

核心引擎基于统一 C ABI 构建，跨平台消除差异。针对 Windows、Linux 与 Android 三大系统底层，提供量身定制的无感驱动接入方案。

Windows 桌面端：系统级三层驱动生态

Windows 环境提供三种互不冲突的接入方式，满足从日常全局聆听、多轨直播录制到专业编曲监听的全部诉求。

全局接入

Windows 系统 APO

深植于 Windows Audio Service (AudioDG)，直接拦截默认输出端点。浏览器、游戏、本地播放器全部无缝接管，音画绝对同步。

系统应用流→Windows APO 钩子→默认音频设备
  • 声学延迟: < 0.8 ms
  • 声道支持: 立体声 / 5.1 / 7.1
  • 适用场景: 日常观影、3A 游戏、系统全局听音
独立隔离

AuraVAIO 虚拟音频驱动

独立内核虚拟音频驱动，在系统注册高规格 24-bit/192kHz 7.1 声道设备。可为指定播放器或推流软件分配专属通道，完全隔离其余系统声音。

指定播放器→AuraVAIO 独立管道→定向硬件声卡
  • 规格: 24-bit PCM / 32-bit Float 192kHz
  • 物理隔离: 独立环绕通道，避免系统提示音干扰
  • 适用场景: OBS 直播推流、Hi-Fi 独占回放、多应用混音
硬件直通

ASIO Direct DMA 直通

彻底绕过 Windows 系统混音器与重采样，通过厂商专属 ASIO 驱动以 64 采样点直连专业声卡硬件 DMA 内存缓冲区。

DAW / 编曲宿主→ASIO DMA 直传→外置专业声卡
  • 监听延迟: 0.67 ms (64 采样点)
  • 数据纯度: Bit-Perfect 位完美旁路
  • 适用场景: 乐器监听、音频母带处理、低延时编曲

Linux 桌面端：原生 PipeWire SPA 节点与对等架构

基于跨平台统一 C ABI 编译，直接编译为原生动态共享库，与 Linux 现代音频架构紧密咬合。

现代架构

PipeWire 原生 Filter-Chain 节点

直接作为 PipeWire SPA 节点运行，完全由系统音频守护进程统一调度，具备极低抖动与高优先级调度特性。完美兼容 Wayland / X11 桌面环境。

PipeWire 图节点→AuraDSP SPA Filter→ALSA Sink
  • 延迟性能: < 0.9 ms (PipeWire 64/128 量子)
  • 多通道: 原生支持立体声与多声道通道映射
  • 图形交互: 独立桌面 GUI 通过 IPC 实时双向同步
传统兼容

ALSA Loopback / PulseAudio 桥接

针对传统 Linux 发行版或无 PipeWire 环境，提供 ALSA 虚拟回环设备与 PulseAudio 插件直通模式，算法矩阵与效果 100% 对等。

ALSA / Pulse→C ABI 引擎库→物理声卡
  • 兼容性: 适配 Ubuntu、Arch、Debian、Fedora 全版本
  • 架构对等: 与 Windows 预设文件完全通用

Android 便携端：Root 注入与免 Root 会话双模

兼顾便携发烧友对全局生效的极致追求与普通用户免提权开箱即用的便捷体验。

硬件级生效

Root 模式 (Magisk / KernelSU / APatch)

通过系统模块深入注入 Android Audio HAL（硬件抽象层）。开机自动生效，无需常驻前台服务，全局所有 App（包括游戏、网易云、Apple Music）全流接管。

全局音频流→Audio HAL 无缝注入→SoC 硬件 DAC
  • 接管范围: 全局系统所有应用与游戏
  • 后台开销: 驱动随音频流唤醒，0 后台耗电
  • 兼容性: 支持 Android 10 ~ 15 各大主流芯片平台
免提权

免 Root 模式 (标准 AudioEffect API)

通过标准 Android AudioSession API 接入，无需解锁 Bootloader 或获取 Root 权限。支持主流音乐播放器的专属音频会话，开箱即用。

兼容播放器→AudioEffect 会话挂载→系统输出
  • 安装门槛: 纯单 APK 安装，无需重启手机
  • 适配软件: 兼容支持标准音效接口的主流音乐应用

所有平台形态共用同一份严苛规范的 C ABI 动态链接库。无论运行在 Windows 核心、Linux 守护进程还是 Android 系统层，算法数学表现与调音预设 100% 精确一致。

04工程

硬实时音频的工程底线

音频回调是硬实时环境，一个缓冲区超时就会引起爆音（XRun）。AuraDSP 的音频线程遵循三大底线规约。

01

零动态内存分配

音频线程绝对不调用 malloc、new 或可能触发堆分配的任何容器扩容。所有滤波器状态、延迟线环形缓冲区与卷积工作内存均在初始化阶段一次性预分配完毕。

02

无锁单生产者单消费者通信

UI 交互线程与底层音频处理线程通过内存屏障与无锁 SPSC 环形队列传递参数更新与电平遥测数据。音频线程绝不持有可能造成线程休眠的互斥锁（Mutex），UI 拖动再频繁也不会阻塞音频流。

03

稳定纯 C ABI 导出层

对外暴露严格标准化的纯 C 接口（零 C++ 符号混淆、零异常抛出、零非平凡结构体跨边界）。无论是 Flutter 桌面端、C# 宿主还是 Rust / Python 绑定，均可跨平台无缝安全调用。

05开始

三步接入日常聆听

开箱即用，默认全物理旁路，零额外音染。

  1. 01 下载对应平台安装包

    Windows 运行安装包完成 APO / VAIO 驱动就绪；Linux 可通过原生包管理器或归档解压运行；Android 支持 Magisk 模块或独立 APK。

  2. 02 保持默认旁路确认原声

    刚装好时所有单元均处于 100% 旁路状态，系统原声零改变。可使用主控台右上角主旁路开关一键对比直通原声。

  3. 03 按需激活算法单元

    根据耳机频响缺陷开启 15 段参量均衡，或激活电子管温暖度消除数字毛刺，亦可加载房间脉冲响应 IR 重塑声场。
