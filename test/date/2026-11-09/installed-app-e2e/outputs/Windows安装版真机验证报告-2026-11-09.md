### 本轮只读实测：Setup 载荷里到底有什么

对 `dist/AuraDSP-Setup-x64-v0.1.0.exe` 的 payload zip（1605 条目）做只读枚举，结果：

```
payload/driver/auraasio_driver.dll
payload/driver/AuraDSP_TestSign.cer

payload/driver/AuraVaioDriver.inf
payload/driver/AuraVaioDriver.sys

payload/driver/install_driver.ps1
```

【实测】结论：

1. 随包脚本/工具**只有** `driver/` 这 10 项，`install_vaio.ps1`、`install_driver.ps1`、`register_asio.ps1` 都在；
2. **没有** `apo_config.py`，**没有** `apo_inspect.exe`；
3. 便携 zip（1594 条目）连 `driver/` 都没有，脚本只进 Setup 载荷；
4. 全载荷无任何 `.py` 文件。

所以 V-03 的「未找到 apo_config.py」不是「没解压到能被识别的位置」，而是
**该脚本未被打进发行包**；V-01 的 `install_driver.ps1` 则是「脚本在包里，但 app 找错了路径」。

### 2.2 问题点（引用 `1fdaa8e` 已归档结论，不重复展开）

| 层 | 结论 | 依据 |
|---|---|---|
| 检测状态机 | `vaioDetectInfo = {}` 初值恒判 false；`vaiodetect` 无启动自动触发，只挂在 3 个「重新检测」按钮与 `refreshAudioDevices()` 上 | `state.dart:283`、`hardware_drivers.dart:304`、`state_vb_asio.dart:232` |

### 2.3 本轮新增的交叉影响（重要）

`1fdaa8e` 结论里有一条**未经 GUI 验证的推论**：「只要点一次『重新检测』或任一『刷新端点』按钮，`found` 就会变为 true」。

V-02 应优先于 V-01 修复。此推断基于代码路径，**未做 GUI 实测**（owner 已观察到崩溃）。

另【观察】截图 01 显示「未检测到」，截图 03 显示「AuraVAIO KMDF 驱动已就绪」——
同一会话内检测状态会变化，与「检测未自动触发」一致；但也需 owner 确认两次截图之间的
确切输入/输出选择与是否点过「重新检测」，本轮不据此下结论。

## 3. V-02 新故障：WASAPI 双标准模式点「刷新设备」卡住后闪退

### 3.1 现象（【观察】）

- 前置：处理范式 → 普通管线模式，输入端与输出端**都选 WASAPI**（`WASAPI 标准模式` / `WASAPI 标准输出`）。
- 操作：点击**任何一个**「刷新设备」按钮（截图 03 展示的是音频输入行的「刷新设备」；
  音频输出行与 WASAPI 驱动行各有一个同名按钮）。
- 结果：界面先卡住（无响应），随后**进程直接退出/闪退**。
- 截图未覆盖崩溃瞬间，无 Windows 错误弹窗、无异常码、无堆栈；本轮也**未取得崩溃日志**（见 §3.4）。
- 影响面：这是标准 WASAPI 路径下最基本的设备刷新操作，且三个入口共用同一实现 → 基础可用性问题。

### 3.2 只读代码定位（【代码】，非根因结论）

| 位置 | 事实 |

## 4. V-03 附加模式：无效感、脚本缺失、刷新按钮无反应

### 4.1 「选择该模式后似乎没什么用」（【观察】+【代码】）

截图 04（附加模式 · System APO）逐字关键文案：

- 处理范式：`附加模式`（选中）/ `普通管线模式`；音频模式：`System APO`（选中）/ `Voicemeeter API`
- 设备：`处理范式 = 附加模式 · System APO`
- `附加目标端点 = 默认音频端点 (Default Render)`，右侧 `刷新驱动`
- `APO 挂载状态 = 未附加`
- 红条：**`未找到 apo_config.py 驱动管理脚本`**
- 操作按钮：`一键附加` / `一键卸载` / `复合插槽` / `刷新状态`
- 底部：`注册表安全保护：所有变更均经 HKLM\SOFTWARE\AuraDSP\Child APOs 及注册表双层快照原子保护，卸载时 100% 还原原始驱动配置。`

截图 06（附加模式 · Voicemeeter API）：`处理范式 = 附加模式 · Voicemeeter API`，
`连接状态 = no-voicemeeter-remote-dll`。

【代码】只读定位到三条导致「无效感」的事实：

1. **System APO 模式切换不接线**：`composeMode()` 在附加模式 + `sysapo` 下返回 `audioMode='sysapo'`
   （`audio_modes.dart:139-144`）；`setAudioMode()`（`state_audio_modes.dart:16-90`）中
   `wasVb/isVb/wasAsio/isAsio/wasVaio/isVaio` 全为 false → **不向 isolate 发任何启停命令**，
   只 `ConfigManager.save` + `_notifyUi()`。该方法头部注释亦写明「其余模式当前仅持久化选择
   （引擎接线待后续版本，重启生效）」。即：切换该模式本身不会改变音频路径。
2. **Voicemeeter API 会接线但目标机缺依赖**：`voicemeeter_api → 'vbcallback'` → 发 `vbmode on`；
   真机未装 Voicemeeter，桥写入 note `no-voicemeeter-remote-dll`（`VmBridge.cpp:1392`）。
   UI 把这个**内部诊断 token 原样当文案**显示（`sections.dart:347`：
   `_InfoRow(l.setConnStatus, ... note ...)`），用户看不到「未安装 / 未启动 / DLL 损坏」中的哪一种。
3. 两个附加模式面板都只有状态行 + 操作按钮，**没有输入/输出设置分区**（与 V-04 R5 相关）。

owner 需裁定：System APO 的「接线」是否本就应该由「一键附加」完成而非模式切换（若如此，
第 1 条属预期行为，但界面应明确说明），还是产品语义缺失。本轮不下结论。

### 4.2 「一键附加」报错：`apo_config.py`（【实测】+【代码】）

- `state_audio_modes.dart:470-476` 的 `_findApoConfigScript()` 四个候选全是源码树 / 相对路径：
  `core/desktop/windows-drivers/03_system_apo/apo_config.py`、`scripts/apo_config.py`、
  `apo_config.py`、`../scripts/apo_config.py`；`findRepoFile` 从 `Directory.current` 上溯 4 层。
- 【实测】Setup 载荷 1605 条目中 **0 个 `.py` 文件** → 不是「解压位置不对」，是**未随包分发**。
- `attachSystemApo()`（`:564-570`）与 `detachSystemApo()`（`:619-625`）在 `script == null` 时
  置 `lastApoError = '未找到 apo_config.py 驱动管理脚本'` 并早退 → 截图红条即此路径。
- `checkApoStatus()`（`:492-549`）在 `script == null` 时跳过整段状态解析，
  末尾只 `_notifyUi()`、**不置 `lastApoError` 也不改任何状态**
  → 「刷新状态」按钮看起来毫无反应。
- 【推断】`apoStatus/apoInstall/apoUninstall` 直接 `Process.run('python', ...)`
  （`windows_system_tools.dart:94-149`）；安装版未自带 Python 运行时，即便脚本随包也未必可执行。
  **未核查目标机 PATH 是否有 python，不作结论。**

### 4.3 「点刷新驱动似乎没用」（【代码】，明确错接）

`sections.dart:513-515`：附加目标端点下拉右侧的「刷新驱动」按钮
（`l.asioRefresh`）的 `onTap` 是 **`model.refreshVaioDetect()`** ——
刷新的是 AuraVAIO 检测，与 APO 端点 / APO 驱动毫无关系。

- 下拉数据源是 `model.vaioPhysicalEndpoints`（`sections.dart:408`），该按钮**不刷新这个数据源**；
- 同面板「刷新状态」→ `checkApoStatus()`（`:662`），因脚本缺失静默无声；
- 因此两个「刷新」类按钮在安装版上都无可见效果，与 owner 观察一致；
- 该按钮还会触发 `vaiodetect`，与 V-02 的刷新路径**同源**，需一并纳入崩溃排查矩阵。
