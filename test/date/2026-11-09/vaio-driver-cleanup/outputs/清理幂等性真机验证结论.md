# AuraVAIO 安装脚本清理幂等性 · 真机验证结论（2026-11-09）

> **结论：脚本修复后能真正清理环境，且可重复执行。** vm-win10 实跑
> `-Action cleanup` 后 MEDIA 节点 **2→1**、DriverStore 同名包 **4→1**、
> OK 音频端点 **4→2**，二次执行**零移除**；控制通道端到端测试仍
> **7/7 ALL PASS**，保留的驱动未受影响。
> 本文是结论与证据索引，原始输出见同目录 `*.out`。

## 一、背景与根因

设备管理器出现两套 `AuraVAIO Virtual Audio Device` 与带 `2-` 前缀的端点。真机
PnP 对账结果：`.sys` / 内核服务 / INF 包均只有一份（`oem12.inf`），但被建了
**两个 root 枚举 MEDIA 节点**：

| 节点 | 硬件 ID | 来源 |
|---|---|---|
| `ROOT\MEDIA\0000` | `Root\AuraVAIO` | 主 ID，正常 |
| `ROOT\MEDIA\0001` | `Root\AuraVaioDriver` | 备用 ID，重复安装残留 |

- **正常的一半**：`AuraVaioDriver.inf:66-67` 把 Wave filter 同时注册到
  `KSCATEGORY_RENDER` / `KSCATEGORY_CAPTURE`，一个节点必然派生 1 扬声器 +
  1 麦克风端点；`2-` 前缀是 Windows 对第二个同名端点的自动编号。
- **多余的一半**：`AuraVaioDriver.inf:37-38` 同时声明主/备两个 HWID；
  `install_driver.ps1` 旧逻辑在 `devcon install` 返回非零时直接 fallback 装备用
  ID（devcon 非零不保证节点没建好），安装前清理又只 `devcon find` 主 ID、依赖
  `LASTEXITCODE` + 英文串匹配 → 多次安装叠加。DriverStore 累积 4 份
  `auravaiodriver.inf`（`oem9/10` 11-05、`oem11/12` 11-09）。

## 二、脚本修复清单（只改 `01_vaio_driver/install_driver.ps1`）

| 位置 | 旧行为 | 新行为 |
|---|---|---|
| 安装前清理 | `devcon find $HwId` + 英文串 / 退出码判定，只查主 ID | `Get-AuraMediaNodes` 按两个 HWID 精确枚举，`Invoke-Cleanup -All` 全量移除 |
| fallback | devcon 非零即装备用 ID | 按**实际节点数**判定，仅节点数 == 0 时 fallback |
| DriverStore | 只按 `auravaiodriver.inf` 删一份 | `Get-AuraDriverPackages` 枚举全部 `oemXX.inf` 逐份删 |
| 节点移除 | `devcon remove <HWID>` | `pnputil /remove-device <InstanceId>` 精确移除，失败回退 devcon |
| 验收判据 | 仅「Status 为 OK」 | **MEDIA 节点数 == 1** + 同名包 1 份 + OK 端点 ≈ 节点 × 2 |
| 端点计数 | `-like 'AuraVAIO*'` 前缀匹配 → 恒报 0（假阴性） | `-like '*AuraVAIO*'` 包含匹配 |
| install 收尾 | 直接 `Show-Status` | 再收敛一次 + `Show-Status` |
| 新动作 / 开关 | 无 | `-Action cleanup`（收敛到单节点单包）、`-DryRun`（真只读预演，跳过签名） |
| devcon 查找 | 固定候选路径 | 补 `AURADSP_DEVCON` 环境变量 + 目录树递归兜底 |
| 安全保护 | 无 | 完全清理前若无 devcon 则**拒绝实跑**，避免清完建不回节点 |

编码约束保持：UTF-8 **带 BOM** + 全 CRLF（PowerShell 5.1 中文解析前提），
本地与真机脚本 SHA256 前 16 位同为 `A91D16A2160FB16A`，PS 5.1 解析 0 错误。

## 五、判据更正与在册问题

1. `.ai/memory/2026-11-09.md` 原记「设备节点 `ROOT\MEDIA\0000 + 0001` 均 OK；
   音频端点 4→6 个 | 通过」属**判据漂移**——把双节点残留当验收通过。已在当日日志
   追加复核更正，历史原文保留；`core/desktop/windows-drivers/README.md` 活文档的
   验收判据已改写为上述三项。
2. **未清的 4 个 `Unknown` 幽灵端点**：清理后 PnP 仍有 6 个 AuraVAIO 端点
   （2 OK + 4 Unknown），它们是历次重装遗留的 `SWD\MMDEVAPI` 软设备，设备管理器
   默认隐藏。本次 `cleanup` 口径只收敛 MEDIA 节点与 DriverStore 包，**不含**幽灵
   端点，登记为观察项，未擅自删除。
3. **install / uninstall 实跑未做**：真机脚本目录无 INF 三件套，`install` 会先因
   INF 缺失抛错；`uninstall` 的完全清理会卸掉当前唯一驱动。两者只跑 DryRun 覆盖
   逻辑路径。「无 devcon 拒绝完全清理」的保护也因此未实跑验证。
4. **installer 侧同类风险**：`installer/windows/custom_installer/driver/install_vaio.ps1`
   只装主 HWID、无 fallback，不产生双节点；但清理依赖随包 `devcon.exe` 存在，且
   没有「节点数 == 1」判据。登记观察，**未改动**（超出本次范围）。
