## 阶段3 第三轮交互加固与脚本库防御体系
- **编译与应用状态互锁**：
  - **防止状态竞态**：当脚本处于已应用状态（`lpEnabled == true`）时，禁用 Compile 编译按钮，避免热编译与音频线程状态冲突；
  - **安全退出通道**：当代码处于脏状态（未编译、编辑修改中）时，禁用 Apply 应用按钮；**但关键改进**：若当前处于已应用状态，允许用户随时点击已高亮的 Applied 按钮以关停/取消应用（`lpEnabled = false`），保证脚本编写错误时具备即时退出机制。
- **脚本库弹窗重构**：
  - 目录切换改为单选圆点（Radio）；
  - 失效目录展示警告感叹号图标，并严格排布在最右侧操作图标组的居左位置并列呈现；
  - `<系统初始>` 目录受系统级保护（不可删除），且当用户本地模板缺失时自动恢复重建；
  - 路径记忆：引入 `slotLiveprogSelectedDir` 持久化记忆最后打开的脚本目录；
  - 统一操作按钮尺寸与水平并排布局。
- **Flutter 测试踩坑与教训**：
  - **现象**：`liveprog_ide_dialogs_test.dart` 中打开脚本库弹窗触发 `pumpAndSettle timed out`（持续 10 分钟死循环）；
  - **根因**：原 `listDirAsync` 使用 `d.list(...)` 真实 Stream 异步流，与 `CircularProgressIndicator` 持续请求帧动画冲突，导致微任务队列永不清空；
  - **修法**：改用 `Future(() { return d.listSync(); })` 在单次微任务队列中完成异步非阻塞扫描，并仅在自定义目录非空时启动目录异步检测，测试平稳 settle。

## 阶段4 引擎补丁 P-039（libjamesdsp & engine_chain）
- **四段式独立扫描与编译**：
  - 官方模板 5/6 包含 `@slider` 代码段，而旧版 `LiveProgStringParser` 仅粗糙切分 `@init` 与 `@sample`，导致模板 5/6 编译报错；
  - 改造为标准四段状态机扫描（`@init`, `@slider`, `@block`, `@sample`），`@slider` 独立编译并挂接到 block 处理首部执行。
- **消除同因抑制与 5 秒假死**：
  - 旧版 `engine_chain.cpp` 中编译被拒绝（格式/语法错误）时未重置 `lastLiveprogCode` 缓存；
  - 用户修正代码后若哈希判断相同，会触发“同因抑制”被静默丢弃，导致 Dart 侧等待引擎事件超时进入 5 秒假死；
  - 修法：在编译被拒绝时立即清空 `lastLiveprogCode` 缓存，确保下次编译请求必达底层。
