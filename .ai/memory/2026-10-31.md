## 工具教训（本轮真实踩坑，全部已修）

### python 字节级替换脚本的四个坑

1. **校验了命中却忘了执行替换**：脚本里 `staged.append((path, rel, norm, crlf))` 存的是**原文快照**，
   写回时只做了换行转换 → 等于没改。但文件 mtime 变了、字节数未变，极易误判为"已生效"。
   修正：必须 `cur = cur.replace(ob, nb)` 后再入队。
2. **同文件多条编辑互相覆盖**：每条编辑各自基于原始快照写回 → 后一条覆盖前一条。修正：**按文件分组**，
   在上一条结果上继续应用。
3. **残留检查把"新串以旧串开头"误判为失败**：编辑"在原句后追加一行"时，新串以旧串开头，
   "旧串必须消失"的校验必然报错。修正：改为"旧串**不是**新串前缀时才要求旧串消失"。
4. **多行新串需按文件换行风格转换**：CRLF 文件直接写 `\n` 会插入混行。修正：按文件实际风格转换后再替换。
   本仓 4 个目标文档均为纯 CRLF（CRLF 数 == LF 数），改后仍是纯 CRLF。

### PowerShell here-string 会破坏反斜杠与引号

- `@'...'@` / `@"..."@` 里的 `` ` `` 是转义符（`assets/` 里的反引号被吞），中文在 `python -c` 传参时
  也被控制台编码破坏（表现为诊断脚本匹配不到目标行）。
- **正解**：诊断/替换脚本一律用 Write 写成 `.py` 文件再 `python file.py` 执行，不走 `-c` 与 here-string。
  这与本仓既有纪律「带反斜杠的代码一律用 Write/Edit，不用 heredoc」同源。

### git 统计非 ASCII 路径必须关 quotepath

`git ls-files` 默认对非 ASCII 路径加引号转义，`Get-Item` 收到的是 `"assets/convolver/.../xxx.irs"`
这样的带引号转义串 → 报「路径不存在」，误判成"文件丢了"。
**正解**：`git -c core.quotepath=false ls-tree -r -l HEAD -- assets`（按大小统计）或 `-z`（NUL 分隔）。

### 登记类数字必须标测量日期与测量命令

文件数/体积这类"登记数字"会随资源持续补入而失真（本次 2214→2443 就是这么漂的）。
**范式**：凡是写入真相源文档的统计数字，一律附「测量日期 + 测量命令」，并在口径变更时显式标注旧值作废。
