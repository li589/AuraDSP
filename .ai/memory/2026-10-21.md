## 进程模式「单位增益直通」根因查明与修复（R-1/E10，用户指令「开始逐步复核+修复」）

**任务延续**：F-1 修复后脉冲复核——进程模式仍不对齐进程内（宿主侧近似单位增益直通），追查根因。

**排除的假设**（均有实验证据）：块大小（activate/proc 4 组合）、种子元数据、PDC、auraConv、CWD（E9 证伪）、插件配置演化。「-256 帧位移」与「0.988553 基线增益」均为假象：前者是探针 `nz` 未加块偏移（帧 32 实为全局帧 288）；后者是限幅器把 1.0 钳到 -0.1dBFS 门限（`limiter_threshold{-0.1f}`=0.988553）。**进程内路径本就是对的（0.6@288，两种块大小一致）。**

**根因（R-1）**：宿主进程 `PluginHostManager` 通道 scratch 从未分配。分配入口只有 `updateFormat` 内的 `ensureChannelScratch`，而宿主只在收到 `Op::UpdateFormat` 时执行它。`PluginHostClient::start()` 只置 `m_processMode`——宿主**懒启动于首个客户端请求**（`request()`→`ensureHostLocked`）。引擎 create 期 `updateFormat` 转发被 `alive()` 守卫跳过；`loadPluginSlot` 远程分支只发 SetChannelHint+Op::Load；代理 `activate()`（唯一另一处发 UpdateFormat 的路径）不被调用；宿主 Op::Load 只手动赋值格式不分配 scratch → `processSlotInterleaved` L400-403 入口静默 return → 宿主原样回声输入 = unity 回声，且 remoteFailed=false、零溢出——**故障全程静默**（遥测盲区：远程模式引擎侧 processCalls=0，代理路径不递增）。

**修复（两处兜底）**：
1. 宿主 `Op::Load` 处理器：手动赋值格式改为 `manager.updateFormat(sampleRate, maxBlock)`（宿主构建含 AURADSP_HOST_INPROC=1，走本地分支 ensureChannelScratch）——`auradsp_plugin_host_main.cpp`；
2. 引擎 `loadPluginSlot` 远程分支：代理 load 成功后补发 `m_remoteClient->updateFormat(...)`——`plugin_host_manager.cpp`。

**验证（红→绿）**：修复前远程 = 0.988553@0/@256（unity 回声）；修复后远程 = **0.593867@544**（插件 0.6 × 限幅器 release 残压；544=288+256 实测管线，量化确认 E7「上报 416 少算一段 128」）。进程内无变化（0.6@288，回归通过）。冒烟 `smoke_plugin_host_process.py` 8/8 节全绿。已更新报告 §11/§12/§13 + 未决清单（E9 裁定、E10、E7 实测注记）；临时探针与 CMake 临时目标已清理。
