### ⚠️ 本轮最大坑：JUCE CLAP 插件的 `set_parent` 死锁
JUCE 插件在 `gui->set_parent()` 内取 `MessageManagerLock`；**调用线程若不是 JUCE
MessageThread，锁永不释放 → 死锁**。四轮试错：

| 方案 | 结果 |
|---|---|
| A 全放子线程 | ❌ 死锁 |
| B 主线程 create+get_size，子线程 set_parent+show | ❌ 死锁 |
| C 子线程建 HWND 起泵，主线程 set_parent+show | ❌ 仍阻塞 |
| **D 子线程建 HWND 后**立即进入消息泵**并**发信号**给主线程 → set_parent+show | ✅ 首次成功 |

实测：`set_parent returned: 1` / `showEditorSlot returned: 1`。
**结论（可复用）**：CLAP GUI 正确时序 =「先在专用线程把 HWND 与消息泵跑起来并就绪发信号，
再回到 CLAP 认可的 main thread 做 `set_parent` / `show`」。
遗留：`test_plugin_direct.exe` 退出码仍为 1（疑 VST3 用例 Sleep/close 时序）。

**Element 启示（写进文档了）**：Element 的 `CLAPEditor` 在 JUCE Component **构造函数**里
`create` + `get_size`，在 `parentHierarchyChanged` / `visibilityChanged` 里 `set_parent` + `show`；
Linux 用 JUCE Timer 轮询 `on_timer`，Windows/macOS 靠原生消息泵派发。
