## 脚本页三件套 + 卡死事故修复轮（00:09~00:50，commit 6f1b462 已推送）

- **卡死事故（用户报：点脚本直接卡死，差点卡死整机）——已修复**
  - 根因：编辑器 Tab 捕获改造时把**同一个 FocusNode 同时挂在外层 Focus（事件
    拦截层）和 TextField 上**。同节点双 attach：debug 下 assert，release 无断言
    → 无限 rebuild 风暴（UI 线程 + raster 双核满转）
  - 复现：点击脚本项后 4s CPU 增量 8.00s（双核满转）；修复后 4 次页面往返
    0.06s 全部正常
  - **教训（重大）**：FocusNode 双持是 release-only 死循环（无 assert 保护）；
    包裹 TextField 加键盘拦截时外层 Focus 必须用自建节点
- **功能落地**：
  - Tab 捕获：Shortcuts/Actions 覆盖 DefaultTextEditingShortcuts（Tab 插入/
    Shift+Tab 反缩进，单光标+选区）；`Action` 无 const 构造，actions map 须非常量
  - EEL 格式化（保守）：printDepth/nextDepth 分离（`} else {` 正确）；
    不改行数与内容
  - 语法检查：注释/字符串状态机 + 括号栈；问题列表点击跳行 + 光标行列显示；
    TextField 无法按行着色——"飘红"=问题列表+跳转（已向用户说明取舍）
- **测试**：test/eel_editor_test.dart 15 项（lint 9 + format 6）全过；
  其中一处是测试期望本身写错（@init 段头深度=0）
- **验证方法论**：沙箱吞 keybd_event/PostMessage 键盘事件 → UI 键盘行为无法
  自动化验证；纯 Dart 逻辑用 flutter test 决定性验证；死循环用
  GetProcessTimes 双采样 CPU 判定（>3s/4s 即死循环）
