## 教训：多智能体并行会话的 git 冲突（本次亲历，值得固化）

- **现象**：本会话已完成的报告勘误 + `git mv` 迁移，在另一并行会话执行 `git reset --hard origin/main`（reflog `reset: moving to origin/main`）后**全部丢失**；对方以同 message 不同 SHA 发布了重复提交（`fa20cdb/d5564e0/448e444` vs 本地 `35e400b/f0e380a/1dd6b71`）并把本地重置到 origin。
- **根因**：同一仓库两个会话并发操作 git；未提交的索引/工作区改动在 hard reset 下零保留。
- **对策（已实践有效）**：
  1. 编辑完成后**尽快提交**，缩小未提交裸奔窗口；
  2. 提交必须**路径限定**（`git commit -m msg -- <paths>`）——对方可能已向索引暂存其文件（本次索引里就有对方暂存的 `未决问题清单`、`push_via_api.py`），全量 `git commit` 会把别人半成品卷进我的提交；路径限定提交只取指定路径的工作区状态，他方暂存原样保留；
  3. 提交前必看 `git status --short` **第一列**（索引列非空 = 有他方暂存，禁用全量提交）；
  4. 被冲掉后按编辑记录重放即可（基线内容未变，edit_block old_string 仍匹配）；重放前先核实 HEAD/reflog 与文件基线，确认冲掉范围。

## 教训（B-1 期间三个值得固化的新坑）

1. **CMake VS 实例校验在 VS 更新待重启期间必炸**：本机 VS 2026 于 10-18 更新后 `isRebootRequired=true / isComplete=false`，vswhere 默认查询隐藏未完成实例 → CMake configure 报 "not known to the Visual Studio Installer"。任何触碰 CMakeLists 的改动都会触发重配置而失败。**临时绕法（本次使用）**：`touch out/CMakeFiles/{generate.stamp,generate.stamp.list,generate.stamp.depend,cmake.check_cache}` + msbuild 加 `/p:BuildProjectReferences=false` 跳过 ZERO_CHECK；**根治=重启机器**。重启后下次正规 configure 自动收编 option（默认 OFF，零行为差异）。
2. **ON 构建（验证编译开关真实生效）的 CLI 技巧**：msbuild 不能用 `/p:PreprocessorDefinitions=...%(PreprocessorDefinitions)`（响应文件解析炸）；正解=`$env:CL='/DAURADSP_DBG_LOG'` 环境变量（cl 原生支持），配 `/p:OutDir=/p:IntDir=/p:TargetName` 落 `tools/archive/dbg_on/`。
3. **flutter 测试会按候选优先级加载陈旧 DLL 副本**：`auradsp_ffi.dart` 候选序第 3 位是 `build/windows/x64/runner/Release/`（flutter build 产物，不会随引擎重建自动刷新）——旧副本（含 cout [DBG）在 flutter test 中被真实 FFI 测试加载，stdout 冒出 [DBG 行（带 "Shell:" 前缀），制造"新 DLL 泄漏"假象。**鉴别手法**：字节扫描新 DLL 无 [DBG 即可排除新码；修法=`flutter build windows --release --no-tree-shake-icons` 刷新（禁手拷，见 verify_dll_copies 规范）。
