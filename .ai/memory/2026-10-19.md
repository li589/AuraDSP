## 教训：多智能体并行会话的 git 冲突（本次亲历，值得固化）

- **现象**：本会话已完成的报告勘误 + `git mv` 迁移，在另一并行会话执行 `git reset --hard origin/main`（reflog `reset: moving to origin/main`）后**全部丢失**；对方以同 message 不同 SHA 发布了重复提交（`fa20cdb/d5564e0/448e444` vs 本地 `35e400b/f0e380a/1dd6b71`）并把本地重置到 origin。
- **根因**：同一仓库两个会话并发操作 git；未提交的索引/工作区改动在 hard reset 下零保留。
- **对策（已实践有效）**：
  1. 编辑完成后**尽快提交**，缩小未提交裸奔窗口；
  2. 提交必须**路径限定**（`git commit -m msg -- <paths>`）——对方可能已向索引暂存其文件（本次索引里就有对方暂存的 `未决问题清单`、`push_via_api.py`），全量 `git commit` 会把别人半成品卷进我的提交；路径限定提交只取指定路径的工作区状态，他方暂存原样保留；
  3. 提交前必看 `git status --short` **第一列**（索引列非空 = 有他方暂存，禁用全量提交）；
  4. 被冲掉后按编辑记录重放即可（基线内容未变，edit_block old_string 仍匹配）；重放前先核实 HEAD/reflog 与文件基线，确认冲掉范围。
