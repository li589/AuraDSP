## 2. 经验沉淀（重要教训）

### 2.1 在断言「某处有 bug」之前，先验证其数据的上游生成逻辑

本轮**两次**出现「以为坏了、查了发现没坏」：

1. **P1 VST 脏缓存**：初判「仓库内无任何代码写这种数据，判定为手工塞入」。
   实为 `plugin_manager_test.dart:136` 调 `onPluginScanned()` → `saveCache()`，
   而 `flutter test` 不沙箱化，`ConfigManager.baseDir` 指向真实 `%APPDATA%`。
   → 全仓检索"没找到"**不等于**"不存在"，尤其当写入路径经过间接调用时。
2. **P5 频谱错位**：初判「`_SpectrumPainter` 均匀摆放与 `FreqAxis` 对数刻度冲突，
   1k 标签下是 322 Hz 数据」，并据此量化。实为引擎 `kBandEdges` 已产出 **32 个对数频带**，
   均匀摆放本就正确；真正的病灶只有 `chrome.dart:310` 的 `pow(t,1.6)` 幂律。
   → 该结论建立在「频谱数据是线性 FFT bin」这一**未经核实的假设**上。

**教训**：定位渲染/数值偏差时，必须先确认**数据本身的空间/频率分布**，
再比对映射函数。对本项目而言，这意味着先读引擎 `emit_viz` 与 `kBandEdges`。

### 2.2 `flutter test` 不沙箱化，任何写文件的测试都要注入临时根目录

已通过 `ConfigManager.baseDirOverride`（`@visibleForTesting`）修复，
并补了回归测试 `onPluginScanned 只写测试临时目录，不污染用户缓存`。
**新增任何会触发 `saveCache()` / 写 `config.json` / 写预设的测试时，必须在
`setUp` 注入 `Directory.systemTemp.createTempSync(...)`。**

### 2.3 带尾部补发的节流不能用「每次取消重建定时器」

`eq.curve` 20Hz 节流（`state.dart`）若写成「每次调用都 cancel 并重建 Timer」，
持续拖拽下定时器会被无限推迟，**曲线永不更新**。正确写法是
「仅在没有定时器在跑时补一个」——用 `_eqCurveTimer ??= Timer(...)`。

### 2.4 同文件内 SDK 变体可能裁剪继承链

本项目 VST3 SDK 的 `IAudioProcessor : public FUnknown`（**不继承 `IComponent`**），
因此没有 `getBusCount` / `getBusInfo`；改用 `getBusArrangement` +
`SpeakerArr::getChannelCount`。移植代码前先确认当前 SDK 变体的继承关系。

### 2.5 `rg -rn` 会被解析成 `--replace n`

`rg -rn "pattern"` 中 `-r` 被当作 `--replace`、参数为 `n`，导致**匹配文本被替换成 n**，
输出看起来像乱码且极具误导性。正确写法是 `rg -n "pattern"`。
