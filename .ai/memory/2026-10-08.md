## 项目定位确认
当前 `D:/temp_desktop/Proj/JamesDSP` 是 JamesDSP 全家桶真实源码：
- `source/JDSP4Linux` = Qt(C++) + libjamesdsp + PipeWire/PulseAudio；`libjamesdsp` 在 `JDSP4Linux/libjamesdsp`（DSP 引擎, C++）。
- `Root/RootlessJamesDSP` = Android（Gradle/Kotlin）；`JamesDSPManager` = 旧 C# ViPER 版；`equalizerAPO64` = Windows APO（Equalizer APO，系统级注入）。
- `element` = Kushview Element（JUCE 系 VST3/AU/LV2/CLAP 宿主，桌面端，不含 Android）。
- `core` / `tools` / `venv` 为空，是用户准备新建的「统一核心」位置。

## 架构选型结论（用户问：跨平台全局音效怎么做）
- 核心原则：DSP 核心(libjamesdsp) 与 UI 跨平台，仅「平台音频 I/O 胶水层」按 OS 分化。
- 全局音频接入：Win=APO(EqualizerAPO, 需驱动签名)；macOS=虚拟设备+AU；Linux=PipeWire 虚拟 sink(可 Root)；Android=Root 守护(真全局需 Root)，Rootless 受限。
- VST 仅桌面端（JUCE/Element）；Android 不支持 VST。
- UI：Qt Quick(复用 JDSP4Linux) 或 Flutter/WebView；可视化走 GPU(WebGL/QML ShaderEffect)。
- 硬件加速 = SIMD(NEON/AVX) + 低延迟后端；GPU 仅用于可视化，不要 promise GPU DSP。
- 构建统一用 CMake；Android 走 Gradle。

## 立项决策（用户已拍板）
- **UI 框架定为 Flutter**（取代之前的 Qt/WebView 备选）。Flutter ↔ C++ 核心用 dart:ffi 直连（C ABI）。
- 用户要求：UI 重新设计、多平台、多声道；需覆盖 Android 12~16、Windows 最低 Win7、Linux 各发行版差异；底层算法/功能参考现有项目，但**架构、进程模型、平台胶水、UI 全部从零重做**。
- 关键改进点（源自实测痛点）：Android 14+ session/audio policy 适配；**不依赖 Voicemeeter 等第三方虚拟声卡**（自研注入）；进程保活 + 关窗最小化到托盘；效果链原子化持久化与崩溃恢复；设备热插拔自动重挂；VST 进程隔离 + 32 位桥接；中文优先 i18n。
- 产出：`docs/项目初衷.md`（v1.0 立项章程，含实测痛点复盘/根因归纳/平台矩阵/技术选型/功能清单/非目标/风险/里程碑/参考项目对照表）。

## M0 调研完成（Android 14+ 失效根因，实锤）
- 产出：`docs/M0-Android音频政策专项调研.md`。
- **根因结论**：Android 14+ JamesDSP Magisk 模块失效主因 = **Audio HAL 迁移 Stable AIDL（API 34 起）**，次因 = **APEX 化挂载点（/apex soundfx）** + **AIDL 库版本碎片（需 patchelf 动态修补）**；session 0 官方「弃用多年但仍支持」，不是主因。
- 社区已验证修复路径：JamesDSP v6.4 自带 AIDL 音效库 / v6.5-RC3 `mount_apex()` + patchelf / PIXAML（Pixel AIDL 桥接）/ V4A RE AIDL（API<35 拒装）→ **AIDL 效果库路线可行但全靠 hack**，印证从零重做决策。
- RootlessJamesDSP 机制 = AudioPlaybackCapture 内部音频捕获；Android 15 屏幕共享隐私防护进一步劣化（需关开发者选项防护）；应用拒捕获（DRM）不可绕。
- 关键技术坑：fast/offload 轨道**绕过全局 session 0 效果**（部分应用无效的底层原因）；Android 15+ 需 **16KB page size 对齐**。

## 17:40 崩溃根因分析 + 并发骨架修复（重大）
- 事故：用户网易云播放 → 网易云卡死 → 手机"重启"。取证：内核 uptime 3 天 = 不是重启，是 system_server 软重启（看门狗）；tombstone_10 实锤 audioserver TimeCheck timeout：EffectHalAidl::close 卡死 13s。
- 根因（三缺陷叠加）：①close() 持 mMutex 后 join worker；②worker 持 mMutex 时调无超时 writeBlocking(statusMQ 深度1)；③worker EventFlag::wait 无超时，mExit 不可达。MiniAttach 无音频流侥幸不触发。
