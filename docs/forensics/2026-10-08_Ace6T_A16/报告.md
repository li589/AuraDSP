# M0 取证报告：OnePlus Ace 6T / Android 16 (ColorOS 16.0.8)

> 取证日期：2026-10-08 | 里程碑：M0 | 原始数据：本目录（01~05 号文件）
> 设备：OnePlus Ace 6T（伪装 Pixel 7 Pro/cheetah）| SoC：SM8845（骁龙 8 Gen5）| Root：KernelSU Next（`su` 经 adb 可用）| SELinux：**Enforcing**

## 1. 设备身份确认

| 项 | 值 | 备注 |
|---|---|---|
| API Level | **36**（Android 16） | `ro.build.version.sdk` |
| oplus ROM | **V16.1.0**（`ro.build.version.oplusrom`） | 真实标识 |
| 伪装 | `ro.product.model=Pixel 7 Pro`，vendor fingerprint=`google/cheetah/...` | 伪装模块生效；`ro.oplus.*` 属性未被伪装，取证有效 |
| 音频 HAL | **AIDL**：`init.svc.vendor.audio-hal-aidl=running`、`vendor.audio.hal.aidl.enabled=true`、`ro.oplus.audio.aidl_volume=true` | ColorOS 全面 AIDL 化 |
| audioserver 内部 | 已加载 `libaudio_aidl_conversion_effect_ndk.so` 等 AIDL 转换层 | 框架内部全 AIDL |

## 2. 音效注册链路实况（核心发现）

### 2.1 配置文件分布（与旧 Android 完全不同）

| 分区 | 文件 | 状态 |
|---|---|---|
| `/system/etc/audio_effects.xml`（7544B） | 原生 AOSP 模板：注册 HIDL 时代旧库（`libbundlewrapper.so` 等）+ 仅为注释示例的 `lib_some_fx_sw/hw.so` | **疑似遗留/低优先级** |
| `/odm/etc/audio_effects_config.xml`（6307B） | **真正生效的主配置**：清一色 AIDL 库 + oplus 私有效果 | ★ 关键 |
| `/vendor/etc/` | **无任何效果配置文件** | — |
| `/system/lib64/soundfx/` | **不存在** | 旧模块死因之一 |
| `/vendor/lib64/soundfx/` | 全部音效库所在（新旧并存：`libbundleaidl.so`、`libdynamicsprocessingaidl.so`、`libOplusAudioxAidl.so`…） | ★ |
| `/apex` | **无音频 APEX 模块**（本设备） | v6.5 的 mount_apex hack 在此机不适用 |

### 2.2 ODM 主配置注册的效果（节选）

- `libbundleaidl.so` / `libreverbaidl.so` / `libdownmixaidl.so` / `libloudnessenhanceraidl.so` / `libdynamicsprocessingaidl.so` / `libvisualizeraidl.so` —— AOSP 标准**AIDL 版**
- **`oplusaudiox` → `libOplusAudioxAidl.so`（uuid `41f6c0f4-5d8f-11ec-bf63-0242ac130002`）** —— oplus 私有全局效果
- `spatializer` → `libOplusSpatializerAidl.so`；`mss_effect` → `liboplusMssEffectsAidl.so`

### 2.3 运行时实锤：session 0 效果链活跃

`dumpsys media.audio_flinger` 显示 `AudioOut_1D` 输出线程上：

```
1 effects for session 0
Effect ID 35: OplusAudioX (Oplus Holdings Corp.)
  State: Registered + Enabled
  flags: conn. mode: insert, insert pref: first
  数据格式: PCM float, 48000Hz, 立体声 (0x3)
```

**结论：session 0 全局效果链在 Android 16 上完全可用**，oplus 自己的 AIDL 效果库正挂在那里工作。旧的「session 0 已死」说法不成立；失效的只是**旧的注册方式**。

## 3. JamesDSP v6.1 在此类设备上必然失败的原因（闭环）

| v6.1 模块行为 | 本设备现实 | 结果 |
|---|---|---|
| 写 `audio_effects.conf` | **系统只读 XML**（conf 路径已无文件） | 效果永不注册 |
| 拷 `.so` 到 `/system/lib64/soundfx/` | **该目录不存在**，库必须进 `/vendor/lib64/soundfx/` | 加载无从谈起 |
| （若能注册）HIDL 版效果库 | 效果工厂吃的是 **AIDL 库**（odm 配置） | 接口对不上 |
| 结果 | App 检测效果不可用 → 「找不到 libjamesdsp.so / 无法初始化引擎」 | ✅ 与你的实测完全吻合 |

## 4. 对新项目的直接设计输入

1. **`EffectRegistrar.AidlRegistrar` 的目标路径明确**：
   - 效果库 → `/vendor/lib64/soundfx/lib<X>aidl.so`（或 Magisk overlay 同路径）
   - 注册 → 修补 `/odm/etc/audio_effects_config.xml`（或等价的 vendor overlay），与 opluaudiox 同类注册
2. **session 0 仍是正解**：A16 上全局 insert 效果链活跃。但 **OplusAudioX 占了 `insert pref: first`** —— 共存策略必须设计（插入其后、或利用链内顺序），避免与之冲突抢链。
3. **数据格式**：该输出线程为 float/48k/立体声，效果库按 float 处理实现即可（libjamesdsp 本身支持 float）。
4. **conf 路线彻底废弃**：新项目不再支持 `.conf` 注册（仅 HIDL 老设备保留）。
5. **Rootless 利好**：`ro.oplus.audio.third_party_playback_capture=1` —— 本机第三方播放捕获是放开的，Rootless 降级模式在这台设备上基础可用（15+ 仍需注意屏幕共享防护）。
6. **SELinux Enforcing 下 su 可用**：KSU Next 的 `su -c` 已验证可读 audioserver maps，后续修补 odm XML / overlay 不需要全局关闭 SELinux。

## 5. 与 M0 报告结论的对照

| M0 推断 | 本机取证 | 判定 |
|---|---|---|
| AIDL 迁移是主因 | vendor.audio-hal-aidl 运行、odm 配置全 AIDL 库 | ✅ 证实 |
| APEX 挂载是普遍根因 | 本机 /apex 无音频模块 | ⚠️ 修正：**设备相关**，ColorOS 16 上主配置在 **/odm/etc** |
| session 0 仍可用 | OplusAudioX 活跃于 session 0 | ✅ 证实 |
| 「找不到 so」= 未注册而非文件缺失 | /system/lib64/soundfx 不存在 + conf 不读 | ✅ 证实（且更彻底） |
