# 第四十七轮立项计划（2026-11-17）

起因：user 宾机装 r46 后实测回告四点（① APO 列表叉不可
逆 ② APO/VB 声道数量/模式/填充不生效 ③ VAIO 报
init-audioclient-failed 0x8889000A 不自愈 ④ 效果链输入
电平不亮）。本轮先诊断定罪（代码 + 宾机取证），修复待
user 开工。

## 诊断结论

### ②-a VB —— 定罪（代码实证）

`VmPumpCore.h` ProcessGroupVm 在引擎处理前先把总线
base+2..base+8 全通道 input→output 原样拷贝（"未进引擎
的通道保持原样透传"，本意是无引擎/mask 关时绝不吞声），
其后 scatter 只覆写 < procCh 的通道。后果：引擎在跑、
procCh=6 时 BL/BR 仍是原始输入直通——设 5.1 输出仍 7.1。
且泵 gather 与 channels.mode 无关（恒顺序取前 procCh），
引擎收到的已是截断流，矩阵折叠无从发生——矩阵与离散在
7.1 以下完全同形；填充同理被直通掩盖。与 user 报告逐项
吻合。

### ②-b APO —— 主嫌：audiodg 内存旧 DLL（宾机取证）

- 注册路径 `…\Programs\AuraDSP\driver\AuraApo.dll` 哈希
  == r46 暂存（`0BA838A6`），文件写入 23:07:26（r46 安
  装）；App 进程 23:08 启动；**audiodg 23:19:52 才启动**
  ——若 APO 实测在 23:08–23:19 窗内（序列与 Voicemeeter
  23:20 启动做 VB 测试衔接，高度吻合），audiodg 内存里
  是 r45 的 APO 宿主（流宽主义、无生效宽决议），与「显
  示跟设置、输出纹丝不动」的症状完全一致。
- 代码侧全链复核无断点：块发布（isolate 按能力钳制后
  onNumeric 发布 eff）、宿主快照（count 记账→决议→
  set_param，引擎 setter 对合法值不可能失败）、
  ProcessDirect（liveEngCh 分支 + 余道清零）均为 r46
  新逻辑且在活路径上。
- 结构性缺陷：**覆盖安装不重启 audiodg，附加端点会继续
  用内存里的旧 APO，直到音频服务重启为止**——历轮验收
  多伴随重启/快照恢复，未暴露。

### ③ VAIO 0x8889000A —— 定罪（桥侧）+ 占用主嫌

- 0x8889000A = AUDCLNT_E_DEVICE_IN_USE。桥以 SHARED
  打开 HD 输出端点仍被拒 → 端点被独占持有。宾机取证：
  Voicemeeter 正在运行且其 A1 输出正是同一 HD 端点
  （WDM)，为主嫌（未实证关闭后恢复，留待复测）。
- 桥侧真缺陷：StartWasapi 失败即终局（startRc=-8、note
  滞留），**无重试自愈**——占用解除也不会恢复；且错误
  只给十六进制码，用户无从处置。

### ④ 输入电平不亮 —— 定罪（引擎计量口径）

输入卡逐声道表读 stage 12（gate 输入）的 stage_ch 网
格。引擎口径（auradsp_engine.h 明文）：矩阵模式下链是
立体声的，stage 12/13 逐声道仅 [0]/[1] 有效、[2..7] 恒
-120；而输出侧最终 channel_levels 是上混后的全声道实
测——于是多声道下「输入只有 FL/FR 亮、输出全亮」，与
报告吻合。链头输入本身是多声道原始信号，逐声道计量
有诚实数据可用，是计量填充口径问题、非数据不存在。

### ① 叉不可逆 —— 设计修订（user 指令）

r46 S3 把锁定做成单向（仅卸载可解）。user 裁定：叉再
点应回暗勾（取消锁定、仍保持附加）。

## 附记（2026-11-17 深夜：APO 定罪更正 + user 口径修订）

user 补充受控复测：只附加高清音频端点（系统设置 7.1)、
App 设 4.0、放 7.1 测试——主页显示 4.0 声道电平，虚拟
机外以 VB 观测宾机输出，确认为仍是 7.1。audiodg 旧
DLL 主嫌不成立（复测时 audiodg 已是新进程），**撤回**。

**真根因（生成器实证）**：`tools/gen_apo_param_layout.py`
的 EXEMPT 豁免表里有 `'channels.count': '几何由音频流
格式唯一决定，APO 消费端显式跳过'`——旧流宽主义被写进
参数块 ABI 生成器：channels.count **根本不在参数块里**
（Dart/C 双侧索引一致地缺席，故 ABI 镜像门禁全绿）。
App 侧 r42 起的 onNumeric('channels.count', eff) 发布
全部落空（无槽可写）；r46 宿主 ApplySnapshot 的 count
分支因 kApoNumParamIds 永不含此 id 而成死代码。链其余
环节（决议/截断/折叠）无辜。

**S3 修订**：(a) 生成器把 channels.count 自 EXEMPT 移
入 CUSTOM_NUMERIC 白名单（int32)，PARAMS_VERSION
3→4，重生成双侧索引；宿主既有分支即刻转活。(b) 遥测
发布 liveEngCh/userCh 保留（防再盲）。(c) 安装重启音
频服务保留为独立加固项（本次虽非主因，覆盖安装不换
audiodg 内存 DLL 的结构问题真实存在，降为 P2）。

**S4 口径修订（user 指令）**：0x8889000A 的提示不用复
杂文案，就一句 Windows 口吻的「该设备正在被另一个人
使用」，不提进程/占用方。自愈重试保留。
