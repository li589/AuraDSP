## 1. 项目定位

基于 JamesDSP 引擎的**跨平台全局音频效果软件**，覆盖 Windows / macOS / Linux / Android。Android 路线已验证：以 **AIDL VINTF 效果 HAL（`android.hardware.audio.effect`）** 形式注入系统音频链路，通过 EffectRegistrar 框架挂载 DSP 引擎。

**品牌与命名体系**（详见 `docs/产品架构总览.md` §1）：应用统一叫 **AuraDSP**（PC/手机同名）；引擎族叫 **AuraDSP Engines**，Android 上拆分为 **(Root)**（KSU 模块，系统全局）与 **(Rootless)**（APK 内置，会话级）两种形态；UI 主体框架基于 Flutter（多语言/多声道/可视化）。APP = AuraDSP Engines + UI 主体框架。

## 3. source/ 整合铁律

1. **禁止使用预编译包**：第三方能力一律从 `source/` 的源码整合进 `core/` 编译体系。唯一例外：NDK 工具链本身。
2. **来源可追溯**：每个从 `source/` 提取的源码子集，必须在 `core/android/vendor-src/ORIGIN.md` 登记上游仓库、分支、提取路径范围、用途、提取日期。
3. **vendor-src 内不改上游逻辑**：如确需补丁（如 libfmq 的 file-backed FMQ 场景），补丁写在调用侧或独立 shim，vendor-src 保持与上游逐字节可 diff；若必须改动，在 ORIGIN.md 中标注 `[PATCHED]` 并说明 diff。
4. **升级路径**：上游更新时重新从 `source/` 提取覆盖 vendor-src 对应目录，ORIGIN.md 更新版本号即可，无历史包袱。

## 4. core/android/ 分层架构

```
┌─────────────────────────────────────────────────────┐
│  examples/ (SpikeEqEngine 等) + 未来 libjamesdsp 引擎 │  ← 引擎层
│  实现 IAudioEngine 接口，纯 DSP，不知道 binder 存在     │
├─────────────────────────────────────────────────────┤
│  registrar/ (AidlEffectBase + Exports)               │  ← 框架层
│  状态机 / FMQ / worker 线程 / extern "C" 三导出       │
├─────────────────────────────────────────────────────┤
│  aidl-gen/ + vendor-src/(libfmq, binder-ndk, ...)    │  ← 平台源码层
├─────────────────────────────────────────────────────┤
│  stubs/ (cutils/libbase/libutils 自写替代)            │  ← shim 层
└─────────────────────────────────────────────────────┘
```

**依赖方向严格自上而下**：引擎只依赖 registrar 的 `Engine.h`；registrar 只依赖 aidl-gen/vendor-src/stubs；stubs 不依赖任何人。禁止跨层反向 include。

### 4.1 关键接口契约（registrar/Engine.h）

```cpp
class IAudioEngine {
    // open/process/reset/close/name()
    // process() 为 RT-safe：禁止 malloc/锁/IO/日志
};
```

- 引擎实现方 **不需要** 了解 AIDL/FMQ/binder；框架负责全部 IPC 细节。
- 新引擎接入三步：① 实现 IAudioEngine；② 构造 RegistrarEntry（uuid + Descriptor + factory）；③ 在 Exports.cpp 注册。

### 4.2 spike-global-effect 的定位

保留为：① 端到端回归参考（Spike2 全链路已验证）；② `deploy/` 部署工具集（KSU 模块打包、MiniAttach 测试器）。**新代码禁止放入**，新工作一律进 `core/android/<新模块>`。

## 5. 构建规范

- **工具链**：NDK 30 `clang++.exe` 直调（不用 `.cmd` wrapper），`--target=aarch64-linux-android34 --sysroot`。
- **C++ 标准**：`-std=c++20`（libfmq 依赖 std::format）；libjamesdsp 为纯 C，单独按 C99 编。
- **链接**：`-Wl,-z,max-page-size=16384`（16KB page 强制）。
- **符号控制**：`version_script.txt` 只导出 `createEffect`/`queryEffect`/`destroyEffect` 三个 extern "C" 符号；所有 C++ 符号 `-fvisibility=hidden`。禁止向进程空间泄漏任何其它符号（防 VNDK 冲突）。
- **构建入口**：每模块一个 `build.sh`（Git Bash 运行），输出到 `out/`（gitignore）。路径处理用 POSIX 变量 + `pwd -W`，禁止在 xargs/子 shell 内嵌套 `cygpath`（会触发引号地狱）。
- **共享中间产物**：aidl-gen、vendor-src、stubs 由各模块 build.sh 直接引用同一份源码，不复制副本。

## 6. 已验证的技术决策（不要回退）

| 决策 | 结论 | 依据 |
|---|---|---|
| FMQ 共享内存 | **file-backed**（`/data/vendor/audio/.spike_fmq_*`） | Oplus Android 16 上 hal_audio_default 域 memfd ftruncate / ashmem EACCES；普通文件 MAP_SHARED fd 可过 binder |
| HAL 形式 | AIDL VINTF 效果库 .so，extern "C" 三函数导出 | Spike2 全链路验证（create→FMQ→biquad→START→close） |
| 符号导出 | version script 白名单 3 符号 | 与进程内 VNDK 零冲突 |
| C++ std | C++20 | libfmq std::format 依赖 |
| AIDL 产物 | 预生成到 aidl-gen/，不依赖 Android 构建系统 | Windows 宿主机无可用的 aidl 工作流 |

## 7. 代码风格与提交规范

- 项目代号：**AuraDSP**（仓库/文档/产物命名统一使用；上游引擎仍称 libjamesdsp 不改名）。
- 用户可见命名：应用名 **AuraDSP**；KSU 模块显示名 **AuraDSP Engines (Root)**（模块 id 保持 `auradsp_jdsp`）。命名体系详见 `docs/产品架构总览.md` §1，新增用户可见名称前先对照该节。
- 语言：核心 C++20；引擎若整合上游纯 C 代码保持 C 原样，wrapper 层用 C++。
- 命名：目录/文件 snake_case；类 PascalCase；成员 `m_` 前缀；namespace `jamesdsp::registrar`。
- 注释：接口契约（RT-safe、线程、生命周期）必须写在头文件；中文注释优先。
- Git：主分支 `main`；提交信息 `模块: 动作` 格式（如 `registrar: add SpikeEqEngine example`）；禁止 `git stash`（沙箱拦截且易丢数据），用 commit 或显式补丁文件。vendor-src 子目录禁止携带嵌套 `.git`（提取后删除，来源靠 ORIGIN.md）。
- 工具：写代码/检索代码结构时优先使用 **codegraph**（项目根有 `.codegraph/` 索引），大型重构前先查调用关系再动手。
- 文档：每个 spike/phase 结束输出一份 `docs/<Phase>-<主题>报告.md`。
