## 0. 结论摘要

APP 侧当前不是「缺少平台层」，而是**平台层只有能力位、没有端口**：

- `lib/platform/` 只有 `platform_profile.dart`（纯查询），所有真实平台调用仍散落在 `core/`、`ui/`、`features/`。
- 文件对话框由 `ui/path_picker_dialog.dart` 直接依赖 `file_selector`；文件管理器打开在 `core/file_shell.dart` 里按 OS 拼 `Process.run`。
- 托盘/自启/媒体会话（SMTC）把 `window_manager`、`tray_manager`、`nativeapi`、`powershell` 分别放在 `core/` 与 `features/` 内部。
- 注册表有 **3 套互不相干的读写方式**：`reg.exe` 查询（VST 目录、ASIO 状态）、`nativeapi.launchAtLogin`（HKCU Run）。
- 「打开/加载/选择」没有统一治理：配置、预设、会话、路径记忆、脚本库、插件缓存各自 `File(...).readAsStringSync()`；坏文件、超限、编码错误策略各写各的。
- 插件目录发现把 Windows/macOS/Linux 三个平台的路径规则 + 注册表读取全部塞在 `core/plugins/plugin_scan_dirs.dart`，插件页只靠 `supportsPlugins` 能力位兜底。

本方案给出四层新结构：

```
UI/features  →  core（状态/持久化/资源治理）  →  platform/port（契约）
                     ↑                              ↓
                 platform/<domain>（唯一平台实现，按领域归类）
```

落地后：业务代码不再直接 import 平台第三方包、不再直接拼注册表命令、不再各自读盘；平台差异只在 `lib/platform/` 内，新增平台只加适配器。

## 2. 设计原则

1. **端口无实现依赖**：`platform/port/*` 只声明契约与数据类型，不 import 任何第三方平台包。
2. **平台实现只落 `lib/platform/`**：按领域分子目录（`dialogs/ shell/ registry/ autostart/ tray/ media/ plugins/ system/`），文件名带平台后缀。
3. **依赖方向**：`features/ui → core → platform/port`；`platform/<domain> → core 模型 + port`；`core` 不得 import `platform/adapters.dart` 或具体实现。
4. **选择/打开/加载统一入口**：
   - 用户可见选择 → `ResourcePicker`（对话框端口 + 校验 + 路径记忆）；
   - 程序内读取（配置/预设/会话/脚本/LRC/缓存）→ `ResourceGate` + `DocumentStore`；
   - 安装目录/资源目录定位 → `ResourceLocator`。
5. **注册表单点**：只有 `platform/registry/registry_windows.dart` 允许出现 `reg.exe`；业务只调 `RegistryPort`。
6. **能力位与实现同源**：`PlatformProfile` 的能力位必须对应一个真实端口实现（无实现 → 返回空/不支持，而不是运行期抛异常）。
7. **可回滚**：纯搬迁阶段保留旧文件薄壳或一次性改 import，不改变行为、不改变持久化格式。

## 4. 端口契约（最小集）

| 端口 | 方法（摘要） | 实现归属 |
|---|---|---|
| `FileDialogPort` | `openFile/openFiles/saveFile/selectDirectory`（扩展名、初始目录、确认文案） | `dialogs/file_selector_dialog.dart`（全平台；未来换 SAF 只改此文件） |
| `ShellOpenPort` | `openPath(path)` | `shell/shell_open_desktop.dart`；移动端暂不支持 |
| `RegistryPort` | `available/keyExists/readString/readStringValues/writeString/deleteValue` | `registry/registry_windows.dart`；非 Windows `NullRegistry` |
| `AutoStartPort` | `available/enabled/setEnabled` | `autostart/autostart_windows.dart`（HKCU Run） |
| `MediaSessionPort` | `supported/create()` → `MediaSessionProvider`（`trackStream/start/stop`） | `media/windows_smtc_provider.dart`；其余空实现 |
| `PluginDirsPort` | `discover({env})`（返回真实存在的目录） | `plugins/plugin_dirs_{windows,desktop,mobile}.dart` |
| `WindowPort` | `visibleListenable/isVisible/setVisible/setFullScreen/show/init/dispose/applyLocale` | `tray/tray_service.dart`；移动端空实现 |
| `WindowsSystemPort` | `vaioDriver/asioDriverScript/apoStatus/apoInstall/apoUninstall/apoInspectDevices/findRepoFile` | `system/windows_system_tools.dart`；非 Windows 返回失败结果 |

组合根：

```dart

  static PlatformAdapters get instance;          // 按 PlatformProfile.os 懒装配
  static void overrideForTest(PlatformAdapters); // 单测注入假端口
```

`ResourcePicker` 由组合根构造（持有 `FileDialogPort`），因此 `core/selection/` 只依赖 `platform/port/file_dialog.dart`，不反向依赖具体实现。

## 5. 加载/选择治理

### 5.1 `ResourceGate`（唯一读闸门）

- 常量：`maxTextBytes = 8 MiB`、`maxJsonBytes = 4 MiB`、脚本沿用 `LiveprogLibrary.maxScriptBytes = 1 MiB`。
- 返回 `ResourceRead{ text, issue }` / `JsonRead{ data, issue }`，`issue` 为 `ok/missing/notFile/notDirectory/tooLarge/unreadable/badJson`。
- 先 `lengthSync` 判超限，再 `readAsStringSync(utf8)`（malformed 判 `unreadable`），所有异常 `swallow` 留痕。
- 迁移点：`ConfigManager.load`、`PresetLibrary.importFromFile/listAll`、`SessionMemory.load`、`PathMemory._ensureLoaded`、`LiveprogLibrary.gateCheck/loadFromPath`、`plugin_manager_cache` 读、LRC 读取。

### 5.2 `DocumentStore`（唯一 JSON 落盘）

- `readJson/writeJson/listJsonFiles/delete`；`ConfigManager.writeJsonFile` 保留为薄委托（旧调用零改动）。
- 写盘统一「自动建父目录 + 2 空格缩进 + 失败不抛」，取代 6 处重复样板。

### 5.3 `ResourceLocator`

- 统一 `resources/{subFolder}`、`assets/{subFolder}`、配置中心、exe 旁的候选顺序；`PlatformProfile.executableDir` 提供 exe 目录。
- `PathMemory.fallbackDir` 改为调用 `ResourceLocator`。

### 5.4 `ResourcePicker`

- `browse(request)`：调 `FileDialogPort`，成功即写 `PathMemory`。
- `validate(path, mode, extensions)`：存在性/扩展名统一判定，UI 只做 l10n 映射。
- `AuraPathPickerDialog` 不再 import `file_selector`/`dart:io`，只经 `PlatformAdapters.instance.picker`。

## 6. 插件模块跨平台口径

1. `core/plugins/` 保留 `PluginScanDirEntry`、去重/规范化、`PluginManager`；**目录发现迁至 `platform/plugins/`**。
2. Windows 发现 = VST3/CLAP/VST2 标准目录 + 环境变量派生系统盘 + `RegistryPort` 读取 `HKLM/HKCU\SOFTWARE\VST`（不再在 core 里拼 `reg.exe`）。
3. macOS/Linux 发现 = 各自标准目录（真实存在才返回）；移动端返回空表。
4. 插件页继续用 `PlatformProfile.supportsPlugins` 做入口降级；新增“端口实现缺失”时表现为空目录/不可用，而不是异常。
5. `PluginManager` 的 VST3/CLAP 格式枚举保持平台无关；宿主二进制名/扩展名仍由 `PlatformProfile` 提供。

## 7. 注册表收紧

| 消费者 | 旧实现 | 新实现 |
|---|---|---|
| 插件目录发现 | `core/plugins/plugin_scan_dirs.dart` 内 `reg query ... /s /v VSTPluginsPath` | `RegistryPort.readStringValues(HKLM/HKCU\SOFTWARE\VST, recursive)` |
| ASIO 状态 | `core/state/state_audio_modes.dart` 内 `reg.exe query HKLM\SOFTWARE\ASIO\AuraDSP Driver` | `RegistryPort.keyExists(...)` |
| 开机自启 | `nativeapi.launchAtLogin` 藏在 `core/tray_service.dart` | `AutoStartPort`（Windows 实现内部仍用 nativeapi，单点） |

## 10. 风险与不做什么

- **不做**：不重写 `audio_isolate.dart`（2259 行）与 DSP/桥语义；不改持久化 JSON 格式/版本号；不改 C ABI；不在本轮引入新平台功能。
- **风险 1：`nativeapi` 在非 Windows 的编译/运行**。缓解：自启端口只有 Windows 实现；其它平台返回 `available=false`，设置页隐藏开关。
- **风险 2：托盘在 Android 编译**。缓解：`TrayService.init` 由 `supportsWindowManagement` 提前返回；移动端保留 `isWindowVisible=true`，不触发 window_manager 调用。
- **风险 3：`ResourceGate` 大小上限误伤合法大文件**。缓解：JSON 4 MiB/文本 8 MiB 仅用于「配置/预设/脚本/歌词」，音频/IR 仍由引擎侧读取，不经过该闸门。
- **风险 4：搬迁造成 import 断链**。缓解：纯机械迁移 + `flutter analyze` 逐阶段验证；旧文件名不做长期薄壳，一次改净。
