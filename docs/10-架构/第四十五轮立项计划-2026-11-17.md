# 第四十五轮立项计划：声道能力源重构（分模式设备事实）+ 桥多声道测试注入

2026-11-17 晚，user 宾机实测 r44 后报告 VAIO 声道怪象并给出分模式
裁定。本计划先定罪、再按裁定重构能力源。

## 一、user 报告与裁定

症状（宾机，VAIO 模式）：

1. 首次切 7.1 时未选 WASAPI 输出声卡，切 7.1 自动调回 2.0。
2. 选了支持 7.1 的 WASAPI 输出设备后，切 7.1 放 7.1 测试音频，
   仅 FL/FR 有电平。
3. 调到 5.1 后再调回 7.1，一直自动回到 5.1。

裁定（user 原话口径）：

- 自动回退功能可以有，但能力必须来自设备事实，按模式分源：
  - APO：按监听模块取 min{设备， 设置}；
  - Voicemeeter：应询问 VB 协商（一并加入系统监听模块）；
    VB 应该都支持 7.1；
  - VAIO：本身肯定支持 7.1；若 WASAPI 输出不支持，按
    min{WASAPI 输出设备， 设置}；
  - WASAPI 输入 + WASAPI 输出：按两设备中最低的
    min{设备， 设置}。

## 二、定罪（宾机 isolate 日志 + 配置 + 代码，一手证据）

宾机 `%TEMP%\auradsp_debug_iso.log`（2026-11-17 20:00–20:05 段）：

```
20:01:34.898 vaiomode: start requested output="" mirror=false
20:01:35.014 channels capability -> 2 (user=2)
20:01:35.961 vaio-geometry: bits/ringSr/ringCh/sr/outCh/outBits
             = 16/48000/2/48000/8/32
20:03:12.062 channels capability -> 8 (user=8)
20:04:21.691 channels capability -> 6 (user=6)
```

宾机 config：`audioMode=vaio, channelsCountMode=1,
channelsCount=8`（用户设置恒为 7.1，回退发生在生效层）。

- **根因（症状 1、3）**：r44 S1 新增的「桥 viz 声道喂
  `updateCapabilityCh`」把能力绑在**当前流几何的回声**上——VAIO
  viz 的 chCount 反映 ring/引擎当前几何（ringCh=端点流格式，
  空闲时为 2；outCh=8 才是输出设备事实）。能力被钳制目标本身
  决定，形成**棘轮回路**：只能降、不能升。空闲 VAIO 首次切
  7.1 → 能力 2 → 回 2.0（症状 1）；几何变 6 后能力 6，用户
  设 8 被 `min{8,6}` 钳回 6、几何永不升 8，死锁（症状 3）。
- **症状 2 双层成因**：(a) Dart 侧非 ASIO 桥的文件注入走
  `decodeWavFile` 默认 fold，7.1 文件先被折成双声道（仅 ASIO
  走 raw 直通，B2c 期口径）；(b) VAIO C++ 注入宽度 =
  ringCh（`FillTestSignalN(..., (int)ringChannels)`），端点
  流格式为双声道时即使 raw 数据也被截断在泵内。两层任一层
  都足以让 7.1 测试音频只剩 FL/FR。

## 三、段落

### S1 拆除棘轮（isolate）

- 删除桥 viz 消费点的 `updateCapabilityCh(bCh)` 喂入
  （r44 S1 第 1 件回滚）；桥 viz 回归纯显示/电平用途。
- 保留两处真设备事实喂入：ASIO 预置（驱动 io 声道）、本地
  WASAPI 泵 devCh（渲染设备混音格式，与引擎声道无关）。

### S2 状态侧能力计算（按模式分源，统一经 'chcap' 下发）

状态侧拥有设备扫描、模式与选择，是唯一权威计算点；在
模式/选择/监听事件变化时重算并下发：

| 模式 | 能力源 |
|---|---|
| sysapo | 选中端点混音声道（现行，保留） |
| vaio | min{8, 选中 VAIO 输出端点扫描声道}；未选输出 → 8 |
| 管线 wasapi 入 + wasapi 出 | min{输入扫描声道， 输出扫描声道} |
| 管线含 vaio/vb 一侧 | 该侧按其规则（vaio 同上、vb 按协商）与另一侧取 min |
| auto/本地 | isolate 泵 devCh（现行） |
| asio | isolate 预置（现行） |
| vb | S3 协商声道 |

- isolate 侧 `capabilityCh` 仍是唯一钳制点（生效 =
  min{设置， 能力} 的既有语义不变）；显示侧钳制同步按同表
  对齐（沿 r44 `_displayCapCh` 扩展，不再出现两处口径漂移）。

### S3 VB 协商入系统监听

- C++ VmBridge 在 Voicemeeter 回调注册/格式变化时记录每组
  协商声道，status 增字段上报（现状 status 无声道面）。
- 状态侧把 VB 协商变化并入系统监听的消费路径（与
  formatChanged 同级触发能力重算）；VB 能力 = 协商声道
  （预期 8）。若实施时证实各版本协商恒 8，则能力恒 8、
  status 只作活性/代次校验，不造假协商。

### S4 桥多声道测试注入（VAIO/VB）

- Dart：vaio/vb 文件源改 raw 直通（同 ASIO 口径，无热切换；
  文件声道变化走既有重注入路径）；波形源桥注入块改双声道
  （现状 mono 块在桥上只落 FL）。
- VAIO C++：注入宽度由 ringCh 改 min{文件声道， 引擎声道}
  ——实施首步先核泵内引擎喂入宽度管道（scratchIn → 引擎
  输入映射是否容许注入宽于 ring），据实决定改法；若管道
  不容许，降级为「端点格式提示」方案并回 user 裁定，不硬改。

### S5 门禁与打包

- 新门禁：状态侧能力计算矩阵单测（模式 × 选择 × 扫描声道）
  + isolate 钳制回归（能力只认 'chcap'/泵/ASIO 三源，viz
  不再影响能力）。
- 开发机全量门（根构建 + 冒烟全量 + Dart 全量，单跑复核
  竞争项）；四件打包（包内 app.so 抽验 + .cat 验签）投
  宾机；验收清单按三症状原路径复现验证 + VB 协商显示核对。

## 四、不做

- 不动引擎声道处理与矩阵/填充逻辑（r43 已验收）。
- 不动 sysapo 'chcap' 既有链路语义（仅并入统一计算点）。
- Linux：无桥模式；管线 min 口径为共享路径，自然受益，
  S5 顺带核对 Linux 设备面板能力显示。
