## 2. 现象口径

- 链路：音乐软件 → AuraVAIO 虚拟端点（输入）→ 桥处理 →
  WASAPI 物理输出，或 VAIO 模式输出（同一桥链的 WASAPI 落点）。
- 表现：输出为持续白噪声（实测频谱并非白噪，见 §3 指纹）；
  有时自行恢复、有时持续很久（2026-11-11 user 项 6 原述）；
  切歌、开关链路、切换默认设备等流生命周期事件与之相关
  （历轮实测记录）。
- 历轮已修且**不等于本专项**的相邻机理：字节错位相位锚
  （第八轮）、格式切换几何重同步（第七轮 S3）、GetPosition
  停滞重对齐（全面复审 S5）、MiniportWaveRTStream::SetFormat
  空实现（第七轮 S3，驱动侧）。上述修复后 user 仍报偶发。

## 3. 已定罪事实（2026-11-12 晚，guest 干净脚手架）

1. 坏状态可在干净脚手架下确定性复现：外部 1 kHz/0.5 正弦 →
   VAIO 端点 → 驱动环 → 桥读环，连续三场全杂波（两个不同
   探针二进制同一指纹，探针代码排除）。
2. 二分定位：① VAIO 端点自身混音环回（audiosrv 送入设备的
   混音）**纯净**；② 桥内测试音（绕环）经引擎到落点**纯净**；
   ③ 仅「外部音源 → 驱动环 → 桥读环」一段杂波。**腐化 confined
   于驱动环一段**（驱动写环 / 环状态 / 桥读环三者之一或组合）。
3. 指纹（每场一致）：1 kHz 分量 ≈0.25、**19 kHz 主导**、
   频谱在 5k/7k/17k/19k 等距峰（= 以 6 kHz 为间隔的镜像，
   48000/6000 → 周期 8 样本量级）、**ac1 = −0.528（逐场恒定）**、
   峰值 ≈0.986（源 0.5，约 ×2）、样本序呈 **ping-pong
   折返**（前进后倒退）。指纹逐场恒定 ⇒ 腐化是一个确定的
   变换，不是随机丢数据。
4. 状态性：坏状态**跨进程重启存续**（App/桥/探针重启不愈）；
   **重启 Windows 音频服务（audiosrv）立即恢复纯净**且其后
   保持；单次流中强杀音源客户端**不能**立即重触发。
5. 在机驱动 `.sys` 与发行包逐字节一致（陈旧驱动排除）；
   参数面已在第十七轮排除（steps 四组参数全程同指纹）。

## 4. 关键推论与待答问题

- audiosrv 重启会销毁全部流实例并重建设备图，但 KMDF 驱动
  本体通常不卸载 ⇒ 坏状态宿主候选：驱动的**流实例/环位置
  状态**（随流销毁而清）、audiosrv 侧设备状态、或环头字段
  被写坏后无人修复（桥只读锚定、驱动按自身位置续写）。
- 待答：① 腐化变换的样本级精确形式（周期、折返长度、增益
  来源）——由存档 raw 反推，变换形式直接点名机理；
  ② 触发事件集合（流启停的哪个相位、格式/默认设备切换、
  多客户端并发中的哪种时序）；③ 坏状态的物理载体（环头哪
  个字段 / 驱动哪块流状态 / 桥哪组锚定状态）；④ 为何桥的
  既有重同步（相位锚、几何重同步、停滞重对齐）对该状态全
  部无感。

## 5. 攻击计划

### S1 代码审计与状态清单（先行）
- 驱动侧：`01_vaio_driver` 写环路径（MiniportWaveRTStream
  的写入/位置推进/流启停与析构）、环的分配与所有权、共享头
  每个字段的写者与时机。
- 桥侧：VaioBridge 读环全路径（游标、相位锚、几何重同步、
  格式判定）、起桥时对既存环状态的假设。
- 产出：**可变状态清单**——逐项注明载体、写者、清零时机、
  以及「若此项坏掉，样本变换是什么」；与 §3 指纹逐项对表，
  收敛到候选机理（≤3 个）。

### S2 样本级反推 + 触发矩阵
- 若存档 garbled raw 尚存（guest / 开发机 r17 产物），以
  `vaio_bridge_loopback_analyze.py` 扩展逐样本比对：由已知
  输入正弦相位反解输出样本的来源索引序列（读序图），把
  ping-pong 的折返周期/步长量出来。
- 触发矩阵（guest 脚手架）：流启停各相位强杀、连续快速
  启停 N 次、采样率/位深切换、中途切默认设备、双客户端
  并发启停——逐格跑 driver 模式判读，找确定性触发格。

### S3 定罪与修复
- 机理定罪后按层修复：驱动状态卫生（流生命周期对称性、
  环头一致性）、桥侧防御纵深（坏状态**检测**——指纹特征
  在线判读 + 自动重锚/重同步自愈，使用户侧永不长鸣）。
- 修复纪律：驱动改动须开发机 WDK 重编重签（`--build-driver`
  通道已通）；桥改动走 J5b ci_check + guest 实跑。

### S4 验证与收口
- guest 压力协议：触发格 ×50 循环 + 全矩阵回归，零杂波。
- 收口 doc 记定罪链、修复、压力结果；user 真机长时使用
  无复发为最终验收。

## 6. 验收标准

- 触发条件被确定性复现并定罪到代码行；
- 修复后同触发格 50 次循环零杂波，全触发矩阵回归通过；
- 即使触发条件有残余未知，桥侧坏状态检测/自愈能保证用户
  听到的杂波在亚秒级内被切断（防御纵深，单独立项条目验收，
  不冒充根治）。
