# EEL 多声道脚本级（liveprog.mc）实施方案

> 2026-11-09 立项。用户裁定**方案 B**：现有立体声 liveprog 原样不动，
> 新增一个引擎级多声道脚本级，脚本可读写 spl0..spl7 全部声道。
> 本文是施工蓝图与验收口径；逐阶段提交、逐阶段验证。

## 1. 为什么不能原位扩展

- jdsp vendor 链是立体声设计：引擎 RT 入口
  `JamesDSPProcessMultiplexedStageSet` 每次只把一对立体声解交织进
  `tmpBuffer[0]/[1]`；`tmpBuffer[2..5]` 是 ASRC/分区卷积草稿区，不是声道。
  liveprog 在链中的位置上不存在第 3–8 声道数据，给它加 spl2..spl7
  只会喂进草稿数据。
- 引擎多声道拓扑（ADR-003）：多声道模式下信号先下混/离散处理再上混，
  全部声道同时存在的点在 `auradsp_process` 的多声道分支（mx_scratch 输入
  与 out 输出）。多声道脚本级只能落在引擎层。

## 2. 总体设计

### 2.1 新模块 `engine/dsp/dsp_mc_liveprog.{h,cpp}`（引擎层，不动 legacy）

独立的 EEL 宿主 `McLiveProgHost`，直接使用 NSEEL VM 公开 API
（`NSEEL_VM_alloc/regvar/freevars`、`NSEEL_code_compile[_ex]/execute/free`、
`NSEEL_init_memRegion` + `aura_eel_ram_clear`，经 jdsp_header.h →
eelCommon.h → ns-eel.h 可达）。立体声 liveprogWrapper.c **一行不改**，
立体声路径零回归面。

宿主纪律**逐条平移 P-016 影子槽范式**（与立体声同构、已实证）：

- 3 个槽（`McLiveProgSlot`），每槽独立 VM + code handle 三件套
  （init/slider/process）+ 环境寄存器指针 + `retiredAt`；
- 控制线程编译进非活动槽，成功后原子换活动指针；在途守卫双条件
  （in-flight 计数为 0，或 proc 计数 ≥ retiredAt），无槽可用时有界
  等待 500ms 后返回 -4（Engine busy），绝不原地编译活动槽；
- RT 侧每块入口/出口维护 proc/in-flight 计数（与 enable 无关），
  块首只读一次活动快照；RT 路径零分配、零锁、零系统调用；
- 编译流程同构：freevars → init_memRegion → RAM 清已提交前缀 →
  重注册宿主变量（slider 值从活动槽结转）→ 编 init（compile_ex）并
  执行 → 编 slider/block 合并段 → 编 sample 段；任一步失败清本槽
  残留 handle、活动快照不受影响、旧代码继续运行；
- 分段解析（@init/@slider/@block/@sample）平移 wrapper 的
  find_sec_hdr 口径：@init 与 @sample 必备，@slider/@block 合并为
  每块执行一次的前置段。错误码口径与 checkErrorCode 对齐
  （0/-1/-2/-3/-4/-5），文案共用 legacy 的 `checkErrorCode` 符号。

### 2.2 宿主变量绑定（脚本可见语义）

| 变量 | 语义 |
|---|---|
| `spl0..spl7` | 当前声道 0..7 的本采样值（读/写） |
| `srate` | 引擎处理采样率（= 设备率；MC 级不在 ASRC 域内） |
| `dev_srate` | 同 srate（与立体声口径一致，P-038） |
| `num_ch` / `nch` | 当前链路声道数（2/4/6/8） |
| `slider1..slider64` | 本级独立滑块（`liveprogmc.paramN`） |

- RAM/gmem 为 MC VM 私有，与立体声脚本互不可见（两套脚本各自独立，
  这是方案 B 的既定语义，手册须写明）。
- 声道映射（缓冲序）：2ch FL/FR；4ch FL/FR/BL/BR（Quad）；
  6ch FL/FR/C/LFE/SL/SR；8ch FL/FR/C/LFE/SL/SR/BL/BR
  （与 speaker_layout.h 的 WAVE 序一致，4ch 除外已注明）。
- **越界声道**：`c >= num_ch` 的 spl 每采样读 0.0、写丢弃（宿主预置
  0 且不写回），脚本可用 num_ch 分支、也可无条件写满 8 路。
- **非有限值**：写回时逐声道 isfinite 卫士，非有限置 0（与引擎链尾
  卫士同口径），防脚本 NaN 污染下游设备。
- 每块语义：slider 段先行一次，随后逐采样
  「载入 8 路 spl → 执行 @sample → 写回有效声道」。

### 2.3 引擎接入

- 句柄：`auradsp_handle` 增 `McLiveProgHost* mc_lp`（create 时构造、
  destroy 时析构）、`Params::lp_mc_enable`、`lp_mc_param[64]`、
  `lp_mc_status`、`lp_mc_code/len`、`lp_mc_slider_ptr[64]`，
  与立体声 lp_* 完全平行。
- 参数面（engine_param_table.h，镜像 liveprog.* 全套）：
  - `liveprogmc.enable`（PARAM_BOOL + hook → apply_liveprogmc）
  - `liveprogmc.code`（PARAM_CUSTOM，1..256KiB，set/get 同口径）
  - `liveprogmc.unload`（CUSTOM_SET_ONLY）
  - `liveprogmc.status`（CUSTOM_GET_ONLY）
  - `liveprogmc.paramN`（indexed set/get，N=1..64；注意
    `liveprog.param` 前缀分发不得吞掉 `liveprogmc.`——第 9 字符
    '.' vs 'm' 天然可分，仍须加断言测试）
  - Dart 侧 param_schema 镜像 `liveprogmcEnabled` +
    `liveprogmcCodeHash`（照 liveprogEnabled/liveprogCodeHash 模式），
    契约 fixture 由 gen_param_contract.py 重生。
  - 引擎导出符号不变（仍走通用 set/get param ABI），ABI 门禁不受影响。
- **链位**：`auradsp_process` 多声道分支内，三种模式
  （binaural / mode0 矩阵 / mode1 离散）分发完成之后、viz 发射与
  gate_update 之前，对 `out`（frames×ch 交织）原地执行。
  语义定位 = **多声道母带位**：脚本看到的是全链处理后的最终多声道
  信号。仅在 `ch > 2 && enable && 编译成功` 时执行；否则整级跳过，
  多声道输出与现行为比特一致。立体声路径完全不经过本级
  （立体声由 jdsp liveprog 覆盖）。
  - 已知口径差（v1 接受）：mode0 的 per-channel 输出峰值
    （viz_scan_out_peak）在本级之前测量，电平表不含脚本增益变化；
    频谱取下混立体声、本就不经本级。
- 声道切换：`reset_channel_state` 在 `LiveProgSetChannels` 旁并列调
  `McLiveProgSetChannels` 同步 num_ch/nch 快照与活动寄存器。
- 采样率：create/open 时以句柄采样率初始化三槽快照
  （srate := 设备率，与 dev_srate 同值）。

### 2.4 App 接入

- EngineBridge 沿用字符串/布尔参数通道下发 `liveprogmc.*`；
  状态轮询读 `liveprogmc.status` 显示编译结果（与立体声同交互）。
- LiveProg 页加目标切换（立体声脚本 / 多声道脚本）：切换编辑器文档、
  滑块绑定前缀与状态行；两份代码各自持久化（多声道代码独立文档键，
  启用位走参数持久化，与 lp_enable 同机制）。
- 手册（eel_manual_registry）：spl 条目改写为双语境（立体声级
  spl0/spl1、多声道级 spl0..spl7 + 声道映射 + 越界语义），
  smoke_eel_manual 期望表按需同步（函数集不变）。

## 4. 范例脚本（S5 实测对象）

1. **逐声道增益**：slider1..8 分别控 spl0..7 增益（8ch）——断言每声道
   输出 = 输入 × 对应 slider。
2. **环绕填充**：7.1 后环绕 BL/BR = 侧环绕 SL/SR × 0.7 经 256 采样
   延迟（gmem 环形缓冲）——断言延迟与衰减。
3. **中置增强**：5.1/7.1 的 C = C×1.25 + (L+R)×0.1——断言合成值。
4. **LFE 保护**：spl3 一阶低通（状态变量）+ 限幅——断言高频衰减、
   状态跨块连续。

### 6.3 v1 口径差（接受，不在本轮扩围）

1. MC 滑块写值不做立体声那套「代码文本对齐」（声明默认值在代码
   下发时采纳、运行时推参为准）——state.dart 已注释标明；
2. `lpMcCompileMs` 暂无测量来源（isolate 未测 MC 编译耗时），
   状态胶囊在未知时不显示耗时，与立体声未知态同表现；
3. mode0 的 per-channel 输出峰值在本级之前测量（蓝图 §2.3 既定）。
