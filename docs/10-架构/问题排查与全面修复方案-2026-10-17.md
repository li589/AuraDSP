## 2. 深度根因分析与代码定位

### 2.1 插件问题 1：插件无音频流通过 (P1)
1. **VST3 规范状态机返回值误处理**：
   在 `engine/host/host_instances.cpp` 的 `Vst3Instance::process` 中：
   ```cpp
   Steinberg::tresult res = m_processor->process(data);
   if (res != Steinberg::kResultOk) {
       m_bypassed = true; // 严重 BUG：kResultFalse (1) 表示静音或空块，非致命错误！
   }
   ```
   Steinberg VST3 规范明确规定：当插件未产生音频输出、处于空闲尾音或处于某些过渡态时，`process()` 返回 `kResultFalse` (即 `1`)。代码直接把非 `kResultOk` (0) 一律当做错误并置 `m_bypassed = true`，导致插件刚启动走过一个静音块后就被永久旁路！
2. **总线数量为 0 的乐器类/无输入插件拒绝**：
   ```cpp
   int32_t numInBusses = m_component->getBusCount(Steinberg::Vst::kAudio, Steinberg::Vst::kInput);
   if (numInBusses <= 0) numInBusses = 1; // 强行设为 1，但该总线在插件内部并不存在！
   ```
   对乐器插件（如 Zebra2），输入总线数量为 0。强设为 1 并下发 stereo 配置会导致插件在处理输入总线 0 时产生空指针或未定义行为。

### 2.2 插件问题 2：Zebra2 关闭界面卡死并闪退整个 UI (P2)
1. **`IPlugView` 析构生命周期颠倒**：
   在 `engine/host/host_instances.cpp` 的 `detachViewOnPumpThread`：
   ```cpp
   void detachViewOnPumpThread(Steinberg::IPlugView* view) {
       try { view->setFrame(nullptr); } catch (...) {} // 错误！
       try { view->removed(); } catch (...) {}
       try { view->release(); } catch (...) {}
       m_view = nullptr;
   }
   ```
   **VST3 官方规范**：`view->removed()` 必须在 `view->setFrame(nullptr)` 之前调用！u-he 插件（Zebra2, Diva 等）在 `removed()` 内部必须访问 `IPlugFrame` 通知宿主解绑。先传入 `nullptr` 导致 `removed()` 访问空指针，引发硬件级 `0xC0000005 (Access Violation)`！
2. **MSVC SEH 异常穿透**：
   MSVC 默认编译选项下，C++ `try / catch(...)` 不捕获 SEH 结构化异常。子线程抛出 `0xC0000005` 时操作系统直接终结宿主进程（`auradsp_app.exe`），Flutter 窗口瞬间闪退。
3. **窗口过程 re-entrant 悬垂指针**：
   `DestroyWindow(hwnd)` 会同步派发 `WM_DESTROY`。在此之前若未通过 `SetWindowLongPtrW(hwnd, GWLP_USERDATA, 0)` 清零实例指针，可能引发后续消息回调已销毁对象的 UAF 竞态。

### 2.3 UI 占用问题 1：托盘后台 15-19% GPU 占用 (R1)
1. **隐藏状态下 Ticker 与 GPU 光栅化未暂停**：
   Flutter 桌面版在窗口被 `WindowManager.hide()` 或最小化到系统托盘后，引擎渲染管线并不一定自动挂起 CustomPainter。
2. **`AmbientSpectrum` 持续进行离屏 GPU 纹理光栅化**：
   `chrome.dart` 中的 `_AmbientPainter` 每 33~66ms 触发一次 `PictureRecorder` -> `pic.toImage()`。`toImage()` 是昂贵的 GPU 异步光栅化操作，在 Windows D3D11 后端上持续创建/销毁离屏纹理，导致即使看不见窗口，GPU 依然空转达到 15-19%。
3. **音频 Isolate 保持 60Hz 连续向主 UI 发送庞大的 `viz` 消息**。

### 2.4 UI 显示问题 1：延迟测量两套逻辑、刷新旋转图标与始终未测量 (U1)
1. **`engine_probe.cpp` 误杀零延迟组件**：
   ```cpp
   if (first == 0 && baseline == 0) return -3; // 严重 BUG！
   ```
   对于所有逐样本即时处理的 IIR 滤波器、动态 EQ、饱和度、噪声门等组件，其物理算法延迟就是 0 个样本。因为这行逻辑，引擎强制返回 `-3`（不可测），导致 UI 始终显示“未测量”！
2. **两套逻辑冲突（标称 vs 实测）**：
   在 `state.dart` 中，未测前返回固定的标称值（例如 `comp` 标称 `≈85.0 ms`），点击测量后测出 0ms，导致显示突变；
3. **冗余旋转标记**：
   `ComponentLatencyBadge` 内部渲染了一个小旋转图标 `Icons.refresh_rounded`。用户希望移去该图标，但保留点击 Badge 本身触发刷新与呼吸边框动效。

### 2.5 UI 显示问题 2：低音增强滑块自动回到 0 (U2)
1. **参数 ID 错位与回读默认值污染**：
   在 `audio_isolate.dart:606`：
   ```dart
   final bassIntensityRb = AuraDspLib.getFloat(p, h, 'bass.intensity') ?? 0.0;
   ```
   但是 C++ 核心引擎参数表 `kEngineParamTable` 中只有 `'bass.gain'`（范围 0.0~15.0 dB），根本没有 `'bass.intensity'`！
   `getFloat` 查不到该参数恒返回 `null` -> 回读值为 `0.0` -> `audio_isolate` 发送 `params` 事件 -> `state.dart` 执行 `bassIntensity = (raw['bassIntensity'] as num).toDouble();`，将滑块瞬间重置回 0！

### 2.6 UI 显示问题 3：处理链分类繁复，改用统一列表加类别方框标记 (U3)
1. `chain_page.dart` 中使用 6 个折叠大组（`kChainGroups`、`_groupHeader`），破坏了 19 个处理节点的连贯流转与自由拖拽；
2. 用户需求：取消组头折叠，恢复整链平铺拖拽，但在每个节点卡片后增加一个简洁精致的方框徽标（如 `[门控]`、`[音色]`、`[均衡]`、`[空间]` 等），并随主题自适应颜色。

### 2.7 UI 显示问题 4：设置页测试面板丢失与标号清理 (U4)
1. **切片越界遗漏**：
   `settings_page.dart` 中：
   ```dart
   final cats = <List<Widget>>[
     [all[0], all[1]],
     [all[2], all[3], all[4], all[5]],
     [all[6], all[7]],
     [all[8]], // 错误：all[8] 是“09 系统”，而 all[9]（测试音频源）被遗漏！
   ];
   ```
   点击第四个 Tab“测试”时，实际展示了 `all[8]`（系统设置），导致“测试成系统”，440Hz / 白噪 / 文件播放按钮不可见。
2. 各 SectionCard 仍保留 `'01'`, `'02'` 等老旧数字前缀。

## 3. 全面修复实施计划

### 阶段一：插件引擎核心稳定性修复（C++ 宿主）
1. **修复 `host_instances.cpp` 的 `Vst3Instance::process`**：
   - 将 `if (res != Steinberg::kResultOk)` 改为仅在真正的严重错误（`res < 0` 且非 `kResultFalse`）时置旁路。
   - 对无输入总线插件（如纯合成器）做安全的空总线兼容。
2. **修复 `host_instances.cpp` 的 `detachViewOnPumpThread`**：
   - 严格遵循 VST3 规范：先调用 `view->removed()`，再调用 `view->setFrame(nullptr)`，最后 `view->release()`。
   - 使用 SEH 宏 `__try / __except(EXCEPTION_EXECUTE_HANDLER)` 隔离视图清理中的插件级访问冲突。
   - 在 `DestroyWindow` 前先通过 `SetWindowLongPtrW(hwnd, GWLP_USERDATA, 0)` 断开关联。

### 阶段二：算法延迟探针与低音参数闭环修复（C++ & Dart）
1. **修复 `engine_probe.cpp` 零延迟判定**：
   - 移除 `if (first == 0 && baseline == 0) return -3;`。
   - 若 `energy` 与 `base_energy` 有显著区别（说明组件已生效介入计算），`delay = 0` 是真实有效的零算法延迟，正常返回 `0`。
2. **修复低音参数双向绑定**：
   - 在 `audio_isolate.dart` 中，根据 `bassGainVal` 换算：
     `final bassIntensityRb = (bassGainVal / 15.0).clamp(0.0, 1.0);`
   - 在 C++ `engine_param_table.h` 增加 `'bass.intensity'` 映射支持。

### 阶段三：后台资源与托盘 GPU 优化（Flutter & Engine）
1. **托盘状态感知**：
   - 在 `TrayService` 与 `AppModel` 中联动 `isWindowVisible` 状态。
   - 当窗口进入托盘隐藏时：
     - 暂停 `AmbientSpectrum` 的 Ticker 与 `toImage` 重绘；
     - 暂停 UI 侧的电平表与频谱监听；
     - 通知 `audio_isolate` 挂起高频 `viz` 事件下发。
   - 窗口还原时无缝恢复动画与数据流。

### 阶段四：UI 界面与交互重构（Flutter）
1. **优化 `ComponentLatencyBadge`**：
   - 移除内部的 `RotationTransition` 及 `Icons.refresh_rounded` 图标；
   - 保持 Badge 整体可点击，点击时触发 `onRefresh` 与边框发光呼吸动效；
   - 规范化展示口径，消除突兀的估算/实测跳转割裂感。
2. **重构处理链（`chain_page.dart`）**：
   - 移除多级折叠大组（`kChainGroups`、`_groupHeader`）；
   - 采用全量统一拖拽列表；
   - 在每个效果器行后增加规范的分类徽标（如 `[动态]`、`[EQ]`、`[空间]` 等），使用主题色边框与背景。
3. **修复设置页（`settings_page.dart`）**：
   - 修正 `cats` 切片映射，将 `_TestSourceChips` 准确挂载至测试分类面板，恢复 440Hz、粉噪/白噪、WAV/MP3 测试功能；
   - 将“系统”面板正确归入“系统”分类；
   - 移除所有卡片的 `'01'`, `'02'` 等多余编号。
