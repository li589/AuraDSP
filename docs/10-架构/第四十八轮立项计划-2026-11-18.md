## S1 电平表群（A5/C3/D1）——先审计定罪、后修

现象：
- A5（APO，7.1+矩阵+填充）：输入门控输出电平只有
  FL/FR 跟随，SL/SR/BL/BR 行不亮（user 描述 SL 亮时应
  FL/BL/C 同亮而只 FL 亮）；实测输出正常。
- C3（VAIO，矩阵+填充）：主页显示与输出正常，但输入
  门控只显示 FL/FR，「即显示的是关闭声道填充时的状态」。
- D1（多声道，模式未指明）：输入卡依然只显前两声道，
  且**全部**处理链效果器电平表皆然。

已知事实（代码核实 2026-11-18）：
- 本地引擎路径已被冒烟证明正确：矩阵模式下 stage
  12/13 逐声道 == 输入幅值（smoke_mc_channel_levels
  [8]，r47 S5 口径）；emit_viz 对 12/13 按 blkCh 门控。
- APO 宿主侧 ApoEngineHost 遥测写者整表拷贝
  stage_ch_levels（ApoEngineHost.cpp:711-719），Dart 读
  者按 u32[186] 的 channelCount（须 ∈{4,6,8} 且遥测版
  本 u32[1]>=5）展开 stageCh，否则回落 chCount=2 +
  stageCh 恒 -90——**回落一旦触发，全部逐级表只剩
  FL/FR，与 D1/APO 症状同形**。宿主遥测结构布局与
  u32[186] 偏移是否真对齐、宿主帧 channel_count 在矩
  阵模式下的取值，未实证。
- 桥路径（VB/VAIO）经 bridge_manager 的
  stageChLevelsTelemetry()，按桥引擎 FFI 帧的
  channelCount 裁剪列数——帧 channelCount 的真实取
  值未实证（若恒 2 则全表裁成两列）。
- 输入门控采样点在引擎入口（原始输入、填充/上混之
  前）：填充在泵/上混侧把流加宽时，门控 in/out 天然
  看不到被填充声道——C3 的「填充关时状态」与此同形，
  属采样点口径问题、与裁剪问题需分开定罪。
- 矩阵模式下链内级（gate 之外）处理立体声下混，逐级
  表只 FL/FR 是架构事实、不修；**离散模式**下逐级表
  应全宽，D1 是否含离散情形需分开复核（审计项）。

审计动作（定罪前不改代码）：
1. APO：宾机/开发机真机读遥测块原文，核 u32[1] 版本、
   u32[186] 值、f32[195..] stageCh 区与宿主结构布局的
   对齐；核宿主帧 channel_count（矩阵/离散各一）。
2. 桥：给桥 viz 事件加一次性判读（日志/探针），核
   VB 与 VAIO 两桥帧 channelCount 与 stageCh 列宽。
3. 离散复核：本地引擎离散 7.1 下逐级表全宽已被冒烟
   [3] 覆盖（gate 逐声道）；宾机侧离散 D1 情形按 1/2
   的路径结论归因。
4. 填充采样点：确认 VAIO/VB 填充的加宽点（泵 remap /
   引擎 mx_upmix）与门控采样点的相对位置，决定门控
   in/out 的口径（维持入口口径并在 UI 明示，或补一路
   填充后计量）——口径选择在审计结论后请 user 裁定，
   不先斩。

修复随定罪结论落点（引擎 emit / 遥测布局 / 桥帧 /
状态层规范化 / 输入卡回退逻辑），每落点配冒烟或单测。

## S2 A1 一键卸载只卸带叉（user 裁定 2026-11-18）

- 口径定版：亮勾=待附加、暗勾=已附加保持、亮叉=待卸
  载。一键附加仍附全部排队者；**一键卸载改只卸带叉
  （锁定集 ∩ 已附加）者**，未标叉的已附加端点保持。
- 锁定集为空时点一键卸载：不执行卸载，给通知明示先
  标记要卸载的端点（或按钮禁用+提示，二选一在实现时
  按现有交互惯例定）。
- **模式切离的自动卸载（r16）保持全卸口径**：切离
  sysapo 必须全部卸净才能离开，与设置页按钮口径分
  开，注释写明分工。
- sections.dart「回空只经一键卸载」注释与三态说明同
  步改版；chcap 单测扩：一键卸载只卸带叉、未标叉保

## S1/S3 审计结论（2026-11-18，代码核实）

S1：三条路径均无「裁成立体声」的代码缺陷——
- 引擎 emit_viz（engine_viz.cpp:273-297）：stage 12/13
  按 last_block_ch（流全宽）逐声道输出，链内级按
  stage_ch_active（矩阵=2、离散=全宽，engine_chain.cpp
  :1513/:1733）——矩阵链内级只显 FL/FR 是真实作用域。
- APO 遥测：ApoShared.h static_assert 钉死 channelCount
  @字节 744（=Dart 读者 u32[186]）、stageChLevels @780
  （=f32[195]），遥测版本 7≥5；宿主整表拷贝帧
  channel_count/stage_ch_levels（ApoEngineHost.cpp:711
  -719）；Dart 读者展开与事件字段（chCount/chLevels/
  stageCh）齐全。
- 桥：bridge_manager.vizRead 与 isolate 主路径同形
  （chCount=帧 channelCount、stageCh 全表）。
真问题=采样点口径：输入门控 in/out（stage 12/13）采
引擎入口原始流；声道填充在链尾 mx_upmix 由处理后立
体声合成（engine_chain.cpp:1202+，源活动门控），被填
充声道结构上不可能出现在门控表——与 C3「显示的是关
闭填充时的状态」严丝合缝；主页/输出电平采填充后最
终输出（viz_write 走 out），故主页正常。A5 同理。
D1 的离散情形代码上应全宽，须以「离散+真 7.1 源」
单独复测才能定罪，不与矩阵条件混判。
修复口径待 user 裁定：甲=矩阵模式下输入卡 OUT 行改
显最终输出逐声道电平（填充后、与主页同源），离散维
持 stage 13；乙=不改数据、卡上加口径说明小字。
**裁定（user 2026-11-18）：选甲，并扩张为全模式统一
——「不重复造轮子，走一个最好」：OUT 行全模式改用最
终输出逐声道电平（vizChannelLevels 现成数据源，引擎
零改动）；卡片两侧标签随之改名「DSP 输入」/「DSP 输
出」（inputStageIn/Out 文案改版，IN 行仍 stage 12 =
DSP 入口原始流）。离散不再维持 stage 13 特例。**

S3：ASIO 测试接线全链有实现、无静态断点——状态层
source 命令 → isolate 以 bridgeManager.active 取桥
（asiomode 启动成功即 switchTo('asio') 记账）→
srcBridge.testStart → ab_test_start → asio_test_start
（AsioBridge.cpp:601，置 testKind/存文件 PCM）→ 驱动
回调 BridgeSink 以 FillTestSignalN 替换输入进同一 DSP
链（:131-134）。无声更可能在 ASIO 驱动会话/输出路由
层（ASIO 把声音交给外部驱动，VM 内为虚拟驱动，其输
出未路由到可听端点时测试与正常音频同无声）。判别：
ASIO 模式先放正常音频——能出声再点测试仍无声，才回
到注入侧深挖（桥 status JSON 含 testKind 可判读送达
与否）。按 user 预批，测试页在 ASIO 模式加 ? 气泡提
示先查驱动输出路由。
