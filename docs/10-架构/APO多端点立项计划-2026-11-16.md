# APO 多端点（v2）立项计划（2026-11-16）

## 1. 背景与问题（user 实测 2026-11-16）

开发机 speaker（仅立体声）与 VB 输出设备（7.1）同时附加
APO 后：

- 主页声道恒显 2 声道——无论怎样切换声道数量/模式，显示
  都被立体声端点钉死，VB 的 7.1 声道在主页与设置里都无
  从体现；
- 进一步审计坐实更深的问题：现行架构下**第二个端点根本
  没有真处理**（见 §2），只是注册层「附加上了」。

user 同场提出交互与架构要求（原文口径见 §3）：附加目标
列表改复选多选 + 选中跟随；采样率/声道数/声道模式/声道
填充跟选中端点同步；每个引擎的声道配置不得影响其它引
擎；须考虑只支持少数声道的硬件端点、热插拔、设置刷新
与音频服务重启。

## 2. 现状审计（代码定级，2026-11-16）

现行 APO 为 P0（2026-11-10）定的 **v1 单端点**架构，多
端点从未在设计范围内：

- **单引擎座位（全局）**：`ApoShared.h` 明文——seatState
  是全系统唯一座位，同端点 SFX/MFX/EFX 三实例**与多端
  点实例中只有一个跑引擎**，其余透传（seatTaken 计数供
  诊断）。即双端点附加时只有一个端点有 DSP，另一个纯
  透传，只是 user 尚未以听感察觉。
- **单参数块**：`Global\AuraDSP_ApoParams` v2（339 数值
  槽 + 字符串槽，seqlock + valid 位图）。channels.mode /
  channels.upmix_fill 为全局单值，所有端点共用；
  channels.count 例外——`ApoEngineHost` 按实例自身流几
  何强制决议（「流声道是几何真相，压过参数块」），故每
  端点声道数本已独立，独立不了的是模式/填充与回传。
- **单 telemetry 块**：`Global\AuraDSP_ApoTelemetry`
  4096B、v6，仅座位胜者发布；主页声道数/电平/频谱全部
  读它——胜者是哪个端点，主页就显示哪个端点。speaker
  先抢座 → 恒显 2 声道，与 user 实测吻合。
- **APO 实例不知自己服务哪个端点**：`CAuraApo::
  Initialize` 忽略初始化数据；类已实现
  `IAudioSystemEffects`，但端点身份从未被取用。这是多
  端点化的头号未知（§5 尖刺 S0）。
- **附加机制**：apo_config 把我方 CLSID 写入端点
  FxProperties 的三槽关联（注册层），端点级注册本就多
  端点无碍；App 侧状态 apoAttached / apoAnyAttached /
  apoAttachedName 与设置页的端点下拉 + 附加按钮为单选
  形态。

## 3. 交互规格（业主原文口径，后续实现不得走样）

- 附加目标端点列表：**左侧复选框、右侧名称**。复选框
  点击可多选且列表不自动收回；**名称区域点击进入「选
  中」状态**（单选高亮）。
- **「一键附加」为所有复选中的设备逐一附加 APO**。
- 列表下方的**采样率、声道数量、声道模式、声道填充**
  与**选中端点**同步设置/显示。
- 每个引擎不能影响其它引擎的声道配置。
- 须处理：硬件插拔、设置刷新、音频服务重启。
- 只支持少数声道的硬件端点必须有明确口径（§4.5）。

## 4. 方案设计

### 4.1 总原则

- 分歧只收敛在**声道族**（mode / upmix_fill 的端点级覆
  写 + count / rate 的端点级回传与显示）；其余 DSP 参
  数（EQ、效果链等）保持全局单值——全端点同声是预期
  语义，不在本立项扩张范围（若业主要求全参数按端点，
  另立项）。
- 端点身份以 MMDevice 端点 id 为准；共享块内只存其
  64 位 FNV-1a 哈希（UTF-16LE 字节流），telemetry 槽
  内回带完整 id 供 App 校验，杜绝哈希碰撞串扰。

### 4.2 端点身份与声道覆写通道（推荐：FX 属性存储）

每端点在注册表已有自己的 FxProperties 属性存储（附加
机制的操作对象）。方案：

- App 在附加时把两样东西写入该端点的 FX 存储自定义
  值：**端点 id 令牌**（自证身份）与**声道覆写**
  （channels.mode / upmix_fill，含 valid 标记）。
- APO 实例在 LockForProcess 时从**自身端点的**属性存
  储（IAudioSystemEffects 初始化给的
  pAPOEndpointProperties）读这两项：身份天然对应、零
  猜测；覆写只影响本实例的引擎。
- 优点：配置随端点注册信息走——音频服务重启、App 不
  在场、端点拔插，覆写都不丢、不串；不需要参数块升
  版。缺点：依赖 FX 存储自定义值的读写权限与 ACL 现
  状（doctor --fix 曾处理过 ACL 拒绝问题，尖刺须验
  证普通附加流程下可写）。
- 备选（尖刺失败时回退）：参数块升 v3，尾部追加覆写
  表（≤8 条 {idHash u64, mode, fill, valid}），实例按
  自身 id 哈希查表——但实例取 id 的问题仍需先解，故
  备选不豁免 S0 的身份部分（令牌路线可与之组合：身
  份走 FX 存储、覆写走参数块）。

### 4.3 座位与处理：按端点分座

- 座位语义收窄为**端点内**：同端点的 SFX/MFX/EFX 三
  实例仍只许一个跑引擎（防同流重复处理），不同端点
  各自选座、各自真处理。
- 实现：座位状态从全局单块拆出——随 §4.4 的端点级
  telemetry 块各自携带 seatState（块本身按端点命名，
  CAS 域天然隔离）；stale 回收沿用既有心跳口径，逐块
  独立。

### 4.4 Telemetry：按端点分块

- 新名 `Global\AuraDSP_ApoTelemetry_<idHash16>`（每附
  加端点一块，布局沿 v6 结构 + 头部回带完整端点 id
  字符串 + version 升 v7 标识多端点代）。
- App 按当前附加集合逐块打开读取；主页 viz 跟随
  **选中端点**的块；选中端点无块（未附加/已拔）时回
  落到任一已附加端点并在 UI 明示，主页不假死。
- 旧全局块在过渡期由「第一个选座成功端点」继续发布
  （兼容旧 App 读法），新 App 只读分块；过渡期长度与
  旧块退役时点在计划评审时定（默认：本立项收口时退
  役，安装器同批换 DLL+App，无跨版混跑承诺——与
  v1→v2 参数块的同批替换先例一致）。

### 4.5 少数声道硬件的口径

- count / rate 恒为端点流几何（只读跟随显示），不可
  跨端点套用——speaker 是 2 声道就只显 2 声道，这本
  身不是缺陷，缺陷只是它污染了别的端点的显示与设
  置。v2 后各端点各显各的。
- 选中端点声道数 < 4 时，声道模式/声道填充控件按无
  效化收敛（置灰 + 说明「该端点声道数不足」）：2 声
  道下 mode/fill 本无作用，避免重演「切了没反应」。
- 端点格式变更（端点被系统改成立体声↔7.1）时，其引
  擎在下一次 LockForProcess 按新几何重决议 count，
  覆写的 mode/fill 继续有效；App 侧经设备看守刷新显
  示（§4.6）。

### 4.6 App 侧改造

- 设置页附加区按 §3 重做：复选列表（复选态 = 期望附
  加集合）、名称点击选中（选中端点 id 入
  session_state）、一键附加逐个执行既有附加路径并汇
  总成败、逐行显示每端点真实附加态（注册实查，非乐
  观置位）。
- 声道族控件绑定选中端点：读其 telemetry（count /
  rate / eff mode / eff fill）显示生效值；改 mode /
  fill 写该端点的 FX 覆写（§4.2），不再写全局参数块
  的 channels.* ——参数块中 channels.mode/fill 自此只
  作「未覆写端点的默认」。
- 持久化：端点声道覆写的**期望值**入 config.json 新
  键（map: 端点 id → {mode, fill}），同提交登记
  config_and_presets_test sentinel；FX 存储是运行时真
  相、config 是 App 侧期望账本，两者由附加/对账流程
  收敛（FX 写失败时以账本重试并报错，不静默）。
- 主页：viz 数据源从单块改选中端点块（§4.4 回落规
  则）；模式级状态行显示选中端点名 + 其声道数。
- 热插拔/刷新：复用既有 4 秒设备签名看守——端点集合
  变化即重查附加态与 telemetry 块清单；选中端点消失
  → 按 §4.4 回落并更新选中；新端点出现 → 进列表未复
  选态，不自动附加。
- 音频服务重启：audiodg 重启后 APO 实例重建、重读
  FX 覆写、重选座；App 侧 telemetry seq 停滞的既有
  stale/落零逻辑逐端点适用；App 不在场时各端点处理
  不中断（与现行 APO 口径一致）。

### 4.7 不做什么（非目标）

- 不做全参数按端点（EQ/效果链仍全局）。
- 不做端点级插件链差异（插件块维持全局；Part III 浮
  条事项不并入本立项）。
- 不动 VAIO/VB/ASIO 管线模式（本立项只及 sysapo 附
  加范式）。

## 5. 关键未知与尖刺（S0，先于一切实现）

1. **APO 取自身端点身份**：IAudioSystemEffects::
   Initialize 的 APOInitSystemEffects 中
   pAPOEndpointProperties 是否为本端点 FX 存储、能否
   读到 App 写入的自定义值（含 id 令牌）。验证法：
   apo 侧探针构建 + apo_config 写值 + 开发机双端点实
   测读回。
2. **FX 存储自定义值可写性**：普通附加流程（现有提权
   路径）下写自定义值的权限与 ACL 现状；与既有三槽关
   联键共存不互相覆盖。
3. **双端点同时选座**：两端点 audiodg 流并发
   LockForProcess 时，分块座位 CAS 无跨端点干扰；同
   时跑两个引擎实例的 CPU/内存占用量级（开发机实
   测）。
4. **telemetry 分块生命周期**：块由 APO 侧创建/打开
   的命名与残留——端点拔除后块随句柄关闭消失，App
   读侧须容忍块不存在/半初始化（magic/version 校验
   沿现行）。

S0 产出：探针实测记录 + §4.2 推荐/备选的最终裁定，
回填本计划书附记后再进 S1。

## 7. 验证矩阵（S3 验收，全过才收口）

场景 = 开发机 speaker（2ch）+ VB 输出（7.1）双附加
（user 原始复现场景），逐项：

1. 两端点同时有真处理（各自喂声、电平/频谱各自回
  传，不再一真一透传）；
2. 主页跟随选中端点：选 VB 显 8 声道、选 speaker 显
  2 声道，切换即时生效；
3. 声道配置隔离：VB 设离散、speaker 设矩阵+填充开
  ——互不串扰（两端 telemetry eff 回读各自核对）；
4. speaker 选中时 mode/fill 控件按 §4.5 收敛；
5. 拔 VB（停用/卸载端点）→ 列表与主页按规则回落，
  speaker 处理不中断；插回 → 配置恢复（FX 覆写仍
  在）；
6. 重启音频服务（audiosrv/audiodg）→ 两端点自恢复
  处理与覆写，App 显示自收敛；
7. App 关闭期间两端点处理持续（APO 既有口径回归）；
8. 一键附加：双复选一次点击两端点逐一附加成功，单
  个失败不连带回滚另一个且有明示。

## 8. 风险与回滚

- 最大风险在 S0-1/2（平台机制不确定性）：若 FX 路线
  不通，回退参数块 v3 覆写表 + 身份令牌组合（§4.2
  备选），UI 与 App 侧设计不变。
- 版本过渡：DLL 与 App 同批替换（安装器原子性沿现
  行）；升级瞬间旧 APO 对新参数块的拒绝面仅在「覆
  写走参数块备选路线」时存在，FX 路线无此面。
- 回滚：本立项全部改动以轮次提交为界，任一期失败可
  整轮回退到 v1 单端点行为（双端点退化为现状，不劣
  化单端点主路径——单端点全量回归是每期门禁）。

## 9. 待业主裁定点（评审时确认）

1. §4.1 范围口径：分歧只限声道族、其余参数全局——
  是否符合预期；
2. §4.4 过渡期旧全局 telemetry 块的退役时点（默认
  收口退役）；
3. 选中端点消失时的主页回落规则（默认：回落任一已
  附加端点并明示）。

## 附记（2026-11-16 晚，第四十一轮 S0 尖刺结果）

S0 尖刺已在开发机实测完成（探针 APO + apo_config probe-fx 写入），四问结论：

1. **FX 属性集可写可读（核心假设成立）**：apo_config 经生产同路
   `OpenFxKeyWritable`（含 ACL 接管修复）把自定义属性集
   {A5C3D21E-9B47-4F1A-8E6D-2F5B7C904E31} 的 pid2 令牌（REG_SZ）/
   pid3 mode / pid4 fill / pid5 flags（REG_DWORD）写进端点
   FxProperties；APO 在 `IAudioProcessingObject::Initialize` 收到
   `APOInitSystemEffects` 后读回。**关键定案：值挂在
   `pAPOSystemEffectsProperties`（系统效果存储），不是
   `pAPOEndpointProperties`**（后者为端点设备属性存储，实测 76
   个设备键、不含 FX 值）——S1 读取顺序以系统效果存储为准。
2. **身份逐端点正确**：Voicemeeter AUX 端点 8 个以上实例
   （SFX/MFX/EFX）在多次音频服务重启后均读到自身端点 id 与自身
   覆写（mode=1/fill=1），无串扰。类型与预期一致（VT_LPWSTR /
   VT_UI4）。
3. **实例化时机**：有持续流的端点（Voicemeeter 引擎常驻）在音
   频服务启动时即被实例化；无流端点在首个流创建时实例化。
   Initialize 的 cbSize 形状校验可挡发现期/异形初始化数据。
4. **未覆盖项**：扬声器（USB）端点在尖刺内未能被测试工具触发
   流（FriendlyName 与另一 USB 端点同名、端点显示名含中文无法
   经 ANSI argv 传递；tone_play 已加端点 id 片段匹配但该端点仍
   未命中，原因待查）——机制与端点无关（同一 DLL/代码路径/存
   储布局，VB 侧已全证），留 S3 以真实播放覆盖。

尖刺后开发机已复原：两端点已卸载、属性集已清除、装机 APO 已
换回原构建（233FA27E）。S1 按 §4 推荐方案开工（三裁定已由
user 2026-11-16 批准均按默认）。
