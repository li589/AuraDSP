# 第四十四轮立项计划（2026-11-17）

来源：user 2026-11-17 晚下达两件事——① 代码审查其余声
道模式是否正常且一致（WASAPI 与 APO 附加应走
min{设置声道， 目标声卡声道}；VAIO 已支持 7.1）；② 设
置 UI 改进（音频卡片重构、系统卡片延迟同源与 OS 显示、
测试卡片功能完整化）。同日晚 user 已验收 r43 并自测
7.1 下 APO/VB/VAIO 三模式矩阵下混、声道填充开关、离散
逐声道模式全部 OK。本计划经 user 批准后分段开工。

## 现状盘点（代码实查，2026-11-17）

### 声道钳制
- 钳制纯函数 `clampChannelsToCapability(want, cap)` 在
  `lib/engine/local_channel_policy.dart`（合法集
  {2,4,6,8}），isolate 以 `capabilityCh` 为能力源在下发
  `channels.count` 时统一钳制（audio_isolate.dart:366/889）。
- `capabilityCh` 默认 8，仅由状态层 `chcap` 命令更新，
  而状态层只从**选中 APO 端点**取声道数下发
  （state_audio_modes.dart:1256）——即 sysapo 路径已接
  （r42 S1b）；**WASAPI 本地路径未接**：isolate 内部其实
  知道输出设备声道（audio_isolate.dart:2348 上报
  deviceCh），但未回填 capabilityCh，WASAPI 选了立体声
  设备又设 7.1 时引擎仍按 8 声道跑。VB/ASIO 桥路径的
  能力来源待逐一核（桥 io 声道）。VAIO 驱动原生 7.1，
  cap=8 与现状一致。
- 矩阵/离散/填充语义在引擎单点（channels.mode /
  upmix_fill），各模式共用同一参数路径——一致性风险只
  在「生效声道数」一处，即钳制接线。

### 音频页结构
- `settings_audio_tab.dart`：处理范式 / 设备 / 采样率 /
  声道数量 / 声道模式 五段。「设备」卡 =
  `_DynamicAudioPanel`（sections.dart）：先驱动层
  （`_DriverLayer`，hardware_drivers.dart：驱动块组 + OS
  行 + 引擎生效值块），后按范式出附加面板（APO 端点 /
  VB 面板）或管线输入层 + 输出层。
- VAIO 指引文案 `ioVaioGuide`（「请在系统声音设置或播
  放器中…」）现位于输出层末行；「已处理帧」计数在输出
  层 VAIO 模式展示、随 UI 高频刷新、无极值格式化。
- WASAPI 块小字现状两处：hardware_drivers.dart:683
  `ABI v·版本·采样率Hz`（本地块）；sections.dart:165 为
  Linux 块 `ABI v·版本`。
- 引擎生效值块（hardware_drivers.dart:144 起）：可展开
  块、逐行长句文案，位于驱动层末尾、OS 行之下。
- 声道模式卡内 sysapo 时另有一行「引擎实际生效：…」
  （apoChannelsActual），与引擎生效值块重复。

### 系统页与延迟
- 系统页 `settings_system_tab.dart`：引擎卡
  （`_EngineInfo`，vb_theme.dart：状态/模式/采样率/延迟
  /ABI 五行）/ 会话与配置 / 系统（托盘开关 + 一行解释、
  自启开关 + 一行解释、卡头 hint 一句）。
- **延迟不同源实锤**：`model.latencyMs` 有两个写入方——
  isolate 状态事件（state_events.dart:92/813，音频路径
  上报的延迟）与 `updateFullChainMeasuredLatency`
  （state_events.dart:1641，把 `fullChainLatencyMs` 算法
  链延迟总和覆写同一字段）。系统卡延迟行读 latencyMs，
  显示值取决于最后到达的事件是哪一类，口径漂移。
  `fullChainLatencyMs` 本身是核心效果 + 插件槽的算法延
  迟求和（实测脉冲值优先），不含设备缓冲；链页频谱卡
  的 total/core/plugin 读同一族，口径自洽但与系统卡混用
  一个字段是问题根源。
- OS 串：`PlatformProfile.osVersion` 直用 Dart
  `Platform.operatingSystemVersion`，Windows 上原样带引
  号与英文括号格式（`"Windows 10 IoT …" 10.0 (Build
  19044)`），无清洗。

### 测试页与测试源
- 测试页 `settings_test_tab.dart` 现仅一张「测试音频
  源」卡（`_TestSourceChips`）；同一组 chips 还出现在音
  频页输出层（hardware_io_output.dart:521 一带）——两处
  入口操作同一状态（sourceKind: ''/tone/pink/file）。
- 发生器能力：本地路径 isolate 内 `ToneSource(440)`
  （正弦、频率写死 440）、`PinkSource`、`FileSource`
  （wav/mp3 解码后播放）；桥路径 `testStart(kind)`：
  1=正弦 440、2=粉噪、3=文件 PCM 注入。方波/三角/变频
  /扫频两侧均无。
- FileSource 的播放位置目前不回传 UI（无进度事件），
  桥文件注入是一次性 PCM 播放（无暂停/定位原语）。

## 分段计划

### S1 声道钳制一致性（审查 + 修复）
- 逐模式核能力来源并接线：sysapo 已接（复核）；WASAPI
  本地路径在设备启动/切换时以实际设备声道回填
  capabilityCh；VB 桥以桥 io 声道为 cap；ASIO 以驱动通
  道数为 cap；VAIO 保持 8。Linux PA/ALSA 输出同理核
  sink 声道并接（或登记差异）。
- 验收口径：每模式下 effCh == clamp(设置， 设备)；引擎
  回读（enginevalues/telemetry）与显示合成口径一致。
- 测试：local_channel_policy 既有单测扩模式矩阵用例；
  开发机实测——WASAPI 立体声设备 + 设 7.1 → 引擎回读
  2；VB 8ch → 8；VAIO 7.1 保持。

### S2 音频页重构
卡片顺序：处理范式（不变）→ **I/O 配置** → 采样率 →
**声道**（数量 + 模式合并一卡）→ **驱动**（置最后）。
- I/O 配置卡：管线范式 = 输入层 + 输出层；附加范式 =
  APO 端点面板 / VB 面板（即现「设备」卡的范式面板部
  分）；Linux = sink/source 行部分。卡内只保留输入/输
  出配置本体，驱动层整体移出。
- VAIO 指引：文案简化为一句（选 AuraVAIO 为默认输出
  之意），移入输入层「音频输入」标题旁 InfoBadge 气泡；
  输出层不再有该行。
- 已处理帧（VAIO 输出）：刷新节流到 1s（独立 ticker，
  不随 viz/心跳）；数值格式化加千分位，超大时单位进位
  （万/亿帧），不撑版式。
- 声道合并卡：数量分段 + 模式分段 + 填充开关同卡；
  sysapo 的「引擎实际生效：…」行删除（驱动卡引擎生效
  值已覆盖）；其余 hint 口径保留。
- 驱动卡：`_DriverLayer` 整体迁出独立成卡（含 Linux
  驱动块）；OS 行移除（S3 接走）；WASAPI/本地块小字只
  保留 `ABI v2`（去版本与采样率）；引擎生效值块做视
  觉与文案收口——短标签 + 两列信息行、删解释性长句，
  只报事实值（声道模式/填充/声道数/采样率等回读项）。
- l10n 三语同步改/加字符串（走 ARB → gen 流程）；设
  置页版式契约测试（F5 组）同步更新。

### S3 系统页（延迟同源 + OS 显示 + 去废话）
- 延迟定源：`latencyMs` 只许 isolate 路径上报写入（端
  到端、含缓冲），摘除 measured 覆写对该字段的写入；
  系统卡「延迟」行即此值（诚实口径，标签可注「端到
  端」）。`fullChainLatencyMs` 族保留在链页，标签明确
  为链路（算法）延迟，不再与系统卡混名。盘点
  LatencyPresenter 全部使用点并逐一归口径（本段内列
  清单入收口文）。
- OS 显示移入引擎卡（新增「操作系统」行，位于 ABI 行
  后）；平台层提供清洗后的 OS 串：Windows 走平台实现
  拼装（注册表 ProductName + DisplayVersion +
  CurrentBuildNumber，形如 `Windows 10 IoT Enterprise
  LTSC 2021 21H2 (Build 19044)`，无引号）；Linux 取
  os-release PRETTY_NAME；其它平台回退清洗 Dart 串
  （去引号）。音频页两处 OS 行（Win 驱动层、Linux 面
  板）删除。
- 系统卡去废话：删托盘开关下解释行、自启开关下解释
  行，卡头 hint 缩为最短或去掉（标题自明）。

### S4 测试页三段化
测试页重构为三卡；音频页输出层的旧测试 chips 移除。
- **波形生成**：波形分段（正弦/方波/三角/粉噪）；频
  率：对数滑杆 20–20000 Hz + 数值输入（0–20000，低于
  20 按 20 执行）；扫频开关：对数扫 20→20000、20 秒
  循环（时长固定值，见裁定点）。发生器泛化：本地
  Dart 源改相位连续的通用波形源（波形/频率/扫频可热
  改）；桥侧扩展 testStart 参数（波形/频率/扫频）到
  共享桥核生成器；Linux 本地源同构泛化。各模式的测
  试源路由保持现状（本地/桥注入路径不变）。
- **使用源测试**：单按钮「打开音频」（文件选择限
  wav/mp3）；未选时左侧显「未选择测试音频源」；选中
  后左侧换为播放/暂停钮 + 可拖进度条（不显时间），
  右侧仍「打开音频」可替换。本地 FileSource 增位置/
  总时长回传（节流事件）与定位/暂停命令；桥文件注
  入的暂停/定位以停 + 按偏移重注入实现（口径入收口
  文）。
- **互斥**：波形与文件源共用唯一 sourceKind 槽——启
  动任一即停另一（状态层单点裁决，UI 两卡选中态互
  斥呈现）；停止回主源的既有语义不变。
- **调试**：占位卡 + 「调试模式」开关一个，绑定既有
  调试图层/详细日志开关（实现时以现存 debug 旗为准
  接线，无则新增 config.debugMode 并门控 isolate 调
  试日志）。

### S5 平台适配与收口
- Linux 全量适配复核（S2 卡片拆分在 Linux 面板的落
  点、S3 OS 串、S4 本地源泛化在 audio_isolate_linux
  的同构实现）。
- 全量门：开发机根构建 + 冒烟全量 + Dart 全量（本轮
  Dart 改动面大，按收口纪律跑全量并区分竞争 flaky）；
  宾机抽验（音频页新版式、声道合并卡、测试页扫频与
  文件播放、系统卡延迟/OS 行）。
- 四件打包投宾机 + 收口文 + 未决登记附记。

## 裁定点（已按推荐口径写入计划，可改）
1. 扫频：20 秒对数循环固定（不做时长选择器）。
2. 系统卡延迟：以端到端路径延迟为唯一「延迟」行；
   算法链延迟只留在链页并改名分口径。
3. 频率下限：滑杆 20 Hz 起（0 Hz 为直流无声学意义），
   数值输入允许键入 0–20000、执行钳到 20。
4. 调试模式开关：只接既有调试设施，不新增调试功能
   本体（占位卡语义）。

## 不做
- 不动处理范式卡与采样率卡的逻辑（采样率仅随卡片顺
  序迁移位置）。
- 不改引擎声道语义与参数（S1 只接钳制线）。
- 不做频响测量/绘图（扫频只发声，不采集分析）。
