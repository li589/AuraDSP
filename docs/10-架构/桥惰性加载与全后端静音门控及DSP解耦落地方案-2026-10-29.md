# 桥惰性加载 + 全后端静音门控 + DSP↔桥解耦 落地方案

- 日期：2026-10-29
- 状态：**P1–P5 已全部落地**（同日实现 + 门禁 + 实机验证，见 §8 落地记录）
- 关联：`Windows通用底层音频驱动与四模式架构方案-2026-10-13.md`、`插件模块深度改良方案-2026-10-12.md`
- 动机实测（2026-10-29，本机）：Release 含三桥 DLL 且 VM（Voicemeeter Potato）监听活跃、无音乐时 = **1143MB WS / 2432MB Priv / 120 线程 / 15.3% CPU**；移出三桥 DLL 后 = **331MB / 0.2%**。桥活跃本身是正确行为（用户后端即 VM），空闲 CPU 的主源是 **DSP 对静音输入仍全速处理**（卷积/EQ/8 总线组插件槽每个 RT 回调都跑）。

## 0. 总目标

1. **全桥惰性加载**：所有桥（VM/ASIO/VAIO 及未来各平台桥）统一为「用到哪个后端才启用哪个」，配专门的管理组件收敛生命周期。
2. **全后端静音门控**：对静音输入降载/跳过处理，信号回来同块内平滑恢复；本地引擎与三桥全部覆盖。
3. **DSP↔桥解耦**：收敛出统一桥契约，DSP 引擎不感知桥；以后所有平台的新后端开发都走同一契约。

约束：除非明显降耗，不改任何行为/UX；每阶段独立可回滚；Dart 改动过 `flutter analyze` + 相关测试；C++ 改动可编译 + smoke 验证。

## 1. 现状勘察（代码事实）

### 1.1 桥加载路径（Dart 侧已是「半惰性」）

| 桥 | Dart 绑定 | `load()` 策略 |
|---|---|---|
| VM | `app/auradsp_app/lib/engine/audio_vbridge.dart` | `static _cached` + `??=`；候选 `auravm_bridge.dll` → `engine\…` → 环境变量 `AURADSP_VB_BRIDGE_DLL`；`BridgePluginFfi.assertBridgeAbi` 协商 ABI |
| ASIO | `app/auradsp_app/lib/engine/audio_abridge.dart` | 同上结构 |
| VAIO | `app/auradsp_app/lib/engine/audio_vaio_bridge.dart` | 同上结构 |

- `audio_isolate.dart` 中三个 start 入口（`startVbBridge` L324 / `startAsioBridge` L475 / `startVaioBridge` L617）均为 `??= XxxBridge.load()`：**首次启用才 `DynamicLibrary.open`**。启动时经 `state_audio_modes.dart`（L52/61/74）恢复持久化后端模式，只恢复一个。
- **缺口**：① `detect`（`detectAsioDrivers` L442 / `detectVaio` L606）也会 `load()` 且**永久驻留**，无任何卸载路径；② 三桥绑定文件、isolate 里 start/stop/镜像回放/互斥切换逻辑**三份复制粘贴**；③ 互斥切换散落在命令 case（`vbmode` L1379 手动 `stopAsioBridge(); stopVaioBridge();` 等），未收敛。

### 1.2 泵循环与 viz（`audio_isolate.dart` L2199–2549）

- 自适应泵间隔（L2208–2215）：桥模式 10ms（只拉 viz + 1s 一次状态）；WASAPI+有源 5ms；无源 20ms。
- 桥 viz 拉取带 stale 检测：null 帧持续 1.5s 补一帧全零（`sendStaleViz` L2180）。
- 本地 WASAPI 路径：每轮 `lib!.process(handle!, …)`（L2430/2440/2464 等）→ **静音也全速跑引擎**；viz 按 `vizIntervalMs` 节流。

### 1.3 引擎 RT 入口（`engine/auradsp_engine.cpp`）

- `auradsp_process()` L264：`ScopedFtzDazGuard` → state 机 → 输入门增益 → **已逐块计算输入峰值**（多声道 `pk_in_ch[]` L295-313；stereo `pk_in_l/r` L380-401 → `input_lvl_in_*` L400-401）→ 效果链 → `emit_viz(h)`（L366/412）。
- 门控挂点天然存在：峰值已经算出来了，无需新增扫描。

### 1.4 桥 C++ 侧（VM 桥为代表）

- `core/desktop/windows-drivers/bridge/vm_bridge/VmBridge.cpp`（1485 行）：VBVMR_Login、RT 回调泵、8 组独立引擎（`PumpCtx::kMaxGroups`，每 8 声道一组）、Z17 组间并行 worker 池（`AURA_VM_PARALLEL=0` 退串行）、Z12 超预算自动保护（`g_autoProtect`/`ProtectTick`）、插件后台加载（`GroupLoadWorker`）。
- RT 回调里**每组引擎每回调都 `process`**，静音也不例外——空闲 15% CPU 的主源。
- `bridge/common/PluginBridge.h`（270 行）：三桥共用插件槽转发 `Fns` 表（18 个函数指针）+ `Resolve(HMODULE)` 从引擎 DLL 解析 + 桥内配置 Mirror 回放（`VmBridge.cpp` `g_mirrorN`/`StrMirrorReplay`）——**DSP↔桥解耦的现有雏形**。
- 三桥导出面：`vb_*` / `asio_*` / `vaio_*` 前缀，语义同构（detect/start/stop/status/set_param/viz_read/test_start/test_stop/bypass/…）但各自定义、各自拼名。

### 1.5 已具备的解耦事实

- 参数路由：Dart isolate `paramMirror`/`paramStrMirror` → 活跃桥 `setParam` → 桥内引擎 handle；DSP 引擎从不感知桥存在。
- 插件控制面：`BridgePluginFfi`（Dart）↔ `PluginBridge.h`（C++），前缀无关函数指针表。
- ABI 协商：`assertBridgeAbi` 已存在（待升级为双向协商）。

## 2. 方案一：全桥惰性加载 + BridgeManager

### 2.1 新组件 `BridgeManager`（音频 isolate 内）

新文件 `app/auradsp_app/lib/engine/bridge_manager.dart`：

- **注册表**：`BridgeDesc { id, displayName, dllName, envVar, prefix }`，内置 vm/asio/vaio 三项；未来平台（Linux/Android/…）只加注册项。
- **生命周期**：`acquire(id)`（`load()` 委托给 manager，缓存计数）/ `release(id)`；`switchTo(id, …)` 收敛互斥切换——内部完成 D4-a `runHandover`（停旧确认→起新→失败回滚），isolate 命令 case 从「手动停另外两个 + start」改为一次 `bridgeManager.switchTo` 调用。
- **镜像回放收敛**：`paramMirror`/`paramStrMirror` 回放 + `setBypass` 同步 + `replayPluginMirrorToBridge` 三桥各一份的复制粘贴 → manager 统一实现，桥仅暴露契约接口（见 §4）。
- **卸载策略**：
  - 默认：stop 后 DLL **驻留不 FreeLibrary**——桥持有第三方 DLL（如 `VoicemeeterRemote64.dll`）引用，反复 dlopen/dlclose 第三方库有崩坏风险；驻留成本只是 DLL 映射，无 RT 线程、无登录会话，代价可接受。
  - `detect` 场景：探测只 load + 查询，不 start；不新增驻留之外的代价。
  - 实验开关：`AURADSP_BRIDGE_UNLOAD=1` 时 stop 后尝试 FreeLibrary（默认关，验证第三方 DLL 稳定性后再议）。
- **「使用什么引擎就启用哪个引擎」**：启动只恢复持久化的那一个后端（现状已如此，保留）；未选中的桥全程不 `load()`。

### 2.2 改动范围（P1 阶段）

- 新增 `bridge_manager.dart`；三桥绑定文件收敛为薄壳（保留类与方法签名，内部委托）。
- `audio_isolate.dart`：`vbActive/ab/vaio` 等散落状态迁入 manager；三个 start/stop 函数体收敛。
- 行为不变式：D4-a 语义、事件名（`vbstatus`/`asiostatus`/`vaiostatus`）、`source = null` 时机、`syncPluginMirrorToLocal` 时机全部保持。

## 3. 方案二：全后端静音门控

三层挂点，全部后端（本地引擎 + 三桥）同一语义。

### 3.1 状态机（所有后端统一）

```
ACTIVE ──(输入峰值 < 阈值 持续 holdMs，且引擎输出峰值 < -120dB)──▶ GATED
GATED  ──(本块任意采样 |x| ≥ 阈值)──────────────────────────────▶ ACTIVE（同块即时恢复）
```

- **阈值**：默认 -90 dBFS（线性 ≈ 3.16e-5）。环境变量 `AURADSP_GATE_DB` 可覆写（防极低电平音乐被误门）。
- **hold**：默认 2000ms。仅统计「输入静音时长」，不单独决定进入——
- **进入双条件**：输入静音 ≥ holdMs **且** 引擎输出峰值 < -120dB。输出条件保证长混响尾音（freeverb 长 decay）自然衰完，**不被截断**。
- **退出即时**：GATED 下本块检测到非零输入，**同一块内**恢复全链处理，0 块延迟、无 fade-in——静音时输出本为 0，即时恢复不会爆音；onset 音头一个采样都不丢。

### 3.2 引擎层（`auradsp_engine.cpp`，P2）

- 挂点：`auradsp_process()` L264 起。输入峰值现成（stereo `pk_in_l/r`；MC `pk_in_ch[]`），输出峰值 viz 侧已有（stage/out levels）。
- GATED 行为：跳过整条效果链；输出写零（memcpy 0，含 MC scratch）；`input_lvl_in/out_*` 置 -120；`emit_viz` 照常（电平帧继续出，UI 表针归零）；状态机/参数原子照常可读（门控只影响音频计算，不影响控制面）。
- `bypass` 路径天然零开销，不涉及。
- 新增导出（可选，供桥与诊断读）：`auradsp_get_gate_state(h)` → 0/1 + 静音时长；或并入现有 status json。**先走 status json，不加 ABI**。

### 3.3 桥层（VM/ASIO/VAIO，P3）

- 新建 `bridge/common/SilenceGate.h`：无状态逐块峰值扫描 + 上述状态机（组级独立实例）。
- **VM 桥**：RT 回调内每组（8 组各自门控）：输入块扫描 → GATED 则跳过该组引擎 `process` 与插件槽 process，输出 memset 零；8 组全 GATED 时 Z17 并行池自然无任务可派。组级独立意味着「只有 Strip 3 有信号」时其余 7 组零消耗。
- **ASIO / VAIO 桥**：回调入口同一 `SilenceGate.h`，单组语义（组=整个 io 块）。
- **必须 memset 输出**：VB 总线/ASIO 输出缓冲残留旧数据会变成嗡嗡声。
- 与 Z12 超预算保护**正交**：Z12 是过载降质，门控是无输入跳过；文档与代码注释注明互不替代。
- viz：GATED 期间 `viz_read` 仍返回帧（电平 -120），Dart stale 机制（§1.2）兜底；status json 增加 `gated`/`idleMs` 字段（向后兼容，旧 UI 忽略新键）。

### 3.4 Dart 泵层（P4）

- 桥模式泵间隔现 10ms；读 status 见 `gated=1` 且持续 → 升到 50ms（viz 拉取仍按 `vizIntervalMs` 节流，不受泵间隔影响——viz 是按需读）。信号回来（`gated=0`）下轮即回落 10ms。
- 本地 WASAPI 路径无需改：`source==null` 已 20ms；引擎门控后 `process` 本身开销 ≈ 0。

### 3.5 验收指标

| 场景 | 现状 | 目标 |
|---|---|---|
| VM 活跃 + 无音乐（用户常态） | 15.3% CPU | **< 2%** |
| 本地 WASAPI + 无源 | ≈0.2% | 持平（门控兜底有人喂静音源的场景） |
| 音乐播放中 | 基线 | **不退化**（±0.5% 内） |
| onset 延迟 | 0 | 0（断言：静音后第一块非零输入 → 同块输出非零） |
| 混响尾音 | 完整 | 完整（断言：尾音期间不进入 GATED，或进入时输出已 < -120dB） |

## 4. 方案三：DSP↔桥解耦（统一桥契约）

### 4.1 目标契约 `aurabridge.h`（C ABI，版本化）

三桥导出收敛为统一 `ab_*` 前缀（语义即现有同构面）：

| 域 | 函数 | 现状映射 |
|---|---|---|
| 生命周期 | `ab_detect / ab_start / ab_stop / ab_status(json)` | `vb_detect…` / `asio_…` / `vaio_…` |
| 参数 | `ab_set_param / ab_set_param_str / ab_get_param / ab_get_param_str` | 各前缀同款 |
| 音频面 | `ab_viz_read / ab_bypass / ab_test_start / ab_test_stop` | 各前缀同款 |
| 能力 | `ab_capabilities`（json：busMask/pluginGroups/autoProtect/driverList/endpoints/gating） | 现散落 status 扩展键 |
| 插件面 | 复用 `PluginBridge.h` Fns 表（前缀无关） | 已解耦 |
| ABI | `ab_abi_version` + host∩bridge 协商 | 升级现有 `assertBridgeAbi` |

过渡期：三桥同时导出旧前缀 alias 一个版本，新 App 优先 `ab_*`，旧 App 不炸。

### 4.2 Dart 侧收敛（随 P1 一并做）

- 三份绑定 → 一份 `audio_bridge.dart`：`AuraBridge(desc)` 按 `desc.prefix` 拼导出名（过渡期）/直接查 `ab_*`（终态）。
- `BridgeManager` 持 `Map<String, AuraBridge>`；isolate 命令 case 只跟 manager 说话。

### 4.3 解耦边界（写成规约，供以后所有平台）

1. DSP 引擎只暴露 `auradsp_*` ABI；**编译期、运行期都不引用任何桥符号**（现状已满足，固化）。
2. 桥按需 LoadLibrary 引擎（现状），桥可独立编译/发布。
3. Dart/UI 只依赖 `aurabridge` 契约 + `BridgeDesc` 注册表；**新平台新后端 = 实现契约 + 注册一项**，不动引擎、不动 UI。
4. 参数/插件镜像真相源在 Dart isolate（`paramMirror`/`pluginMirror`），桥内 Mirror 仅应对 CHANGE 重建——此口径不变。

## 6. 风险清单

1. **onset 瞬态被吃** → 同块即时恢复 + smoke 断言（§3.5）。
2. **混响尾音被截** → 进入双条件（输出 < -120dB）+ 断言。
3. **FreeLibrary 第三方 DLL 崩坏** → 默认驻留；卸载仅实验开关（§2.1）。
4. **极低电平音乐误门控** → -90dBFS 阈值 + `AURADSP_GATE_DB` 覆写。
5. **门控与 Z12 保护交互** → 正交声明；P3 代码注释 + 测试同开。
6. **VM 组级门控漏 memset** → 桥输出缓冲必须整块写零，code review 检查点。
7. **测试 flaky** → 已知 VM 级 "did not complete" 非回归，单文件复跑口径不变。
8. **双前缀过渡膨胀** → P5 限定 alias 只活一个版本，写进验收。

## 7. 不做清单（明确排除）

- 不改 WASAPI 轮询推为 event-driven（独立议题，开销已忽略）。
- 不动 viz 帧格式与 `vizFps` 语义。
- 不改 D4-a 互斥切换的用户可见行为。
- 不为门控引入新的持久化设置项（阈值走环境变量，不进 UI）。
