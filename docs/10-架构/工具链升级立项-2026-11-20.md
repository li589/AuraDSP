# 工具链升级立项（2026-11-20，user 裁定立项）

登记出处：未决问题登记 A5。本文件只立项与定计划，**开工需 user 另行
排期确认**；升级本身不在任何收口轮次内顺带进行。

## 一、背景与现状

- 现行钉版：Flutter **3.47.9**，钉在三处 CI——`ci.yml` 两处（J6 dart-tests、
  J8 build-app-linux，注释明言「钉 3.47.9，勿随 stable 漂移（nativeapi
  实验 API）」）与 `windows-installer.yml` 一处；开发机本地 Flutter 与之
  对齐。
- 钉版原因：`nativeapi` / `nativeapi_flutter`（pubspec `^0.5.2`，窗口与
  原生互操作层）建立在 Dart 实验 API 之上；Dart 3.14 移除 `Isolate.create`
  等实验面后，nativeapi 0.5.10 一线失效。0.5.11 已按新 API 适配。
- 附带面：构建钩子链 `cnativeapi` / `native_toolchain_c` 随 Flutter 分发
  版本走；开发机现有一处本地补丁（native_toolchain_c 0.19.5 的
  run_process.dart GBK 解码，2026-11-20 r58 事故处置），升级后须复核
  上游是否已修、补丁是否可弃。
- 不升级的代价：与 stable 通道持续脱节，安全修复与新平台要求（商店/
  系统 SDK 下限）迟早倒逼；且 A4 插件编辑器原生浮条同在 nativeapi 面上，
  在旧 API 上先行开发有返工风险——**顺序口径：A5 先于 A4 开工**。

## 二、升级目标

| 组件 | 现行 | 目标 |
|------|------|------|
| Flutter | 3.47.9（钉版） | 3.50.x 最新补丁 |
| Dart | 3.13.x（pubspec `^3.13.5`） | 3.14（约束改 `^3.14.0`） |
| nativeapi / nativeapi_flutter | ^0.5.2（实解 0.5.10 线） | 0.5.11 线 |
| cnativeapi / native_toolchain_c | 随行 | 随行核对，含 GBK 补丁去留 |

## 三、影响面盘点（开工时逐项复核）

1. CI 三处 `flutter-version` 钉版点与注释口径同步改。
2. `pubspec.yaml` sdk 约束 + `pubspec.lock` 全量重解；逐包比对大版本跳变
   （尤其 ffi / build hooks 相关包），不接受静默大跳。
3. 构建钩子：克隆 `.dart_tool/hooks_runner` 全清重编（r58 教训：只删
   子目录不生效）。
4. gen-l10n 产物可能被新版格式化重排——按既有口径处理（生成即提交、
   同步前还原纯格式 diff），不让格式漂移混进功能提交。
5. Dart 3.14 语言/分析器变化：新 lint 与弃用警告逐项处置，analyze 须回
   到零问题，不许以 ignore 批量压过。
6. nativeapi 行为面回归：窗口管理、托盘、插件编辑器托管窗口等消费点
   逐项真机/冒烟复核（清单开工时按消费点全量列）。
7. 打包链：packkit 与向导构建在新工具链下全量重跑，四件与上一轮比哈希
   （Setup 必须不同，相同即事故——既有门禁口径）。

## 四、实施分段

- **S1 依赖预研**（副本/分支上）：pubspec 升约 + lock 重解 + analyze，
  列出全部不兼容点与处置，不动主线钉版。
- **S2 主线切换**：CI 三处钉版 + sdk 约束同轮切换；开发机 Flutter 切到
  目标版并复核 GBK 补丁去留。
- **S3 全量验证**：开发机仲裁全套（analyze、flutter test 全量按单文件
  复跑口径判读、runner、打包四件比哈希）；CI 九作业全绿实查。
- **S4 收口**：登记附记关闭 A5；`docs/00-总览/项目架构与开发规范.md` 等
  活文档的钉版表述同步；开发机本地补丁若可弃，记录弃用与还原路径。

## 五、风险与回滚

- 最大风险：nativeapi 0.5.11 的行为差异落在窗口/编辑器托管面，自动化
  覆盖薄——S3 须含真机手验清单，不以全绿冒充。
- 回滚：钉版与 lock 均为单点配置，整轮以独立提交组织，出问题直接
  revert 回 3.47.9 口径，不留半升级状态。
- 时机约束：避开版本收口/打包窗口；与 A4 的顺序按 §一（A5 先行）。

## 六、待裁定

- 目标补丁版（3.50.x 的具体 x）开工时按当时 stable 现状定。
- 开发机 Flutter 是否与 CI 同步切换、还是双版本并存过渡——S2 开工前定。
