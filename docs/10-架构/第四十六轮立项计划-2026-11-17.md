# 第四十六轮立项计划：显示生效宽 + 离散截断 + APO 列表三态

2026-11-17 晚立项。起于 user 宾机实测 r45 后三条反馈与两轮
裁定（初版裁定 + 「选中保留、只用整行底色呈现」的修订）。

## 一、user 反馈与定罪

### 反馈 1：APO 切声道数量，主页电平数不变，要补点声道模式

显示合成有「流活跃（2 秒内有帧）用流真值、合成不覆盖」
的门（r42 S3）。APO 遥测在端点有流时连续到达，流真值
（端点流宽）恒钉住 `vizChannelCount`，改声道数量算出的
合成值推不进去；点声道模式触发更完整的参数重下发才带
过去。静默时无帧则正常——与 user「有时候」吻合。

### 反馈 2：APO 设 5.1、放 7.1，主页变 7.1（声道跟内容走）

双层原因：
- 显示层：遥测块 `channelCount` 是端点流格式宽（ApoShared.h
  「帧来源块声道数」），主页直接拿它当显示宽。
- **处理层（真根）**：`ApoEngineHost` 的声道决议是「流声
  道是几何真相，压过参数块 channels.count」——引擎宽恒
  = 流宽（{2,4,6,8} 直通；其余走 stereo adapt 且多余声
  道**原样直通**）。参数块的 channels.count 在
  ApplySnapshot 被显式跳过。即 APO 模式下声道数量设置
  从未生效过，引擎永远全宽离散处理。

### 反馈 3：离散逐声道疑似做了声道映射（VAIO 等）

审计（VAIO `RemapInterleavedAudio`）：下行对全是折叠
混音——8→6 把 BL/BR 以 0.707 折入 SL/SR、8→2 全下混、
6→2 折 C/SL/SR、6→4 折 C、8→4 折 C 并合后置；上行对
（4→6/4→8/2→N/通用回退）为位置映射 + 补零。泵内
in→引擎、引擎→出两处适配都走它。故 VAIO 设 5.1 放 7.1
时 BL/BR 被折进 SL/SR——user 感知属实。

## 二、user 裁定（本轮口径）

1. **生效宽教义**：声道数量设置在所有模式（含 APO）都
   生效；生效宽 = 手动时 min{用户设置， 硬件能力}、自
   动时流宽受硬件能力封顶。显示按生效宽，不按原始流宽。
2. **离散逐声道 = 截断**：多出的声道丢弃/无声，不做任
   何映射/折叠（无论上限来自人设置还是硬件）。矩阵下
   混模式不受影响（折叠是其本职；但引擎宽同样受生效
   宽封顶——此点为 Lux 拟制口径，验收时 user 可否决）。
3. **APO 端点列表**：保留「选中」（其身后挂遥测跟随与
   声道能力），但选中态只以**整行遮罩样底色框**呈现，
   不再有「选中」文字标；复选框三态状态机：
   - 空 → 只能点到勾（排队待附加）；
   - 勾（亮勾、正常文字）→ 可点取消回空；一键附加后：
     成功 → 亮文字 + 偏暗的勾（已附加），失败 → 维持
     亮勾 + 正常文字（可取消）；
   - 已附加（暗勾）再点 → 亮的叉（锁定，个体不可取消）；
   - 叉 → 只能经一键卸载回空；
   - 一键卸载期间全部选项禁用变暗；成功回空；失败口
     径（Lux 拟制）：卸成功的回空、失败的留在叉并提示。

## 三、分段

### S1 显示生效宽（Dart 状态层）

- viz 事件写 `vizChannelCount` 与 `noteStreamChannelCount`
  前统一过 `clampStreamChForDisplay(cc)`：手动 →
  min{流宽， clamp(用户设置， 能力）}；自动 →
  min{流宽， 能力（已知时）}。
- 效果：APO 播放中改声道数量，下一帧遥测即带新显示宽
  （治反馈 1）；设 5.1 放 7.1 显示恒 6（治反馈 2 显示侧）。
- 单测：流真值钳制矩阵并入 display/chcap 测试族。

### S2 离散截断与生效宽落地（C++ 宿主层 + 审计）

- **APO（主战场）**：`ApoEngineHost` 声道决议改版——
  engCh = min{流宽， 参数块 channels.count（合法
  {2,4,6,8} 时；缺失/非法回落流宽）}；ApplySnapshot 不
  再跳过 channels.count，变化时重算 engCh 并 live 下发
  引擎（引擎 API 本就支持运行中改 count，App isolate
  重派发同路）。ProcessDirect 泛化 N 宽适配：engCh ==
  流宽直通；engCh < 流宽时 gather 前 engCh 声道 →
  引擎 → scatter 回前 engCh、**其余声道清零**（离散截
  断）；矩阵模式 gather 用折叠表（与 VAIO remap 同系
  数）、scatter 位置拷贝 + 补零。缓冲按流宽预分配，
  engCh 以原子量发布、RT 路径只读。旧 stereo adapt 的
  多余声道直通一并改为清零（mono 流特例保留复制）。
  telemetry 的 channelCount 维持流宽（来源真相），显
  示钳制在 App 侧（S1）完成。
- **VAIO**：泵记录 channels.mode（桥参数转发点），离
  散模式下 in→引擎与引擎→出两处适配改走截断版
  （TruncateRemap：位置顺序拷贝 min 宽、余清零）；
  矩阵模式维持现有 remap。旁路直通路径不改（其语义
  为显式直通）。
- **VB**：审计 VmPumpCore 组内适配（总线 8 宽 ↔ procCh）
  是否折叠；若仅顺序拷贝则记录无改，若折叠则同 VAIO
  口径按 mode 分流。
- **本地/WASAPI 链**：审计 isolate 泵与 windowsCapture
  的宽适配（devCh → effCh）是否折叠，同上口径处理。
- 引擎本体不改：channels.mode/count 语义即现行实现。

### S3 APO 端点列表三态（Dart UI + 状态）

- 行：去掉「选中」标与「已附加」标；选中行整行加底色
  （遮罩样半透明强调色），名称/图标不再因选中变色加粗。
- 复选框改自绘三态件：空（边框）/ 亮勾（排队）/ 暗勾
  （已附加）/ 亮叉（已附加且锁定）。文字亮度：已附加
  = 亮（提亮 + 半粗），其余正常。
- 状态：新增会话级 `apoLockedEndpoints` 集；行态由
  (attached, locked, checked) 派生。点击规则按裁定 3；
  附加成功保持派生态自动转暗勾；分离成功清 checked
  与 locked。
- 操作中（附加/卸载任一进行时）整表禁用 + 变暗
  （Opacity + IgnorePointer），卸载失败按拟制口径：
  成功者回空、失败者留在叉（已附加者保留其态）并走
  既有错误提示面。
- 选中仍走 `setApoTargetEndpoint`（行主体点击），遥测
  跟随/能力/声道卡绑定不变。
