## 0. 现状审计结论（定罪）

### 0.1 资源源与分级包

- 仓库资源源目录是根 `assets/`（非 `resources/`）：`convolver/`（IR）
  + `ddc/`（VDC）+ `liveprog/`（EEL）+ `manifest.json`（2584 条清单：
  convolver 2007、ddc 449、liveprog 128 条/47 个唯一文件）。
- `.irs`/`.vdc` 被 .gitignore 排除：干净克隆里 IR/VDC 文件数为 **0**，
  全量库只存在于清单与业主构建机；EEL 47 个 `.eel` 全量在库（360K）。
- 分级 zip 由 `tools/resource_pipeline/build_packages.py` 构建：
  core（约 20MB，tier=core 213 条 + 全部 EEL 恒纳入）、full（约
  180MB）、addons 三件（headphone-ddc 2.5MB / acoustic-spaces 40MB /
  community-tuning 90MB），产物入 `dist/resources/` 并带 SHA256SUMS
  对账门。**插件包不存在实体**：全仓无随包分发的插件二进制，插件
  内容 100% 来自用户系统已装目录。

### 0.2 打包通道（内容系统性不全）

- 第一道关口是 CMake install（Win/Linux 同口径）：`manifest.json`
  存在才启用；恒装 `ddc/`、`liveprog/` 整目录与清单；**convolver 只
  装 8 个分类中的 3 个**（01_headphone_correction / 02_spatial_3d /
  07_speaker_devices，写死子集），其余 5 类永不经 CMake 进包。
- Windows `pack.py --resources`：core = CMake 子集原样；full/addons
  才把 `dist/resources/` 的 zip 合并进 staging 的 `resources/`（exe
  旁）；资源 zip 不存在时 full/addons 直接失败——**在没有全量库的
  机器上只能打 core，core 包里 IR 恒为 0 个文件**（源目录本身为空）。
- **Linux 无资源合并通道**：`installer/linux/pack.sh` 无 `--resources`
  概念，四件产物恒等于 CMake 子集；deb 落 `/usr/lib/auradsp/
  resources/`（无 `/usr/share/auradsp` 路径）。
- Windows 向导对载荷的唯一过滤是未勾选「DDC 预设」组件时剔除
  `resources/ddc/`（默认勾选）；EEL 不会被向导丢弃。

### 0.3 App 侧目录模型（安装资源未登记、脚本不可见）

- **没有任何「安装程序生成配置、App 启动读取」的通道**告知 App 资源
  位置。App 定位资源 100% 靠相对 exe 探测（`ResourceLocator` 候选
  链：exe 旁 `resources/<sub>` 等 8 个候选），且仅用作文件选择器的
  起始目录，仅探测不创建。
- 插件「内置」条目指向**用户数据根**的 `plugins/`（访问即自动创
  建），不是安装目录；平台预置目录首次播种时带存在性过滤，不存在
  的目录不入列（谈不上失效标记）。
- **随包 `resources/liveprog` 的 47 个脚本没有任何代码注册进脚本
  库**：脚本库只有本地库（数据根 `liveprog/`）+ 用户手动添加的自
  定义目录。脚本在包里、库里看不见——这是业主观感的主要来源（与
  convolver 的真丢失叠加）。
- convolver IR / DDC VDC 没有「库/目录列表」概念，只有单文件选择。

### 0.4 标记先例（业主问「之前如何设计」——已有完整先例）

- 「内置」标：插件扫描目录行有 accent 色 chip「内置」+ Tooltip
  （`plugin_scan_dirs_section.dart`）；脚本库默认目录有「<系统初
  始>」chip。
- 「失效」标：脚本库弹窗已有完整三件套——目录异步存在性检测、失效
  时文件夹图标换 `folder_off_outlined` + 路径变 error 色 +
  `warning_amber_rounded` 感叹号图标 + Tooltip「目录不存在或已失
  效」+ 浏览按钮禁用。插件扫描目录行只有弱化版（图标变色，无文
  字/Tooltip）。**本计划统一采用脚本库口径**。

### 0.5 APO 文件可达性（Part III 骨架已锁，未实施）

- audiodg 以 LocalService 身份运行，读不到用户任意选址的文件——
  APO 模式现行口径是进模式自动关 + 拦截开启卷积/DDC（v1 文件效果
  门）。Part III 已定稿骨架：中转目录 `%ProgramData%\AuraDSP\
  apo-assets\`（安装期创建 + ACL：LocalService 读、管理员/本机用
  户写；便携版首次进 sysapo 经提权通道创建）、选文件时按内容哈希
  命名复制去重、参数块新增两条「中转路径专用」通道、APO 侧围栏
  （规范化后必须以中转根为前缀）、引用计数 + 启动对账清孤儿。
- Part III 原范围仅 IR/VDC。EEL 在 APO 模式走文本经参数块、引擎内
  编译的既有口径，**不需要中转**；插件二进制的中转不在原范围，
  本计划按业主并案指令扩入（§4.3）。

## 1. 目标口径（业主指令归纳）

1. 资源包四分（卷积 / VDC / EEL / 插件），统一置于安装目录
   `resources/` 下；三种分发形态（安装 / 便携 / 解压文件夹）内容
   一致。
2. 四类内容的默认内置扫描位置包含：① 安装内置目录（外部配置文
   件指定）；② 用户级目录（运行时按当前用户决定，非安装程序指
   定）。
3. 软件每次启动检查内置目录：不存在则创建；无法创建/不可达时，
   在对应列表中呈现「内置」标 +「失效」标（沿用 §0.4 先例）。
4. 内置内容对所有用户可用（安装内置为机器级，用户级为本人）。
5. Linux 同一方案（路径按平台规则映射，机制一份代码）。
6. APO 模式文件不可达问题并案：文件/插件经中转目录运行（Part
   III 骨架 + 插件扩围）。

## 2. 设计 Part A：资源包构成与打包口径

### A1. 目录构成（安装目录内）

```
<安装目录>/resources/
  manifest.json            资源清单（既有）
  builtin_dirs.json        新增：内置目录登记（见 Part B）
  convolver/  ddc/  liveprog/  plugins/   四分目录
```

`plugins/` 为新增第四分：随包分发的插件落点（内容待裁定，见 §7
Q1；目录与登记机制先行，空目录也登记）。

### A2. CMake 子集写死 → 全量存在性安装

- Win/Linux 两端 CMakeLists 改为：`assets/` 下四分目录**存在什么装
  什么**（整目录安装，删除 convolver 3/8 写死子集）；缺失目录跳
  过不报错（干净克隆无 IR/VDC 的现实不变，打包完整性由 A3 的资
  源 zip 合并保证）。
- 构建机纪律不变：发包前须先跑 `build_packages.py` 备齐
  `dist/resources/`（已有 SHA256SUMS 对账门）。

### A3. 双平台统一的资源合并档位

- `pack.py --resources` 档位（core/full/addons/none）语义不变，但
  **正式发包默认档位需裁定**（§7 Q2）。现状 core 的 IR 内容为空
  壳，是「装了但没内容」的最大来源。
- Linux `pack.sh` 新增 `--resources` 同名档位与同一套合并实现
  （抽 `tools/resource_pipeline/merge_resources.py` 供双平台共
  用，含对账门/路径穿越防护/512MiB 上限，与 pack.py 现实现同口
  径），四件产物（deb/AppImage/tar.gz）全部消费合并后的
  staging，消除「Linux 恒子集」。
- 便携包/解压文件夹形态天然携带 staging 的 `resources/`，无需额
  外处理（现状即如此，缺的只是内容与登记）。

### A4. 资源版本线衔接

资源包继续走既有独立版本线（`resources-v{version}`，首版
0.0.1 尚未构建发布——沿既有裁定，待业主发令）。本计划只改「进
包内容与登记」，不改版本线规则；Release notes 标注配套资源版
本 + URL + SHA-256 的既有口径不变。

## 3. 设计 Part B：内置目录体系（核心）

### B1. 外部配置文件 `builtin_dirs.json`

由打包期生成（pack.py / pack.sh 合并 staging 时写出，安装器与
便携包零改动即随包携带），App 启动读取：

```json
{
  "version": 1,
  "dirs": [
    {"kind": "convolver", "rel": "resources/convolver"},
    {"kind": "ddc",       "rel": "resources/ddc"},
    {"kind": "liveprog",  "rel": "resources/liveprog"},
    {"kind": "plugins",   "rel": "resources/plugins"}
  ]
}
```

- `rel` 相对 exe 目录解析；文件缺失（老包/手拼目录）→ 安装内置
  条目为空集，其余机制不受影响（向后兼容）。
- App 只读不写该文件；它取代 `ResourceLocator` 里硬编码的候选
  猜测成为安装侧单一真值（候选链保留作老包回退，见 B4）。

### B2. 两级内置条目（四类内容统一）

每类内容（convolver/ddc/liveprog/plugins）的目录列表统一为：

| 条目 | 路径 | 来源 | 可移除 | 可禁用 |
|---|---|---|---|---|
| 安装内置 | `<exeDir>/resources/<sub>` | builtin_dirs.json | 否 | 插件/脚本沿既有口径可取消勾选；IR/VDC 作选择器与库的置顶来源恒在 |
| 用户内置 | `<数据根>/<sub>` | 运行时按当前用户派生（APPDATA/XDG 数据根） | 否 | 同上 |
| 用户自加 | 任意 | 用户手动 | 是 | 是 |

- 插件：现有数据根 `plugins/` 内置条目保留，新增安装内置条目
  （并入 `pluginScanDirs` 列表，`builtin: true`，归一逻辑扩展为
  「安装 + 用户」两条内置并存；原「只允许一条 builtin」的归一
  规则同步修订）。
- 脚本：`customScriptDirs` 引入 builtin 条目概念，安装内置 +
  本地库（既有，升格为用户内置）在弹窗目录列表中呈现，脚本库
  聚合扫描纳入两级内置（修复 §0.3 的不可见问题）。
- 卷积/VDC：新增轻量「库」呈现——文件选择器起始目录与（若已有
  的）预设浏览入口统一消费 B4 的候选真值；是否新增与脚本库同
  形的 IR/VDC 库弹窗列为裁定点（§7 Q3）。

### B3. 启动检查、创建与失效标记（统一口径）

- 每次启动（AppModel 构造期，testing 跳过）对全部内置条目做一
  次存在性检查：不存在 → 尝试 `create(recursive)`；结果（存
  在/已创建/创建失败/不可达）记入条目运行时状态（不落盘，启
  动重查）。
- 列表呈现统一为 §0.4 脚本库口径：「内置」chip 恒显；失效时
  `folder_off_outlined` + 路径 error 色（插件行为 dim 色，一并
  对齐）+ `warning_amber_rounded` + Tooltip「目录不存在或已失
  效」+ 打开/浏览动作禁用。失效条目不参与扫描/聚合（插件扫描
  集、脚本聚合、选择器候选都跳过），但不自动删除条目。
- 安装目录只读（Program Files、/usr/lib）且目录缺失时创建必失
  败——属「安装损坏」信号，失效标即预期呈现；打包侧保证目录
  恒存在（空目录以 .keep 落盘进包），正常安装不会触发。

### B4. ResourceLocator 收敛

- 候选链优先级改：builtin_dirs.json 登记路径 → 既有硬编码候选
  （老包回退）→ 数据根。convolver/ddc/liveprog 三个 slot 的起始
  目录从同一真值出发，消除「打包放了、选择器找不到」的缝。

### B5. Linux 映射

机制一份代码，路径按平台：安装内置 = `<exeDir>/resources/<sub>`
（deb 为 `/usr/lib/auradsp/resources/...`，系统级只读、全用户可
读，正合「所有用户可用」；AppImage 在只读 squashfs 内恒存在恒
有效；tar.gz 便携为解压目录内）。用户内置 = XDG 数据根（现状已
成立）。deb 安装不写用户家目录（用户内置由 App 首启按当前用户
创建，符合「不由安装程序指定」的裁定）。

## 4. 设计 Part C：APO 文件中转（Part III 并案扩围）

### C1. IR/VDC：按 Part III 已锁骨架实施（不改口径）

中转根 `%ProgramData%\AuraDSP\apo-assets\`、哈希命名去重、参数
块中转路径专用通道（`convolver.ir.path` / `ddc.load`）、APO 侧
围栏校验、引用计数 + 启动清孤儿、安装期/提权通道建目录与 ACL。
APO 模式的文件效果门随之修订：允许从中转目录加载后，卷积/DDC
在 APO 模式下改为「可用（经中转）」；现行「自动关 + 拦截」口径
仅保留给中转失败的降级路径（选定文件复制失败 → 通知并保持关
闭，不静默）。

### C2. 与 Part B 的衔接（顺手的红利）

安装内置的 IR/VDC 本就位于 Program Files/安装目录——若安装在
Program Files，其 ACL 对 LocalService 可读，理论上可直读；但
便携/用户目录安装不可读，且路径随安装形态变化。**统一口径：
APO 模式下一律走中转**（不为 Program Files 开直读特例），避免
双路径行为差；中转复制有哈希去重，成本可忽略。

### C3. 插件中转（扩围新增）

- 触发：sysapo 模式下用户在链上启用某插件时，若插件文件不在
  audiodg 可读位置（用户目录等），App 将插件**整包复制**入
  `apo-assets\plugins\<sha256-of-manifest>\`（.vst3/.clap 多为
  目录包：按文件清单聚合哈希；单文件 .dll/.so 直接哈希），参
  数/插件块下发中转路径，APO 侧围栏同 C1。
- 已在系统目录（CommonProgramFiles 等 LocalService 可读处）的
  插件不复制、直用原路径（可读性探测：以文件 ACL 含
  LocalService/Users/Everyone 读权为准，复用第十轮 doctor 的
  DACL 探针逻辑）。
- 插件中转的隔离宿主/进程外托管沿 Part I 既有机制，路径替换发
  生在下发层，不动宿主协议。
- 风险登记：带外部资源依赖（同目录数据文件、硬编码绝对路径）
  的插件复制后可能行为异常——加载失败按 Part I 故障闩锁呈现，
  并回退提示「该插件无法在 APO 模式使用」；不承诺全兼容。

### C4. Linux

Linux 无 audiodg 等价物（引擎恒在用户进程内），**无中转需
求**；Part C 为 Windows 专属，ModeCaps/门禁改动不触 Linux 路
径。此点与「统一方案」不冲突：统一的是 Part A/B 的资源与目
录体系。

## 6. 验收清单（要点）

1. 正式包（full 档）解压后 `resources/` 四分齐全，convolver 8
   分类俱在；Linux 四件同口径。
2. 首启后：插件扫描列表见两条内置（安装 + 用户）；脚本库能直
   接看到并加载随包 47 个 EEL；卷积/VDC 选择器默认落安装内置
   且能选到文件。
3. 删掉安装目录下某内置子目录后重启：App 尝试重建（可写形态
   下重建成功）；只读形态下该条目标「内置 + 失效」、其余功能
   不受影响、无崩溃。
4. 换一个 Windows 用户登录：用户内置目录按新用户数据根出现，
   安装内置不变。
5. APO 模式：选用户目录下的 IR/VDC/插件 → 自动中转、真处理生
   效；卸载/分离后中转孤儿在下次启动对账清理。
6. 老包（无 builtin_dirs.json）启动不报错，行为回退旧候选链。
