## 1. 背景与核心演进

AuraDSP 原有插件宿主设计中，存在以下发展阶段与需求演进：
1. **原单宿主局限**：原 `auradsp_plugin_host` 仅面向 64 位环境构建，无法加载 32 位插件（此前通过 PE 头拦截阻断）；
2. **多架构共存诉求**：Windows 历史上存在海量顶尖且无可替代的 32 位经典效果器（尤其是 32 位 VST2 与早期 VST3）；
3. **跨格式支持需求**：
   - **VST3 / CLAP**：目前已作为一等公民在 AuraDSP 中成熟运行；
   - **VST2**：用户存量巨大，亟需补齐支持；
   - **AU (Audio Unit)**：苹果 macOS 专有格式，在 Windows 平台完全不具备运行环境，必须明确排除；
   - **LV2**：依赖重度 Turtle/RDF 解析链（lilv/serd），在 Windows 端几乎无商业生态，首期暂缓，后续有余力再行适配；
4. **进程隔离与沙箱化**：插件崩溃不应导致 AuraDSP 主引擎与宿主崩溃。

## 2. 插件双宿主体系（Dual Plugin Host）

### 2.1 架构分工与重命名

AuraDSP 在 Windows 及未来跨平台上，将插件进程外宿主正式拆分为**两个独立宿主程序**：

| 宿主程序名称 | 编译目标架构 | 职责定位 | 承载插件类型 |
|---|---|---|---|
| **`plugin_host_x64`** | `x86_64` (64位) | 64 位插件进程外沙箱宿主（原 `auradsp_plugin_host` 重命名） | 64 位 VST3、64 位 CLAP、64 位 VST2 |
| **`plugin_host_x86`** | `x86` (32位) | 32 位插件位桥（Bit-Bridge）宿主（新增独立 32 位构建） | 32 位 VST2、32 位 VST3 |

### 2.2 跨平台可执行文件命名规范

双宿主的可执行文件名严格遵循平台本地原生扩展名规范：

| 平台 | 64位宿主文件名 | 32位宿主文件名 | 说明 |
|---|---|---|---|
| **Windows** | `plugin_host_x64.exe` | `plugin_host_x86.exe` | 随 Release 包放置在 `engine/` 或应用根目录 |
| **Linux** | `plugin_host_x64` | `plugin_host_x86` | 无扩展名 ELF 二进制（Linux 上需系统支持多架构 multilib） |
| **macOS**（规划） | `plugin_host_mac64` | — | macOS 10.15+ 已全面废除 32 位执行环境 |

## 3. Windows 平台插件格式支持策略

### 3.1 格式矩阵定案

```
                  ┌─────────────── AuraDSP 插件支持矩阵 (Windows) ───────────────┐
                  │                                                               │
  【一等公民/已就绪】  ├─► VST3 (64位原生进程内 / 进程外沙箱 plugin_host_x64)             │
                  ├─► CLAP (64位原生进程内 / 进程外沙箱 plugin_host_x64)             │
                  │                                                               │
  【高价值扩展/计划中】├─► VST2 (64位 plugin_host_x64 / 32位 plugin_host_x86)             │
                  │                                                               │
  【明确排除/隐藏】   ├─► AU (macOS CoreAudio 专有，Windows 下完全排除并在 UI 隐藏)     │
                  │                                                               │
  【暂缓适配】       └─► LV2 (Turtle/RDF 依赖沉重且 Windows 生态极其贫瘠，暂缓)       │
                  └───────────────────────────────────────────────────────────────┘
```

### 3.2 格式实现规范

1. **VST3 (已就绪)**：
   - 依赖：`vendor/plugin-api/steinberg/vst3/`；
   - 驱动：`engine/plugins/formats/vst3/`；
   - 状态：成熟稳定。
2. **CLAP (已就绪)**：
   - 依赖：`vendor/plugin-api/clap/`；
   - 驱动：`engine/plugins/formats/clap/`；
   - 状态：成熟稳定。
3. **VST2（2026-11-03 已落地，ADR-013）**：
   - 版权合规：编译只认 `vendor/plugin-api/vst2/vst.h`（Xaymar 净室，BSD-3-Clause）；仓库内非净室 LSP 三头已删除；Steinberg 官方 2.4 归档仅 `source/vst2sdk/vstsdk2.4/` 只读；
   - 驱动：`engine/plugins/formats/vst2/{vst2_driver,vst2_instance,vst2_metadata}.cpp`，标准 `AEffect` dispatcher + `processReplacing`；
   - 架构分派：64 位 VST2 由 `plugin_host_x64` 或主进程加载；32 位 VST2 由 `plugin_host_x86` 桥接；
   - **扫描安全策略**：64 位 VST2 在引擎进程内只做 PE 快扫（实测真实插件深扫 AV 崩溃），真实元数据由加载路补齐；32 位深扫经 IPC `Op::QueryMetadata` 由桥宿主代查；深扫仅在进程外宿主内允许；
   - **32 位回调 ABI**：宿主必须用 `intptr_t` 自定义签名（Xaymar `vst_host_callback_t` 的 `int64_t` 在 32 位下会错位）。
4. **AU (明确排除)**：
   - 苹果专有格式，依赖 macOS CoreAudio 与 AppKit，在 Windows 上完全无法运行；
   - UI 层面：在非 macOS 环境下**完全隐藏 AU 筛选按钮**（代码已落地于 `plugins_list.dart`）。
5. **LV2 (暂缓推进)**：
   - 依赖 `lilv`、`serd`、`sord`、`sratom` 复杂的 Turtle/RDF 解析库，Windows 上几乎无商业插件生态，性价比极低，暂缓后续再考虑。

## 4. 进程外桥接（IPC 与音频流传输设计）

### 4.1 协议基础（复用既有成熟 IPC）
AuraDSP 在 `engine/plugins/platform/win32/host/` 中已具备工业级 IPC 协议脚手架（`plugin_ipc_protocol.h`）：
- **控制通道**：命名管道 `\\.\pipe\auradsp_host_<uuid>`，支持 `Op::Load`, `Op::Unload`, `Op::SetBypass`, `Op::ShowEditor` 等；
- **音频通道**：共享内存环缓冲区（`SlotAudioRing`），单块 128 采样点 8 声道传输，RT 端无锁 SPSC；
- **心跳守护**：看门狗线程探测父进程 PID，父进程异常退出时子进程自销毁，杜绝僵尸进程。

### 4.2 路由透明化分派
主引擎中的 `PluginHostManager` 在加载插件时：
1. 探测 PE 文件头位数（`peIs64Bit(path)`）；
2. 若为 64 位：
   - 默认走 `plugin_host_x64` 进程外沙箱（或根据配置直通进程内）；
3. 若为 32 位：
   - 自动启动 `plugin_host_x86.exe` 位桥子进程；
   - 主引擎通过 `ProcessPluginProxy` 与其建立共享内存与命名管道连接；
4. **GUI 跨进程嵌入**：
   - 利用 Windows 原生 `SetParent(child_hwnd, parent_hwnd)` API，32 位插件窗口直接作为子控件挂在 64 位主窗口内，用户操作无缝透明。

## 5. UI 搜索栏自适应展长与贴右布局优化

### 5.1 缺陷现象
插件界面的插件列表顶部包含一个搜索输入框与右侧的一组格式筛选药丸（All, VST3, CLAP, VST2, LV2 等）。
原实现使用 `Row` 包裹 `Expanded(搜索框)` 与 `Flexible(药丸)`，由于两者 flex 均为 1，可用空间被强制 1:1 对半切分，导致宽屏下药丸右侧留有大片多余空白，搜索栏无法充分展开。

### 5.2 优化落地
- **布局重构**：
  使用 `LayoutBuilder` 动态检测可用视口，去除 `Flexible` 瓜分，右侧药丸采用 `ConstrainedBox` 设置最大宽度上限并贴齐右边界；
- **效果**：
  搜索输入框使用 `Expanded` 自动展长，填满所有空余水平空间；右侧分类药丸紧凑贴齐右边界；窄屏下受限保护并支持横向滚动，彻底消除了空位，视觉饱满专业。
- **落地文件**：`app/auradsp_app/lib/features/plugins_page.dart` 与 `plugins_list.dart`。
