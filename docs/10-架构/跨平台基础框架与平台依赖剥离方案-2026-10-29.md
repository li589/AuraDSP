# 跨平台基础框架与平台依赖剥离方案（2026-10-29）

> 性质：**方案 + 执行记录**。M0–M6 已全部落地（2026-10-29）；仅建框架与契约，不实现新平台。
> 目标：为 Linux / Android 建立**可扩展的基本框架**（模块边界 + 平台适配层 + 统一构建/门禁），
> 不实现新平台功能、不改 Windows 行为、不动 C ABI。
> 上游方案：`docs/源码重组与目录规范方案-2026-10-13.md` §8（`engine/platform/<os>` 意向）、
> `docs/10-架构/桥惰性加载与全后端静音门控及DSP解耦落地方案-2026-10-29.md`（P1–P5 已落地的
> `BridgeManager` / `ab_*` 统一桥契约）。
> 决策方法：architecture-decisions（forces / alternatives / consequences / cost to change course）。

---

## 0. 结论（TL;DR）

1. 平台边界统一为**端口-适配器**：`engine` 核心只依赖 `engine/platform/port/*.h` 的纯声明，
   OS 实现放 `engine/platform/<os>/`；Dart 只依赖 `lib/platform/platform_profile.dart` 与
   `lib/engine/audio_out/`。核心代码里不再出现散落 `#ifdef _WIN32`。
2. **真正阻断跨平台编译的只有 1 处**：`engine/engine_internal.h:15` 的 `#include <windows.h>`，
   且该头内没有任何 Win32 符号使用（历史残留），可直接移除。其余是已带非 Windows 回落的双路实现
   （`engine_convolver.cpp` / `engine_audiofile.cpp` 已有 `fopen` 分支），或 Windows 强依赖子系统
   （插件宿主 / 桥 / 驱动 / APO）。
3. Windows 强依赖组件**已有物理归属**：`core/desktop/windows-drivers/`（VAIO / VM / APO / ASIO /
   三桥）、`engine/plugins/platform/win32/`（既有平台子目录先例）。本方案只补 `engine/platform/windows/`
   与 Linux/Android 占位目录，**不重排已稳定的 chain/dsp/plugins 结构**。
4. **修正 2026-10-13 §8 的一处事实误差**：本地设备输出（WASAPI）不在引擎里，而在 Dart 侧
   `app/auradsp_app/lib/engine/audio_device.dart`（`ole32.dll` COM vtable 直调，`WasapiOut`）。
   因此 `AudioOut` 端口应落在 **App 侧**（桌面平台），Android 走 HAL 路径、不经过该端口。
5. 落地按 **M0–M6** 分批，每批独立提交、Windows 行为零变化、全量门禁绿；**M6 只建占位目录与
   契约文档，不构建 Linux/Android**。

## 1. 决策问题、目标、非目标、约束

**决策问题**：在不改 Windows 行为、不实现新平台功能的前提下，如何把现有代码切成
「可移植核心 + 平台适配层 + 平台强依赖组件」，使 Linux/Android 后续只新增适配器而不改核心？

### 1.1 目标

| # | 目标 | 可验证结果 |
|---|---|---|
| G1 | 可移植核心不依赖 OS 头 | `engine/{api 根文件,chain,dsp,integration}` 内 `windows.h/_WIN32/WINAPI` 命中数为 0 |
| G2 | 平台差异有唯一落点 | 新增平台只加 `engine/platform/<os>/` 与 `lib/platform/` 分支，不改 dsp/chain |
| G3 | Windows 强依赖组件有唯一归属 | 桥/驱动/APO/插件 Win32 实现各自只在平台目录内 |
| G4 | 统一构建入口与产物目录 | 根 `CMakeLists.txt` + `CMakePresets.json`；产物 `build/<platform>/<arch>/` |
| G5 | Dart 平台查询单点收敛 | `Platform.is*` 仅出现在 `lib/platform/`（+ 过渡期白名单） |

### 1.2 非目标

- N1 不实现 Linux 音频后端（PipeWire/PulseAudio/ALSA）、不实现 Android AAudio/Oboe。
- N2 不改 C ABI（`auradsp_engine.h` / `AURABRIDGE_ABI=1`）、不升 ABI 版本。
- N3 不把 WASAPI/桥/驱动改写成跨平台库；不引入 Qt/SDL/Boost 等重型框架。
- N4 不做插件生态的跨平台移植（Linux/Android 插件宿主为后续独立立项）。

### 1.3 约束

- C1 **C ABI 是 UI↔引擎唯一契约**（`engine/auradsp_engine.h` + `.def`；Dart 禁直连 vendor 符号）。
- C2 **RT 铁律**：音频线程零分配、零锁、零系统调用；端口只允许控制线程调用。
- C3 **每步验收**：`python test/runner.py` 100%、`flutter analyze`、`flutter test --concurrency=1`、
  `tools/bin/verify_dll_copies.py` 三处同哈希。
- C4 **搬迁提交纯移动零改行**（blame 保历史）；迁移窗口冻结目录级并行重构。
- C5 `core/android/aidl-gen/` 为生成物，已被 `.gitignore:30-32` 排除（本机 552 文件，git 跟踪 0），
  保持不入库，并补生成命令文档。

## 3. ADR（架构决策记录）

### ADR-CP-1 平台边界采用「端口-适配器」，不做代码树分叉

- **状态**：已接受（M1 起执行）
- **Context / Forces**
  - F1 核心 DSP/链有 25k 行 Dart + 7k 行 C++ 的真实资产，分叉即双倍维护。
  - F2 现存 OS 耦合点少（P0 仅 1 处硬阻断 + 插件子系统整体），适合收口而非重写。
  - F3 RT 铁律不允许在音频路径引入虚调用/间接层。
- **决策**：`engine/platform/port/` 只放**纯声明**（`fs/env/log/module/gui`），实现按平台放
  `engine/platform/<os>/`，构建期选择；不可移植的整块子系统（插件远程宿主、GUI）用**编译特性开关**
  排除，而不是 `#ifdef` 撒进核心。
- **Alternatives（拒绝）**
  - A1 继续在核心内散落 `#ifdef _WIN32` 最小补丁：30+ 处且新增平台仍要改核心 → 拒绝。
  - A2 引入 SDL/Qt/Boost 等跨平台框架：依赖与 ABI 体积上升，且不解决音频 HAL/桥接差异 → 拒绝。
  - A3 Windows/Linux 双代码树分叉：违反 F1，历史修复无法互通 → 拒绝。
- **Consequences**
  - 正：新增平台只加 adapter；核心可用纯文本 grep 门禁；插件子系统可整体裁剪。
  - 负：一次搬迁成本（约 10 个文件）；端口头增加一层阅读跳转；需维护「哪些实现属于哪个 target」。
- **Reversibility**：**双向门**（目录与端口可回滚）。真正的单向门是 **C ABI 与 RT 语义**，本方案不动。
- **重估触发**：若某平台要求音频回调在 C++ 侧且需要端口的 RT 直调（如 Android HAL 进程内），
  端口契约需增加 RT-safe 子集并重新评审。

### ADR-CP-2 Windows 强依赖组件按平台目录隔离，核心不感知

- **状态**：已接受（M2 执行）
- **Context / Forces**
  - F1 插件宿主（共享内存 + `CreateProcess` + Win32 窗口嵌入）在三平台语义完全不同。
  - F2 桥/驱动/APO 已是独立 CMake 目标，物理边界清晰。
  - F3 用户明确要求「强依赖组件按平台归类到子目录」。
- **决策**：
  - `engine/plugins/host/*`（远程宿主）→ `engine/plugins/platform/win32/host/`；
  - 插件格式加载走 `port/module.h`，GUI 走 `port/gui.h`（Windows 实现先行）；
  - 非 Windows 构建 `AURADSP_PLUGIN_HOST_REMOTE=OFF`，插件链阶段退化为直通（由 integration 层保证）；
  - `core/desktop/windows-drivers/` 与 `core/desktop/windows/` 保持原地，不加新抽象。
- **Alternatives（拒绝）**
  - A1 立即实现 Linux 插件宿主（dlopen + X11 嵌入）：超出本轮非目标 N4 → 拒绝。
  - A2 把插件子系统整体删除以求可编译：损失 Windows 现有能力 → 拒绝。
  - A3 用统一 `#ifdef` 混写三平台实现：可读性与门禁都不可控 → 拒绝。
- **Consequences**
  - 正：核心可编译集合明确；插件平台实现互不污染；Windows 行为零变化。
  - 负：非 Windows 构建暂时无插件能力（记录为已知缺口）。
- **Reversibility**：双向门（目录可回迁，特性开关可改默认）。
- **重估触发**：Linux/Android 明确要求插件宿主时，另立方案（届时评估进程模型与 ABI）。

### ADR-CP-3 设备输出归 App 侧 `AudioOut` 端口（修正 2026-10-13 §8）

- **状态**：已接受（M4 执行）
- **Context / Forces**
  - F1 事实：WASAPI 输出由 Dart 直调 COM（`audio_device.dart:113+`），引擎 DLL 只做 DSP，不持有设备。
  - F2 Android 的模型不同：引擎运行在 effect HAL 进程（AIDL），UI 不拥有音频设备。
  - F3 桌面 Linux 需要一个与 WASAPI 对等的「拉块」后端（PipeWire/Pulse/ALSA 后续实现）。
- **决策**：
  - 桌面端设备输出收敛为 `lib/engine/audio_out/`：`AudioOut` 接口（`init/start/stop/write/format`）
    + 条件导入的 `audio_out_wasapi.dart`（现实现迁入）+ 未来 `audio_out_linux.dart`；
  - Android 不实现该端口，走 HAL 注入路径（`core/android/registrar` 既有能力）；
  - 引擎保持纯 DSP，不新增设备相关 C ABI。
- **Alternatives（拒绝）**
  - A1 把 WASAPI 搬进引擎 `engine/platform/windows/`：需新增设备管理 C ABI、改 UI 生命周期，
    行为风险高且对 Android 无收益 → 拒绝（保留为远期选项）。
  - A2 只在 Dart 里散落平台分支：违反 G5 → 拒绝。
- **Consequences**
  - 正：与现状行为完全一致；Linux 只需补一个 Dart 实现 + FFI 绑定；Android 不受影响。
  - 负：设备 RT 路径仍在 Dart isolate，跨平台后需分别验证泵间隔与抖动。
- **Reversibility**：双向门（接口仅 App 内部）；若某平台要求 C++ 低延迟设备层，可再迁引擎。
- **重估触发**：Linux 实测泵抖动/延迟不达标，或需要独占模式（WASAPI Exclusive/ALSA dmix 直通）。

### ADR-CP-4 单一构建入口 + 平台 target 分层

- **状态**：已接受（M3 执行）
- **Context / Forces**
  - F1 现状无根 CMake，源表在 Windows CMake 与 Android 脚本中各写一份。
  - F2 Windows 产物路径被 DLL 分发/哈希脚本依赖，不能变。
  - F3 目前本机只有 Windows 工具链，Linux/Android 构建无法在本轮验证。
- **决策**：
  - 新增根 `CMakeLists.txt` + `CMakePresets.json`，target 分层：
    `auradsp_core`（STATIC，可移植：`dsp/`+`chain/`+根 api 文件）、`auradsp_engine`（SHARED，
    core + 平台适配）、`auradsp_plugin_host`、`auradsp_bridges`（Windows 条件）；
  - 产物统一 `build/<platform>/<arch>/<config>/`；**Windows 保留现有
    `build/windows/x64/Release/auradsp_engine.dll` 路径**（兼容既有脚本）；
  - `tools/build_windows.ps1` 改为调用 preset，命令行为不变；
  - Linux/Android preset 只写注释占位（`linux-x64`/`android-arm64`），**不设默认构建**。
- **Alternatives（拒绝）**
  - A1 维持各平台独立 CMake：源表漂移继续 → 拒绝。
  - A2 本轮直接接 Android Gradle `externalNativeBuild`：无法本机验证，且属新平台开发 → 拒绝。
- **Consequences**
  - 正：新增源文件只改一处；平台差异集中在 target 条件；CI 可按 preset 扩展。
  - 负：多一层 CMake 间接；需保证 Windows 现有脚本与产物路径零变化。
- **Reversibility**：双向门（根 CMake 可删回旧入口）。
- **重估触发**：Android 需要 Gradle 驱动 NDK 构建时，在根 CMake 之上加 wrapper，不推翻。

### ADR-CP-5 Dart 平台查询单点 + 测试/工具平台标记

- **状态**：已接受（M4/M5 执行）
- **Context / Forces**

  - F3 测试/工具 Windows-only，跨平台 CI 需要「可跳过、可汇总」而不是整批失败。
- **决策**：
  - 新建 `lib/platform/platform_profile.dart`：os、能力位（`supportsBridges/supportsPlugins/

- **Alternatives（拒绝）**

- **重估触发**：出现 profile 无法表达的平台差异（如按发行版区分的音频栈），改为能力插件注册表。

## 4. 系统图

```text
┌─────────────────────────────── Flutter App (Dart) ───────────────────────────────┐
│ UI 页 / features                                                                  │
│   └─ core (state/config/session/plugins)  ── 禁 import features                  │
│        └─ engine (audio_isolate / audio_out / auradsp_ffi)                        │
│             ├─ [桌面] AudioOut 端口 ── WASAPI 实现（now）/ Linux 实现（future）    │
│             └─ C ABI ─────────────────────────────┐                              │
└───────────────────────────────────────────────────┼──────────────────────────────┘
                                                    ▼
┌──────────────────────── Engine (C++ 同进程 DLL) ─────────────────────────────────┐
│ auradsp_engine (C ABI)  ← 唯一契约                                               │
│   ├─ chain/  dsp/            ← 可移植核心（零 OS 头）                             │
│   ├─ plugins/integration     ← 插件链阶段（可裁剪）                                │
│   ├─ plugins/{driver,host,formats} ── port/module|gui ──┐                        │
│   └─ port/{fs,env,log} ────────────────────────────────┼─┐                      │
│                                                         ▼ ▼                      │
│                                     engine/platform/windows/*（唯一 Win32 落点）  │
│                                     engine/platform/linux/*（占位）              │
│                                     engine/platform/android/*（占位）            │
└──────────────────────────────────────────────────────────────────────────────────┘
        ▲ ab_*（AURABRIDGE_ABI=1）                ▲ AIDL effect HAL（Android）
┌───────┴──────────────────────────┐      ┌───────┴────────────────────────────┐
│ Windows 桥（独立 DLL）            │      │ core/android registrar/stubs      │
│ vm / asio / vaio + common 插件槽  │      │ （引擎注入音频 HAL 进程）          │
└──────────────────────────────────┘      └────────────────────────────────────┘
```

- **依赖方向**：`features → core → engine(Dart) → C ABI → engine(C++) → vendor/legacy`；
  禁止反向，禁止 Dart 直连 vendor 符号。
- **信任边界**：引擎 DLL 与 App 同进程（共享地址空间）；桥是独立 DLL、可被第三方 DLL 依赖
  （Voicemeeter/ASIO）；插件宿主是独立进程（共享内存 IPC）。跨平台框架不改这些边界。
- **故障域**：桥崩溃只影响该后端（惰性加载已隔离）；插件宿主崩溃隔离在子进程；DSP 崩溃影响整个进程。

## 6. 交互风格决策

| 面 | 现状 / 选择 | 备选与拒绝理由 |
|---|---|---|
| 音频数据 | **拉模式块回调**：App isolate 定时拉引擎 `process`，桥回调推块；RT 零分配 | 事件流/消息队列：RT 不可用；服务化：微服务溢价无收益 |
| 控制面 | **同步 C ABI**（`set_param/get_param`，原子参数） | 异步队列：增加延迟与状态机复杂度，现有 UI 依赖同步回读 |
| 插件数据面 | 进程内直调；远程宿主用共享内存 + 独立进程（Windows 现状保留） | 网络 IPC：延迟与安全边界不划算 |
| UI ↔ 引擎 | isolate 消息（`SendPort` 命令/事件） | 直接 UI 线程 FFI：阻塞帧循环，已废弃 |
| 构建/门禁 | 本地脚本 + smoke 全量 | 远程 CI：本轮不引入，保留 preset 扩展点 |

结论：**跨平台框架不改变任何交互风格**，只改变「实现放在哪」。这也是 Android 能复用 Engine Core
（HAL 进程内直调）与桌面复用 App 泵循环的原因。

## 8. 端口契约（`engine/platform/port/`）

最小集，全部**纯声明 + 控制线程可用**；音频 RT 线程不得调用（除纯计算）。

```cpp
// fs.h — UTF-8 路径文件读写（Windows 内部转 wide，其他平台直通）
bool port_read_file(const char* utf8_path, char** out_buf, size_t* out_size, size_t max_bytes);
void port_free_file(char* buf);

// env.h
bool port_get_env(const char* name, char* buf, size_t cap);   // false = 未设置

// log.h — 宿主诊断（替代 OutputDebugStringA / fprintf）
enum class LogLevel { Warn = 1, Info = 2 };
void port_log(LogLevel lvl, const char* file, int line, const char* msg);

// module.h — 动态模块（VST3/CLAP 加载）
void* port_module_open(const char* utf8_path);
void* port_module_symbol(void* module, const char* name);
void  port_module_close(void* module);

// gui.h — 插件编辑器（Windows 先行；非 Windows 返回 false）
bool port_gui_is_available();
```

约束：

- 端口实现按 target 选择（`if(WIN32)` 编 `platform/windows/*.cpp`）；**核心不 include 任何 OS 头**。
- `port/module.h`、`port/gui.h` 在非 Windows 平台可返回不支持，插件链阶段由 integration 层直通。
- 端口函数不得进入 `auradsp_process` 调用图（保持 RT 零 syscall）。

## 15. 决策表

| 面 | 默认决策 | 已拒绝的替代 | 例外条件 |
|---|---|---|---|
| 引擎平台边界 | 端口-适配器（`engine/platform/port` + `<os>`） | 散落 `#ifdef`、引入重型框架、双代码树 | 某平台要求 RT 侧直调端口时重评 |
| 插件宿主 | Windows 保留；非 Windows 编译裁剪 + 直通 | 立即跨平台实现、删除插件能力 | 新平台明确要求插件时另立项 |
| 设备输出 | App 侧 `AudioOut` 端口（桌面） | 搬进引擎 C ABI、Dart 散落分支 | 延迟/独占模式不达标时迁引擎 |
| 构建 | 根 CMake + preset，Windows 路径不变 | 维持多入口、直接接 Gradle | Android 需要 Gradle 原生构建时加 wrapper |
| Dart 平台查询 | `PlatformProfile` 单点 | 散落判断、第三方包装库 | 出现发行版级差异时改能力注册表 |
| Android vendor | 平台绑定第三方留 `core/android/vendor-src` | 全部迁 `vendor/` | 某库变为多平台共用时迁 `vendor/` |
| 测试 | 现状保留 + 平台标记/跳过 | 重写跨平台测试框架 | 需要 Linux CI 时再扩 runner |

## 16. 重估触发（何时推翻本方案）

1. Linux 实机验证发现 Dart isolate 泵循环抖动/延迟不达标 → 触发 ADR-CP-3 重评（设备层迁引擎）。
2. Android 要求 App 直接控制音频设备（非 HAL 注入）→ 触发 ADR-CP-3 例外分支。
3. 插件跨平台成为硬需求 → 触发 ADR-CP-2 重评（独立立项）。
4. 根 CMake 与 Windows 现有脚本产生不可调和差异（产物路径/编译选项）→ 回退 M3，保留双入口。
