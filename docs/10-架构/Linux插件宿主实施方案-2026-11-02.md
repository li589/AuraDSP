## 1. 执行顺序（owner 指定）

先进程内、后隔离主机。进程内路径（`AURADSP_HOST_INPROC`）既存
且经 P0 探针实测可用，是全部后续阶段的地基；隔离主机按双宿主
架构在 §4 落地。

## 2. 阶段一：引擎进程内启用（Linux，PLUGINS=ON 正式化）

- Linux CMake：`AURADSP_ENABLE_PLUGINS` 转正为真实选项（默认 ON，
  与 Windows 对齐；OFF 仍走 stub 且产物目录分离，沿用 Windows 的
  `out` / `out-noplugins` 防污染口径）；编入 driver + formats +
  integration 真实源表，定义 `AURADSP_HOST_INPROC=1`；引擎目标补
  `CXX_STANDARD 20`（插件层用 C++20 原子等待语义）。
- `engine/auradsp_gcc_shim.h`：预包含补齐插件层用到的标准头
  （deque/condition_variable/filesystem 等，须赶在 legacy min/max
  宏之前；本文件仅 Linux 注入，Windows 零影响）。
- `engine/plugins/platform/posix/`（新，与 platform/win32 对位）：
  - `win32_util.h` + `plugin_util_posix.cpp`：7 个工具函数的 Linux
    语义实现（路径原生 UTF-8；`peIs64Bit` 改判 ELF class——与双
    宿主方案的位数路由探测同语义；版本资源提取返回空，元数据由
    工厂查询主路径兜底；DLL 目录为空操作；默认搜索路径给 Linux
    插件目录）；
  - `module_pump.h`：任务队列泵的 POSIX 版（条件变量队列；本质
    不变量保留：按模块共享线程、串行执行、毒化不复用、停摆泄漏
    不 delete；编辑器登记为空操作）；
  - `win32_compat.h`：最小 Win32 类型/常量与惰性窗口 API 集，
    供 formats 的编辑器代码在无编辑器阶段编过且运行期惰性失败
    （见阶段三的收口）；其中 `GetSystemTimeAsFileTime` 为真实
    实现（process 上下文在用，非编辑器路径）。
- PluginHostManager 的三个编辑器槽方法（show/close/isEditorOpen）
  经查明是与平台无关的实例委派代码，从 `plugin_gui_win32.cpp`
  移回 `plugin_host_manager.cpp` 本体（纯移动，Windows 行为不变；
  这也是链接期仅有的 3 个未定义符号的归位）。

验收：PLUGINS=ON 构建成功；.so 导出仍恰 56 符号；探针 CLAP
插件（增益 0.5）经 C ABI 扫描/加载/process 实测生效（同 P0
口径，固化为阶段四门禁）。

## 3. 阶段二：App 接线

- `PlatformProfile.supportsPlugins` 在 Linux 打开；S5c 隐藏的
  插件目录 UI 恢复展示（`PluginScanDirsSection`），Linux 预置
  目录播种（/usr/lib/vst3、~/.clap 等，与引擎默认搜索路径对齐）；
- A6-1 `PluginHostPort` 实接：插件页在 Linux 走真实扫描/加载
  通路（引擎为 stub 构建时按能力降级，与 Windows 裁剪构建同
  口径）；
- 设置与插件页文案复核（Linux 下不再出现「不支持插件」类提示）。

验收：analyze 0；Dart 套件全过；真机/VM 内从 UI 扫描并加载
阶段一的探针插件出声。

## 4. 阶段三：formats 收尾与门禁/CI

- `vst3_metadata.cpp`：`Steinberg::wscast`（Windows SDK 专有，
  3 处）改 char16→UTF-8 直转（非 Windows 分支，Windows 路径
  不动）；
- `vst3_instance.cpp`：一处未守卫的 MSVC SEH 改 `_MSC_VER`
  守卫 + try/catch 回退（与 module_pump 既有手法一致）；
- 编辑器收口：两个 instance 的 `showEditor` 在非 Windows 显式
  返回不可用（不依赖惰性窗口 API 的假成功），`isEditorOpen`
  恒 false；编辑器本体（X11 嵌入）不在本方案范围，属后续
  独立阶段（原评估 P5）；
- 门禁：新 `smoke_linux_plugin_host.py`（自建 CLAP 探针插件入
  测试资产，构建后经 C ABI 全链断言），登记 runner；在 CI 增
  插件引擎构建与该门禁的执行路径（J2 产物即插件版时 J3 直接
  跑；否则独立 job）；
- 跨平台可移植的既有插件冒烟（链一致性/隔离区等使用假实例
  者）评估 Linux 化清单，能跑的纳入 CI。

验收：冒烟与 CI 全绿；VST3 侧以自建最小 VST3 插件或 SDK 样例
补一条加载断言（若工具链成本过高，降级为 CLAP 单格式门禁 +
VST3 编入断言，并在本节记录）。

## 5. 阶段四：隔离主机 plugin_host_x64（POSIX）

按双宿主架构方案落地 Linux 版进程外宿主（可执行名
`plugin_host_x64`，无扩展名）：

- 传输层 POSIX 化：控制通道命名管道 → Unix domain socket；
  音频共享内存环（`SlotAudioRing` 协议结构平台无关）→
  `shm_open`/`mmap`；看门狗父进程探测 → `getppid` 轮询/kqueue
  等价物（Linux 用 prctl `PR_SET_PDEATHSIG` 更直接）；
- 宿主主程序与客户端代理（host main / plugin_host_client /
  process_plugin_proxy）的 POSIX 对应物置于
  `engine/plugins/platform/posix/host/`，协议定义
  （`plugin_ipc_protocol.h`）与 Windows 共用同一份；
- PluginHostManager 路由：位数探测（ELF class）→ 64 位插件
  默认远程 `plugin_host_x64`（可配置进程内直通，同 Windows
  口径）；远程不可用时按既有降级语义处理；
- 打包：宿主二进制随 bundle 同梱（bundle 布局门禁同步扩展）。

验收：远程模式下探针插件加载/process 全链（经冒烟固化）；
宿主崩溃注入下主进程存活（隔离区语义与 Windows 对齐）。

## 6. 阶段五：隔离主机 plugin_host_x86（32 位桥）

- 以 `-m32` 独立构建 32 位宿主（需 multilib 工具链；CI 侧
  安装 gcc-multilib，VM 本地同）；32 位 VST3 插件加载通路；
- 32 位 CLAP 按双宿主方案不在 x86 宿主承载范围（方案表：x86
  宿主承载 32 位 VST2/VST3），路由按方案执行；
- 验收：32 位测试插件（自建最小 VST3 x86）经桥加载出声；
  无 multilib 的用户机上按缺失宿主降级提示。

## 7. 不在本方案内

- 插件编辑器 GUI（X11 嵌入）：后续独立阶段；
- VST2 驱动本体：Windows 侧 formats 落地后，Linux 侧以
  「编入 + 冒烟」跟随（驱动共享、平台面已由本方案备好）；
- LV2：暂缓（同双宿主方案）；把 AuraDSP 自身导出为插件：
  需独立立项（ADR-012 D-7 原文）。
