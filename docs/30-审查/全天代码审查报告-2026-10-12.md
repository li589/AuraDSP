## 二、关键缺陷（Findings）复盘与修复对照

### Finding 1 (P1 - 内存安全)：`prepareInstance` 容器元素裸指针跨锁逃逸与 UAF 风险
- **问题文件**：[`core/desktop/engine_api/auradsp_plugin_host.cpp`](file:///d:/temp_desktop/Proj/JamesDSP/core/desktop/engine_api/auradsp_plugin_host.cpp#L3942-L3955)
- **根因分析**：在 `prepareInstance` 中，查找扫描期种子插件时，在 `m_hostMutex` 锁内获取了 `m_scannedPlugins` 容器元素的裸指针 `seed = &p;`，但在释放锁后才调用耗时达 1000ms+ 的 `instance->load(path, pluginId, seed)`。若异步加载期间发生扫描任务（如后台定时快扫或用户手动刷新），`m_scannedPlugins` 扩容重新分配内存，该裸指针即变为悬垂指针（Dangling Pointer），导致不可控的 Use-After-Free 崩溃。
- **修复方案**：改为在锁内进行深拷贝到局部栈变量 `PluginMetadata seedCopy; bool hasSeed = false;`，传参传栈地址 `hasSeed ? &seedCopy : nullptr`。
```diff
-   const PluginMetadata* seed = nullptr;
+   PluginMetadata seedCopy;
+   bool hasSeed = false;
    {
        std::lock_guard<std::recursive_mutex> lock(m_hostMutex);
        for (const auto& p : m_scannedPlugins) {
            if (p.path != path) continue;
            if (!pluginId.empty() && !p.id.empty() && p.id != pluginId) continue;
-           seed = &p;
+           seedCopy = p;
+           hasSeed = true;
            break;
        }
    }
-   bool lRet = instance->load(path, pluginId, seed);
+   bool lRet = instance->load(path, pluginId, hasSeed ? &seedCopy : nullptr);
```

### Finding 2 (P0 - 并发与死锁)：异步挂载时未等待 RT 线程退出并在锁内同步销毁
- **问题文件**：[`core/desktop/engine_api/auradsp_plugin_host.cpp`](file:///d:/temp_desktop/Proj/JamesDSP/core/desktop/engine_api/auradsp_plugin_host.cpp#L3974-L3995)
- **根因分析**：C3 异步加载如果在目标槽已有插件时提交，`commitInstanceLocked` 直接通过 `s.instance = std::move(instance)` 替换，且在其内部立即调用 `old->closeEditor(); old->deactivate(); old->unload()`。这产生两大致命问题：
  1. **破坏音频 RT-Safe 契约**：完全没有等待音频实时线程退出临界区（`inFlight == 0`），如果音频线程正在该插件的 DLL 代码段内执行 `processSlot`，DLL 被瞬间 `FreeLibrary` 卸载，必发 `0xC0000005` Access Violation 闪退；
  2. **违反 C3 锁外销毁原则**：`commitInstanceLocked` 由调用方持有 `m_hostMutex`，在此处同步调用耗时数十到数百毫秒的卸载收尾，会死锁阻塞其他所有需要排他互斥的控制命令。
- **修复方案**：
  1. 在 `runControlTask` 的 load 分支中，挂入新实例前先调用 `oldInstance = detachInstanceLocked(t.slot)`（在此阶段由原子握手等待 `inFlight == 0`，静默排空 RT 线程）；
  2. 释放 `m_hostMutex` 锁之后，在锁外安全执行 `destroyInstance(std::move(oldInstance))`；
  3. 在 `commitInstanceLocked` 内部将未解挂的残留实例防御性移入静态隔离区，严禁锁内同步 unload。
```diff
+   std::unique_ptr<IPluginInstance> oldInstance;
    {
        std::lock_guard<std::recursive_mutex> lock(m_hostMutex);
        m_sampleRate = t.sampleRate;
        m_maxBlockSize = t.maxBlockSize;
        if (instance) {
+           oldInstance = detachInstanceLocked(t.slot);
            commitInstanceLocked(t.slot, std::move(instance));
            m_slots[t.slot].taskState.store(2, std::memory_order_release);
        } else {
            m_slots[t.slot].taskState.store(3, std::memory_order_release);
        }
    }
+   if (oldInstance) {
+       destroyInstance(std::move(oldInstance)); // 锁外销毁
+   }
```

### Finding 3 (P1 - 异常安全)：控制线程未捕获异常导致线程终止与状态永久死锁
- **问题文件**：[`core/desktop/engine_api/auradsp_plugin_host.cpp`](file:///d:/temp_desktop/Proj/JamesDSP/core/desktop/engine_api/auradsp_plugin_host.cpp#L4070-L4098)
- **根因分析**：`runControlTask` 中直接调用 `prepareInstance` 与 `destroyInstance`。若第三方插件在 `createInstance`、`init` 或析构时抛出 C++ 异常，该异常穿透 `runControlTask`，导致控制线程触发 `std::terminate` 异常终止；且当前槽的 `taskState` 永久停留在 `1`（进行中），前端 UI 发生假死（永远 `_slotBusy=true`，按钮置灰且无法取消）。
- **修复方案**：为 `runControlTask` 增加 `try { ... } catch (...)` 结构，发生异常时安全更新 `taskState.store(3, std::memory_order_release)`（状态置为失败），保全控制线程循环生命周期。

### Finding 4 (P1 - 逻辑残留)：虚构 Win32 API 导致尺寸稳定化定时器无法自停
- **问题文件**：[`core/desktop/engine_api/auradsp_plugin_host.cpp`](file:///d:/temp_desktop/Proj/JamesDSP/core/desktop/engine_api/auradsp_plugin_host.cpp#L1438-L1465, L1956, L2972)
- **根因分析**：代码原先尝试用不存在的 Win32 常量 `GWLP_USERDATA2 (-5)` 在窗口句柄上保存定时器轮询计数。实际上 Win32 `SetWindowLongPtr` 遇到非法索引会直接返回 0 并报 `ERROR_INVALID_INDEX (1413)`，导致读取的计数永远为 0，轮询永远无法达到 `kSizeSettleMaxTicks (6)`，100ms 定时器在编辑器打开期间无止境空转消耗 CPU。
- **修复方案**：在基类 [`IPluginInstance`](file:///d:/temp_desktop/Proj/JamesDSP/core/desktop/engine_api/auradsp_plugin_host.h#L118-L124) 中增加受保护的计数器成员 `m_sizeSettleTicks` 及访问器；彻底清除关于 `GWLP_USERDATA2` 的虚构宏与代码，在打开编辑器时调用 `resetSettleTicks()`，在 `WM_TIMER` 中调用 `incSettleTicks()`。

### Finding 5 (P1 - UI 布局)：窄窗口下 `clamp` 下限大于上限引发 Red Screen 崩溃
- **问题文件**：[`app/auradsp_app/lib/features/interactive_eq.dart`](file:///d:/temp_desktop/Proj/JamesDSP/app/auradsp_app/lib/features/interactive_eq.dart#L127-L128)
- **根因分析**：交互式 EQ 选中频点的半透明浮框宽度计算为 `(oct * (w / _logOctaves) * 0.9).clamp(84.0, w * 0.55)`。在小窗或分屏等极窄场景（`w < 153` 时，`w * 0.55 < 84.0`），Dart 的 `double.clamp(min, max)` 会抛出 `ArgumentError: lowerLimit (84.0) must be <= upperLimit (x)`，导致页面直接红屏崩溃。
- **修复方案**：引入 `math.max(84.0, w * 0.55)` 约束上限，并明确转为 `.toDouble()` 杜绝类型收缩风险。
```diff
- final bw = (oct * (w / _logOctaves) * 0.9).clamp(84.0, w * 0.55);
+ final bw = (oct * (w / _logOctaves) * 0.9)
+     .clamp(84.0, math.max(84.0, w * 0.55))
+     .toDouble();
```

### Finding 6 (P2 - 内存泄漏)：`AmbientSpectrum` 挂载更新时遗漏监听器重绑
- **问题文件**：[`app/auradsp_app/lib/features/chrome.dart`](file:///d:/temp_desktop/Proj/JamesDSP/app/auradsp_app/lib/features/chrome.dart#L324-L331)
- **根因分析**：`_AmbientSpectrumState.didUpdateWidget` 仅处理了 `widget.palette != old.palette`，遗漏了 `widget.spectrum != old.spectrum` 的判定。若频谱数据流控制器发生更替，旧 `spectrum` 的监听器未能释放（导致对象泄漏），且新 `spectrum` 未能附着，导致氛围频谱界面假死不刷新。
- **修复方案**：在 `didUpdateWidget` 补全监听器解绑与重绑逻辑。
```diff
    @override

      super.didUpdateWidget(old);
+     if (widget.spectrum != old.spectrum) {
+       old.spectrum.removeListener(_onFrame);
+       widget.spectrum.addListener(_onFrame);
+     }
      if (widget.palette != old.palette) {
        _painter.dispose();
        _painter = _painter.withPalette(widget.palette, clock: _clock);
      }
    }
```

## 三、五大专项领域审查结论

### 1. 关联组件状态与接口调用
- **卷积器 (Convolver) 采样率与重采样提示**：经审查 [`presets.dart`](file:///d:/temp_desktop/Proj/JamesDSP/app/auradsp_app/lib/core/presets.dart)、[`state.dart`](file:///d:/temp_desktop/Proj/JamesDSP/app/auradsp_app/lib/core/state.dart) 及 [`effects_page.dart`](file:///d:/temp_desktop/Proj/JamesDSP/app/auradsp_app/lib/features/effects_page.dart)，统一将采样率比对基准收敛至 `deviceRate`（声卡实际硬件采样率），不再误比对 `convSrcRate`；块长抖动不再无谓重建卷积器；
- **EQ 输出频谱合成**：[`composeEqOutputSpectrum`](file:///d:/temp_desktop/Proj/JamesDSP/app/auradsp_app/lib/core/state.dart) 严格判定 `responseCurve == expectedCurve` 签名一致性。当响应测量滞后时安全退化为输入谱，杜绝了用旧响应叠加新曲线造成的假波形显示。

### 2. 旧代码残留与死代码
- **插件宿主 C ABI 兼容性**：经审查，旧有单槽兼容符号（`auradsp_plugin_load` 等）已被封装并在内部正确映射到 `slot=0`；清理了废弃的 `GWLP_USERDATA2` 虚构常量及其冗余注释；
- **EQ 曲线头元数据**：`eqm:<interp>:<op>;` 已实现可选前缀解析与向后兼容，缺省时平滑回退到历史默认值 `(1, 0)`。

### 3. 底层内存安全、资源泄漏与状态死锁
- **RT-Safe 铁律达成**：实时音频处理线程 `processSlot` 全程无锁，仅通过原子 `inFlight` 计数器与 `hasActive` 标志与控制线程握手，严禁任何动态内存分配与 Win32 系统调用；
- **异常隔离与线程隔离**：已登记的 `quarantineAbandonedInstance` 确保挂死或异常析构的插件实例安全滞留于静态堆隔离区，杜绝进程退出阶段的野指针反向调用；控制线程被全局 `try-catch` 包裹保活。

### 4. 音频算法精度、无损处理与适配
- **Hann 窗中心对齐**：[`probe_eq_response`](file:///d:/temp_desktop/Proj/JamesDSP/core/desktop/engine_api/auradsp_engine.cpp) 冲激脉冲固定置于窗函数有效区，杜绝了端点为零导致的响应衰减失真；
- **Nyquist 边界安全**：高频点均通过 `engineRate / 2.0 * 0.999` 统一钳位，低采样率（如 32kHz、44.1kHz）下不再发生越界断言或插值扭曲；
- **每点 Q 钟形合成**：各频点带宽计算符合声学对数尺度模型，平坦频带过滤机制消除了冗余的 FIR/IIR 系数重算开销。

### 5. UI 层内存泄漏与组件隔离
- **生命周期资源回收**：`AppModel.dispose` 已全量清理 `eqInSpectrum`、`stageLevelsL`、`stageLevelsR` 等新增 `ValueNotifier`；
- **帧率渲染开销控制**：`_AmbientPainter` 将放大画笔 `_blitPaint` 转为成员变量固定复用，杜绝了每秒 60 帧下的画笔对象高频分配与 GC 抖动。
