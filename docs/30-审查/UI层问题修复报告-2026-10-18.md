## 1. 通知条重复弹出（症状 6）——详述

### 1.1 根因

**（a）引擎事件零去重**（`lib/core/state.dart` `case 'paramResult'`）：
```dart
if (rc != 0) {
  lastGuard = GuardRejection(id, ...);   // 每次拒绝都设一次性事件
  eventSeq.value = ++_guardSeq;          // 每次拒绝都弹一个 SnackBar
```
已知可连发的路径：
- `PresetLibrary.apply` 全量复写 22 节参数（`lib/core/presets.dart:318`）——旧预设/session 里任何一个越界值（见 §3）都产生一次拒绝；
- `replaySessionToEngine`（引擎 ready 即回放，`state.dart:1202`）；
- EQ 曲线 `_flushEqCurve` 节流下发（拖动 EQ 时约 220ms 一次，`state.dart:5044`）；
- liveprog 编译失败后的反复 `setParamStr`。

**（b）EventBanner 消费逻辑挂在 build 里**（`lib/features/shell.dart` 旧实现）：
`ValueListenableBuilder` 的 builder 内 `addPostFrameCallback`——`eventSeq` 首次自增后永不为 0，此后父级**每一次重建**（切页/主题/任意 `notifyListeners`）都会再注册一个回调重跑消费逻辑；帧间连发两个事件时先到的消息还会被后到者覆盖吞掉。

### 1.2 修复

`state.dart`：新增 `_admitEngineEvent(key)`——同一 `kind|id|msg` 在 5s 窗口内只放行第一次，后续同因静默抑制（不 bump seq、不动一次性字段），窗口外再现视为新事件；不同成因永远立即放行。回读（`getParams`）与提示解耦：被抑制时依然回读抹掉乐观假象。时钟可经 `debugNowOverride` 注入以便测试。

`shell.dart`：`EventBanner` 改 `StatefulWidget` + `eventSeq.addListener`——每次自增恰好触发一次 post-frame 消费，与重建彻底解钩。

### 1.3 验证

- 新增 `test/ui_event_dedup_test.dart`（7 项全过）：同因 5s 窗口抑制（含连续第三次）、异因立即放行、窗口过期放行、error 与 guard 共用抑制、liveprog 编译失败仍写 `lpError`、EventBanner 一次事件一个 SnackBar、不同成因排队不吞。

## 2. 延迟徽标假接通（症状 3）——详述

### 2.1 根因

引擎 `probe_is_supported`（`engine/chain/engine_probe.cpp:119`）明确：
- 支持 17 个组件（bass/reverb/eq/tube/crossfeed/limiter/post/shelf/comp/bassmono/exciter/stereo/arbmag/dyneq/filter/gate/loudness）；
- **haas 不入列**（注释：探针打双声道脉冲，haas 只延迟一侧必测出 0ms，"伪造零延迟比报不可测更危险"）；
- convolver/ddc/liveprog 需外部资源。

而 Dart `isLatencyProbeSupported`（`state.dart` 旧集合）含 `haas` 与 `bass_shaping`，且 `refreshComponentLatency` 为二者内置假测量：
```dart
if (compId == 'haas') { Future.delayed(120ms, () => _measuredLatencyMs['haas'] = haasDelayMs); }
if (compId == 'bass_shaping') { Future.delayed(100ms, () => _measuredLatencyMs['bass_shaping'] = 0.0); }
```
→ 用户点 ↻ 后徽标从「≈X.X ms」变成无 ≈ 的"实测"值——**把标称值冒充实测**。同时 spatial 不在集合中（正确）却与 haas posture 不一致。同一功能三套口径。

### 2.2 修复

- `isLatencyProbeSupported` = 引擎 kSupported 中有卡片的部分 + 资源型 `{convolver, ddc}`（17 项，见代码注释）；
- 删除两处假测量分支；
- `componentLatency` 的 ≈ 标称态保留（haas/spatial/ddc 等），徽标三态（实测/≈/未测量）不变。

### 2.3 验证

- 新增 `param_contract_test.dart` **Part G**：解析 `engine_probe.cpp` 的 kSupported 表与 `state.dart` 集合，断言 Dart 集合 ⊆ 引擎表 ∪ 资源型白名单，且白名单成员必须在 `latencyProbeResource` 有分支（防豁免腐烂）；
- **阴性对照**：临时把 `'haas'` 注回 Dart 集合 → Part G 立即报警（列出越界组件）→ 还原。

## 3. 块自己变：7 条 UI 超界参数（症状 2）——详述

指令五 Part F 已登记 12 条范围分歧，其中 7 条为「UI 超界」（spec 宽于引擎表）。本轮全部对齐：

| spec | 旧范围 | 引擎表 | setter 旧态 |
|------|--------|--------|------------|
| bass.subFloor | 10..80 Hz | 10..40 | **无 clamp** |

| filter.q | 0.1..10 | 0.3..10 | 0.3..10 ✓ |

# 追加轮（2026-10-19）：用户实测反馈三项

## A. 低音塑形 / 差分环绕（haas）/ 空间音效的延迟测量按钮点不动

**根因**：上一轮摘除假测量时把三张卡的 ↻ 一并禁用（`onRefreshLatency=null`）——
"按钮存在但永远点不动"同样是不诚实 UI。用户明确要求可用按钮。

**修复（三档口径，`hasLatencyRefresh` + `refreshComponentLatency` 分支）**：
1. **低音塑形（bass_shaping）**：恢复真探针——合并卡映射到引擎实名
   `kLatencyProbeAliases = {'bass_shaping': ['shelf', 'bassmono']}`，
   逐段打脉冲实测求和（任一段失败即整体失败，不拼凑数字）；
2. **差分环绕（haas）/ 空间音效（spatial）**：引擎探针结构性失明
   （haas 纯延迟线必测出 0ms / spatial 直达+并行反射），↻ = **标称刷新**
   （脉冲动效 + 重算估算值），保持 ≈ 估算态，绝不写 `_measuredLatencyMs`；
3. 顺带清除 `setHaasDelay` 中残留的假实测写入。

**门禁**：Part G 扩展——别名目标必须 ⊆ 引擎 kSupported；haas/spatial 不得混入真探针集。

## B. 立体声扩展：打开滑块全是 0 → 自己跑到 50%；高级面板 0%；归位按钮却回到 50%；0% 不是会话记忆

**取证**：用户机 `%APPDATA%/AuraDSP/session_state.json` 数据完好
（mix=0.5, bands=[0.158…0.375], on=true）——是**显示/回写链路**丢数据，非存储丢失。

**根因（两个叠加缺陷）**：
1. **getParam 自填充缓存不随字段直写失效**（`state.dart` 旧实现）：
   会话恢复（PresetLibrary.postApply）、readback、`resetStereoBand` 全是
   字段直写，不经过 `_paramValues` 缓存 → UI（ParamSlider→getParam）读到
   陈旧值；"归位默认"按钮恰好走 `setParam`（同步刷缓存）才显示正确——
   同一数值两条显示链路互相打架。
2. **readback 把引擎静音值当滑块真相回写**：`stereoOn=false` 时回放/推送
   按设计给引擎发 `stereo.mix = mix × widenMax × 0 = 0`（静音语义），
   但 `case 'params'` 无条件 `stereoMix = raw/widenMax` → **UI 滑块被清零**
   → autoSave 把 0 存回会话（**会话记忆被静默销毁**，即"0% 不是我上次的
   记忆"）→ 下次打开开关被 `setStereoEnabled` 兜底拉回 0.5（"自己跑到
   50%"）。完整链条与用户描述逐字吻合。

**修复**：
- `getParam` 改为 **getter（字段真相）优先**，`_paramValues` 仅保留镜像写入
  （供 getParamById 未注册回退与诊断），不再参与读取——陈旧缓存类问题连根消除；
- readback 的 stereoMix 回写加 `if (stereoOn)` 守卫：静音值 0 不覆盖 UI 记忆；
  开关开启时对账照常（引擎钳位/纠正仍生效，roundtrip 0.4→0.3→0.4 已测）。

**新增测试** `test/ui_stereo_restore_test.dart`（6 项）：字段直写立即可见、
关闭态 readback 不清零、开启态正常对账、开关兜底 0.5、三卡 ↻ 口径、
标称刷新不冒充实测。
