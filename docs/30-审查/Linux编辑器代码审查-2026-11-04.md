## 修复

- **F1（鲁棒性，最重要）**：X11 层原未安装 X 错误处理器。
  libX11 默认处理器遇到协议错误（如与插件/WM 的窗口销毁竞态
  产生的 BadWindow——编辑器场景的常态竞态）会打印并**终止整个
  进程**：进程内模式即整个 App，隔离模式即宿主进程。已在 API
  初始化时全局安装非致命处理器（吞错续行，出错的查询由后续
  事件/登记表收敛）。**实证**：引擎 X 层初始化后，同进程对不
  存在窗口发 XGetGeometry+XSync 进程存活；对照组（无处理器）
  打印经典致命错误并退出。IO 错误（X 服务器断开）不接管——
  会话本身在消亡。门禁加 [sec] 不变量钉住。
- **F2**：DestroyWindow 原在调用线程无连接时借用属主线程的
  Display 跨线程销毁——其线程安全依赖 XInitThreads 先于进程内
  任何 XOpenDisplay 生效，而插件可能抢先开自己的连接，不保。
  改为只用调用线程自己的连接（无则为本线程新开），窗口是服务
  端对象、任意连接可操作，跨线程 Display 共享彻底消除。
- **F3**：DestroyWindow 的 XEmbed 登记清理只清容器侧，漏了本
  窗作为他人子窗口的条目（DestroyNotify 分发路径两侧都清）。
  两侧同口径，防 XID 复用后误抑制一次 EMBEDDED_NOTIFY。
- **F4**：分发事件循环无上限，病态插件以事件洪流可饿死本泵的
  任务处理（任务超时→实例被隔离）。单轮上限 256，余量留下
  一 10ms 节拍。门禁加不变量钉住。
- **F5（文档）**：plugin_util_posix.cpp 中 ResizeDirectChildren
  上方的过期注释（仍称「本阶段为空操作/后续阶段」）与真实现
  矛盾，已替换。

## 复核无误（要点）

- 分发在递归锁内调实例回调：回调回入本层 API 同锁递归，跨线
  程调用至多等一轮 X 往返，非 RT 路径，可接受。
- 定时器分发用 due 快照迭代，回调增删定时器不影响本轮迭代。
- WM_DELETE 分发中实例同步 DestroyWindow：事件已拷贝到栈上，
  登记表擦除与后续事件按「无此窗口」跳过，安全。
- GetWindow 的 GW_CHILD/GW_HWNDNEXT 遍历（见 O1）唯一消费方
  ResizeDirectChildren 双平台同实现、只求全量覆盖。
- 泵循环钩子：快照在等待前取、stop 谓词优先、任务先于钩子；
  空任务+stop 正确退出。
- 门禁 [editor] 节在 main() 链序末尾，其 DISPLAY 环境写入不影
  响其他节；Xvfb 自启只终止自有进程。
- 引擎符号面未变（CI J4 ABI 已于 75aaff9 全绿佐证）。

## 观察（不改）

- O1：XQueryTree 子窗口为自下而上的堆叠序，GW_CHILD 返回最底
  子窗口、GW_HWNDNEXT 向上走——与 Win32 的 z 序方向相反。
  唯一消费方遍历求全覆盖，顺序无关；若将来有依赖顶层子窗口
  的代码须注意。
- O2：CLAP 插件定时器（timer_support）双平台都只登记未分发
  到 on_timer（E1 发现）——dev 侧如修应双平台同修。
- O3：调用线程的 Display 惰性创建后不关闭（线程数有界），与
  Win32 线程消息队列同寿命，可接受。
- O4：canEdit 仅凭 DISPLAY 非空判断；DISPLAY 已设但服务器不
  可达时 canEdit=true，打开逐次干净失败（caps 注释已注明）。
- O5：XEmbed 键盘协商完整度仍待真机真实插件验证（清单 §3f）。
