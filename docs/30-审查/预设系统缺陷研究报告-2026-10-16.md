## 0. 根因总图：三套互不一致的默认值

预设系统不存在「唯一真相源」，同一参数有三套默认值，任何修复必须先统一口径：

| 层 | 位置 | 作用 | 问题 |
|---|---|---|---|
| Dart `ParamDefaults` | `state.dart` L64-171 | UI 初始显示值 | 与引擎默认值有 5 项不一致（见 §4.1） |
| 引擎 `struct Params` | `engine/engine_internal.h` L101-227 | 引擎实际运行默认值 | 注释与自身默认值矛盾（L213） |
| isolate `getParams` fallback | `audio_isolate.dart` L565-665 | 引擎回读缺失时的兜底 | 第三套值（如 `limiterEnable ?? 1`，L575） |

此外 **snapshot ↔ apply 契约是隐式的**：`snapshot()` 写 110 个叶子字段 / 23 个顶层节，`apply()` 逐节 `if (x.isNotEmpty)` 读回——没有声明式 schema，字段对称性全靠人工对齐。已暴露过两次同类事故（eqGains 按下标被吞，已修；bandUsed 被副作用覆盖，本轮修）。

## 1. 代码自带硬置入问题

### 1.1 出厂预设硬编码在 Dart 源码里（设计缺陷，未修）

`_builtInPresets`（`presets.dart` L873-1140）把 6 个出厂预设（Pop Vocal Clarity / Rock Bass Impact / Symphonic Concert Hall / Vintage Vinyl Tube / V-Shape Smile Hi-Fi / Studio Flat Monitor）完整写在源码中。

### 1.2 出厂 JSON 落盘后永不更新（实证，未修）

`ensureInitialized()`（`presets.dart` L72-87）L81 为 `if (!f.existsSync())`——只在文件不存在时写盘。**代码内 `_builtInPresets` 的任何后续修改都不会同步到老用户磁盘**，出厂预设只能首装定版，运营期无法热修。

### 1.3 出厂预设缺 16-17/23 个效果节（实证，未修）

| 出厂预设 | schema | 缺失节数 | 缺失清单 |
|---|---|---|---|
| Pop Vocal Clarity | v2 | 17/23 | arbmag, bassmono, chainOrder, comp, convolver, crossfeed, ddc, deesser, dyneq, exciter, filter, gate, haas, **input**, liveprog, loudness, shelf |
| Rock Bass Impact | v2 | 17/23 | 同上 |
| V-Shape Smile Hi-Fi | v2 | 17/23 | 同上 |
| Vintage Vinyl Tube | v2 | 17/23 | 同上 |
| Studio Flat Monitor | v2 | 16/23 | 同上（少 shelf） |
| Symphonic Concert Hall | v2 | 16/23 | 同上（少 shelf） |

注意 **input 节全部缺失**。配合 apply 的合并语义（§3.2），出厂预设实际上只能「锦上添花」，永远关不掉用户态。

### 1.4 `preset: -1` 分支用硬编码兜底覆盖用户自调值（已修复 ✅）

`presets.dart` L488 起的 `apply()` reverb 节，旧代码 6 个 `?? 硬编码` 兜底：

```dart
// 旧（缺陷）：preset=-1 且预设未携带该键 → 无条件写死默认值
m.setReverbCustomParam('decay', (rev['decay'] as num?)?.toDouble() ?? 0.5);
m.setReverbCustomParam('wet',    (rev['wet']    as num?)?.toDouble() ?? 0.35);
m.setReverbCustomParam('roomSize', (rev['roomSize'] as num?)?.toDouble() ?? 1.2);
// ...damp/dry/stereoWidth 同理
```

4/6 出厂预设的 reverb 节只有 `{'enable': false, 'preset': -1}` 两个键（L943/L1038/L1081/L1120）——预设本意是「关混响」，但 apply 走 -1 分支时**仍无条件把 6 个 customParam 全部写成硬编码默认值**。实证：用户自调 `decay=0.9 / wet=0.8 / roomSize=2.2`，apply「Rock Bass Impact」后变为 **0.5 / 0.35 / 1.2**。

**修复**（`presets.dart` L493-522）：6 个 customParam 全部改为 `if (rev['key'] != null)` 按键守卫——缺键 = 不碰用户现值。用户预设（snapshot 必写全 6 键）行为不变；出厂/手写预设不再污染用户值。回归测试：`config_and_presets_test.dart`『apply() reverb preset=-1 分支：缺键不碰用户自调值，显式键照常写入』（双向：缺键保持 + 显式键写入）。

### 1.5 出厂预设 EQ 无频率信息（实证，未修）

出厂预设 eq keys = `[enable, bandsCount, gains, q, filter, interp, presetName]`，**无 frequencies、无 qs**。`apply()`（`presets.dart` L539-580）只能退化为「按段数 + 下标灌 gains」。代码注释 C4（L562-569）已自承：跨采样率/跨段数时会把增益贴到错误频点。用户预设有 frequencies 可走频率重映射；**出厂预设永远走不了**。

### 2.2 复核裁定：`bass.gain` 是假阳性（撤销 v1.0 结论）

v1.0 断言「snapshot 写 `bass.gain`（L260）、apply  bass 节不读回」——**代码事实成立，但不是缺陷**：

- `setBassIntensity`（`state.dart` L2630 起）内部 `bassGain = intensity × 15.0`（L2633）——**gain 是派生字段**；
- UI 唯一入口是 bass 滑块调 `setBassIntensity`（`features/effects/bass_card.dart` L46），**没有任何 UI 路径独立设置 gain**；
- 实证（复核探针 R1/R3）：intensity 0.0/0.25/0.5/0.9/1.0 → snapshot gain 恒等于 intensity×15，apply 经 intensity 完整还原 gain。探针 A1 的 MISMATCH 是**直接写 `m.bassGain` 造出了 UI 不可达的状态**。

教训：探针造状态必须走 UI 可达路径，否则证明的是不存在的问题。

### 2.3 改判：`stereo.bandUsed` 的真缺陷是「强制置真」（已修复 ✅）

v1.0 说「只写不读」；复核发现 apply 从不直接读 bandUsed，但 **`setStereoMix`（`state.dart` L1711）与 `setStereoBand` 自带 `bandUsed = true` 副作用**（保持旧 `_mirror` 行为）。而 apply 的 stereo 节只要快照带 mix 键（snapshot 恒带）就调 `setStereoMix` → **任何会话恢复后 bandUsed 恒为 true**。`engine_chain.cpp` L84 按 `stereo_band_used` 二选一展宽模式 → 「从未调过分带」的用户恢复后也被切成 per-band 模式，与全新安装（bandUsed=false）行为不一致。

**修复**（`presets.dart` L633-637，stereo apply 节末尾）：读回快照值覆盖副作用。

```dart
if (st['bandUsed'] != null) {
  m.stereoBandUsed = st['bandUsed'] as bool;
}
```

回归测试：『apply() 对称读回 stereo.bandUsed（setStereoMix 副作用不得覆盖快照值）』，双向断言（true→true / false→false，后者修复前必红）。

## 3. 用户记忆与预设打架

### 3.1 会话与预设共用同一份 schema（结构性耦合，未修）

`SessionMemory.save()`（`session_memory.dart` L23-66）内部调 `PresetLibrary.snapshot(m, name: '__session_memory__')`——snapshot 的每个缺陷同时污染预设与会话两条链路。会话额外在顶层存 `convIrPath / ddcPath / lpCode / arbmagString / slots`。

### 3.2 apply 是「合并」不是「替换」（实证，未修）

`apply()` 逐节 `if (x.isNotEmpty)` 守卫 → **缺节 = 不碰该效果，而非关闭该效果**。实证：用户开 gate/dyneq/haas/exciter/bassmono 五效果，apply「Studio Flat Monitor」后**五个全部仍为 true**。出厂预设只有 6-7/23 节（§1.3）→ 应用任何出厂预设，用户态在其余 16-17 个效果上原样残留。UI（`features/effects/preset_card.dart`）只提示「已应用」，无合并告知。

### 3.3 apply 的隐藏副作用：改写 activePresetName（未修）

`apply()` 末尾执行 `m.activePresetName = preset.name`。`restoreMemoryImage` 靠「先存后还原」（`session_memory.dart` L146-154，`__restored__` 傀儡预设）绕开。此坑只有注释固化，无测试守护。

### 3.4 启动恢复无回放保护，立即回写自身（已修复 ✅）

`scheduleAutoSave()`（`state.dart` L717-724）守卫为 `if (_testing || _isReplayingSession) return`，但 `_isReplayingSession` 原先**只在 `replaySessionToEngine()` 内置位**；构造期 `restoreMemoryImage` 不置位 → 每次冷启动恢复后 500ms 把刚读入的数据原样写回磁盘（自写），且与引擎异步 getParams 有竞态窗口。

**修复**（`state.dart` L665-678）：构造期恢复包 try/finally 置守卫，与 `replaySessionToEngine` 同模式。不变量测试：『setGraphOrder 挂自动保存、两处回放均有守卫』断言 `_isReplayingSession = true` 恰好出现 2 次。

### 3.5 自动保存覆盖缺口（部分修复，一项改判）

| 方法 | v1.0 结论 | 复核后 |
|---|---|---|
| `setGraphOrder`（L1789） | 不持久化 | ✅ **已修**：补 `scheduleAutoSave()`。chainOrder 确实被 snapshot 采集（`presets.dart` L433）并被 apply 读回（L631 起），修复有效 |
| `setSource`（L3593） | 不持久化 | ⚠️ **改判**：`SessionMemory.save` payload 与 snapshot 均**不采集** sourceKind/sourcePath —— 单补 `scheduleAutoSave()` 是空转。真缺口在上游 schema，需 v5 扩 schema + replay 下发（含 UX 决策：是否接受启动即恢复播放源） |
| `toggleBypass`（L3609） | 不持久化 | ⚠️ **改判**：同上，bypass 未被 schema 采集；且 replay 也不下发 bypass。需 schema + replay 联动改造 |
| `resetConfig`（L3662） | 不清会话 | ✅ **已修**：见 §3.6 |

### 3.6 「恢复默认」不清会话记忆（已修复 ✅）

旧 `resetConfig()` 只重置 `config.json`。用户点「恢复默认」后下次启动 autoRestore 把旧参数全部还原——与心智模型直接冲突。

**修复**（`state.dart` L3662-3673）：

```dart
_debounceSaveTimer?.cancel();   // 先取消挂起防抖，否则 500ms 后文件被写回
SessionMemory.clear();
```

回归测试：『resetConfig 连带清除会话记忆（恢复默认 = 全部归零）』——先 save 造文件，resetConfig 后断言文件消失。

## 4. 初始化的 UI 显示参数 vs 实际参数冲突（均未修）

### 4.1 默认值三方不一致（36 项比对 5 项不符）

| 参数 | UI 初始显示（Dart） | 引擎实际默认（C++） | 影响 |
|---|---|---|---|
| `stereoOn` | false | **1**（`engine_internal.h` L106） | UI 显示立体声关，引擎实际开着跑 |
| `limiterOn` | true | **0**（L108） | UI 显示限幅器开，引擎实际关着 |
| `tubeGain` | 4.5 | **0.0**（L123） | UI 显示 4.5dB 驱动，引擎 0dB |
| `fvWet` | 0.35 | **0.3**（L211） | 混响湿度显示偏差 |
| `fvRoomSize` | 1.2 | **1.0**（L213） | 房间尺寸显示偏差 |

L213 注释自相矛盾：`fv_roomsize{1.0f} /* ...（UI 默认 1.2，session 回放对齐）*/`。第三套值在 isolate 兜底（L575 `limiterEnable ?? 1`）。

**用户可见场景**：全新安装、未开会话恢复时，UI 显示与引擎真实状态不一致。

### 4.2 getParams 回读不完整：UI 永远得不到引擎真相

`audio_isolate.dart` L566-665 的 `params` 事件只回读约 30 项，**14 类参数缺失**：

```
stereo.enable / tube.gain / stereo.band1..5 / input.gain / input.balance.1/2
fv.roomsize / fv.width / eq.band gains, qs, filter, interp, bandsCount
graph.order / bass.intensity / bass.mode / arbmag.string / liveprog.code
```

叠加 `_mirror`/`_markSent` 乐观镜像设计（UI 只信自己发的值），不回读 = **盲飞**：引擎侧若因守卫拒绝、脚本改写、真机差异偏离 UI 值，界面永远显示错误的态且无从发现。

## 6. 剩余项与决策点

探针文件（`zz_preset_defect_probe.dart` / `zz_verify_roundtrip.dart`）在修复期间被外部从工作区删除，未重建（诊断使命已完成，剩余缺陷形态已固化在本报告 §1.3/§3.2/§4.1/§4.2 的实证描述中）。剩余问题及所需决策：

5. **source/bypass 持久化（§3.5）**：session schema v5 扩展 + replay 下发 + 「启动是否恢复播放源」UX 决策。

### 语义定版（铁律）

- **全局预设 = 全部复写**：缺节/缺键 = defaults 基线复位（不再「缺节不碰」）；例外不复写：chainOrder（全局路由）、资源路径（lpCode 等，会话级）。
- **效果器自有预设（fullRewrite=false）= 只覆盖自己的所有配置**：只应用实际携带的节，节内缺键不碰现值（F2 守卫沿用）。
- **一点偏离即未保存**：任意参数偏离已应用预设指纹 → 「自定义（未保存）」，随会话记忆，重启不丢。
- **测试音永不持久化**：关闭前开着测试音，重启必须默认关闭。
