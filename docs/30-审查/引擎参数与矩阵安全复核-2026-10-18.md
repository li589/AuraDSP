# 引擎参数与矩阵安全复核（2026-10-18）

> 范围：`auradsp_set_param` 浮点写入、mode-0 矩阵 LFE 直通、声道/模式切换、spatial ITD/反馈状态、平台约束。
> 方法：逐项对照当前源码 + 定向 smoke；修复后跑全量 `runner.py --smoke`。

## 1. 复核结论

| # | 报告项 | 是否属实 | 结论/处理 |
|---|---|---|---|
| 1 | `set_param` 浮点 `< / >` 钳制不拒绝 NaN/Inf | **属实** | `auradsp_set_param` kFloat 分支新增 `std::isfinite` 拒绝；NaN/Inf 返回 `AURADSP_E_PARAM`，原值保持不变 |
| 2 | mode-0 矩阵 LFE 原始直通未过 NaN 卫士 | **属实** | `mx_upmix` 的 LFE 写入改为 `isfinite(sp[3]) ? sp[3] : 0` |
| 3 | `channels.count` / `channels.mode` 切换不触发 spatial_reset | **属实** | 两个 setter 均调用 `spatial_reset(h)` |
| 4 | ITD 127 样本钳制在 192kHz 饱和 | **属实** | `kSpatItdLen` 128 → 256；spatial 内 128/127 字面量改用 `kItdLen`，192k 0.8ms≈154 样本可容纳 |
| 5 | 128/32768 魔数与常量耦合 | **属实** | 新增 `kItdLen`/`kHistLen` 别名，早期反射/延迟环全部改用常量 |
| 6 | channel_count / JSON / 分配锁 / VizRing 安全 | **复核通过** | 与报告一致：2/4/6/8 白名单、JSON 边界、RT 无分配/锁、SPSC 64 槽 |
| 7 | 桌面引擎 Windows-only | **属实，需固化** | `engine/` 桌面 DLL 目标为 Windows x64（Win7+）；Android 走独立 AIDL 壳，不在同一二进制 |

## 2. 关键细节

1. **NaN 的持久污染**：链尾卫士只能把输出 NaN/Inf 清零，不能清除已经进入二阶节/延迟线/FDN 的内部状态。因此必须在参数入口拒绝，而不是依赖链尾。
2. **注入面**：Dart UI 的 `ParamSpec.clamp` 对 NaN 也会返回 NaN（`num.clamp` 对 NaN 不抛错），所以引擎侧拒绝是必要的第二道门。VM 桥/AIDL/预设回放同样受益。
3. **LFE 直通**：mode-0 的 LFE 是刻意 bit-exact 直通，不能用“链尾已清洗”推断安全；现已单独清洗。
4. **ITD 与 192k**：`kSpatItdLen=256` 支持 192k 下 0.8ms（154 样本）完整 ITD；超过上限仍钳制，避免越界。

## 4. 平台约束（固化）

`engine/` 是 **Windows 桌面 DLL** 目标（MSVC x64，Win7+；`CreateFile2` 等 API 有 Win7 shim）。Android 使用独立的 AIDL effects HAL 壳（`core/android/`），不复用该二进制；Linux 尚未落地。后续新增引擎平台能力时必须先明确平台分支，不得默认 `engine/` 跨平台。
