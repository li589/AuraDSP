## 1. 复核口径

本轮把每一项按三种状态归档，避免"登记过 = 还在做"的模糊账：

| 状态 | 判定标准 | 处置 |
|---|---|---|
| **已闭环** | 代码或产物实测已达登记项的目标状态 | 销账，从在册清单移除，补记证据 |
| **仍在册** | 代码实况确认未修 | 保留原编号与级别，补记本轮取证位置 |
| **待裁定** | 需 owner / 产品决策才能定方案 | 单列，不与技术遗留混排 |

> 判定纪律：凡称"已闭环"者，本轮均给出可复核的取证位置（文件行号 / 产物时间戳 / 测试名）。

### 2.6 L-01 / L-02 / L-03（高危并发三项）—— 已销账（2026-10-31 晚，P0 双池专项）

**触发**：用户选定 P0 双池专项，把 §3.1~§3.3 三项合并为一个专项闭环。

**先核事实（三项的根因都比登记描述更硬）**：

- L-01 / L-03（池）是**崩溃级**，不是听感问题：`FFTConvolver1x1LoadImpulseResponse` 首步即
  `FFTConvolver1x1Free`（`engine/legacy/jdsp/Effects/eel2/numericSys/FFTConvolver.c:386-387`），
  会 free 掉 `_fftBuffer` / `_overlap` / `_inputBuffer` / `_segments*`；与 RT 的
  `FFTConvolver1x1Process` 并发 ⇒ **释放后使用（UAF）**。
- L-03（主 conv）是**撕裂级**：vendor 的 `ArbitraryResponseEqualizerStringParser`
  （`engine/legacy/jdsp/Effects/arbEqConv.c:29`）对 `arbMag.conv` 做**原位**
  `RefreshImpulseResponse`，RT 的 `stage_arbmag` 同时在同一对象上跑
  `FFTConvolver2x2Process`（`arbEqConv.c:53`）⇒ RT 读到「一半新、一半旧」的 IR。
- 三项此前**都不在任何锁的保护范围内**：`ctrl_mutex` 明确不挡 `process`；
  `kAuraStages` 里 eq / arbmag 两条 stage 的 `lock` 均为 0。

**落地**（ADR-011 [](../adr/ADR-011-no-shared-mutable-dsp-state.md)）：

1. **L-01 / L-03（池）**：eq 与 arbmag 两个逐声道池各改为 **2 个 bank（活动槽 + 影子槽）**，
   控制侧只在影子 bank 上重建 IR 后原子发布 `active`；RT 在 `process_multichannel_chain`
   入口取一次快照，块内不碰换出的 bank；`loaded` 标志下沉到 bank 内（不再是跨线程裸 `int`）。
   在途守卫与 comp B1-c 同式（`in_flight == 0` 或 `proc_count >= retired_at`），
   有界等待 500ms 墙钟，仍不可用则放弃本次重载（旧 IR 继续生效）。
   取证：`engine/engine_internal.h`（`PoolBank` / `EqPool` / `ArbmagPool`）、
   `engine/chain/engine_chain.cpp`（`pool_pick_shadow` / `pool_publish` /
   `eq_pool_reload` / `arbmag_pool_reload`）。登记：PATCHES.md **P-047**。
2. **L-03（主 conv）**：`kAuraStages` 的 `arbmag` stage 由 `lock 0` 改为 **`lock 1`**，
   控制侧刷新前同持 `jdsp_lock`。取证：`engine/legacy/jdsp/jdspController.c`（`kAuraStages[]`）、
   `engine/engine_param_table.h`（`arbmag_refresh_vendor_conv`）。登记：PATCHES.md **P-048**。
3. **L-02**：`reset_channel_state()` 拆为控制侧（置位 `reset_req`）+ RT 侧
   （`reset_channel_state_rt`，在 `auradsp_process` 入口消费）。取证：
   `engine/chain/engine_chain.cpp`（两个函数）、`engine/auradsp_engine.cpp`（入口消费）、
   `engine/dsp/dsp_spatial.cpp`（`spatial_reset` 迁至 RT 线程）。

**门禁**：`test/smoke/smoke_pool_race.py`（已挂 `runner.py` 的 `smoke_files`），四阶段
（eq 池 / arbmag 池 / 主卷积撕裂 / 拓扑重置）+ 收尾健康检查。

### 3.1 L-01（高危并发）—— eq 逐声道池与 RT 共享同一卷积实例 → **已于 2026-10-31 销账（见 §2.6）**

### 3.5 VST2 / AU / LV2 插件格式 —— 引擎侧无驱动

**实况**：

- 引擎侧仅两个格式驱动目录：`engine/plugins/formats/{clap,vst3}`。无 VST2 / AU / LV2 驱动实现。
- Dart 侧 `PluginFormat` 枚举**已含** vst2 / au / lv2，但注释明确其定位是"引擎产出这些格式时列表角标/筛选即刻可用"的预留，不是挂载支持。
- 扫描目录侧已为 VST2 预留（`lib/core/plugins/plugin_scan_dirs.dart:64-67` 提到 VST2 常见目录与注册表探测）。

**结论**：枚举与扫描已就位，**驱动与挂载未实现**。补驱动前需先做授权与 ABI 取舍（VST2 需 `fst` 头，AU 仅 macOS，LV2 与 CLAP 有 ABI 冲突面）。
