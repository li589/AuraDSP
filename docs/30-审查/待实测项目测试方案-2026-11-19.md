# 待实测项目测试方案（2026-11-19）

对象：《未决问题登记》B 类全部未回告项（B1–B12、B14）。
按机器分组，每项给：目的 / 前置 / 步骤 / 判读 / 回告什么。
协议口径：贴 user 实际能做的动作；文件源测试用整段播放 +
电平/听感时序判读，不要求精确截段。测完回告「编号 + 过/
不过 + 异常现象」即可，异常时附 App 桥 status 或截图更好。
B13（LiveProg DNC 抖动）是测试基建根因追查、非实测项，
不在本方案内；C1/C4 为观察项，C4 的行为级覆盖并入 B7。

## 一、宾机 vm-win10（装 r56 Setup 后）

### B1 VB 离散环绕复测

- 目的：VB 模式离散 7.1 逐声道是否各自正确送达（历史症：
  SL/SR/BL/BR 单独发声不亮、齐鸣才亮）。
- 前置：Voicemeeter（宾机为标准版，先按现有条件测）里把
  A1/A2 总线声道模式设为 7.1；AuraDSP 输出指向 VB。
- 步骤：① AuraDSP 切 VB 模式，声道模式选「离散」、数量
  7.1；② 播一段 7.1 逐声道测试音（整段播完即可）；③ 全程
  看 App 的输入/输出电平条与 Voicemeeter 回送电平。
- 判读：每个声道单独发声时，只有对应电平条亮 = 过；某声
  道不亮或串到别的条 = 不过，记下声道名。
- 回告：B1 过/不过 + 异常声道名。

### B2 ASIO 模式 ioCh 回告

- 目的：确认 ASIO 桥协商到的设备声道数与电平口径是否一致。
- 步骤：① 切 ASIO 模式，选日常用的 ASIO 设备，播放任意
  立体声内容；② 打开 App 里 ASIO 桥的状态/诊断信息，看
  ioCh 的数值；③ 看电平条实际在动的有几条。
- 判读：ioCh=2 且两条电平在动 = 正常；ioCh≥6 但只有两条
  电平在动 = 真缺陷。
- 回告：B2 ioCh=<数字> + 电平在动条数。

### B14 ASIO 监听下混方位确认（r55 新立）

- 目的：r55 纠正了 ASIO 监听下混的错序（旧版 LFE 误折入
  左声道、SL/SR 互换、BR 未入折），听感复核。
- 步骤：① ASIO 模式，声道模式「矩阵」，播 7.1 逐声道测
  试音（监听输出为立体声）；② 逐声道听方位。
- 判读：左/右方位与声道名一致（SL 应偏左后、SR 偏右后、
  BL/BR 同理）、LFE 不应让左声道独响 = 过；左右反了或某
  声道消失 = 不过。
- 回告：B14 过/不过 + 异常声道名。

### B3 切换落零复验

- 目的：模式切换当刻频谱/电平应落零，不残留旧画面。
- 步骤：① 任一模式播放中（频谱在动）；② 依次切换到其它
  模式（APO→VB→VAIO→ASIO→本地管线）并切一次「无声/静
  音」类选项；③ 每次切换盯频谱与电平条。
- 判读：每次切换当刻频谱与电平立即落零、随后按新模式恢
  复 = 过；旧频谱定格残留 = 不过，记下是哪次切换。
- 回告：B3 过/不过 + 残留发生在哪次切换。

### B7 VAIO 端点格式试选 + 驱动块目检

- 目的：① VAIO 端点在非默认格式下的行为级覆盖（含 C4
  的 24 位/多声道端到端）；② 驱动信息块版式目检。
- 步骤：① 设置页看 VAIO 驱动信息块：驱动名 + 状态行 +
  明细行、按钮在同行右侧、末行是操作系统信息（目检）；
  ② Windows 设置 → 声音 → AuraVAIO 扬声器 → 高级，把默
  认格式分别改选 24 位（如 24 位/48000）与浮点（如有该
  选项）各播一段多声道内容；③ 逐声道电平与听感正常后
  改回日常格式。
- 判读：两种格式都出声、电平与声道对应正常 = 过；无声/
  错位 = 不过，记下格式名。
- 回告：B7 目检过/不过 + 格式试选结果。

### B8 VB→VAIO 输出报错判别

- 目的：判别 VB 以 VAIO 为 A1 输出时的 Initialize 报错
  是端点通路问题还是 VB 打开方式问题。
- 步骤：Windows 设置 → 声音 → 输出选 AuraVAIO 扬声器 →
  点「测试」按钮。
- 判读：响 = 端点通（问题在 VB 打开方式，B8 关闭）；
  不响 = 端点通路问题（回告后立项）。
- 回告：B8 响/不响。

### B4 资源计划四项验收

1. **APO 中转**：切 sysapo（APO）模式，在卷积（IR）或
   DDC 里点选一个本机任意目录下的文件，播放。判读：有效
   果（中转自动完成）、界面仍显示原文件路径 = 过。
2. **卸载清 APO 回归**：保持某端点已附加 APO 的状态，
   运行 Setup 卸载。判读：卸载完成后该端点声音正常、
   系统声音设置里端点无 AuraDSP 残留附加 = 过。再重装
   一次（覆盖装变体）能正常装回 = 过。
3. **内置行目检**：打开 LiveProg 脚本库与插件页。判读：
   内置脚本（47 个）带内置标记正常列出、可打开 = 过。
4. **默认层首启**：把 `%APPDATA%\AuraDSP\config.json`
   改名备份后启动 App。判读：各项设置为默认值、无报错
   = 过（测完可把备份改回）。
- 回告：B4-1/2/3/4 各自过/不过。

### B5 第十四轮两项

1. **附加态覆盖安装**：先给一个端点附加 APO 并确认有声，
   再运行新版 Setup 覆盖安装。判读：安装成功、装后该端
   点仍有声且 APO 仍在处理 = 过。
2. **稀疏保存目检**：把设置全部保持默认（或改名 config
   后首启），打开 `%APPDATA%\AuraDSP\config.json`。判
   读：内容仅 `{"version": 4}`（或近乎为空）= 过。
- 回告：B5-1/2 过/不过。

### B12 r42 清单余五项

1. **改格式自动回退**（S1b）：手动声道数设 7.1 后，把输
   出设备格式改成立体声（如在声音设置改默认格式或换一
   台立体声设备）。判读：App 显示/生效声道自动回退到设
   备能力、不报错不出怪声 = 过。
2. **静默显示即时性**（S3）：无播放时改声道数量设置。
   判读：界面显示的声道数立即跟着变，不需等播放 = 过。
3. **端点列表目检**（S4）：APO 端点列表的外观与滚动、
   加载态显示正常 = 过（r56 后顺带复看滚轮不串页）。
4. **LFE 峰位目检**（S6）：矩阵模式播带 LFE 内容，看频
   谱：LFE 能量应落在低频段位置 = 过。
5. **系统变化自动跟随**（S5）：App 运行中在系统里改默认
   输出设备或插拔一个音频设备。判读：数秒内 App 设备列
   表/状态自动跟上、无需手动刷新 = 过。
- 回告：B12-1..5 各自过/不过。

### B9 第九轮手工回归两件（apo_config 命令行，宾机管理员终端）

1. **手工毒化回归**（Phase B）：前置是附加过 APO 的端点。
   步骤：① 在注册表里手工给某端点 FxProperties 留一个
   AuraDSP 的 CLSID 残留（模拟毒化，无台账记录）；② 跑
   安装目录 `driver\apo_config.exe status`——应如实报出
   残留（真值可见）；③ 跑其 strip/修复命令剥离残留；
   ④ 再 status 应干净、端点播放正常。判读：四步如述 =
   过。具体子命令名以 `apo_config.exe --help` 为准，卡住
   把帮助输出发我。
2. **testenv-off 守卫**（Phase C）：端点仍挂载 APO 时跑
   `apo_config.exe testenv-off`（子命令名以 --help 为
   准）。判读：被拒绝（退出码非 0、给出仍有挂载的提
   示）= 过；直接关掉 = 不过。
- 回告：B9-1/2 过/不过 + 异常输出原文。

## 二、开发机（日常机，顺手测）

### B6 第十六轮三项（COM 指回为 D4，另行处理）

1. **切离 sysapo 等待 UX**：sysapo 模式下切到其它模式，
   观察等待提示/整页覆盖是否出现、等待时长可接受、切
   换最终成功 = 过。
2. **UAC 拒绝路径**：触发一次需管理员的操作（如装/卸
   驱动），在 UAC 弹窗点「否」。判读：App 给出明确失败
   提示、状态与实际一致、不假死不误报成功 = 过。
3. **插件三动作**：插件页对任一插件分别用「立即应用 /
   自动应用 / 恢复」三动作各一次。判读：三者行为与文案
   一致（立即生效 / 改参自动生效 / 回到默认）= 过。
- 回告：B6-1/2/3 过/不过。

## 三、vm-linux（需先同步：Lux 需 user 给口令把克隆同步到当前头）

按 `docs/40-回顾/Linux真机验证清单.md` 未确认节执行，
此处给判读要点：

- **§3b ALSA 专家模式**：后端切 ALSA 直连后引擎自动重
  启、状态区显示协商结果（period 256 / buffer 1024）；
  填 `hw:<卡>,<设备>` 真声卡直开出声且延迟明显低于 PA
  模式；被 PipeWire 占用的声卡直开应明确报 EBUSY 不崩
  溃；snd-aloop 后 driver 模式采集走 ALSA 直连出声。
- **§3c 插件宿主**：插件页可打开、扫描目录可见；放真实
  VST3/CLAP 进目录能扫到并挂载出声（进程内）；设
  `AURA_PLUGIN_HOST_MODE=process` 启动后挂载，`pgrep
  plugin_host_x64` 见宿主进程，播放中 kill 宿主引擎不
  崩、重载可恢复；编辑器按钮在 Linux 应明确不可用。
- **§3e VST2**：真实 VST2（.so）放 ~/.vst 能扫到（格式
  显示 VST2、名称厂商为真值、普通依赖 .so 不入列），
  挂载出声、参数页可调。
- **§3f 编辑器 GUI**：真实 CLAP/VST3/VST2 插件点编辑器
  能开 GUI、渲染完整、旋钮可拖且参数回写；拉伸窗口跟
  随无白框；点 X 关闭干净、重开正常；编辑器内数值控
  件可获焦录入；纯 Wayland 无 XWayland 时编辑器入口保
  持不可用而扫描/挂载/出声不受影响。
- 回告：按小节编号逐项过/不过 + 异常现象（附日志行更好）。
