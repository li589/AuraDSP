## 项 1：vm-win10 开机必崩（卡住后闪退）——定罪并三层修复（`3e0fc8ca`）

历轮悬案（第四轮项 5「刷新设备崩溃」、第五轮项 5 同型）在本轮由用户提供的 WinDbg dump（LocalDumps 全内存转储）一举定罪：

- **dump 实证**：崩溃模块 `auravaio_bridge.dll+0x6d51`，读违例，指令 `cmp dword ptr [rax+1Ch], r15d`（r15=2）；进程存活 6 秒；崩溃线程为桥泵线程。
- **指令还原**：`AURA_VAIO_SHARED_HEADER.Channels` 偏移恰 0x1C，泵主循环每轮执行 `pHeader->Channels != ringChannels`（ringChannels 初值 2）——读的那一刻映射已不存在。
- **全链（代码）**：`vaio_detect` 每次调用都 `CreateFileW` 打开 VAIO 控制设备、查完 `CloseHandle`；驱动 `AuraControlDevice_DispatchCleanup`（IRP_MJ_CLEANUP）在句柄关闭时到达，旧实现**只按进程判定**便 `MmUnmapLockedPages` 全局唯一映射——不区分关闭的是哪个文件对象。桥运行期任何一次 detect（开机起桥后紧跟的自动检测、设置页刷新设备）都会拆掉泵正在读的环映射。泵在 WASAPI Start 重试分支里不读头，故拆映射后不立即死；渲染一起跑、首次读头即 AV，整进程死亡——与「刷新后即刻闪退」「开机数秒后闪退」两种时序都吻合。无 VAIO 驱动的 Win11 从不闪退亦与此链一致（无控制设备可开）。
- 本轮日志旁证：S1 持久化真机实证（VAIO 模式还原起桥）；S5 双埋点齐全，排除 detect 的 Dart 回程；S4 取证首采干净（静音首块，游标对齐），噪声线与本链无关。

修复（三层，任一生效即断链）：
1. **驱动根治**（`ControlDevice.cpp`）：映射归属记到 FILE_OBJECT（MAP 时记 `stack->FileObject`）；CLEANUP 仅当关闭的文件对象 == 归属者才解映射；UNMAP/Destroy 同步清归属。**需重编并重装 VAIO 驱动后生效。**
2. **桥侧兜底**（存量驱动立即有效）：`vaio_detect` 在桥运行期不再打开控制设备——驱动在场由「桥在跑」自证，版本改用 `vaio_start` 在同一控制句柄上查一次的缓存（新增 `drvVer*` 字段），状态由环几何合成；端点枚举部分不变。
3. **第二入口封堵**：`vaio_stop` 等泵退出 2 秒超时旧实现无视结果继续拆解——改为写 note `pump-stop-timeout: teardown deferred` 并中止本次拆解（return -6），不在活泵脚下解映射/毁引擎，句柄与映射保留待后续 stop 收尾。

## 项 2：Win11 ASIO 装不上 + 应用内注册只报 UAC 泛话——双缺陷修复（`16ddd4e7`）

截图横幅文案反推命中「`toolOk == null && 未注册`」兜底分支，即脚本真实结论被吞：
- **缺陷 A**：随包 `register_asio.ps1` 的结果文件由 PS 5.1 `Set-Content -Encoding UTF8` 写出，带 UTF-8 BOM；Dart `_parseApoJson` 以 `trim().startsWith('{')` 过滤行，U+FEFF 不被 trim 剥除 → 恒解析失败。修：解析入口先剥 BOM（单点，三通道受益）。apo_config.exe 写无 BOM 文件，故 APO 通道从未暴露此问题。
- **缺陷 B**：pack.py 生成脚本以 `Start-Process regsvr32 -ArgumentList @("/s", $dll)` 传参，数组按空格拼接不带引号——安装路径含空格（默认 Program Files）即断。修：DLL 路径预加引号（注册/注销两处）。vm-win10 的无空格路径使该缺陷长期潜伏。
- 向导安装期注册失败的原因不在上述两处（其 Process.run 传参无引号问题）：若重装再现，请记录向导警告里的 regsvr32 退出码（5=未提权 / 3=DLL 加载失败为候选）。
- 钉：pack fixture 断言生成脚本含引号形；Dart 源码契约组「第六轮项 2」。

## 项 3：Win11 蓝牙耳机 APO 已附加却不处理 + 卸载语义错乱——面板语义修复（`a83edcfd`）

- **语义半（已定罪已修）**：`apoAttached` 旧口径只表达「当前所选目标」的附加态。装在 A、切到 B → 状态翻「未附加」（A 的附加被藏匿），点卸载对 B 执行 → apo_config 报 `not_found` 且错误文案露出 B 的端点 id（截图 2 实证）；切回 A 状态亦误导。修：新增与所选无关的真值 `apoAnyAttached`/`apoAttachedName`；面板状态行三态（已附加 / 已附加（{name}）/ 未附加，新 l10n 键 `apoAttachedOn` 三语）；卸载先静默刷新清单、对**实际已附加的端点**执行并按其复核裁定；心跳橙片与引擎注记的门改从 `apoAnyAttached`。
- **不处理半（未定罪，待真机判读）**：截图 2 心跳未活 = 该机 audiodg 内从未有 AuraApo 实例运行。候选：① 该机 `driver\` 载荷不全/过旧（与项 2 的安装侧异常互证）——请列安装目录 `driver\` 下 AuraApo.dll、auradsp_engine_apo.dll、apo_config.exe、auraasio_driver.dll 的存在与日期/大小；② 蓝牙通路特异性（A2DP 与 HFP 是两个端点、附错兄弟端点；或蓝牙硬件卸载绕过软件 APO）——请在同一台 Win11 上对有线/USB 端点附加并播放判读。
