# 引擎尖端对标深度评估 — FabFilter / iZotope / Dirac / Weiss 级

> 日期：2026-10-17 · 范围：`engine/` 全部自研模块（`dsp/`、`chain/`）+ 关键 legacy 内核抽样
> （`dynamic.c`、`multimodalEQ.c`、`convolver` 路径）· 基线：全局审查报告 / 引擎扩展调研 /
> EasyEffects×Viper 差距分析 / 预设系统缺陷研究（均 2026-10-13~16）
> 方法：逐文件通读源码，按六个尖端维度对照 FabFilter Pro-Q3/Pro-L2/Saturn、
> iZotope Ozone/Neutron、Dirac Live、Weiss EQ1/DS1-MK3 的公开能力集评估。

## 0. 总评

**综合：6.7 / 10 —— 工程纪律达到尖端级，算法资产处于"优秀消费级"，个别模块仍是 1990s 配方。**

这个引擎最突出的不是某个效果的音色，而是**实时安全纪律与诚实的可观测性**：
零分配零锁的 RT 契约、FTZ/DAZ 守卫、次正常数截断、SPSC 无锁可视化环、
探针"测不到就报测不到"（haas 拒测、convolver 无 IR 拒测）、IR 文件四层门卫——
这套东西 FabFilter 也这么做，大量开源项目做不到。

差距集中在四件事上：**没有过采样、限幅器太原始、参数平滑粗糙（块率跳变）、
混响还是 Freeverb（1999）配方**。这四件恰好都是"耳朵能听出来"的。

| 维度 | 得分 | 一句话 |
|---|---|---|
| RT 安全与延迟 | **8.5** | 契约清晰、执行彻底、探针诚实；业界开源第一梯队 |
| 数值精度 | **7.0** | 系数 double、状态 float 混用；FTZ+截断双保险 |
| 算法质量 | **6.0** | 频域动态是亮点；无限幅前瞻、无过采样、混响偏老 |
| 参数平滑与切换连续性 | **5.0** | 多处块率增益直跳；EQ 曲线重建仍有停泵风险 |
| 多声道/采样率自适应 | **6.5** | 系数全 fs 感知、IR 自动重采样；DSP 核心仍纯立体声 |
| 计量与可观测性 | **7.0** | 阶段峰值+探针+频谱齐全；无 LUFS/GR 表 |

## 1. RT 安全与延迟 —— 8.5/10

### 达到尖端级的部分

- **契约成文且被执行**（`engine/AGENT.md` §1）：`process_stereo_chain` 及以下零分配、
  零锁、零 syscall。通读全部 11 个 `dsp_*.cpp` + `engine_chain.cpp`，**未发现一处
  RT 路径分配或加锁**。这在同等规模的开源引擎里罕见。
- **系数下发双模式**：控制线程重算 + `std::atomic<double>` 表（`shelf`/`filter`
  模式），或每块现算 ~90 flops（`dyneq`/`bassmono` 模式）——两条路径都在注释里
  写明了取舍理由，这是成熟做法。
- **FTZ/DAZ 全局守卫**（`ScopedFtzDazGuard`，engine_internal.h:18）+ 每模块
  块末次正常数截断（`1e-15`/`1e-18` 双阈值），静音时 CPU 不会掉进微码陷阱。
- **探针是"测出来的"不是"查表来的"**（`engine_probe.cpp`）：独立 handle、
  基线相减、确定性 LCG 噪声激励（拒绝单位冲激——注释里写明了 VDC 高通会把
  冲激滤光导致假 0ms）、能量校验防"组件没接上却报实测 0ms"、haas 明确拒测。
  **这套诚实性设计超过大多数商业插件的延迟报告口径。**
- 链尾统一 NaN/Inf 清洗 + ±10.0 钳位（engine_chain.cpp:470-480），单效果不重复设防。

### 差距

1. **块率参数快照**：所有自研模块每块开头一次性 load 参数（如 `spatial_process`
   L62-69）。在 2048 帧块下（48k，42.7ms），快速拖滑块会产生可闻的阶梯跳变。
   FabFilter Pro-Q3 逐样本/逐子块平滑。→ 见 §4。
2. **`fv_retune` 清缓冲必然 click**（engine_internal.h:510 注释自认"并发瞬间最多
   一个 click 级伪影"）。尖端做法是长度渐变 crossfade 或双缓冲交叉淡化，
   不是 memset 直清。

## 2. 数值精度 —— 7.0/10

### 做对了的

- 系数计算全面 double（`shelf_recalc`/`filter_recalc`/`dyneq` 全部 RBJ 用 double），
  高 Q 峰值与低频 shelf 的系数量化误差可控。
- `dyneq` 检波与滤波全 double 状态；`stereo_block_rms` 用 double 累加防长块
  浮点吞没。

### 差距

3. **状态精度分裂**：`filter`/`shelf` 状态是 double（好），但 `gate`/`exciter`/
   `loudness`/`psycho`/`bassmono`/`spatial`/`freeverb` 状态全是 float。
   float 状态 + 高反馈（freeverb feedback 0.98 上限）在长混响尾会积累
   噪底抬升（limit cycle），Weiss/Eiosis 级产品全 double 状态或加 dither。
4. **无抖动（TPDF dither）**：输出直通 float→宿主，post.gain 降增益时低位
   量化噪声无随机化。母带级（Weiss EQ1）会在输出级加 TPDF/double-precision
   累加。当前 ±10 钳位直接截断（非软限幅），也是硬跳变。
5. **`expf`/`log10f` 单精度系数**：`gate_process` L21-22 每块用 float expf 求
   attack/release 系数。48k 下短 attack（1ms）的系数对精度敏感，
   double 系数成本可忽略。

## 3. 算法质量 —— 6.0/10

### 亮点（不输消费级尖端）

- **EQ（legacy multimodalEQ）**：makima 插值 + 最小相位 IR + FFT 卷积 +
  双卷积器交换（`activeConv`/`convB`），等效"拖动时 crossfade 切换 IR"——
  这是 FabFilter Pro-Q3 之外少见的实现深度。15 点任意曲线自由度高。
- **动态（legacy dynamic.c）**：gammatone ERB 滤波器组 + 8192 点 FFT 频域
  压缩（DRS）+ 谱减式 de-esser/dyneq 自研——频域动态这条技术路线本身是对的，
  iZotope Neutron 同族。
- **空间（dsp_spatial）**：Woodworth ITD + 头影 ILD 低通 + 8 tap ±配对早期反射
  （注释里记录了 7 tap 左右能量差 7% 的实测修正）+ 等能量归一化——
  参数化简洁、量纲正确，超过大多数"伪环绕"实现。
- **卷积门卫（engine_convolver）**：L1 magic 嗅探 / L2 尺寸 / L3 控制线程 /
  L4 NaN 扫描+静音拒绝+时长上限，四层防御 + 离线重采样对齐 fs。

### 硬差距（按听感影响排序）

6. **全引擎零过采样**——最大的算法差距。`exciter`（tanh drive 2.0）、
   `basspsycho`（tanh 2.5）、tube（vendor 内 waveshaper）全部在基带率做
   非线性：高次谐波折返混叠直接可闻，尤其 44.1k 内容 + 高激励量。
   Saturn/Trash2 提供 2x–32x。**建议：非线性模块前插 2x 半带上采样 +
   后置抗混叠，优先 exciter/tube 两处。**
7. **限幅器是 1990s 配方**（legacy `JLimiter`）：单包络 + release 系数 +
   threshold，**无 attack、无前瞻（lookahead）、无 true-peak（ISP/BS.1770-4）、
   无软膝、无增益衰减计量上报**。Pro-L2 / Weiss DS1-MK3 差着两代。
   链尾 ±10.0 硬钳位是最后防线但会削出 harsh 谐波。**建议：自研 lookahead
   限幅（1.5ms 前瞻 + 平滑包络 + 真峰 4x 过采样检波）替换，放在 Stage 4 之前。**
8. **混响是 Freeverb（1999）**：8 comb + 4 allpass、固定拓扑、damp 只有一阶。
   与现代 FDN（64+ 线、可变扩散、早期/晚期分离、Megapulse/MDAPT 级）差距
   一个时代。外置 19 预设（reverb_legacy.json）缓解了预设面，没缓解算法面。
   **建议：中期自研/引入 FDN 晚期 + 多 tap 早期的混合结构，或高质量卷积 IR
   池做程序化混响（卷积基建已就绪）。**
9. **dyneq 攻防共用 attack/release 全局一组**（`attCoef`/`relCoef` 块级单值），
   三段不能独立时间常数，无 lookahead。Pro-MB 动态每段独立双时间常数 +
   前瞻。当前实现"能用"，不到专业动态 EQ 手感。
10. **gate 无迟滞（hysteresis）、无 range 参数**（地板写死 -60dB `ga` 下限）、
    de-esser 固定 2ms 包络 + 归一化阈值 0.05 不可调。SSL/Pro-G 级应暴露
    range/hold/hysteresis。
11. **loudness 是简化 ISO226 曲线跟随**（200Hz LP + 6kHz HP 补偿，固定 ±10/6dB
    上限），**不是 BS.1770-4 LUFS 感知计量**。与 Ozone 的 True Peak Loudness
    Maximizer 完全不同量级。名字叫 "loudness" 容易让用户误预期。

## 4. 参数平滑与切换连续性 —— 5.0/10（最弱维度）

12. **块率增益直跳**：`freeverb_process` 的 outgain/autogain 补偿系数在块边界
    直接乘（L96-114）；`gate` autogain 同款（L80-85）；`spatial` outgain 同款。
    2048 帧块下，拖 autogain 或 outgain 会产生 ~43ms 周期的台阶——听感是
    "颗粒感/抖动"。**全部应改为每样本一阶平滑（或块内线性斜坡）。**
13. **EQ 曲线重建停泵风险**（PATCHES.md / 全局审查已记录）：`eq.curve` 下发
    触发 makima+最小相位 IR 重算 + FFT 卷积重载（~760µs 控制线程，但
    `JamesDSPRebuildChain` 与处理链共享卷积器对象曾致爆音，P-00x 修复后
    仍有交换窗口）。拖 EQ 节点的连续性是 Pro-Q3 的立身之本，此处是
    目前体验上最大的工程债。
14. **preset 切换**：`Reverb_SetParam` 重建整套混响状态（apply_reverb 注释自认），
    已用"精准下发只动改动链"缓解，但混响预设切换仍是状态清零 → 尾音截断。
    尖端做法是双混响 crossfade（30~100ms）。

## 5. 多声道 / 采样率自适应 —— 6.5/10

### 做对了的

- 所有自研系数现算模块 fs 感知（含 44.1k Nyquist 修正 P-007、w0 钳位到 0.99π）。
- IR 加载自动离线重采样对齐引擎 fs；Freeverb 按 fs 缩放 comb/allpass 长度。
- ADR-003 多声道矩阵（≤8ch、LFE 直通、环绕并入 LR、上混回填）+ smoke 测试覆盖。

### 差距

15. **DSP 核心全部硬编码立体声**（`io[i*2]`/`io[i*2+1]` 遍地）：多声道只在
    链外做 downmix→立体声链→upmix。5.1/7.1 内容的空间信息在入口就丢了。
    Dirac Live 的核心正是逐声道房间校正。Phase B 若做真多声道需重写全部
    `dsp_*.cpp` 的平面遍历（工作量大，建议先抽 `ch` 步长模板）。
16. **haas 延迟是整数采样**（无分数插值，dsp_haas.cpp:21 `(int)(...)`），
    而 spatial ITD 有线性插值——同族能力不一致，haas 在 44.1k 下
    25ms 档位分辨率约 1/44 样本的相位误差可闻于 mono 兼容检查。

## 6. 计量与可观测性 —— 7.0/10

- 阶段峰值表（sample_stage_peak 0~20）+ SPSC 频谱环 + IR 频谱 + 探针，
  覆盖面好。
- 差距：
17. **无 GR（增益衰减）计量**：limiter/comp/dyneq 的当前衰减量不对外上报，
    UI 无法画 Pro-L2 式 GR 表——这是专业动态处理的"必要器官"。
18. **无 LUFS 积分/短时计量**：loudness 模块只做补偿不做测量上报。
    BS.1770 K-weighting + 400ms/3s 窗是 Ozone 的基线功能。
19. **`compute_latency` 是名义表累加**（kLat* 查表），探针实测值与它并存
    但未合并为单一真源。ADR-006 后延迟不再阻断，但 UI 应明确标注
    "实测/名义"口径（探针数据已有，接线即可）。

## 8. 结论

引擎的**下限很高**（几乎不可能崩溃、爆音路径基本堵死、可观测性诚实），
这是 FabFilter 级产品真正的护城河，已经摸到。
**上限受限于三块短板**：非线性无过采样、限幅器原始、混响配方老。
建议下一个攻坚周期按上表顺序推进：先做"平滑 + GR 计量"两个低成本高收益项，
再做过采样与新限幅器（两者都是中成本、听感跃迁），
混响 FDN 放到有卷积程序化池之后。
