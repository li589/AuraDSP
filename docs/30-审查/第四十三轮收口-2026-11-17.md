来源：r42 包宾机验收（user 2026-11-17 上午装包）两故障——
① APO 附加报 `endpoint_props_failed`；② 附加后全机无声
（托盘喇叭红叉、设置能列设备但所有播放失败、音乐软件播

## 事件定罪（宾机实证）

- **缺陷一（全机无声，元凶）**：`OpenFxKeyWritable` 的接
  管退路 `TakeOwnershipRepair` 以
  `SetEntriesInAclW(2, ea, nullptr, &dacl)` 构建全新 DACL
  并整表替换目标键 DACL，只剩 SYSTEM + Administrators 完
  全控制——Audiosrv / AudioEndpointBuilder / TrustedInstaller
  / Users 等原 ACE 全部剥除，且分离/卸载不还原。被附加的
  Voicemeeter Input 恰为系统默认端点：其端点键 +
  FxProperties 键 DACL 被剥后（审计实证：20 端点仅此一
  个 audiosrv=False、owner 变 Administrators），音频引擎
  读不到默认端点键 → `GetDefaultAudioEndpoint` 报
  0x80070490、其它端点 `GetMixFormat` 报
  AUDCLNT_E_UNSUPPORTED_FORMAT、被附加端点自身报
  E_ACCESSDENIED → 全局播放瘫痪。枚举/PnP/驱动/服务/
  SFC 全部正常，极具迷惑性。开发机端点键本可写、从未触
  发接管退路，故开发机矩阵未暴露；r42 S1a 把接管扩到父
  端点键后，宾机无 FxProperties 键的端点附加必触发。
- **缺陷二（附加报错）**：r42 S2 起附加恒传
  propsMode/Fill='clear'，`WriteEndpointProps` 的 applyOne
  对不存在的 pid3/pid4 值调 `RegDeleteValueW` 得
  ERROR_FILE_NOT_FOUND 被当失败 → 无 r41 残留 props 的端
  点附加必报 `endpoint_props_failed`（APO 实际已挂载、
  pid2 令牌/pid5 已写入）。开发机端点有残留值被掩盖。
- 宾机已于当日下午先行人工修复（给 ad89efb7 两键按标准
  模板补回服务 ACE），全部端点播放实测恢复（ep_probe /
  tone_play 全绿）；诊断副产物：HD 端点因删除重装换 GUID
  （94fed531→808fb9db）、DisableProtectedAudioDG=1 保留、
  端点存储备份在宾机 `C:\Users\li\diag\mmdev_backup.reg`。

## 修复（`62dba722`）

- **Fix B（ACL）**：`TakeOwnershipRepair` 改合并式授予——
  接管第二步先以 READ_CONTROL 读回原 DACL 与控制位
  （`RegGetKeySecurity`），`SetEntriesInAclW(2, ea, oldDacl)`
  合并追加 Administrators/SYSTEM 完全控制，并以
  `SetSecurityDescriptorControl` 原样保留 SE_DACL_PROTECTED
  位；读不到原 DACL 宁可修复失败、绝不整表替换。函数头
  注释立 r43 不变式。全仓排查：同类整表替换仅此一处
  （文件侧 `GrantAudiodgRead` 本就是合并式，未动）。
- **Fix A（props）**：applyOne 的 clear 路径把删值的
  ERROR_FILE_NOT_FOUND 映射为 ERROR_SUCCESS（值不存在即
  已达 clear 目标态）。同类删值点排查：clearAll 分支本就
  忽略结果、StripOursFromFx 的删除针对已读到的现值、其
  余为清理性删除，均不改。

## 回归门禁

映射）+ 反向自检。修复前判红 4 项、修复后全绿（VM 与开
发机全量套件内均实测）。
