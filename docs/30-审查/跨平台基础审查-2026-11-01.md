## 2. P0 — 阻断非 Windows 构建或导致双内核分叉

### CP-01 非 Windows 无可用构建入口，连“只编可移植核心”都做不到

- **证据**
  - 根 [CMakeLists.txt](../../CMakeLists.txt#L20-L24)：`if(NOT WIN32)` 直接
    `message(FATAL_ERROR ...)`。
  - [core/desktop/windows/CMakeLists.txt](../../core/desktop/windows/CMakeLists.txt#L92-L107)：
    `auradsp_core`（方案里的“可移植核心”）私有选项全部是 MSVC 专用：
    `NDEBUG`、`_WIN32_WINNT=0x0601`、`/utf-8 /W1 /EHsc`、`/FI auradsp_msvc_shim.h`、
    `MSVC_RUNTIME_LIBRARY`。
  - 同文件 `L145-L171`：`auradsp_engine` 再叠加 `.def` 导出、`link_libraries(version)`。
  - [CMakePresets.json](../../CMakePresets.json#L18-L30)：`linux-x64` / `android-arm64`
    仅注释占位，description 明说“不启用”。
- **影响**：Linux/macOS 上无法配置，也无法只编 `auradsp_core` 做 ABI/DSP 回归；
  “新增平台只加 adapter”的前提（目标 G4）目前不成立。
- **修复方向**：把 MSVC 选项收进 `if(MSVC)`；把 `.def`/`version`/`Win32` 源表收进
  `if(WIN32)`；根工程增加 `AURADSP_PORTABLE_ONLY` 分支（只 `add_subdirectory` 可移植核心）。
  需要 Linux 工具链验证，本轮先完成“条件化”，不宣称 Linux 全链路可构建。

### CP-02 插件子系统无裁剪开关，`REMOTE=OFF` 并不等于“可移植”

- **证据**
  - [core/desktop/windows/CMakeLists.txt](../../core/desktop/windows/CMakeLists.txt#L23-L41)：
    `AURADSP_PLUGIN_HOST_SOURCES` 无条件包含
    `plugins/platform/win32/plugin_gui_win32.cpp`、`win32_util.cpp`、`plugin_paths.cpp`、
    `plugin_module.cpp`，以及 `plugins/driver/*`、`plugins/formats/{clap,vst3}/*`。
  - 同文件 `L48-L55`：`NOT AURADSP_PLUGIN_HOST_REMOTE` 只清空
    `AURADSP_PLUGIN_REMOTE_SOURCES`（远程宿主），**没有清空上面的 Win32 插件源**。
  - 同文件 `L121-L131`：`auradsp_engine` 无条件编入 `AURADSP_PLUGIN_HOST_SOURCES` 与
    `AURADSP_PLUGIN_INTEGRATION_SOURCES`。
  - [plugin_scanner.cpp](../../engine/plugins/driver/plugin_scanner.cpp#L6)：直接
    `#include "win32_util.h"`（PE 版本资源、`std::wstring`）。
  - [plugin_host_manager.cpp](../../engine/plugins/driver/plugin_host_manager.cpp#L11)：
    `#include <windows.h>`；`L107-L115` 用 `GetTickCount64` / `Sleep(1)` / `YieldProcessor`。
  - [vst3_instance.cpp](../../engine/plugins/formats/vst3/vst3_instance.cpp#L12)、
    [clap_instance.cpp](../../engine/plugins/formats/clap/clap_instance.cpp#L12)：
    插件格式实现直接包含 `<windows.h>`（编辑器 HWND、Sleep 等）。
  - [plugin_engine_state.cpp](../../engine/plugins/integration/plugin_engine_state.cpp#L2)：
    `integration` 依赖 `driver/plugin_chain_component.h`，因此 F1 把 `integration` 当作
    “可移植核心”扫描，但实际编译闭包仍拖入插件驱动。
- **影响**：Linux/macOS 上即使设 `AURADSP_PLUGIN_HOST_REMOTE=OFF`，仍会因
  `windows.h`/`win32_util.h`/PE 读取而编译失败；方案 `engine/platform/linux/README.md`
  写的“OFF 即直通”与实况不符。
- **修复方向**：新增 `AURADSP_ENABLE_PLUGINS`（Windows 默认 ON，非 Windows 强制 OFF）；
  OFF 时排除全部 `AURADSP_PLUGIN_HOST_SOURCES` / `AURADSP_PLUGIN_INTEGRATION_SOURCES`，
  用 stub 实现 `plugin_chain_adapter` 五函数与 `.def` 里的 38 个插件导出
  （保持 C ABI 导出集不增不减，F3 不破），并定义 `AURADSP_NO_PLUGINS`。
  这是 Linux 引擎可编译的前置条件。

### CP-03 Android 与桌面已经是两套 DSP 内核，且无漂移门禁

- **证据**
  - [build_jdsp.sh](../../core/android/registrar/examples/jamesdsp_engine/build_jdsp.sh#L26)：
    `M=$(cygpath -m "$CORE_W/vendor-src/libjamesdsp")`；
    `L49` 用 `find .../vendor-src/libjamesdsp -name '*.c'` 收集源文件。
  - [vendor-src/ORIGIN.md](../../core/android/vendor-src/ORIGIN.md)：
    `libjamesdsp/` 为 `github.com/joshua-8/JamesDSPManager main @ 提取时点` 的上游快照。
  - 与桌面的 `engine/legacy/` 对比：**14 个共有文件内容不同**，合计
    `+756 / −3103` 行；桌面独有的 AuraDSP 文件：
    `aura_eel_ram.c`、`aura_eel_ram.h`、`essential.h`、`jamesdsp.c`、`MemoryUsage.h`、
    `PATCHES.md`。Android 副本**没有** `aura_eel_ram.c/h`，也没有
    P-016（liveprog 影子 VM）、P-045（惰性 gmem）等补丁。
  - [engine/platform/android/README.md](../../engine/platform/android/README.md#L14-L15)：
    “两条路径共用同一份引擎与 C ABI（`engine/auradsp_engine.h`）”——与上述实况不符；
    [core/android/README.md](../../core/android/README.md#L59-L60) 也把
    “完整 libjamesdsp 静态编入”当作引擎接入。
  - [PATCHES.md](../../engine/legacy/PATCHES.md) 已登记 40+ 条本地补丁，但只覆盖桌面路径。
- **影响**：
  1. Android 端享受不到桌面近期的内存（576MB→~0）、并发（L-01/L-02/L-03）、
     稳定性（NaN、清空悬空等）修复；
  2. 两套内核长期双份维护，必然继续漂移；
  3. 文档声称“共用引擎”，会让后续平台开发者按错误前提做设计。
- **修复方向**（分两步，不能一次强拆）：
  - 短期：在 `core/android/vendor-src/ORIGIN.md` 与 README 明确“**当前不是同一引擎**”，
    并新增 `tools/bin/legacy_copy_drift.py`（或 smoke）输出 `engine/legacy` ↔
    `vendor-src/libjamesdsp` 的差异清单，防止“静默”漂移；
  - 中期（独立立项）：Android 改为编译 `engine/legacy + engine/dsp + engine/chain`，
    通过 `engine/platform/android/*` 适配，HAL 只做 AIDL/FMQ 胶水；这依赖 CP-02 的裁剪开关。

## 3. P1 — 可移植性/契约/发布链的实质缺口

### CP-11 `module_last_error` 端口契约自相矛盾（数值 vs 文本）

- **证据**：[module.h](../../engine/platform/port/module.h#L17) 声明
  `unsigned long module_last_error();`；[linux/README.md](../../engine/platform/linux/README.md#L35-L36)
  却要求“返回最近一次失败的文本（Linux 为 `dlerror()` 捕获串）”。
  `dlerror()` 返回 `char*`，无法装进 `unsigned long`。
  调用方 [vst3_instance.cpp](../../engine/plugins/formats/vst3/vst3_instance.cpp#L561) 与
  [clap_instance.cpp](../../engine/plugins/formats/clap/clap_instance.cpp#L74) 用
  `std::to_string(module_last_error())` 拼诊断。
- **影响**：Linux 实现若按 README 走必然编译失败；若按头文件走，则丢失 `dlerror` 文本，
  Linux 插件加载失败只能看到数字。
- **修复方向**：端口增加 `const char* module_last_error_text()`（Windows 用
  `FormatMessage`/`GetLastError` 拼文本，Linux 用 `dlerror` 快照），保留数值函数兼容
  现有调用；或统一改为文本并同步调用方。二者都要同步 README。

### CP-12 `plugin_host_manager` 在 driver 层直接使用 Win32 时间/睡眠/自旋

- **证据**：[plugin_host_manager.cpp](../../engine/plugins/driver/plugin_host_manager.cpp#L103-L115)
  `GetTickCount64` + `Sleep(1)` + `YieldProcessor`；`L11` 为 `<windows.h>`。
  这与 M2 的“Win32 调用收口到 `platform/win32`”约定不一致（F1 扫描面排除了 driver，
  所以长期未被发现）。
- **影响**：即使只做“Linux 进程内插件宿主”的最小验证，也必须先改这里；同时它是
  CP-02 裁剪前应清理的“隐形 Win32 依赖”。
- **修复方向**：新增 `engine/platform/port/time.h`（`now_ms` / `sleep_ms` / `cpu_relax`，
  header-only 标准 C++ 实现），`plugin_host_manager` 改走端口并删除 `<windows.h>`
  （SEH 常量在 MSVC 下用 `<excpt.h>`）。

### CP-13 Android 构建脚本只能在 Windows + Git Bash 上跑

- **证据**
  - [build_jdsp.sh](../../core/android/registrar/examples/jamesdsp_engine/build_jdsp.sh#L13-L21)：
    `pwd -W`、`cygpath`、`NDK_BIN="D:/myPrograms/.../windows-x86_64/bin"`、`clang.exe`。
  - [registrar/build.sh](../../core/android/registrar/build.sh#L10-L22)：同样硬编码。
  - [spike-global-effect/build_aidl.sh](../../core/android/spike-global-effect/build_aidl.sh#L6-L10)：同样。
- **影响**：macOS/Linux 开发者无法按文档复现 Android 构建；“跨平台开发”第一步就卡住。
- **修复方向**：NDK 根目录改为 `ANDROID_NDK`/`NDK_ROOT` 环境变量优先，缺省回退到现有
  Windows 路径；用 `uname -s` 选择 `windows-x86_64` / `darwin-x86_64` / `linux-x86_64`
  宿主标签与 `clang`/`clang.exe`；仅在 `cygpath` 存在时做路径转换，否则直通 POSIX 路径。
  同步 README 的三条命令。

### CP-14 F7（依赖方向）仍无门禁

- **证据**：方案 [§13 F7](../10-架构/跨平台基础框架与平台依赖剥离方案-2026-10-29.md#L814)
  自己标注 “**NEEDS CHECK**：当前无专用门禁”；[smoke_dart_platform_quarantine.py](../../test/smoke/smoke_dart_platform_quarantine.py)
  只扫 `Platform.is*`。
- **现状核对**：`lib/core/` 当前没有 import `features/` 或 `ui/`（本轮已 grep 确认），
  但门禁缺失意味着下一次重构可无声破坏。
- **修复方向**：在该 smoke 增加“`lib/core` 零 import `features/`/`ui/`、`lib/engine`
  零 import `features/`”断言（含反向自检），并登记新门禁名。

### CP-15 发布链缺口：Linux/Android/macOS 的“壳已就位”但引擎与资源未接入

- **证据**
  - [linux/CMakeLists.txt](../../app/auradsp_app/linux/CMakeLists.txt#L94-L128)：只安装
    runner、Flutter 库、插件 bundled libs、assets；**没有** `libauradsp_engine.so`，
    也没有 `resources/{ddc,convolver,manifest.json,liveprog}`。
  - Android：`app/src/main` 只有 `MainActivity.kt` 与 `GeneratedPluginRegistrant`，
    无 `jniLibs`、无 JNI 桥；引擎目前只走 `core/android` HAL 路径（且是上游内核）。
  - `app/auradsp_app/` 下**没有 `macos/` 目录**，而 `PlatformProfile` 已声明
    `macos` 与 `supportsWindowManagement`。
- **影响**：Linux 上即使完成引擎构建，启动后仍找不到 `.so` 与 IR/DDC 资源；
  macOS 连 runner 都未生成；Android App 与 HAL 引擎之间无数据面。
- **修复方向**：Linux runner 增加引擎与资源安装规则；macOS runner 用
  `flutter create --platforms=macos` 补齐；Android 明确“App 不直连引擎，HAL 由
  系统挂载”的边界，或补充 JNI 桥（另立项）。

### CP-16 门禁扫描面不完整，恰好漏掉本轮 P0/P1

- **证据**
  - [smoke_platform_isolation.py](../../test/smoke/smoke_platform_isolation.py#L46)：
    `SCAN_DIRS = ("", "chain", "dsp", "plugins/integration")`——**不含
    `plugins/driver`**，因此 CP-12 的 `<windows.h>` 长期未被判红。
  - `PLATFORM_ANY` 仅两项；任何新增纯源码门禁（如 F7、漂移检查）必须同步登记，否则
    Linux 上会被 runner 标成 `windows` 而 SKIP。
- **修复方向**：F1 增加“driver 不得直接 include `<windows.h>`（Win32 头须经
  `platform/win32`）”与“formats 零 `<windows.h>` 之外的模块加载 API”两条定向断言；
  F7 并入 F2；新增门禁同步写入 `runner.py` 的 `PLATFORM_ANY`。

## 5. 已核对为非问题 / 设计取舍（避免重复登记）

1. **`aura_eel_ram.c` 的 POSIX 回退**：`#else` 分支用 `calloc`（惰性零页），语义与
   Windows VEH 路径等价；不是平台缺陷（但 Android 未使用该文件，见 CP-03）。
2. **`legacy` 内的 `_WIN32` 双路**：`liveprogWrapper.c`、`dynamic.c` 等
   `now_ms/sleep_ms/yield` 都有 `clock_gettime/nanosleep/sched_yield` 回退，
   不属于“新引入的不可移植代码”。
3. **`PlatformProfile` 的 `Platform.environment/pathSeparator`**：跨平台 API，
   不违反 G5（G5 只约束 `Platform.is*` / `defaultTargetPlatform`）。
4. **插件槽作为 `Post-Limiter` 例外**：ADR-010 已登记，与跨平台无关。
5. **`AURADSP_PLUGIN_HOST_REMOTE=OFF` 的既有语义**：Windows 上仍可用进程内插件，
   这是设计取舍；问题在于它被误读为“非 Windows 可编译”（CP-02/CP-26）。

### 9.3 S3：插件子系统裁剪开关（CP-02）— ✅；CP-01 待后续

**新增 `AURADSP_ENABLE_PLUGINS`（`core/desktop/windows/CMakeLists.txt`）**

- 默认 ON（Windows 行为不变）；`NOT WIN32` 强制 OFF；OFF 时同时强制
  `AURADSP_PLUGIN_HOST_REMOTE=OFF`（远程宿主依赖插件子系统）。
- ON：`AURADSP_ENGINE_PLUGIN_SOURCES = host + integration + remote`（原三表）；
  OFF：只编 `plugins/integration/plugin_chain_adapter_stub.cpp` 与
  `plugin_abi_stub.cpp`，并给 `auradsp_core` / `auradsp_engine` 同时定义
  `AURADSP_NO_PLUGINS=1`（`engine_internal.h` 的 handle 在 core 内编译，必须同视图）。

- `engine_internal.h`：`plugin` 成员与 `plugin_engine_state.h` 在裁剪构建下整段移除；
  插件阶段改由 stub 直通，C ABI 导出集不增不减（F3）。
