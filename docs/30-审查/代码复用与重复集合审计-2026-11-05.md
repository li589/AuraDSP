# 代码复用与重复集合审计报告（2026-11-05）

> 性质：只读静态审计，不改代码。
> 范围：`app/auradsp_app/lib/**`（core / engine / features / ui / platform）与 `engine/plugins/**`、`engine/chain/engine_probe.cpp`。
> 排除：`build/`、第三方头文件、l10n 生成文件、测试夹具代码。
> 方法：按“功能模块”横向比对 + 按“集合/列表/字典”纵向计数，所有结论均给出 `file:line` 证据。

---

## 一、结论摘要

1. **最严重的问题是“效果器 stage 注册信息”没有单一数据源**：同一个概念（效果器 id、引擎顺序、默认链序、分组、探针能力、计量槽位）在 Dart 与 C++ 中至少存在 **11 份手写清单**，且已经出现顺序分歧（`kStageMeta` 是 `gate→dyneq→filter`，`kDefaultCoreOrder` 是 `gate→filter→dyneq`）。
2. **UI 层最大的机械重复是 19 张效果卡的 8 行延迟参数块**：每张卡调用 `componentLatency` 4 次，共 **76 处调用点**；探针能力判定还分成了两套（16 张卡用 `isLatencyProbeSupported`，3 张卡用 `hasLatencyRefresh`）。
3. **配置持久化是“三处手写同一字段清单”**：`AppConfig` 构造函数、`fromJson`、`toJson` 各写一遍（约 40 个字段），新增字段漏改会静默丢配置，属于用户数据面风险。
4. **跨语言契约靠人肉同步**：槽位 `4`、总线通道 `8`、VST2 数组上限 `64` 在 Dart 与 C++ 各自硬编码，编译期无法保证一致。
5. **平台层存在高价值但也高风险的重复**：Win32 与 POSIX 插件宿主主程序各约 590 行，结构逐条对位、各含 5 处 IPC 命令分发；合并收益大，但必须双平台回归。

风险总览：**高严重度 4 项、中 7 项、低 7 项**；其中整改风险真正偏高的是跨平台宿主合并（R-07）与效果器注册表重构（F-01），其余多数是低风险机械收敛。

### F-09 跨语言常量与上限多头定义

**类型**：重复集合（跨语言契约）
**严重度**：高｜**整改风险**：中

**证据**：
- Dart 槽位：`app/auradsp_app/lib/core/plugins/plugin_manager.dart:46`（`kMaxSlots = 4`）
