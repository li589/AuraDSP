# 预设系统与硬置入复检（2026-10-28）

定位：用户指定「预设系统检查 + 硬置入检查」一轮专项。
基线：`git log -1` = 9994cb7（工作树仅本轮改动）。
方法：逐函数通读 + 三个实机审计测试（临时文件，已删）+ 反向验证（撤掉修复必须转红）。
标注：**亲验** = 本人逐行读过并实测；**扫描** = 正则横切后抽样核对。

---

## TL;DR

- **预设系统 3 个 P1 全是同一类病**：契约写在注释/标志里，但没有任何代码执行它。
  ① `sessionOnly` 标志零消费方 → 载入预设会清空用户输出设备与 ASIO 配置并即时落盘；
  ② `defaults.json` 落后于 `ParamRegistry` 4 个键 → 全局预设「全部复写」静默漏复位；
  ③ 指纹含路由镜像参数、apply 却不写它们 → 只切音频模式就被标「自定义（未保存）」。
- **硬置入：运行时真特判 0 处**，与 2026-10-24 结论一致。「检测到某插件就走特殊分支」的
  生产代码全仓不存在（唯一命中是测试断言里的 `zebra2`）。
- **新增 2 处 P3 反模式**：扫描目录把 `C:\Program Files*` 写死兜底（F1 批评过的「盘符钉死」
  同类）；设备枚举为空时塞 4 条带 Realtek/Intel 名字的**假设备**。
- **处置**：P1 三项已修 + 新增常驻门禁 8 条 + 基线资产重生成。P2/P3 记档不修。

## 2. 预设系统

### 2.1 P1-1 `sessionOnly` 标志无消费方（亲验）

`ParamFlags.sessionOnly` 的定义是「仅存会话记忆，不入公共预设」，14 个 `routing.*` spec 全部
带此标志（含设备端点、ASIO 驱动/缓冲/输出对、VAIO 端点、APO 目标、监视镜像、模式镜像）。
但全仓 `isSessionOnly` 的引用数在修复前是 **0**（只有 getter 自身）：`snapshot()` 只判
`isPresetSerializable`，`apply()` 也一样。

实测（加载出厂预设 `Pop Vocal Clarity`，`AppModel(testing: true)`）：

| 项 | 载入前 | 载入后 |
|---|---|---|
| `pipelineInputDevice` | `Mic (USB Audio)` | `""` |
| `pipelineOutputDevice` | `Speakers (Realtek)` | `""` |
| `asioBufSize` | 512 | 0 |
| `asioOutPair` | 3 | 0 |

`setPipelineOutputDevice` 等 setter 内部直接 `ConfigManager.save(config)` —— 用户的设备选择
**当场落盘丢失**，重启也回不来。

三处既有约定同时被破坏：
① `ParamFlags.presetSerializable` 注释「DSP 参数=1，设备 GUID=0」；
②《预设系统缺陷研究报告》§245「例外不复写：chainOrder（全局路由）、资源路径」；
③ `sessionOnly` 标志自身的语义。

例外检查：资源路径那条是守住的——`convIrPath` / `ddcPath` / `lpCode` 确实不在 `ParamRegistry`
里，只由 `SessionMemory` 的显式字段持久化。

修法（泛化，不点名 `routing`）：新增 `_isSessionOnlySection()`，`snapshot` 与 `apply` 双侧跳过
「全部 spec 带 sessionOnly」的整节，并在逐 spec 循环里补 `isSessionOnly` 跳过。会话恢复不受影响——
`SessionMemory` 的 payload 里 14 个 routing 键本来就是显式字段。

### 2.2 P1-2 `defaults.json` 漂移 4 键（亲验）

`fullRewrite=true` 的「全部复写」以 `assets/presets/defaults.json` 为基线。实测该文件缺 4 个键：

| 缺键 | 现象 |
|---|---|
| `bassmono.pairs` | 载入预设后保留用户值（实测 0x0F 不动） |
| `bassmono.merge` | 同上（实测 1 不动） |
| `comp.mode` | 同上（实测 1 不动） |
| `post.channelTrims` | 8 路后级 Trim 保留用户值（实测 -3.0 dB 不动） |

根因：`defaults.json` 生成于 2026-10-25，之后 `param_schema.dart` 新增了这些 spec，而生成器
`test/zz_gen_factory_presets.dart` 是**一次性工具、不在门禁里**，没有任何测试校验两者一致。

同类腐化：6 个出厂预设里还躺着 `tube.oversampling` —— 现行 spec 键名是 `tube.oversample`，
该键 `apply` 永远不命中，是纯垃圾数据（4/6 个文件有）。

修法：重生成基线 + 剔除 `routing` 与 `tube.oversampling` + 新增契约门禁（见 §4）。

### 2.3 P1-3 切换音频模式把预设标脏（亲验）

`fingerprintOf` 是 snapshot 的 JSON 编码。`routing.modeCategory` / `attachmentMode` /
`pipelineInput` / `pipelineOutput` 是 `audioMode` 的只读镜像：它们进快照（→ 进指纹），
但 `routing.postApply` 从不写它们。指纹因此只朝一个方向变。

实测：载入预设后 `evaluatePresetDirty()==false`；仅调用 `setAudioMode('asio')` 后变 `true`
（界面徽标跳「自定义（未保存）」，用户没动任何 DSP 参数）。P1-1 的修法顺带解决此项——
routing 整节退出快照，四个镜像参数不再参与指纹。

### 2.4 P2 明细

- **P2-1 资产清单硬编码**：`pubspec.yaml` 按**目录**打包 `assets/presets/factory/`，而
  `_factoryAssetFiles` 是 6 条文件名字面量，`ensureInitialized` 只落盘登记过的。新增出厂预设
  只放文件不改代码 → 编译通过、资产在包里、但永远不出现。已加双向门禁（清单 vs 目录）。
- **P2-2 列表顺序**：`Directory.listSync()` 是文件系统序，增删文件后 chip 位置跳变。已加排序
  （出厂在前，各自按名称不区分大小写）。
- **P2-3 脏标记残留**：`apply` 只更新锚点不清 `presetDirty`，要等下一个防抖窗口的
  `evaluatePresetDirty` 才归零，徽标多挂 500ms。已在 `apply` 末尾直接归零。
- **P2-4 文件名碰撞**：`_safeFileName` 把 `\ / : * ? " < > |` 与空白统一替换为 `_` 并转小写，
  `My Song` 与 `My_Song` 落到同一个 `my_song.json`，保存静默覆盖。修法需要设计（追加短哈希/
  冲突时改名提示），记档。
- **P2-5 无确认**：删除按钮点即删（无二次确认/撤销）；同名保存静默覆盖；
  `importFromFile` 不看 `schemaVersion`、不做去重，v1/v2 老格式若无对应节名则 apply 静默什么
  都不做。记档。
- **P2-6 静默降级**：`_mergeDefaults` 在资产未预载（`_defaultsJson == null`）时原样返回，
  语义悄悄从「复写」退回「合并」，且无任何留痕。记档（建议 `error_sink` 留一条一次性告警）。

## 3. 硬置入检查

### 3.1 复核结论：运行时真特判 0 处（扫描 + 亲验）

判据沿用 2026-10-24：**「检测到某个插件/厂商/路径 → 就写死走特殊分支」**。三路扫描：

1. Dart 侧 `contains/startsWith/endsWith/indexOf/==` 对厂商名字面量（u-he、FabFilter、
   Kushview、Valhalla、Antares、Ozone、iZotope、Pro-Q、KV-Element 等）→ **零命中**；
   反向形态（字面量在左）同样零命中。
2. 引擎 C++ 侧同型正则（含 `wcsstr`/`find`/`compare` 变体）→ **零命中**；
   `win32_util.cpp:233` 命中项是注释，描述「原实现只服务 iZotope，已改通用」。
3. 出厂预设名（Pop Vocal / Rock Bass / Studio Flat …）→ 只出现在 `_factoryAssetFiles`
   清单与测试夹具，**没有任何按预设名分叉的分支**。

### 3.2 遗留弱式（维持记档）

- **F2 隔离名单**：`plugin_tables.json` 的 `editorQuarantine.close` 含 `zebra2`，匹配方式是
  小写子串。触发键仍是插件名，但名单已外置为可编辑 JSON、且有崩溃日志自愈路径，判 P2 可接受。
- **F3 厂商表**（本轮新增证据）：`vendorTable` 用 3~6 字符泛型子串且**无条件覆盖**引擎真值。
  新增两点观察：
  - 无最短长度与词边界约束 —— `hive` ⊂ `archive`、`element` ⊂ `Elements`/`Elemental`，
    误归厂商无法从代码层拦；
  - 结果**依赖 JSON 键序** —— `kv-element` 恰好排在 `element` 前面才不误伤，这个隐式优先级
    没有任何机制保证（重排 JSON 即改变归属）。
  建议（未实施）：两级匹配，先按非字母数字切词做整词比较，再退化为「长度 ≥ 4 且带边界」的子串。

### 3.3 新增 P3 反模式

- **P3-1 盘符钉死复现**：`core/plugins/plugin_scan_dirs.dart:83-86` 用
  `C:\Program Files`、`C:\Program Files (x86)`、`C:\Program Files\Common Files` 作为
  环境变量缺省值。这正是 F1 点名批评过的写法（严重度低得多：仅 env 缺失时兜底）。
  建议改由 `SystemDrive` 派生。
- **P3-2 假设备占位**：`core/state.dart` 的 `filteredWasapiInputs` / `filteredWasapiOutputs`
  在枚举结果为空时塞入 4 条硬编码条目（「扬声器 (Realtek High Definition Audio)」
  「麦克风阵列（英特尔 智音技术）」「立体声混音 (Realtek Audio)」「耳机 (USB Audio Device)」）。
  启动初期引擎尚未上报枚举结果时，UI 显示并不存在的设备；用户选中即写入 config 并落盘，
  下次被 `routing.postApply` 的 exists 校验清成空串。属「写死厂商名当占位」。
- **P3-3 半死语义**：`isEditorOpenBlocked()` 恒 `false`，但 `openQuarantine` 仍被维护、
  仍从资产播种（`"open": []`），实际只用于 `isEditorCrashKnown()` 提示。命名与行为不符。

## 5. 未做与建议

1. **出厂清单去硬编码**：现为「常量白名单 + 双向门禁」。更彻底的做法是运行时用
   `AssetManifest.loadFromAssetBundle` 枚举 `assets/presets/factory/*.json`，彻底消除清单，
   代价是 `ensureInitialized` 的前置预载必须成功（失败即 0 个出厂预设）。
2. **文件名碰撞**（P2-4）：建议 `_safeFileName` 后追加名称短哈希，或保存前查重提示。
3. **删除/覆盖确认**（P2-5）：删除加二次确认，同名保存给「覆盖/另存」选择。
4. **F3 匹配加固**：整词优先 + 子串兜底，顺带消除对 JSON 键序的隐式依赖。
5. **P3-2 假设备**：建议改为「枚举中」占位态（禁用下拉 + 文案），而不是伪造设备的可选项。
