## P0 ASIO 停后重开必失败（B2 定罪 + 修复）

- 现象：App 进程内首次 ASIO start 必成功，stop 后再 start 必
  失败（rc=-2，旧文案「loadAsioDriver failed at COM step」），
  AuraDSP Driver 与 Voicemeeter Virtual ASIO 同症；声道选择因
  会话从未打开而不可用、自动回落 2 声道（非独立缺陷）。
- 证据链：宾机 `%TEMP%\auradsp_debug_iso.log` 全日时序 100%
  确定性（多进程多日无一例外）；干净进程内 CoCreateInstance
  反复创建/释放两驱动均正常（类工厂与注册无罪）；三态对照
  harness（完整流会话 ×2，新线程执行第二会话）——新线程预置
  STA 成功、MTA 与未初始化均失败，复现 App 报错原文。
- 根因：IASIO 是 Apartment 模型 COM 类且无 proxy/stub，SDK 以
  CLSID 本身作 IID 调 CoCreateInstance，只能在 STA 套间线程
  成功。桥旧实现直接在 Dart FFI 调用线程上 open：首启靠 SDK
  单例 `asioDrivers` 构造时在当线程 CoInitialize(STA) 侥幸
  成功；stop 后 isolate 换线程（未初始化/MTA）重开必死。进程
  级状态中毒，与安装状态无关——user 反复安装-卸载-重启不能
  治愈的原因在此（卸载程序本身经查无缺陷）。
- 修复（桥内 STA 控制线程）：`AsioBridge.cpp` 新增 `asioctl`
  ——InitOnce 懒建一条 CoInitializeEx(APARTMENTTHREADED) 的
  专用线程 + 消息队列，detect、start 的 open→caps→create→
  start 段、stop 全序都投递到该线程串行执行；引擎 DLL 预加载
  仍在调用线程（2026-10-15 loader lock 序不变）；投递失败退化
  为调用线程直执，绝不悬挂。RT 回调与参数/viz 面不经此线程。
- 失败口径：删除 `AsioHost` 的 `LookupAsioRegistry` 注册表反推
  启发式（实证误导）；open 失败后以 `ProbeOpenRc` 直取
  `asioOpenDriver` 真实 rc 写入 note：-5002 明示 device
  already open、其余给 `rc=%ld (0x%08lX)` 原码、未枚举给
  not-in-enumeration。
- 回归：新增 `smoke_asio_restart_threads.py`（主线程启停 →
  新线程再启 → 另一新线程停 → 回主线程再启），runner 双表
  登记；`smoke_round5_forensics` 的 ASIO 取证段改钉新口径并
  断言旧口径已删除。

## P3 可视化页频谱偶尔不落（B3 附带观察定罪）

- 定罪：`PeakPhysicsEngine` 的衰减只在新帧到达时推进
  （viewport 在 spectrum 通知里调 update）。停声方式决定帧
  流形态：链路仍在跑时静默帧续到、衰减正常走完；而链路
  停止/模式拆除/viz 挂起时帧流**戛然而止**——连静默帧都
  没有，stage 的静默迟滞计时器靠静默帧武装、无从触发，
  柱体与峰帽冻在最后一张有声帧上。故「偶尔」。
- 修复：`VisualizerStage` 加帧流停摆看守——记录末帧时刻，
  有声后武装 120 ms 周期看守；帧龄 >250 ms 且物理未落定
  时本地补零帧、走同一条衰减路径推进；全部落定（柱与峰帽
  ≤0.001）后看守自停并关闸。帧流正常时仅查帧龄，无行为
  变化；暂停/切页/销毁时随既有路径取消。
