## 0. 结论摘要

1. A1~A4 的端口-适配器边界可成立：`core/` 已不依赖具体平台实现（F11），进程/注册表/第三方平台包只存在于 `lib/platform/`（F9/F10）。
2. 仍存在 3 个「接口层未闭环」点：`FileDialogPort` 的 `openFiles/saveFile` 无消费方、`RegistryPort.writeString/deleteValue` 无消费方、`WindowPort.show()` 无消费方。它们不是错误，但属于**预埋接口**，需要明确“保留到哪个阶段”或删除。
3. 仍存在 2 个「命名/模型双份」点：`AuraPathPickerMode` 与 `ResourcePickMode` 语义重复；`MediaSessionPort` 与 `MediaSessionProvider` 双层接口（后者可视为实现对象，尚可接受）。
4. A5（Android）目前只有 Flutter 空壳与 HAL 侧独立工程：**没有 App→引擎 JNI/FFI 桥、没有内容 URI 资源句柄、没有 Android 配置根目录端口**。三者为 P0 阻断，必须先做 A5-0~A5-2。
5. A6（插件跨平台）当前宿主实现 100% 为 Win32：进程宿主、共享内存、编辑器窗口均绑定 HWND/Win32 消息循环。跨平台化不是“改路径”而是“换宿主运行时”，建议独立立项，先做 A6-1 元数据/扫描端口，再做 A6-2 进程宿主。

### 2.2 接口审查

| 端口 | 未消费成员 | 判断 | 建议 |
|---|---|---|---|
| `FileDialogPort` | `openFiles`、`saveFile` | ✅ 本轮已删除 | 真实调用只有 `openFile/selectDirectory`；需要多选/另存时再加 |
| `RegistryPort` | `writeString`、`deleteValue` | 预埋 | 与自启端口职责重叠；若未来自启改走 RegistryPort 再启用，否则删除 |
| `WindowPort` | `show()` | 预埋 | 可由托盘菜单/通知点击复用；保留并补一个调用方（或标注预留） |
| `WindowsSystemPort` | 无 | ✅ 全部有消费方 | 保持 |
| `PluginDirsPort` / `AutoStartPort` / `ShellOpenPort` / `MediaSessionPort` | 无 | ✅ | 保持 |

**接口一致性意见**：`FileDialogPort` 的 `title` 参数在 Windows 原生选择器上无法真正设置窗口标题（仅用于 `XTypeGroup.label`）。当前实现已降级为过滤器标签，接口可保留，但文档应明确“标题是提示性，不保证原生标题”。

## 3. A5 Android 细致审查（只读，不改代码）

### 3.1 现状矩阵

| 组件 | 当前实现 | 缺口 | 严重度 |
|---|---|---|---|
| App 壳 | `MainActivity.kt` 只有 `FlutterActivity`；`build.gradle.kts` 无 `externalNativeBuild`/JNI | 无 Java/Kotlin ↔ C++ 桥；无 NDK 构建接线 | **P0** |
| 引擎加载 | `PlatformProfile.engineLibraryCandidates` 对 android 返回 `[]` | Flutter 侧无法拿到任何引擎句柄 | **P0** |
| 音频输出 | `supportsLocalDevice = false`；`createAudioOut()` 返回 null | Android 侧应走 HAL/AIDL，而非 App 内泵；尚无 HAL 客户端桥 | **P0** |
| DSP 内核 | App 侧 `engine/legacy`（桌面 DLL）；Android 侧 `core/android/vendor-src`（HAL 独立工程） | 双内核分叉（CP-03），效果/参数表两套真相 | **P0（独立立项）** |
| 配置根 | `configDir` 非 Windows 走 `HOME ?? '.'` → `~/.config/auradsp` | Android 无可靠 HOME；应走 `getApplicationSupportDirectory`/`filesDir` | **P1** |
| 文件选择 | `file_selector_android` 返回 SAF `content://` URI | `ResourceGate/PathMemory/ResourceLocator` 全部按真实 `File` 路径设计，读不了 URI | **P1** |
| 插件 | `supportsPlugins=false` → 插件页占位 | 无 Android 插件宿主；短期应保持禁用 | P2（可接受） |
| 媒体会话 | `mediaSession.supported=false` → 歌词“不支持” | 需 MediaSession/通知监听实现（A5-3） | P2 |
| 托盘/窗口 | `TrayService.init` 提前返回；可视页用 `SystemChrome` 全屏回退 | 可接受；移动端无需桌面托盘 | ✅ |
| 文件管理器 | `ShellOpenPort` 在移动端 `Null` | 可接受；如需“打开文件夹”应改为 SAF 文档 UI | P3 |
| 生命周期/音频焦点 | 无 foreground service、无 audio focus 处理 | 后台播放下沉、被打断恢复都缺 | P1 |

### 3.2 A5 关键阻断（按依赖顺序）

1. **A5-0 存储根端口**：新增 `AppStoragePort`（应用私有目录/缓存/外部导入目录），`ConfigManager.baseDir` 经它取 Android `filesDir`。否则 `~/.config/auradsp` 不成立。
2. **A5-1 资源句柄**：`ResourceGate` 当前只接受 `String path`。Android SAF 需要 `content://`；建议引入 `ResourceHandle`（`path | uri`）或“选择后复制到 app cache 再交现有闸门”的临时策略。后者最快，但大 IR/脚本会有拷贝成本。
3. **A5-2 引擎桥**：新增 `engine/platform/android` 的 JNI 入口 + App 侧 `AndroidEngineBridge`（Dart FFI 到 `libauradsp_android.so` 或 MethodChannel 到 HAL 客户端）。当前 `engine/platform/android` 只有 README，没有可编目标。
4. **A5-3 HAL/双内核**：确定 Android 使用 `core/android/registrar` + `vendor-src`（现状）还是改造 `engine/legacy` 可移植（CP-03）。在动 App UI 前必须先定，否则参数表/效果语义两套。
5. **A5-4 媒体会话/歌词**：实现 MediaSession/MediaBrowser 或通知监听；否则歌词层只能“本地 LRC”。
6. **A5-5 构建与发布**：`android/app/build.gradle.kts` 需要 `externalNativeBuild.cmake`、ABI filters、签名；当前 release 用 debug 签名。

### 3.3 A5 验收门槛（建议）

- `flutter build apk --debug` 产出可安装包，启动不崩、能读 `filesDir/config.json`。
- 选一个 IR/脚本经 SAF 选择后能被 `ResourceGate` 读取（先拷贝策略也可）。
- 引擎桥至少暴露 `abi/version` 与一条 `setParam/getParam` 往返。
- 无媒体会话时歌词层显示“不支持”而非空转（现状已具备）。
- 不要求 A5 首版支持插件。

## 4. A6 插件跨平台细致审查（只读，不改代码）

### 4.1 现状矩阵

| 组件 | 当前实现 | 跨平台缺口 | 严重度 |
|---|---|---|---|
| 插件元数据/扫描 | `engine/plugins/api/plugin_host.h`、`driver/plugin_scanner.cpp`、`plugin_format_driver.h` | 元数据结构含 `path`/`arch`/`vendor`/`logo`，但扫描依赖 Win32 扩展名与 PE 读取 | P1 |
| 插件宿主进程 | `platform/win32/host/*`（`CreateProcess`/共享内存/IPC） | 无 POSIX spawn/socket/shm 实现；`AURADSP_HOST_INPROC` 仅回退 | **P0** |
| 编辑器 | `plugin_host.h:101-107` 明确 `Win32` 编辑器窗口；`HWND`/消息循环 | macOS 需 NSView、Linux 需 X11/Wayland surface；嵌入 Flutter 窗口模型也不同 | **P0** |
| 格式驱动 | VST3/CLAP（`engine/plugins/formats/`） | 平台库名/动态加载 API 差异；macOS 需 `.dylib`/bundle，Linux `.so` | P1 |
| Dart 侧 | `core/plugins/plugin_manager*.dart` 已平台无关；`plugin_dirs_*` 已平台化 | `PluginManager` 仍隐含“宿主已存在”；无宿主能力的显式状态机 | P1 |
| 能力位 | `PluginHostPort`（A6-1 已落地）；Windows = win32Process，其它 = none | 尚无 A6-2/A6-3 方法；宿主缺失时有显式能力对象 | P1（A6 续做） |
| 注册/路径 | `platform/plugins/*`；VST 注册表仅 Windows | macOS 需要 `~/Library/Audio/Plug-Ins`（已有）；Linux 标准目录（已有） | ✅ 目录层已就绪 |

### 4.2 A6 关键结论

1. **A6 不是目录问题，是运行时问题**：现有宿主 = Win32 进程 + HWND 编辑器 + 共享内存 IPC。跨平台必须新增 `PluginHostPort` 及 OS 实现，而不是在 `core/plugins` 加 if/else。
2. **A6-1 已落地**：`platform/port/plugin_host.dart` 提供 `PluginHostCapabilities`（supported/canScan/canMount/canEdit/runtime），插件页改读端口能力，不再直接读 `PlatformProfile.supportsPlugins`。
3. **建议端口形态**：
   - `PluginHostPort`：`scan/scanProgress/enumerate/mount/unmount/setParam/getParam/openEditor/closeEditor/hostStatus`；
   - `PluginMetadataDto`：id/name/vendor/format/arch/path/logo（避免 Dart 直接依赖引擎结构体）；
   - `PluginEditorPort`：`show(handle)/resize/close/isOpen`，各 OS 用独立 surface。
4. **进程宿主优先**：A6-2 先做 macOS/Linux 的 spawn + IPC（可复用现有协议抽象），再评估 in-proc 回退；编辑器最后做。
5. **元数据先解耦**：A6-1 可只做“扫描+元数据+能力位”，不碰编辑器；这样 UI 插件页可在非 Windows 展示“可扫描但不可编辑/不可挂载”的分级状态。
6. **风险**：插件授权（VST3/CLAP SDK）、GUI 线程模型（macOS 主线程/NSView；Linux X11）、代码签名/沙箱、arm64 插件架构、崩溃隔离。
7. **不做**：不在 A6 里引入 AU/LV2（引擎侧仍无驱动，见未决清单）；不改 C ABI 冻结面。

### 4.3 A6 建议分期

| 阶段 | 内容 | 验收 |
|---|---|---|
| A6-1 | `PluginHostPort` + 能力 DTO；Dart 侧不再假设宿主存在 | ✅ 本轮已落地（能力位）；A6-2 起补扫描/挂载方法 |
| A6-2 | POSIX 进程宿主 + IPC 协议移植 | macOS/Linux 可扫描并挂载一个最小 VST3/CLAP |
| A6-3 | 编辑器 surface 适配（NSView/X11） | 打开/关闭/缩放不崩，UI 线程不阻塞 |
| A6-4 | 打包/签名/崩溃隔离 | 发布包可加载签名插件；崩溃不拖垮主进程 |
