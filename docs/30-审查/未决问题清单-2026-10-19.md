## B. 结构缺口（门禁覆盖不到 / 键位分裂）

### B1. 11 个 `*.channels` 声道掩码绕过 ParamRegistry —— ✅ 已注册 spec（2026-10-19，B-3）

- **代码位置**：根源已修——`lib/features/effects/channel_routing_selector.dart` `_updateMask` 改走 `setParamById`（spec 链：setter→setInt+镜像）；11 个 int spec（0..255，默认按引擎：dyneq/exciter=0xF7、其余 0xFF）已注册进各自 section（`param_schema.dart`），getter 走 `mirrorInt`。契约 Part C `kEngineOnlyIds` 已删 11 条 `.channels`（`.channel_mask` 别名仍仅引擎侧）。

### B2. 8 个孤儿 spec + comp 14 个动态 spec 未挂 section

- **代码位置**：
  - 孤儿清单：`app/auradsp_app/test/param_contract_test.dart` L278-284 `kOrphanStaticSpecIds`（Part E 精确差集断言）；spec 定义本体在 `lib/core/param_schema.dart` L499-563（stereo 族）与 L1200-1215（comp.threshold/ratio）。
  - comp 动态 spec：`lib/core/param_schema.dart` L1216-1236 —— `compFreqs`/`compGains` 由 `List.generate(7, ...)` 工厂生成 14 个 spec（comp.freq1..7、comp.gain1..7）；comp section 定义在 L1690-1694，**只挂了 6 个 spec**（timeconstant/granularity/tfresolution/autogain/outputgain/enable），14 个动态 spec 全部不在其中。
- **影响原因**：
  - 8 个孤儿 spec 不在 registry.allParams → 不进 spec 驱动的预设/会话路径，UI 若改走 registry 消费会突然摸空。
  - comp 的 14 个动态 spec 更特殊：`List.generate` 不产生字面 `id:`，**静态解析器连它们存在都解析不到**——Part E 门禁对它们是绝对盲区，这正是门禁"源码解析"路线的已知局限。
- **建议处置**：stereo.band.1..5 与 B3 一并决策（挂 section 需先统一键名）；bass_shaping.enable 与 shelf.enable 二选一删一个；comp.ratio 引擎无此参应删 spec 或标 neverSend；comp.freq/gain 14 个决定注册或显式豁免，并在门禁注释里写明"List.generate 盲区"的原因。

### B3. stereo band 键名分裂：`stereo.band.1` vs `stereo.band1`（潜伏高危）

- **代码位置**（同一条物理参数、两种字符串 id）：
  - spec 层（带中间点）：`lib/core/param_schema.dart` L521-560 —— `stereoBand1..5` 的 id 是 `stereo.band.1`…`stereo.band.5`（key 为 band0..band4）。
  - 引擎/镜像/直发层（无点）：`lib/core/state.dart` L2290 `_mirror` 正则 `r'^stereo\.band([1-5])$'`（无点，L2288 有防呆注释解释此正则的历史坑）；L2032、L2440 直发 id `'stereo.band${i+1}'`（无点）。
- **影响原因**：当前因 band spec 是孤儿（B2，未挂 section、不在 registry）而**未实际相撞**。但只要按 B2 把它们挂进 registry，`getParamById('stereo.band.1')`（spec 键）与引擎回读/镜像键 `stereo.band1` 将对不上号——预设写入用带点 id 落 `_paramValues`，镜像与直发用无点 id，两套键位永久分裂，届时会复现一类"值写了却不生效/回读对不上"的隐形缺陷。
- **建议处置**：统一为无点 `stereo.band1..5`（与引擎表、`_mirror` 正则、直发 id 三处既有约定一致），只改 spec id 一侧；反向全改（镜像+直发+引擎）代价大且引擎已对外，不推荐。**此项应排 B 组第一优先。**

### B4. stereo 分带值无引擎回读对账

- **代码位置**：回读处理 `case 'params'`（`lib/core/state.dart` L1290 起）——对账了 `stereoMix`（L1308 附近，带 `stereoOn` 守卫，10-19 修复点）与 `stereoBandUsed`（L1351 附近），**唯独不回读 stereoBands[0..4]**。
- **影响原因**：`_pushStereoChain`（L2422-2447）下发分带时做了 `(stereoBands[i] * stereoMix * 2.0).clamp(0.0, 1.0) * stereoWidenMax * k` 换算，引擎侧实际生效值经钳位/换算后可能与 UI 滑块记忆出现单向漂移；且任何引擎侧的分带值变化（拒收回退、外部写入）UI 不可见。与 stereo.mix 已有的 roundtrip 对账不对称。
- **建议处置**：仿 stereo.mix 的对账写法，在回读处理补 stereoBand0..4（引擎 raw 键，注意换算回 UI 刻度）映射回 `stereoBands[]`，同样带 `stereoOn` 守卫；并补 ui_stereo_restore_test 对应用例。

## C. 体验与口径遗留

### C1. 关闭态卡片 ↻ 无"效果器已关闭"提示；`showRefresh` 静默隐藏模式仍是坑

- **代码位置**：
  - `lib/features/widgets.dart` L97 —— `showRefresh: onRefreshLatency != null`：回调为 null 时按钮**静默消失**，无任何"为什么没有刷新按钮"的解释。
  - 各卡折叠判定：stereo_card.dart:16、bass_shaping_card.dart:18、haas_card.dart:19 等 `collapsed: !model.xxOn`——折叠时标题行延迟徽标+↻ 仍显示，点击只重算标称值。
- **影响原因**：10-19 三按钮点不动的原始事故模式（按钮存在但无效/无声消失）在框架层仍被允许：新卡片漏接 `onRefreshLatency` 会静默退化，没有任何报错或提示。关闭态下点 ↻ 得到的"标称值"也可能让用户误以为是实测。
- **建议处置**：① `ComponentLatencyBadge` 在卡片关闭（collapsed 或 effect off）时加"已关闭·标称"角标或 Tooltip；② SectionCard 对"latencyMs 非空但 onRefreshLatency 为 null"的组合加 debug 断言，把静默模式变成开发期红字。

### C2. 用户旧会话 stereo 值已被 0 写穿（历史损失，代码缺陷已修）

- **代码位置**：缺陷本体已修——`getParam` getter 优先（state.dart）+ readback `stereoOn` 守卫（L1308 附近）。损失发生在修复前的会话写入。
- **影响原因**：修复前"显示 0%"的假值经 autosave 覆盖了 `session_state.json` 里的真实分带值；取证已确认该文件 stereo 节当时 mix=0.5、on=true（部分完好），但用户上一次记忆的分带值已不可考。
- **建议处置**：无需代码动作，告知用户重新调节即可。可选增强：会话恢复时对"开关 on 但全部值≈0 且历史值存在"的节做坏值告警（低优先级）。

### C3. stereoMix 默认值三口径：0.0 / 0.5 / 双击重置

- **代码位置**：`lib/core/state.dart` L100 `static const double stereoMix = 0.0`（ParamDefaults）；L2492-2493 开关兜底 `_lastStereoMix > 0.0 ? _lastStereoMix : 0.5`；L2472 `resetStereoWiden` 用 `ParamDefaults.stereoMix`（=0.0）。
- **影响原因**：三条"回到默认"路径结果不一致——① 打开开关兜底 → 0.5；② 双击主滑块重置 → 0.0（语义上等于关掉展宽量）；③ spec.defaultValue（预设全量重置）→ 0.0。用户感知"重置"结果随入口变化。
- **建议处置**：产品定义 stereoMix 默认语义（0=无展宽 vs 0.5=中性档）后统一 `ParamDefaults.stereoMix` 与开关兜底值，二者只允许一个真相。

### C4. ~~Dart 延迟估算表与引擎 kLat* 表无一致性守卫~~ —— 已解决（2026-10-19）

- **结论**：采取「删表」方向——`componentLatency` 内全部预设标称（comp=85.0、spatial=1.0、arbmag=2.67、ddc=6.0、haas=设定值、bass_shaping=0.0）已删除；徽标改为引擎真实脉冲实测驱动（含本轮新增的 haas/spatial 探针），未实测即「未测量」，不再有可漂移的 Dart 侧表格。
- **遗留说明**：引擎 `kLatComp=85ms` 与实测 14.2ms（默认参数下）存在量级差——属引擎侧标称校准问题，总延迟口径是否应改由实测驱动需产品定夺，暂不动引擎 kLat* 表。
