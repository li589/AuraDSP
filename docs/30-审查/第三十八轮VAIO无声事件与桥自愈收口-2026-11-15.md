# 第三十八轮收口：VAIO 无声事件定罪与桥非计划死亡自愈（2026-11-15）

## 事件（user 实测 2026-11-15 上午，vm-win10）

VAIO 输入 + WASAPI 输出突发无声：AuraVAIO 端点会话电平在
跳，但 App 无可视化、无处理、无输出。只读取证（iso 日志
`auradsp_debug_iso.log`）：桥两次起桥 rc=0、帧在跑，但驱动
环输入恒纯零（peakIn=0、TotalBytesWritten=0），其后桥的
WASAPI 输出流被作废（面板 note `wasapi-output-lost:
0x88890004`），UI 自 11:20 起持续补发 vaiomode 而桥再未
起来。user 改端点为立体声 + 重启 App + 点「仍然启动」后
恢复（11:46:56 新桥 peakIn=peakOut=0.442）。

## 定罪（含一次自我更正）

- **初判「8ch 端点格式致驱动环不送数」——实验证伪、正式
  作废**：恢复后单变量实验，user 切回 7.1 无事发生；驱动
  GET_STATUS 探针实测 8ch/16bit 渲染流满速 48k 帧/秒写入
  驱动环、桥几何跟随 ringCh=8；11-14 日志亦有 8ch 正常
  流动会话。7.1 格式无辜，驱动零改动。
- **真触发**：user 复现实验定罪——点输出设备（高清音频）
  的扬声器「配置」，无改动走完/取消也会让 Windows 重建
  该端点音频图，桥的 WASAPI 渲染客户端被作废
  （AUDCLNT_E_DEVICE_INVALIDATED）；桥泵连续失败 400 轮
  后按既有口径自判死亡、报 running=false + note。当日上
  午 user 为设 7.1 反复进出同一批对话框，与首发时序吻合。
- **楔死机制（永久无声的根源）**：isolate 的 BridgeManager
  只在成功 start / 主动 stop 时记账/清账，桥自发死亡无人
  清账；`startVaioBridge` 首行见记账在跑即静默早退（且在
  日志行之前），UI 补发与切走切回全被吞——唯改 VAIO 落点
  （vaiorestart）或重启 App 可恢复。三桥同构（VB/ASIO 亦
  然），一并修。

## 修复（S1 `40832474` + S2 `6854d94c`，均 isolate 侧）

- 新增纯逻辑 `BridgeDeathGate`（`lib/engine/
  bridge_death_gate.dart`）：120 秒窗口内最多自动重启
  3 次，窗口滚动剪枝（龄期 > 窗口才滚出）。
- 状态轮询对账：当前后端自报 running=false 而记账在跑
  → 必为非计划死亡（计划内停止在消息处理内同步清账，
  轮询看不到中间态）→ `recycleDeadBridge` 走正式
  stop→start 回收（原生 stop 对泵自死形态有全拆解口径，
  第四轮项 3 已备），重启参数用死前在用会话快照（stop
  会清 in-use 字段）；超限只拆不启并回
  `bridge-died-repeatedly` 状态。
- 三处 start* 早退前先验原生死活：记账在跑但桥已死先
  回收再真启动（覆盖轮询未及的窗口）；为满足「isolate
  局部函数不提升」的既有口径，三处 stop* 声明前移至
  对应 start* 之前，逻辑未动。
- 显式切模式/热重启指令 reset 闸门重新布防；轮询自动
  重启路径不 reset。
- S2：闸门单测「窗口过期」用例时间戳修正——121000 时
  死亡@1000 龄期恰 120000 未滚出（剪枝口径为龄期 >
  窗口），用例算错边界、闸门逻辑无误，改跳 124000。
