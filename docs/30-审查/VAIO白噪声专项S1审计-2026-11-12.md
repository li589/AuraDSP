# VAIO 白噪声专项 S1 审计记录（2026-11-12）

专项计划书：`docs/10-架构/VAIO白噪声专项计划书-2026-11-12.md`。
本记录汇总 S1 三路并行审计（指纹数值反推 / 桥侧读环审计 /
驱动侧状态审计）与主审复核的代码实证。结论先行：

## 结论：腐化变换与注入机理均已定型（待 S2 触发实证收口）

### 1. 腐化变换 = int16 采样字节序旋转（数值定罪）

对干净 1 kHz/0.5/48k 正弦逐一验算候选变换，仅 **int16 双字节
交换**（等价于读游标差 1 字节）全指标命中实测指纹：

| 指标 | 实测 | 字节交换仿真 |
|---|---|---|
| 1 kHz 分量 | ≈0.25 | 0.280（见残留说明） |
| 19 kHz 分量 | 0.65–0.74 | **0.742** |
| 17 kHz 分量 | 有峰 | 0.200 |
| ac1 | **−0.528** | **−0.5288** |
| 峰值 | 0.986 | **0.9851** |
| RMS | 抬升 | 0.607（干净 0.354） |

- 「ping-pong 折返」是错觉：低字节被提升为高字节后，输出是源
  值的锯齿折叠函数，正弦峰顶附近样本序天然回文（仿真序列
  实证），无任何游标反转。
- 该变换对幅度敏感：仅在 0.5 满幅正弦附近逐场恒定复现
  （ac24 ≈ −0.9994 为其内签名）；节目素材上呈电平相关的
  粗糙波形整形噪声——与 user「白噪声」口述一致。
- 全部游标/求和类候选被结构性排除：纯置换峰值必 ≤0.5、
  ac1 必 ≥+0.82；线性求和不产生新频率。

### 2. 注入机理 = 驱动字节粒度位置数学（代码定罪）

环内字节流以帧为格式（int16 立体声帧 = 4 B），但驱动的位置
与搬运全程**字节粒度、无帧对齐**：

- `VirtualClock::Advance()`（`01_vaio_driver/src/VirtualClock.cpp`）：
  `BytesAdvanced = (余数 + ΔQPC × BytesPerSecond) / QpcFreq`，
  任意字节数，**从不向 BlockAlign 取整**；PlayOffset/WriteOffset
  随之任意字节累积。
- `AdvanceAndCopyLocked()`（`MiniportWaveRTStream.cpp:263+`）：
  停滞钳制（全面复审 S5 的 VAIO-2 修复）——单次推进超过 DMA
  缓冲时丢弃 `bytesAdvanced − m_ulBufferSize` 字节后只搬最近
  一缓冲。**丢弃量 generically 非帧倍数** ⇒ 环字节流自此点起
  相对帧格旋转 r = 丢弃量 mod 4 字节，流生命内永久驻留。
- `AuraControlDevice_WriteRenderSamples()`（`ControlDevice.cpp:683+`）：
  逐字追加、无对齐钳制；其环溢出修剪（`ByteCount − dataSize`
  前丢）为同一缺陷类的第二注入点。
- 旋转后果按 r 分型：r∈{1,3} → 字节旋转 = §1 指纹（毒性）；
  r=2 → 采样完好但左右声道互换（隐蔽，可能构成部分「偶发」
  事件而从未被识别）；r=0 无害。故单次停滞事件 75% 概率致毒。

### 3. 与全部现场事实的对表

- 跨进程存续 ✓：旋转驻留在环字节流相位 + 驱动流时钟里，
  桥/App/探针重启不触碰。
- 重启 audiosrv 即愈 ✓：流对象销毁重建，时钟自 0（帧对齐）
  重新起步，新数据正确成帧（旧旋转数据随播放冲走）。
- 单次流中强杀不重触发 ✓：强杀不产生 GetPosition 停滞，
  无丢弃事件。
- 桥遥测全绿（phaseSkew=0、几何健康）✓：桥审计实证——
  phaseSkew 度量的是 WO−TW 字节一致性，帧相位不在其视野；
  桥从不校验内容，首块取证只在起桥时抓一次，运行中 onset
  无 witness。峰值 ×2 亦在环内（桥在 ringCh=2 时无求和路径，
  桥侧审计代码实证）。
- 端点混音环回干净、桥测试音干净 ✓：两者都不经「驱动按
  字节窗口搬运 DMA→环」这一段。
- 偶发 ✓：需单次 GetPosition 停滞超过 DMA 缓冲时长（VM
  vCPU 调度抖动、WER 写 500 MB dump 等均为合格停滞源）且
  丢弃量 mod 4 ≠ 0。

### 4. 被排除项（证据/算术）

- 桥内状态为载体（桥审计：坏状态跨桥进程存续，进程内状态
  全部排除）；恒定 WO/TW 偏移（锚吸收或 skew 可见）；
  DataSizeBytes 倍率错（skew 可见/或崩或无杂波）；TW 清零
  （桥 :922 自愈）；位深误读（峰值算术矛盾 0.9932）；
  双渲染流交错（引脚 MaxGlobalInstanceCount=1，PortCls 强制）；
  内核拷贝内反转/复制/求和（驱动审计逐行实证不存在）；
  共享头字段为驻留状态（Create 后从不复位、audiosrv 重启
  不清——与「重启即愈」矛盾，排除）。
- 驱动审计另报的真实缺陷（与本案关系待 S2 分辨，先登记）：
  SetFormat 运行中改格式不重置时钟/不重锚（同类相位风险）；
  FreeAudioBuffer 无条件清零时钟、AllocateAudioBuffer 无
  在用守卫。

### 5. 残留与未决

- 1 kHz 分量仿真 0.280 vs 实测 ≈0.25：差 0.03，判为实测侧
  窗口效应（捕获含 onset 段；仿真为稳态极限），不影响定型。
- DMA 缓冲实际时长未测：决定停滞触发门槛，S2 以暂停时长
  扫描实测。
- SetFormat 路径是否亦为触发源，S2 触发格覆盖。

## S2 确认协议（据本定型靶向化，不再撒网）

1. **LSB 斜坡判读**：以逐样本递增的 LSB 斜坡为刺激经环回
   读，旋转量 r 可直接读出（字节腐化下斜坡呈 ×256 阶梯），
   与任何游标机理瞬时区分。
2. **VM 暂停触发格**：driver 模式播放中暂停 guest 梯度时长
   （50/100/200/500/2000 ms）后恢复，逐格判读：预测在某门槛
   以上以约 75% 概率出现毒性指纹（ac1 ≈ −0.53），其余为
   r=2（用 L=1kHz、R=静音的非对称刺激识别声道互换）或无恙。
3. 确认后进 S3：① 驱动根治——时钟推进按 BlockAlign 量化
   （余数累加器保留亚帧滴答，Play/WriteOffset 恒帧格上）+
   SetFormat 重格 + 捕获侧 snap 对齐；② 桥侧防御纵深——
   int16 内容帧相位自检（多相位质量度量）+ 自动重相位，
   使旧驱动亦可自愈；③ guest 压力回归（触发格 ×50 零毒性
   旋转）。
