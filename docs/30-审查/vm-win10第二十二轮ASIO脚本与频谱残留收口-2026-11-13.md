## 项 1 定罪：pack.py 模板 `\r` 转义事故（与 BOM 无关的第二病灶）

取证（开发机实读字节 + Lux 当场复现）：

- 已装脚本与当前 staging 产物**字节一致且 BOM 完好**（EF BB BF）——先前 BOM 修复无恙。
- 但文件内有 **3 个孤立 CR 字节（0x0D）**，十六进制实证：`#   .<CR>egister_asio.ps1 …`。根源在生成端：`installer/windows/pack.py` 的 `REGISTER_ASIO_PS1` 是**普通（非 raw）Python 字符串**，其中三处单反斜杠 + `r` 被 Python 转义为真 CR——两处用法注释 `.\register_asio.ps1`、一处 `$regsvr` 路径 `\regsvr32.exe`。
- 后果链：注释行被 CR 从中劈开，后半截（`egister_asio.ps1 …`）被 PowerShell 当命令执行（CommandNotFound）；碎片语句使 `param()` 脱离首语句位置、按参数模式误解析（SwitchParameter 转换错误）；`$regsvr` 路径含 CR → Start-Process 报「系统找不到指定的文件」。Lux 以当前已装脚本在开发机原样复现全部三类错误（rc=1、注册表无变化、结果 JSON 未生成）。
- 为何装得上卸不掉：向导的 ASIO **注册**走自有 regsvr32 直调（不经脚本），故安装生效（CLSID 在位）；**卸载**路径（App 脚本通道/手动跑脚本）必经此脚本，恒死。取证时注册表实况：CLSID InprocServer32 在位、HKLM `SOFTWARE\ASIO\AuraDSP Driver` 发现键缺位（半程状态）。驱动侧 `DllUnregisterServer` 本身经复审已是全量删除 + 事后核验 + 诚实失败返回，非本项病灶。
- 历史注记：2026-11-11 定罪的是旧手写脚本的**无 BOM**问题（已修）；本 `\r` 病灶自模板引入起潜伏，旧门禁（`smoke_ps1_bom`）只钉 BOM 与引号、从未对生成脚本做过真解析/真执行，故历次打包均带病出厂。本轮如实记档。

修复（`c794a8c3`）：

- 模板三处转义改正（源码 `\\r` → 发射字节 `\` + `r` 两字符）；发射值全量复核：仅剩 4 个合法反斜杠（用法行 ×2、`\System32`、`\regsvr32.exe`）。
- pack.py 发射点加**纵深断言**：生成字节含 CR 即 `die` 拒绝打包（模板通篇 LF，CR 只可能来自转义事故）。
- 门禁 `smoke_ps1_bom.py` 扩展：以 AST 求值模板常量，钉「无 CR / 用法行反斜杠在位 / regsvr32 路径完整」三项（本地 12/12 PASS）。
- 产物实证：新包 staging 与驱动 zip 内的 `register_asio.ps1` 均为 1687 字节、CR=0，哈希与本地按新模板生成的基准文件逐字一致（`C01B44BF…`）。
- 遗留验收（user 侧）：装新包后从 App 内执行一次 ASIO 反注册→注册（或手动跑随包脚本），应双向成功且结果 JSON 正常——这是该脚本自引入以来第一次具备真执行条件，建议顺手验掉。

## 项 2 定罪与修复：APO 流停止后频谱残留

机理（代码实证）：APO worker 仅在引擎产出新 viz 帧时写 telemetry 并推进 `updateSeq`；流停止（播放器退出/流拆除）后帧停、seq 冻结；App 侧 `ApoTelemetryReader` 对 seq 不变恒静默返回，状态层永远停在最后一帧热谱；主页活动门的无声迟滞（2s）只能由**新到达的帧**武装，冻结即永不落闸——图 2 中电平已 -INF 而频谱柱高悬即此形态。进程内通路在停流时有清零帧发射（`audio_isolate.dart` 两处 zeroed spectrum），独 APO 读者缺此环。

修复（`c794a8c3`，`audio_isolate_apo.dart`）：读者在 seq 冻结满 500ms 时补发**一帧清零 viz**（每冻结周期一次，seq 恢复即复位），与正常帧同形状同键集，声道数沿用最后一帧真值；状态层与活动门随即按无声口径收口（2s 迟滞后落闸冻结于零谱）。验收（user 侧）：APO 模式播放后关闭播放器/停流，频谱应在约 2.5s 内落零。
