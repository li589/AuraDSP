## 事件定罪（guest 实证 + 代码实证）

- 现场：HD 渲染端点 {ff69ca35…} 的 FxProperties 槽 ,5/,6/,7
  仍为本方 CLSID，而 `apo_config uninstall --yes` 报「未发现
  任何挂载了 AuraAPO 的端点」、status 已挂载数=0、doctor 的
  fx_writable 查「0 个」端点；同一 status 的实时推断却如实
  报 sfx-efx——工具自相矛盾。
- 根因（代码）：`GetInstalledChildApos()` 只枚举自家台账键
  `HKLM\SOFTWARE\AuraDSP\Child APOs`，从不扫 MMDevices 真值；
  uninstall / status 计数 / doctor 三处把台账当存在性真值。
  台账与 FX 现实分叉后集体失明，唯 Part II 推断（扫真值）
  看得见。
- 毒化基线：当日 16:45 两次附加的磁盘快照
  `backup_preserved:false` 且槽内已含本方 CLSID——残留早于
  当日附加；无台账时 BackupEndpoint 把残留当「原始基线」
  存下，之后的 detach 把毒化基线原样写回并删台账记录，
  残留就此不可见、不可清。首次污染来源为推断（v1 Python
  时代台账格式与 C++ 工具不互认）。
- 致命放大器（代码）：CmdUninstall 收尾在（台账口径）
  剩余为空时自动删 DisableProtectedAudioDG 关 testenv；
  FX 残留还在、testenv 关掉后，受保护 audiodg 拒载未签名
  APO → 音频图构建失败 → 全端点无声且不可测。残留在
  testenv 开着时无症状。
- ACL 墙（guest 实测）：管理员直写 FxProperties 被拒，写入
  须接管所有权（SeTakeOwnershipPrivilege）；旧版
  RestoreEndpoint 虽校验写结果并在失败时保留台账记录，但
  无接管重试、无回读验证。

guest 当场修复（已完成并验证）：删除 System32 残留旧 DLL
（落点规矩）；接管所有权清三槽为空 GUID 并还原原 SDDL；
testenv 复原 absent；全端点（Render+Capture）CLSID 扫描
0 命中；播放测试 OK。其后用户自行清装，Lux 收尾清 FX、
COM 注册与装机目录——guest 进入完全无 AuraDSP 状态。

## 项 4（并行定罪）：App 退出崩溃

用户以 WinDbg 打开 `C:\CrashDumps\auradsp_app.exe(1).9580.dmp`
提供 `!analyze -v`（实测证据）：16:44 进程 uptime 1:53:06，
为**退出崩溃**非启动崩溃（先前「启动间歇崩」定级更正）。
故障在 `flutter_windows+0x1e220`（rcx=0），栈为
Win32Window::Destroy → FlutterWindow::OnDestroy →
FlutterDesktopViewControllerDestroy → 引擎销毁期子窗口
DestroyWindow 同步重入 MessageHandler →
HandleTopLevelWindowProc 对半毁控制器解引用。机制：
OnDestroy 里 `flutter_controller_ = nullptr` 的 unique_ptr
析构先于成员置空执行，重入消息看到成员仍在。同签名
2026-10-24 WER 亦有记录，跨版本间歇。

## 新发现（定罪，实测）：用户目录 DLL 对 LocalService 不可读

Phase A 初次播放时 APO 仍不处理：注册（CLSID +
AudioProcessingObjects，Flags=0xf、接口齐全）、FX 槽、
testenv、新鲜 audiodg、交互会话逐项排除后定罪——
**audiodg 以 LocalService（S-1-5-19）身份运行，而用户目录
下的 AuraApo.dll ACL 只有 SYSTEM / Administrators / 本人，
LocalService 无任何读权限**，LoadLibrary 在 audiodg 内
根本到不了。给便携 driver 目录授 LocalService 只读
（RX，含 AuraApo.dll 与 auradsp_engine_apo.dll）后，同一次
播放立即出现 telemetry 块 + 心跳映射，引擎真处理链路在
真机上首次完整跑通。

影响面：Program Files 安装（开发机）目录世界可读、不受
影响；**per-user 安装（AppData\Local\Programs\AuraDSP，
vm-win10 装机实况）与便携包解压在用户目录时，附加「全绿
成功」但永不处理**，且一切管理员侧检查（status/doctor）
都看不出来。与第五轮 telemetry-absent、第七轮项 2、第八轮
的「不处理」现象可能同源（共犯，非本轮可定全案）。
修复方向待用户裁定（建议：apo_config install 期对 driver
目录做 LocalService 可读校验/授予 + doctor 增检该项），
本轮未动。guest 现留状态：便携目录
`C:\Users\li\AuraDSP-test-361afd78` 保留，driver 子目录带
上述验证用 LocalService 读授权；COM 注册现指向该便携
DLL，装新包时由现行性校验接管。
