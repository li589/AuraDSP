## 项 1（= 第七轮项 2）APO 不处理 —— 定罪：残留注册指向旧 DLL

证据链（guest 实测）：
- 装机 driver\ 全套为当日新包（时间戳 14:50；AuraVaioDriver.sys
  49,064 B 与 S5b 核验值一致）——「装的旧包」排除（用户亦确认
  清空 dist 后重打包）。
- apo_config status：已挂载端点恰 1 个 = HD 扬声器（sfx-efx），
  VAIO/捕获端点均未挂——「座位被他端点抢」排除。
- iso 日志两轮运行（12:12、14:51）恒报 `apo telemetry: block
  absent for 5s`——audiodg 内 APO 从未创建 telemetry 块，即
  引擎宿主（ApoEngineHost.TryStart）从未运行。
- 决定性：HKCR\CLSID\{415AD8ED-7A45-4F4F-AC69-043830EBC174}\
  InprocServer32 指向 `C:\Windows\System32\AuraApo.dll`
  （178,688 B），随包 `driver\AuraApo.dll` 为 247,296 B。
  audiodg 按注册路径加载的是 v1 透传时代遗留在 System32 的
  旧副本：只有心跳与透传、无引擎宿主——与全部症状严丝合缝。

代码根因：apo_config 的 EnsureComRegistered() 只校验注册键
存在、从不校验 InprocServer32 路径；status 的 com_registered
与 doctor 的 com_registration 探针同口径（doctor 只验「路径
DLL 存在」，System32 旧文件存在即过）。旧注册遂在历轮安装/
附加中永久蒙混。

guest 当场处置（Lux 经 SSH）：以随包 DLL 重跑 regsvr32 +
重启 Audiosrv；重启后实测 audiodg 加载模块路径 =
`...\Programs\AuraDSP\driver\AuraApo.dll`（新版）。用户按播放
验证处理与可视化恢复一项，收口时仍待回（见验收清单 1）。

代码修复（`784edd9d`，apo_config.cpp）：
- 新增 RegisteredDllPath / SameDllPath（去引号+绝对化+大小写
  不敏感）/ ComRegistrationCurrent（键齐 且 注册路径规范化后
  与 FindDll() 随包 DLL 一致）。
- EnsureComRegistered 改为：不现行则 regsvr32 随包 DLL 并
  复核——附加流程自动自愈残留注册。
- status：JSON com_registered 收紧为「键齐+路径现行」，新增
  com_registered_path / com_path_current；文本版打印注册路径、
  指向旧路径时明示（App 不消费 com_registered，无兼容影响）。
- doctor com_registration 探针改用 ComRegistrationCurrent
  （检查名不变；--fix 随之可治旧路径）。

连带结论：全面复审遗留 APO-3（telemetry 无座位端点身份）与
本项的合并处理到此分开——本项根因与 telemetry 布局无关，
APO-3 维持遗留待裁定（面板四态判读在注册修复后是否够用，
待用户实测反馈再议）。

## 项 2 输出下拉锁定 —— 定罪：呈现层入口缺失（非枚举问题）

- guest 日志 `vaiodetect: ui received endpoints=1`：vaio_detect
  正确枚举到唯一物理端点（HD 声卡），枚举层无罪。
- VAIO 桥链 + pipelineOutput=wasapi 时，输出层只呈现置灰的
  WASAPI 下拉（字段不被桥链消费，恒显系统默认）；桥物理落点
  vaioOutputEndpoint 的选择器（_VaioOutputSubpanel）此前仅在
  pipelineOutput==vaio 时呈现，桥链 + wasapi 输出下全仓无
  入口——即用户所见「锁定系统默认、刷新/改系统默认皆无变化」。
  composeChain 口径下 input=vaio 恒合成桥链、output 值不改
  链路，故此缺口纯属呈现层。

修复（`b0d0509a`，hardware_io_output.dart + 三语 arb）：
- 输出层在桥链激活且 output==wasapi 时，于 WASAPI 子面板下方
  续接落点面板（asBridgeLanding 形态：隐藏虚拟声卡输出提示与
  监听镜像块，只留落点下拉与桥状态行）。
- ioOutputOverriddenByVaio 三语文案改指下方落点面板。

## 项 3 开关随缘白噪 —— 定罪：桥读环 +1 字节相位错位

证据（guest iso 日志 S4 取证，桥首块统计）：
- 噪声 start（如 15:15:18/15:15:19 两轮）：正位口径
  peak=1.0、meanAbs≈0.495（满幅垃圾）；+1 字节错位口径反呈
  结构化低峰（peakShift=0.24、meanAbsShift≈0.064，似正常
  音乐）——取证设计本身即以此为「读游标错位一字节」的判读。
- 正常 start（如 15:15:22）：正位 meanAbs=0.134 为结构化、
  错位口径反成满幅（peakShift=0.9998）——同批 toggles 内
  两态并存，与用户「随缘」报告一致。
- 全天所有 start 几何恒为 16 bit / 48000 Hz / 2 ch，
  fmtResyncs 恒 0——格式闩/重同步路径排除；装机驱动为新版
  49,064 B 且 System32\drivers 加载副本同版——旧驱动排除。

机理：泵以 userBytesRead % dataSize 直算物理偏移，隐含假设
WriteOffset ≡ TotalBytesWritten (mod dataSize)；实证某些
start 后 WriteOffset 与该恒等式差 1 字节（偏差来源在驱动侧
计数/流生命周期交界，本轮未在驱动内定点；桥侧锚定后来源
不再致病）。帧内错位一字节后，消费增量恒为帧长整数倍、
模偏移永不自愈 → 持续满幅噪声至重启桥。

修复（`b0d0509a`，VaioBridge.cpp）：
- 泵读环物理偏移改以一致对 (TotalBytesWritten, WriteOffset)
  为锚换算：phys = (anchorWo + (T − anchorTw)) mod dataSize；
  锚每轮以「TW/WO 各连读两遍不变」的一致对刷新，写入中途的
  混合对弃用。恒等成立时 skew 恒 0、行为与旧实现逐字节一致。
- status 新增 phaseSkew / phaseResyncs（恒输出）；面板在
  phaseResyncs>0 时增一行观测（含 skew 字节数），与
  fmtResyncs 同口径——下轮实测凭它验「偏差出现且被校正」。
- 已知边界：锚对读取与驱动「先写 WriteOffset 后加
  TotalBytesWritten」之间存在纳秒级竞窗，至多令一周期读偏、
  下轮锚刷新自愈，与旧实现的永久错位有本质区别（代码注已
  明记）。
