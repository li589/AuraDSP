## 架构与实现（feature/linux，三提交）

镜像的唯一正确落点是 **VAIO 桥内的第二路 WASAPI 渲染客户端**
（任何 VAIO 参与的链都合成 vaio 桥链；引擎输出只存在于桥内）：

- `f209b654` 原生：桥泵在主落点 `ReleaseBuffer` 成功后同帧分流喂镜像路。
  - 目标 = **系统默认 eConsole 渲染端点**。三类排除（桥照常启动、
    状态 `mirrorNote` 标注原因）：默认端点 == 主落点
    （`mirror-target-is-primary`）、默认端点是 AuraVAIO
    （`mirror-target-is-virtual`，防反馈回路）、无默认端点。
  - 镜像客户端：共享模式、无事件回调、40 ms 缓冲，泵内按 padding 轮询，
    永不反压主链。喂流规划在纯头 `VaioMirrorFeed.h`：分数相位结转保证
    长期帧数守恒，超额计入 drops 截断丢弃。
  - 通道重映射 → 线性重采样 → 格式转换写出，与主路共用转换函数。
  - 镜像路连续失败 400 轮只停镜像自身（`mirrorNote=mirror-output-lost`），
    主链不受影响。
  - 状态 JSON 恒输出 `mirror/mirrorFrames/mirrorDrops/mirrorEndpoint/mirrorNote`。
  - 原生单测 `vaio_mirror_feed_test`（21 断言）+ 冒烟
    `smoke_vaio_mirror_feed.py`（31 项，四层，已注册 runner 双处）。
- `e7137507` Dart/面板：`config_json` 新增 `mirror` 键（isolate
  `vaiomode/vaiorestart` 两路都读 `monitorMirror`，五处起桥载荷全带）；
  `setMonitorMirroring` 改真 setter（VAIO 链活跃时热重启桥生效）；
  面板删除常显提示框与「尚未实现」整行，镜像行 = 标签 + InfoBadge
  （`virtualSinkNotice` 三语精简并纳入镜像说明）+ 真开关；
  l10n 键 `monitorMirroringHint` 三语删除。
- `26f7c1d9` + `41e34433` 测试同步：`settings_paradigms_test` 的 ADR-009
  用例仍断言旧提示全文常显——按新口径改判（旧文案不以正文出现、
  镜像行子树含气泡与开关；断言形态经开发机直跑取证修正为子树判定）。
