# 双端性能优化收口（2026-11-12）

业主指令：① 本体——最小化/托盘化不占 GPU、CPU 不处理图形，托盘时释放部分图像节点内存，还原显示时恢复；② 安装程序——内存与 GPU 占用（70%+）过高需治理。

## 普查结论（先行底座已相当完整，本轮补的是缺口）

本体侧既有门控在位：viz 事件在窗口不可见时不更新任何 ValueNotifier（state_events `case 'viz'` 首行 `if (!window.isVisible) break;`）、可视化舞台自有时间轴已按可见性停转、主页有 `_HomeActivityGate`（页面+窗口双门）、PulseDot 已示范「监听 visibleListenable 停/续控制器」型、插件页状态轮询已按页+生命周期暂停、MaterialApp 根重建已改按 appearanceTick 订阅。缺口为下表五处。

## 本体（e2ced563）

1. **AuraChip 故障呼吸**（计划书裁定的呼吸闪动本体，此前无门控）：注册可见性监听，隐藏停转、恢复且仍 pulse 时续转（PulseDot 同型）。
2. **链页科幻面板电流脉冲**（展开态 repeat）：同型门控，恢复后续转以展开态为准。
3. **插件扫描占位闪烁**（repeat reverse）：同型门控。
4. **歌词 20Hz 同步 tick**：隐藏时整 tick 跳过——歌词定位由单调时钟锚点推算，恢复后下一 tick 即按真实位置续上，不丢拍不回跳；隐藏期不再驱动歌词视图逐行重建。
5. **图像内存释放**：组合根（main.dart）监听可见性转入不可见 → `imageCache.clear()` + `clearLiveImages()` + 精灵图集 `releaseImage()`。图集新增释放语义：dispose 图像本体、不动失败标记、解码在飞时以代次号作废落地结果（不回填）；恢复显示后下一帧 `ensureImage()` 自动重新解码。图集类头「永不替换」的旧生命周期注释已同步修订。回归测试 `atlas_release_test`（解码→释放→再解码、 在飞作废两案）开发机全量在跑。

## 向导（5b115b81）

1. **极光背景冻结**：新增 `auroraFrozen` 开关，app 层以 setState 覆写单点同步（运行安装/卸载或等待提权时置位）；背景在冻结或生命周期非 resumed 时取消 900ms 步进定时器——重活期间与窗口不可见时零全窗渐变重绘。
2. **步进式部件替代 60fps 连续动画**：提权等待遮罩的 CircularProgressIndicator 与进度页不确定态（Material 不确定进度条同为连续动画）改为 120/125ms 步进自绘部件（约 8fps，每档仅重绘自身小区域）——软件渲染环境（虚拟机/远程桌面）下整窗合成频率从 60 降到约 8，是 GPU 占用的主导项。确定态进度条改静态自绘（仅值变才重绘）。
3. **备份步逐文件报分数**：覆盖安装备份数千文件此前全程无分数、进度条长时停在不确定态动画；现按 0.04–0.049 频段逐文件上报，备份期即为确定态静态条。
4. **载荷内存治理**：extractPayload 落盘后原本把每个文件整份 readAsBytes 回内存只为算 SHA——改 `sha256.bind(openRead())` 流式摘要（1MB 分块量级），内存峰值与文件大小脱钩；size 走文件长度。
5. 回归：向导测试 35/35（新增 perf_widgets 存活/定时器清理/冻结切换两案）。
