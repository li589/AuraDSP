## 3. 执行偏差与口径注记（与 Q0 定版的差异，逐项登记）

1. **Q1b 扫描源保留**（已登记于计划书 Q0-5 注记）：scanner/paths 因与管理器同 TU 耦合改为保留编入，能力排除改由 ABI 门承担。
2. **telemetry 事件名**：D5 写作「合成同形 pluginSlotStatus 事件」，实现用独立事件名 `apoPluginStatus`——避免与本地句柄的状态轮询回执竞写同一消费点；状态层合并进同一槽状态存储，呈现与语义与 D5 一致。
3. **状态收获通道**：Q2 预留的 base64 命令在 Q3 被 isolate 内收获取代（savePreset→本进程临时文件→发布器），字节全程不出 isolate，攻击面与拷贝都更小。
4. **pluginLiveMeters 注记**：sysapo 槽表头数据由 telemetry 的 inRms/outRms 回填（APO 侧真实值，Q3b 合并）；ModeCaps 中 sysapo 的 false 指「影子/本地链无实时表头来源」这一事实，不屏蔽 telemetry 值。
5. **Q0-8 远端核查项关闭**：宿主命令分发 `Op::GetStatus` 直接转发宿主侧 `getStatusJsonSlot` 原文——远端模式下宿主进程内的 fault 闩锁自动随状态 JSON 回到 App 侧，无需补转发。
6. **PE 纪律**：APO 风味 /MT + /guard:cf 旗标未动；插件子系统新增导入均为 MSVC 默认库的系统 DLL（ole32/oleaut32/uuid/user32/gdi32/shell32/advapi32）。CI 无 dumpbin 导入表审计步骤，本轮未做导入表单列复核——以 J5b 每轮实际加载该 DLL 跑通冒烟为在位证据，此项登记为已知缺口。

## 4. 真机验收清单（用户侧，vm-win10）

1. sysapo 下挂载真实 VST3/CLAP 插件 → 可闻处理效果（此前是静默假象，现应为真处理）；
2. 插件编辑器在 sysapo 下打开（影子实例）、调音、关闭编辑器 → APO 侧状态生效（可闻变化跟随）；
3. sysapo 下插件页无 VB 路线下拉；槽电平表随 telemetry 动；
4. 插件状态 >512KB 的大型插件（少数采样类）关闭编辑器时应出现「状态过大」通知、APO 侧保持旧状态不崩；
5. （可选，难触发）真实插件崩溃时旁路 chip 呼吸闪动、点击重试。
