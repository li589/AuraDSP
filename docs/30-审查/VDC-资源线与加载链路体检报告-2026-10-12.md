## 3. 文件格式规范

**物理形态**：纯文本，UTF-8，无换行要求（实际为单行），无二进制头、无校验和。

```
SR_44100:b0,b1,b2,a1,a2,b0,b1,b2,a1,a2,…,SR_48000:b0,b1,b2,a1,a2,…
```

**解析约定**（`core/android/vendor-src/libjamesdsp/jdsp/Effects/vdc.c:44 DDCParser`）：

1. 必须**同时**存在 `SR_44100` 与 `SR_48000` 两个子串，缺一即返回 0（`:46-49`）。
2. 二阶节数由 **`SR_48000` 段**的逗号数决定：`numCount = countChars(fs48, ',') + 1`，`sosCount = numCount / 5`（`:50-51`）。
   → 由此得约束：**两段数字个数必须一致**，且必须是 5 的整数倍。
3. 每 5 个数为一个二阶节，依次写入 `b0, b1, b2, a1, a2`；`a1` 与 `a2` **取负号**后存入（`:76`、`:79`、`:105`、`:109`），即文件里写的是分母多项式的负系数。
4. 处理链为 `DirectForm2` 转置形式级联，`vdc.c:352 DDCProcess` 对每个采样顺序跑全部节。

**Dart 侧镜像解析**（`app/auradsp_app/lib/core/state.dart:1189 parseVdcMetadata`）：按行扫 `SR_` 前缀，`split(':')` 取采样率与 stage 数，**仅用于卡片展示**（`effects_page.dart:843-851`），不参与 DSP。二者格式理解一致，不存在双真相源。

**第三方兼容**：libjamesdsp 原生语义等同蝰蛇音效（ViPER FX）DDC 文件；l10n 文案已按此表述（`.arb` 中 `ddcNoFile`：「兼容蝰蛇音效 DDC」）。

## 4. 加载链路

```
Dart: _pickVdc → AppModel.loadVdc(path)        effects_page.dart:859 / state.dart:1220
  → setParamStr('ddc.load')                    auradsp_ffi.dart:51
  → 引擎 ddc.load                              auradsp_engine.cpp:1933
      ├ 路径长度 ≤ 4096                        :1935
      ├ read_text_file（UTF-8→宽字符，≤4MiB）   :1945 / 定义 :519
      └ DDCStringParser                        :1948
  → ddc.enable（前置检查 ddcReady）            :1960
```

**返回值语义（易踩）**：`DDCStringParser` 返回 **1=成功 / 0=与当前文件相同跳过 / -1=失败**。
`rc != 0` 判"失败"会把"跳过"误报成错误；`rc < 0` 才是失败（`:1951`）。该坑已记录在 `.ai/memory/MEMORY.md` §高频坑速查。

**使能契约**：加载成功**不自动使能**（`:1957` 注释），且未加载时 `ddc.enable` 直接返回 `AURADSP_E_STATE`（`:1962`）。UI 必须先点「打开」选文件、再拨开关。

## 5. FileGate 现状与偏差

`AGENT.md` §3.1.3 规定「加载 IR 脉冲文件或 VDC 文件必须经由六道门卫校验」。实测两侧并不对称：

| 门卫 | 卷积 IR 路 | **VDC 路** | 证据 |
|---|---|---|---|
| 路径非空 | 有 | 有 | `:1935`（VDC 在 `read_text_file` 内 `:521`） |
| 路径长度限额 | 有 | 有（≤4096） | `:1935` |
| UTF-8 → 宽字符 | 有 | 有 | `:526-533` |
| 文件体积上限 | **有，走 config `gate.maxFileMb`**（兜底 64 MiB） | **硬编码 `4*1024*1024`** | IR `:622-630, :667` / VDC `:1945` |
| 内容合法性（magic / 结构） | dr_flac 解码 + 时长门卫 `gate.maxIrSeconds` | 仅「两段关键字存在」由 parser 兜底 | IR `:749-756` / VDC 依赖 `vdc.c:46-49` |
| 数值健全性（NaN / Inf） | 有（样本级钳位与 Rebuild 校验） | **无** | VDC 链路无对应检查 |

**补充说明，避免误读**：
- VDC 是纯文本，**客观上不存在 magic 头**，因此「无 magic 校验」是格式性质使然，不能按 IR 的二进制标准苛责；真正应补的是结构层的**数字个数合法性**与**数值健全性**。
- 畸形系数的当前行为：`get_doubleVDC` 内 `strtod` 失败时 `get_doubleVDC` 返回 0，`DDCParser` 执行 `startingPoint++` 逐字符继续扫（`vdc.c:86-87`）——即**静默跳过非法字符**，不产生任何错误，最终得到一套错位或残缺的滤波器系数并成功"加载"。这是比"报错失败"更难排查的失败模式。

## 6. 采样率包线（本次新裁决）

**事实**：文件只携带 44.1 kHz 与 48 kHz 两套原生系数。

| 情形 | 行为 | 证据 |
|---|---|---|
| `fs == 44100` | 直接采用 `SR_44100` 段 | `vdc.c:266-271` |
| `fs == 48000` | 直接采用 `SR_48000` 段 | `vdc.c:272-277` |
| 其它采样率 | `PeakingFilterResampler` 重拟合 | `vdc.c:278-286`、`:181` |

**重拟合是有损近似**，不是精确变换：它对每个二阶节算 32768 点对数幅频响应，取幅值极值点反解出 peak 滤波器的增益/中心频率/带宽（`vdc.c:184-226`），再按目标采样率用 `designPeakingFilter` 重新合成（`:228-232`）。相位响应与级联累加误差都不会被保留。

`fs` 的取值还受 ASRC 策略影响（`jdspController.c:1179-1184`）：非整数倍/非整除关系时一律收敛到 48k 或 44.1k 之一，因此实际落到"重拟合"分支的场景比直觉少——但这不能替代文档声明。

**裁决（2026-10-12 用户拍板）**：写明有损，UI 与文档都要标注，不限制启用。
