## 定罪

- **反馈 1**：r46 列表三态把「锁定」做成终态，与 user
  预期相反——user 裁定点叉应回暗勾（可逆）。
- **反馈 2 · VB（代码实证）**：`VmPumpCore::ProcessGroupVm`
  在引擎处理前把总线全声道输入→输出整块透传拷贝，
  scatter 只覆写 procCh 内槽位——设 5.1 时 BL/BR 原始直
  通；gather 与 mode 无关（恒顺序），矩阵折叠在 VB 侧
  根本不存在，三模式同形。
- **反馈 2 · APO（生成器实证）**：`tools/gen_apo_param_layout.py`
  的 EXEMPT 表豁免了 `channels.count`（旧注「几何由音频
  流格式唯一决定」）——**APO 参数块 ABI 根本没有这个槽**
  （Dart/C 双侧索引一致缺席，故镜像门禁全绿），App 发布
  恒落空，r46 宿主的 count 分支是死代码。先前「audiodg
  驻留旧 DLL」主嫌经 user 受控复测（只附加 HD、App 设
  4.0、主页显 4.0、机外实测仍 7.1）撤回。
- **反馈 3**：0x8889000A = AUDCLNT_E_DEVICE_IN_USE（宾机
  Voicemeeter A1 以 WDM 占用同一 HD 端点为主嫌，待验收
  关 Voicemeeter 后自愈与否证实）；桥启动失败是终态——
  失败桥从未进入活动簿记，既有死亡回收网够不着它；且
  错误以原始十六进制码呈现。
- **反馈 4**：引擎在处理入口按原始输入逐声道填
  `stage_peak_ch[12]`（全模式），但 `emit_viz` 对全部自有
  级列统一按 `stage_ch_active`（矩阵模式 =2）门控，stage
  12 的 [2..7] 列恒发 -120；stage 13 矩阵路径从未逐声道
  采集。输入卡读 stage 12、输出卡读全宽 channel_levels，
  故「入不亮出亮」。
