# AuraDSP 内存优化专项记录（2026-10-31）

> 范围：`engine/`（EEL2 gmem、comp 槽位）、`app/auradsp_app/`（可视化渲染、氛围层）
> 方法：WinDbg `!address -summary` / `!heap -s` / `!heap -stat` + GPU 计数器 + 进程 RFC
> 结论：**播放态基线与可视化页峰值均降到 ~1.0GB**；修正前可视化页可达 2.3GB。

---

## 1. 实测对比（同一台机器、同一份会话与 liveprog 脚本）

| 场景 | 修正前 | 修正后 |
|---|---|---|
| 空闲/效果页（播放中） | Private ~1390–1600MB，WS ~876–1035MB | Private **970.6MB**，WS **949.3MB** |
| 可视化页 · 脉动星云 + 歌词 | Private ~2336MB，GPU Local ~1155MB | Private **980.1MB**，GPU Local **342.7MB** |
| 可视化页 · 频谱柱 | Private ~1821MB，GPU Local ~1007MB | Private ~1047MB，GPU Local ~336MB（画笔修正后、槽位收缩前实测） |
| 可视化页 · 赛博网络 | （同量级 2GB+） | Private ~1031MB，GPU Local ~322MB（同上阶段） |
| 9 个空引擎（VB 8 总线 + 1） | 327.7MB | 250.7MB |

> WinDbg 定位：单进程 CRT 堆 1.05GB，其中 9 × 64MB（EEL2 gmem）+ 9 × 24.7MB
> （`JamesDSPLib` 的 comp 槽位）几乎解释了全部超标部分。

## 2. 根因与修复

### 2.1 EEL2 gmem：每 VM 实打实 64MB（P-045）

- 现象：脚本引用 gmem（`x[y]` / tds / IIR 分频）时 `calloc(1<<24 floats)`；
  每次编译还整块 `memset` 64MB（把所有页触碰一遍）。VB 回调 8 总线 + 1 软件
  引擎 = 9 个 VM → **576MB 常驻**。
- 修复：`aura_eel_ram.c` 新增「地址空间保留 + 按页提交」分配器：
  `VirtualAlloc(MEM_RESERVE, PAGE_NOACCESS)` + 预提交 1MB + VEH 首次访问按
  64KB 页提交；编译前清零改为只清已提交前缀（未提交页天然为零）。
  POSIX 继续 `calloc`（本身惰性零页）。
- 验收：`smoke_liveprog_gmem.py` [E] 单句柄 < 60MB（旧 ~89MB）、[F] 8 并发
  gmem 引擎 < 320MB（旧 ~700MB）、[G] 深层 `gmem[3000000]` 页提交读写正确。

### 2.2 comp 槽位 16 → 9（P-046）

- 现象：P-034 的设计是「8 活动 + 1 轮换影子」，宏却写成 `CHANNELS*2=16`。
  每个 `FFTCompander` ~1.5MB → 每引擎白占 ~10.8MB，9 份共 ~97MB。
- 修复：`AURA_COMP_SLOTS = AURA_COMP_CHANNELS + 1`。提交路径本来就在
  「逐声道选非活动槽 → 换指针 → 退休槽安全后复用」，与 9 槽完全兼容。
- 验收：`smoke_b1d_comp_startup`(82)、`smoke_comp_band_order`、
  `smoke_liveprog_race`（RT max 2.49ms < 5ms）、`smoke_chain_meter` 全绿。

### 2.3 可视化逐帧原生分配与帧积压（Dart）

- 现象：`buildVisualizerPainter(time)` 每帧新建画笔 → `Path` / `Paint` /
  `Shader` / `Vertices` 等 Skia 原生对象只能等 GC finalizer 回收；60fps 下
  光栅线程一旦落后，GPU 表面排队，可视化页 Private/GPU 同步涨到 2GB+。
- 修复：
  1. **画笔实例缓存**：视口按「风格/配置/调色板/数据缓冲身份」缓存同一份
     painter，逐帧只更新时间（`VisualizerTimeAware`）。
  2. **数据驱动风格不再逐帧重绘**：频谱柱/示波器/相位仪不挂时间监听，
     只在频谱帧重建时重绘（~20fps）。
  3. **时间轴 30fps**：舞台时间每两帧推进一次；氛围层再独立节流到 ~20fps。
  4. **原生对象复用**：示波器/相位仪/星云/赛博网络的 Path 与列缓冲跨帧复用；
     频谱柱渐变 shader 按尺寸缓存；氛围光晕改为「单位圆 shader + 画布缩放」
     按激活度 8 档缓存；星云粒子色预计算。
  5. 背景氛围 `_AmbientPainter`：整幅离屏图共用一份垂直渐变 shader
     （旧实现 72 根柱 × 每帧新建）；`withPalette` 转移小图所有权，避免换主题
     遗留未 dispose 的 GPU 图。

### 2.4 附带修复

- `visualizer_viewport` 的氛围层缓存键补上数据缓冲身份，避免首次
  `rawBands → renderedBands` 切换后氛围层一直读旧列表。
