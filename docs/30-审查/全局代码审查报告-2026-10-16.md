## 二、发现清单

### M1（中）`build_engine.sh` 在当前工作区不可执行 —— 验证入口可复现性受损

- **实测**：`bash core/desktop/windows/build_engine.sh` 失败：`$'\r': command not found`、`line 20: /c/.../cmake: No such file or directory`、`syntax error: unexpected end of file`。
- **根因拆解**：
  1. 工作区行尾为 CRLF（`git ls-files --eol` → `i/lf w/crlf`：**入库 LF 正常，工作区被本地 `core.autocrlf` 转为 CRLF**），bash 解析空行/续行即报错；
  2. 该 bash 环境 `command -v cmake` 落空，fallback 硬编码路径 `/c/FreeRulesPrograms/...` 执行失败（PowerShell 侧 `where.exe cmake` 能找到同路径 `cmake.exe`，环境 PATH 语义不一致）。
- **影响**：Phase 2 提交信息声称同一命令 `BUILD OK`，当前同一命令失败 → 构建真相源脚本在本机的可复现性已断。**非仓库代码缺陷**（入库侧 LF 干净），但威胁"脚本即真相源"承诺。
- **建议（未执行，待裁定）**：
  1. `.gitattributes` 增补一行 `*.sh text eol=lf`（与该文件自身"仓库内一律 LF"的注释精神一致，且对 `core.autocrlf=true` 机器免疫）；
  2. 脚本 fallback 由 `command -v cmake || echo <硬编码>` 改为多候选探测 + 去 `\r` 容错。
- **本次绕行方式（已验证可用）**：`cmake -S core/desktop/windows -B core/desktop/windows/out -G "Visual Studio 18 2026" -A x64` → `cmake --build ... --config Release`。

### 发现并落实（1 项 HIGH，已修复提交 `81cc180`）

**H1 — 字符串回读副本 OOM 悬垂指针（use-after-free 读）**

- **位置**：`engine/auradsp_engine.cpp` 三处字符串副本写入——`eq.curve`（`free→malloc` 序列）、
  `arbmag.string`、`liveprog.code`。
- **机理**：原写法为 `free(h->xx); h->xx = malloc(bytes+1); if(h->xx){...} else { h->xx_len=0; }`。
  OOM 时旧指针已 `free` 但仍悬垂（非 NULL），且 `lp_code_len` 未清（保持旧长度）。
  后续 `get_param` 侧 `if(!h->xx)` 判空被绕过 → `memcpy(out_value, h->xx, len+1)` **读已释放内存**。
  属失败路径 UAF（仅 OOM 触发，但内存安全红线）。
- **修复**：改为「先生成新副本、成功后再 free 旧指针替换」——OOM 时保留旧副本可安全回读，
  并彻底消除 free-then-malloc 的悬垂窗口。三处统一，注释点明原因。
- **验证**：`smoke_string_readback.py` 5/5 全过；全量 `test/runner.py --smoke` 100%；
  `abi_consistency.py` 47 符号一致（未动 ABI）。提交 `81cc180`。
