# vm-win10 第十八轮：App 退出闪退定罪与修复收口（2026-11-12）

## 现象

user 实测：已装最新版（@09f9a60b，per-user 安装）的 App 在 vm-win10 退出时仍闪退，
一次退出产生两个 dump（`auradsp_app.exe.6184.dmp` 与 `(1)`，2026-11-12 17:06）。
第十轮项 1 就此**第二次重开**：第十轮结构性修复（destroying_ 闩锁 + 撤销
GWLP_USERDATA + move-out reset）与第十二轮 A2 修正均在场，仍崩。

## 取证（guest 内全内存 dump 解析，无 WinDbg）

WER 事件两条同签名：先 `0xc0000005` @ `flutter_windows.dll+0x1e220`，
后 `0xc000041d`（FATAL_USER_CALLBACK_EXCEPTION）同址——异常逃出窗口回调
被系统二次抛出，故一退两 dump。

guest 内置 Python（嵌入式发行版）+ `minidump` 纯 Python 解析包就地解析
500 MB 全内存 dump（解析包经隧道送入；嵌入式 Python 须先给
`python312._pth` 追加路径才认包）。关键事实：

- 异常参数 `[0, 0x10]`：读访问、故障地址 **0x10**，即 `[null + 0x10]` 解引用；
  异常上下文 RCX = 0。
- 崩溃线程（主线程）栈扫描 + 对装机 exe 的 `.pdata` 函数表与反汇编定名：
  `Win32Window::WindowProc` → `FlutterWindow::MessageHandler` →
  `FlutterViewController::HandleTopLevelWindowProc` 包装 → flutter C API →
  内部函数 → 崩点。**MessageHandler 在崩溃链中**。
- MessageHandler 帧内实参区数值集合 `{hwnd=0xD0716, 0x210, wparam=2, lparam=0xC0748}`
  唯一自洽读法：消息 = **WM_PARENTNOTIFY（0x0210）**，wparam 低字 = **WM_DESTROY**，
  lparam = 被销毁的子视图 HWND。

## 定罪

退出时引擎在自身关闭流程中销毁 Flutter 子视图 HWND，父窗口随之收到
`WM_PARENTNOTIFY(WM_DESTROY)`。此刻 `flutter_controller_` 仍完整登记、
`destroying_` 仍为 false（**OnDestroy 尚未运行**），`MessageHandler` 照常把
消息委托给 `HandleTopLevelWindowProc`，而引擎内部视图指针已在销毁中置空，
读 `[null+0x10]` 触发 AV。

此前三轮守卫全部布防在 **OnDestroy 路径**（移空、闩锁、撤销分发关联），
致命投递却**先于 OnDestroy 到达**，故全部落空——这是「修复在场仍崩」的
完整解释，第十轮「微观机理未定罪」至此定罪关闭。

## 修复（`app/auradsp_app/windows/runner/flutter_window.cpp`）

`FlutterWindow::MessageHandler` 在委托前拦截销毁类通知，一律直走基类
并置 `destroying_`：

- `WM_PARENTNOTIFY` 且 `LOWORD(wparam) == WM_DESTROY`（子视图销毁通知，
  引擎自己拆的，无插件语义）；
- 本窗口的 `WM_DESTROY` / `WM_NCDESTROY`（委托它正是让引擎在拆解中自伤
  的入口；控制器的有序拆除由 OnDestroy 的 `controller.reset()` 完成）。

`WM_CLOSE` 不拦截：window_manager 的 preventClose（托盘拦截）依赖它被
委托（第十二轮 A2 口径不动）。OnDestroy 既有闩锁/撤销/move-out 保持不变。

## 验证（开发机构建 + guest 实测）

- 开发机 `flutter build windows --release` RC=0（仅 runner 重编）。
- guest 交互会话实测：修复版 bundle 置于 `C:\Users\li\aurafix18\`，
  临时置 `ui.closeToTray=false`（测后已按备份还原 config/session），
  连续 **5 次启动 → WM_CLOSE 退出：全部干净退出、零新 dump**
  （基线 2 个为 user 17:06 的旧 dump）。旧版同路径 2/2 必崩。
- 遗留验收：托盘菜单「退出」路径与点 X 挂托盘路径请 user 在正式包上
  复核（机制层面同为窗口销毁，已被本修复覆盖）。

## 附带结论（本轮同查的 CI 错误，另行收口）

`feature/linux` 最新 CI 四红实为两因：① J1/J3 同因——资源计划 P4 的
`lib/engine/apo_transit.dart` 在 platform 层外直用 `Process` 跑 icacls，
触 F9/F10 隔离门；② J6/J8 同因——ci.yml 两处 `subosito/flutter-action`
只写 `channel: stable` 未钉版本，CI 装到最新 Flutter（Dart 3.14 已移除
实验 API `Isolate.create`），锁定的 `nativeapi 0.5.10` 编译不过；开发机
与 VM 均为 Flutter 3.47.9 / Dart 3.13.7 故本地恒绿。修复随第十八轮
后续提交处理。
