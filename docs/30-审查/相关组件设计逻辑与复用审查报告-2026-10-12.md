## 一、组件设计逻辑

### 1. 脉冲响应/IR：可变块长 + 容量增长才重建

- `audio_isolate.dart:1153-1184`
  - 每轮按 `min(avail, maxBlock)` 取帧并直接处理；
  - 块长天然抖动，不能要求音频泵输出固定块。
- `auradsp_engine.cpp:1396-1399`
  - 正常入口把超过 `max_block` 的帧数截断；
  - 因此正常运行时不应出现容量增长。
- `jdspController.c:1007-1032`
  - P-009 只在以下情况重建卷积器：
    - 首次初始化；
    - 当前块超过历史容量上限；
  - 容量内的块长变化只更新 `blockSize`，不再重建。
- 设计结论：
  - 正确：分区 FFT 卷积器可以用 FIFO 消化小于容量的任意块。
  - 仍保留直接调用 API 造成容量增长时的重建路径。
  - 残留可规范化点：`blockSize` 仍记录瞬时块长；
    将来在播放中重载 IR 时，分区选择可能读到一个瞬时值，
    而不是稳定的容量值。

### 2. EQ 输出频谱：前级 tap + UI 合成

- `auradsp_engine.cpp:1474-1479`
  - 在 vendor 单体链之前复制 `src`；
  - tap 为只读监听，不改主音频缓冲。
- 双 tap 共享 `compute_bands`：
  - 同一套频带边界、汉宁窗、DC 抑制和归一化；
  - 两路历史窗和 DC 状态相互独立。
- `auradsp_ffi.dart:164-203`
  - Dart `VizFrame` 字段顺序正确新增 `eqInSpectrum`。
- `state.dart:1645-1674`
  - 按 `|Y| = |X|·|H_eq|` 合成 EQ 输出；
  - bypass 时退化为恒等；
  - 响应缺失时退化为输入谱。
- 设计结论：
  - 链路方向正确；
  - 合成数学在 LTI 假设下成立；
  - 但控制参数、响应缓存和采样率权威存在下面记录的多处不一致。

### 3. 氛围频谱：状态与绘制分离，聚焦有效频段

- `AmbientEnvelope`
  - 72 根柱映射被预计算为源频带下标；
  - 80Hz–14kHz 集中使用 25 个源频带，省掉两端 7 个空频带；
  - 衰减与陈旧帧隔离逻辑保持正确。
- `_AmbientPainter`
  - 离屏低分辨率渲染保持约 66ms 节流；
  - 只有静默状态变化时才重新光栅；
  - 画笔、颜色和渐变对象已移出每柱循环。
- 设计结论：
  - 方向正确；
  - 氛围频段与全局 `VizBands` 的 20Hz–20kHz 有意分叉，
    需要把“装饰性聚焦”与“测量性全频段”写成明确契约。

## 三、不一致与细节缺陷

### F0：EQ 架构/插值/Q 控件与引擎断开

位置：

- `state.dart:1433-1441、1489-1492`
- `auradsp_engine.cpp:1768-1786`
- `multimodalEQ.c:155、171-183、198-253`
- `auradsp_engine.cpp:1592-1603、1661、1685-1696`

事实：

- `setEqFilter` 和 `setEqInterp` 只改本地状态并通知 UI，
  不向引擎发送任何参数。
- 生产链固定调用：

```text
MultimodalEqualizerAxisInterpolation(&jdsp, 1, 0, ...)
```

  即 Makima + 最小相位 FIR。

- UI 响应探针调用：

```text
MultimodalEqualizerAxisInterpolation(jd, 1, 1, ...)
```

  即 Makima + 4 阶 IIR。

- `setEqQ` 会重推一条内容相同的曲线：
  - 引擎侧因此重建 EQ 卷积；
  - UI 响应缓存因曲线字符串相同而命中旧值；
  - Q 本身不进入频率/增益锚点。

影响：

- “FIR/IIR6/IIR12”、插值切换和 Q 旋钮看起来可用，
  但生产音频路径不受它们控制；
- 响应探针测的不是生产路径的 FIR 实现；
- Q 拖动可能引入无意义的 EQ 重建开销。

建议未来规范化：

- 要么删除或禁用未接线的控件；
- 要么把架构、插值和 Q 真正编码进曲线/引擎参数；
- 探针必须与生产路径使用同一工作模式。

### F1：实测响应签名未参与失效判断

位置：

- `interactive_eq.dart:579-587、711-730`
- `state.dart:1645-1663、1696-1715`

事实：

- `measuredForCurve` 已传入 painter，但绘制时没有比较；
- 合成函数也没有接收期望签名；
- 曲线更新后约 220ms 内，背景柱仍用旧响应合成；
- 探针失败时，旧响应可能长期残留。

建议未来规范化：

- 合成和绘制统一接收“响应 + 期望签名”；
- 签名不一致时退化为输入谱或本地近似。

### F1：EQ 全局关闭没有进入合成条件

位置：

- `state.dart:131、238、884、1005-1012、1494-1497`
- `interactive_eq.dart:168-179`
- `effects_page.dart:863-873`

事实：

- 合成只看 `model.eqBypass`；
- 全局 `eqOn=false` 时，`eq.enable=0`，但旧响应仍会被叠加到背景柱；
- 面板折叠后该问题不可见，但状态契约仍不一致。

建议未来规范化：

```text
isEqActive = eqOn && !eqBypass
```

并让曲线、背景柱和合成共用该条件。

### F1：采样率权威分散

位置：

- `audio_isolate.dart:266-300、1101`
- `state.dart:1595-1614、1706-1707`
- `interactive_eq.dart:721-730`
- `effects_page.dart:708-714、759-764`
- `state.dart:1751-1758`

事实：

- 引擎实际采样率是协商后的 `wasapi.mix.sampleRate`；
- `config.sampleRate` 可能被设备拒绝而回退；
- EQ 网格、曲线和响应探针使用 `config.sampleRate`；
- 绘制和合成硬编码 `20–20000`，而引擎探针会按 Nyquist 收窄 `f1`；
- IR 提示用硬编码 `48000` 判断是否重采样，但注释自己说应以设备采样率为准；
- 延迟兜底用重采样后的 `convFrames` 除以原始 `convSrcRate`，
  而界面时长用 `deviceRate` 计算。

建议未来规范化：

- 以协商后的实际设备/引擎采样率为唯一权威；
- 配置采样率只作为请求值；
- 响应轴携带实际 `fMax`，而不是两端硬编码。

## 六、附录：EQ 每点 Q 正式接入（归档后落地）

归档后，用户要求把 EQ “正式接入”：每个可调频点自有 Q 值，
并在 UI 上用半透明浮框跟随选中频点（框宽即 Q 带宽）。实现要点：

- 模型新增与网格等长对齐的 `eqQs`；`setEqBandQ`、`applyEqQs`、
  预设/会话 `qs` 字段（旧标量 `q` 按全频带填充兼容）。
- Q 按 RBJ 峰值钟形叠加烘焙进 `eq.curve` 目标增益，
  走既有最小相位 FIR 路径发声；响应探针自动如实测量。
- `eq.curve` 新增可选头 `eqm:<interp>:<op>`，把插值/架构选择
  下发引擎（无头回退 `(1,0)`，旧字符串行为不变）；
  IIR 模式下插值选项置灰禁用（vendor IIR 分支不用插值模式）。
- 选中浮框：`AnimatedPositioned` 跟随选中频点，
  框宽 = Q 带宽换算像素；Q 旋钮改为调节选中频点，无选中时置灰。
- 快照改为深拷贝（浅拷贝曾导致“快照被后续改动污染”的真 bug，
  已用回归测试钉住）。
- 验证：`flutter analyze` 0、`flutter test` 全绿、
  `runner.py --smoke` 100%（含新增的 4 项 `eqm:` 头用例）。
