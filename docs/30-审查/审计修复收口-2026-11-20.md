## 一、AUD-01（P1）：进程外插件 preset 后 PDC 延迟错位 —— 属实，已修

`ProcessPluginProxy::loadPreset()`（`engine/plugins/platform/win32/host/
process_plugin_proxy.cpp`）在 preset 加载成功后只写 `m_latency = latency + 128`，
从不更新 `m_pluginLatency`，也不计当前传输块在途深度。处理路径仅在块数变化
时才以 `m_pluginLatency + chunks×kTransportFrames` 重算总延迟，故 preset 后
上报延迟长期错误，宿主 PDC（`plugin_host_manager` / `plugin_chain_component`）
按错值补偿。核对范围：全仓仅此一处受影响（进程内实例直接存延迟、不经此路）。
修复（`f8dd5196`）：先存 `m_pluginLatency = latency`，再按处理路径同一公式
`latency + m_targetInFlight × kTransportFrames` 写 `m_latency`。
遗留：动态复现（可变延迟测试插件 preset 前后比对宿主上报）未做，证据为
静态核对 + 公式一致性 + 双平台编译通过，登记待补。

## 二、AUD-02（P1）：发布工具 `--clean-work` 可删任意目录 —— 属实，已修

`installer/release.py` 的 `--work-dir` 可任意指定，`--clean-work` 对其直接
`shutil.rmtree(..., ignore_errors=True)`，无归属校验，误传路径可删工作区外
目录。修复（`2f34a8c6`）：新增 `clean_work_dir()`——双路径 resolve 后断言
work_dir 的父目录恰为 out_root 且目录名匹配 `^\.release-r\d+$`，不合即 die
拒删；缺失目录记日志跳过；rmtree 去掉 ignore_errors。新增单测
`installer/tests/test_release_clean_work.py`（纯标准库，10 项：合法清理、
out_root 本身、deliver 形目录、外部同级、嵌套、无点前缀、符号链接逃逸且
目标完好、缺失目录空操作等），并接入 linux-pack 与 windows-installer
两条 CI 工作流。

## 三、V-02：DDC 重采样跳节错位 —— 属实（当前 API 下潜伏），已修（P-050）

`PeakingFilterResampler`（`engine/legacy/jdsp/Effects/vdc.c`）第一循环把
全部节按原下标写入、第二循环却按压缩后的 `0..outSOSCount-1` 读取：中间
节被跳过时，保留集错位（读到被跳节的系数、丢掉尾部保留节）。现行引擎 API
经 ASRC 映射后 `fs` 只落在 {44100, 48000} 或其开区间，节中心 ≤24 kHz 恒
小于 outFs，跳节不可达——属潜伏缺陷，未来低采样率调用方接入即触发，按
静态证明修复：改为「满足保留判据才按 outSOSCount 下标紧凑写入」，判据与
设计公式不变。C 直测判别（`test/smoke/vdc_resampler_test.c`，outFs=22050、
节中心 1000/5000/23000）：修复后保留集 {1000, 5000}；修复前为 {1000, 950}
（23000 节按 22050 设计折叠至约 950 Hz 且 5000 节被丢），与预测签名一致。

## 四、V-03：DDC 解析器三项缺陷 —— 属实，已修（P-051）

`DDCParser` / `get_doubleVDC`（同文件）：① strtod 接受 `nan`/`inf` 字面量
作系数（毒化整条滤波器）；② 两节共用按 48k 节数得的计数且计数扫到串尾，
44.1 节过短时跨节串读、极端时越过结尾 NUL 越界读；③ 计数非 5 的倍数时
尾组写 `df[sosCount]` 堆溢出。修复：`get_doubleVDC` 拒绝非有限值；
`DDCParser` 重写为按节边界严格解析（节范围 = 本节标记后至另一节标记前
或串尾；计数只在本节内数逗号；两节计数必须相等且为 5 的倍数，否则整文件
拒绝），malloc 失败回滚释放。合法文件解析结果与修复前逐值一致。
`engine/legacy/PATCHES.md` 已登记 P-050 / P-051。

## 五、V-04：DDC 文件上限写死 4 MiB —— 属实，已修

`set_ddc_load`（`engine/engine_param_table.h`）把上限硬编码 `4*1024*1024`，
不理 `gate.maxFileMb`（卷积路径早已走 gate 口径）。修复（`b152beb3`）：
`gate_file_bytes()` 上移 `engine/engine_internal.h` 为单一实现（存值 ≤0 时
回退 64 MiB），卷积侧删本地副本改共用；`set_ddc_load` 改用 gate 值并钳到
2 GiB−1（32 位 long 平台防溢出）。因此文件改动使 APO 参数布局摘要漂移，
已按规矩重跑 `tools/gen_apo_param_layout.py` 再生两文件（仅摘要行变化，
参数计数 340 不变）。
