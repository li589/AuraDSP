# 第五十五轮收口：声道适配表统一重构（2026-11-19）

## 起因

r54 验收后 user 问矩阵（下混）模式在声道数 <7.1 时的正常口径，
核对中发现 VAIO 桥 `RemapInterleavedAudio` 的 8→4 折叠主次仍是
r47 修正前旧表（SL/SR 为主），与 APO/VB 定案（BL/BR 为主）漂移。
user 裁定（2026-11-19 12:24）：同表，或做小量重构——把各驱动
（含未来 Linux）的声道配置表单开一个文件统一存放。本轮即该
重构。

## 盘点

全仓手抄声道适配表共四处：APO `ApoEngineHost`、VB
`VmPumpCore`、VAIO 桥 `VaioBridge`+`VaioChannelMap.h`、ASIO 驱
动 `AuraAsioDriver` 的监听下混。引擎核心 `engine_chain` 的
mx_downmix/mx_upmix 是 DSP 链内立体声矩阵级（异层、且本就全
平台共享），不在合并范围。Linux 侧尚无宿主适配层（仅引擎与构
建脚手架），共享头因此放引擎树，供未来 Linux 宿主 include
同一份。Dart `channel_layout.dart` 为 UI 侧，不在原生重构内。

## 实施（`73d2068a`）

新单一真相 `engine/chain/channel_map.h`（与 speaker_layout.h
同目录、平台中立）：

- `chmap_stream_pos`：引擎声道→流内位置表（eng=4：流宽 8→+4、
  6→+2）。
- `chmap_fold_frame`/`chmap_fold`：下混全表（→2 布局驱动 +
  3ch/5.0 显式序、8→6、8→4、6→4 显式、其余回退截断补零；
  LFE 永不入折，折入系数 kChmapFoldK=0.70710678）。
- `chmap_gather_discrete`/`chmap_scatter_discrete`：离散位置
  映射 gather/scatter（scatter 整帧清零后放置，兼作窄→宽扩
  展）。

四宿主全部改为委托，旧表删除：APO 的 StreamPosForCh 删、
FoldGather 留壳委托、离散 gather/scatter 直调 chmap；VB 的
BusChForSlot 与两处折叠 gather 委托；VAIO 的
RemapInterleavedAudio 改为按宽对分发（同宽直通/下混 fold/
上扩 scatter），VaioChannelMap.h 降为委托垫片；ASIO 驱动监听
下混改走 →2 折叠。

随收编纠正两处偏差：

1. **VAIO 矩阵 8→4 主次**改回定案：BL/BR 为主（原量）、
   SL/SR ×0.7071 折入。
2. **ASIO 驱动监听下混错序**（本轮盘点新定罪）：旧手写表按
   位置索引误读声道序——f[3] 实为 LFE 却被折入左声道、
   SL/SR 左右互换、f[7]（BR）从未入折。统一表按标准序折入
   后四者皆正。

数值单测 `channel_map_test`（bridge/common，21 项：位置表/
离散 gather/scatter/下混全表含 8→4 主次哨）取代
vaio_channel_map_test；smoke 改名 smoke_channel_map 并双表登
记；r46/r49 源码契约改守统一表与委托关系；根构建 Step 3b 清
单同步改名。
