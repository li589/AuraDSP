> 来源：业主 2026-11-12 11:20 实测 @b40999cf Setup 覆盖安装失败（错误页裸 PathAccessException errno 32，AuraApo.dll 被占用）+ 指令启动 Part D 后置步「用户配置稀疏保存，要求考虑全面」。代码头 `4bc20505`，验证以开发机为主仲裁。

## 一、向导覆盖安装撞 DLL 占用 — 定罪与修复（`9709bfb1`）

### 定罪

- S0-4 的 `_cleanupApo` 已在动文件前全端点分离，apo_config 内部也重启音频服务——但**服务重启返回 ≠ audiodg 已解除镜像映射**：有音频流在播时 audiodg 排空更慢，分离与写文件之间存在竞态窗口。
- 向导写路径**没有任何占用处理**：备份步裸 `File.copy`、解压步裸 `OutputFileStream`，任一文件被锁即抛裸异常 → 整单失败回滚（业主照片）。`_cleanupApo` 注释里「文件步对锁定文件有重试 + 具名报告」一句与代码不符（该重试只存在于卸载的退出后清理脚本），本轮一并改正注释。

### 修复（四层纵深，任一层失效不整单陪葬）

1. **等锁释放**（install 覆盖路径 step 1.6 + uninstall 同步接入）：分离后以 append 打开探针轮询 `driver\AuraApo.dll`/`auradsp_engine_apo.dll`（≤8s）；仍锁且已提权 → 向导显式重启 Audiosrv（等 STOPPED 后 start）再等 ≤8s；仍锁只记警告，靠第 3 层兜底。
2. **备份降级**：备份单文件拷贝加短重试；最终失败登记 `backupFailed` 并具名警告，不再整单失败；回滚时该文件保留新版而非删成缺失（恢复不了旧版时，留新版严格优于留空洞）。
3. **写路径让位**（payload.dart）：条目写入遇 errno 32/33 → 短重试 3 次 → 把旧文件**改名让位**（`.aside-<毫秒>`，镜像映射可改名不可覆盖）→ 写新文件并警告报告；让位文件在后续安装/卸载启动时扫除。非占用错误仍立即抛出。
4. **错误人话化**：install 顶层 catch 对 FileSystemException 输出「文件被其他进程占用或无法访问：<路径>。请关闭正在播放音频的程序、退出 AuraDSP 后重试。（技术详情……）」，不再裸抛异常类名。

## 二、用户配置稀疏保存 — 全面设计与实施（`46b6a588`，电池修正 `4bc20505`）

### 语义与基线

- `ConfigManager.save()` 改为稀疏落盘：用户档只写与**基线**不同的键。基线 = load 时垫在用户档之下的同一张表——默认层在场用默认层（发行口径可与代码默认不同），缺失时用代码默认（进程内缓存一次 `AppConfig().toJson()`）。核心收益不是文件体积，而是默认层随版本升级时，**未被用户改过的键自动跟随新默认**（全量落盘会把旧默认冻进用户档永久盖住）。
- 纯函数 `DefaultsLayer.sparseDiff(baseline, full, {forceKeep})` 与 `deepMergeUnder` 严格对偶：相等子树整棵省略；双 Map 逐键递归；List/标量/类型翻转整值收录（合并对 List 是整体替换）；仅 full 有的键整值收录。

### 全面考虑清单（设计时逐项过的坑）

1. **version 必须强制落盘**：load 的迁移判定读**用户原始档**的 version（防默认层顶版）。若 version 与默认同值被稀疏，旧档会被误判远古档**重复执行迁移**——v4 的 asioOutPair 换算二次执行即数据损坏。故 `forceKeep: {'version'}`，全默认用户的 config.json 就是 `{"version": 4}` 一行。
2. **迁移期保存自洽**：load 内 v<3/v<4 迁移调用的 save() 同样走稀疏路径，基线一致、无特殊分支。
3. **基线可达性不变量**：sparseDiff 的前提是 full 为 load 可产生的有效配置（每层 Map 键集 ⊇ 基线）。AppConfig.toJson 恒全量发键、默认层由 toJson 生成型导出，该不变量构造上成立；合并语义无法表达「删除基线键」，此类状态本不可达——电池首跑曾因测试自造模式外键（顶层 themeId，真键位在 ui 节内）触发该边界，诊断证伪后改用真实键位（见下）。
4. **显式设成与默认同值 ≡ 未改**：稀疏语义本体，不可区分也无须区分（与 VS Code settings 同口径）；将来默认变更时该键跟随新默认，属预期行为，文档明示。
5. **旧全量档兼容**：load 路径不变（合并对冗余键幂等），旧档照读；下一次保存自动变稀疏。resetToDefaults 即写出仅 version 的最小档，语义恰为「全部跟随默认」。
6. **范围外（明示不做）**：预设文件是可独立分发的完整参数快照，不稀疏化；session_state.json 是运行时状态而非配置，不参与分层。
7. **num 等值口径**：基线经 JSON 解码可能出现 int/double 形态差异，深相等按数值比（1 ≡ 1.0），避免形态差异造成假落盘。

### 等价性回归电池（`test/config_sparse_save_test.dart`）

- 纯函数规则 6 例（嵌套剪枝、List 整表、类型翻转、null 语义、num 形态等）；
- 往返电池：两类基线（代码默认 / 模拟发行层）× 四类状态（纯基线、单节标量、列表与字符串、大杂烩），每例断言 `merge(baseline, sparse(full)) ≡ full` 且 `fromJson` 往返恒等、version 在盘；
- 落盘集成 3 例（默认档只剩 version、改过的键按节最小落盘、旧全量档可读且再存变稀疏）。
- 首跑两红均属测试自身：断言键位写错层（themeId 在 ui 节内）+ 发行层基线注入模式外键。用只读诊断用例打出叶子级 diff 后定罪修正，sparseDiff 本体未动。
