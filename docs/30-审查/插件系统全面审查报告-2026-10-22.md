## 2. 代码逻辑缺陷详录

### A1（中）VB 下 -1 路预设 save/load 不对称 → 重挂跨路由污染

**现象**：VB 模式下挂插件、只编辑路由 0 与路由 3，卸载后重挂（或切换驱动模式
触发引擎重建）——路由 1/2/4-7 获得路由 0 的参数与 Ch 选择，而非保持出厂态。

**根因链**（跨三层语义核对实锤）：
1. `unloadPlugin` / `onAudioModeSwitching` 在 VB 下也执行 `autoSaveAb(group:-1)`
   （编辑器关闭后 `_editorRoute` 已重置 -1，卸载前兜底存「当前状态」）；
2. isolate `pluginSlotSavePresetG` 的 group<0 回落 `pb.savePreset` →
   `vb_plugin_slot_save_preset` → `PluginEngine()` = **eng[0] 单发**；
3. 重挂时 `_restoreAbAfterLoad` 恒含 route -1 → isolate `pluginSlotLoadPresetG`
   的 group<0 回落 `pb.loadPreset` → `vb_plugin_slot_load_preset` →
   **全组扇出**（n 个引擎逐个 loadPreset）；随后的 `setSlotChannels(group:-1)`
   同样经 `vb_plugin_slot_set_channels` **全组扇出**；
4. per-route 预设随后逐路覆盖——有自己预设的路正确，**没有自己预设的路**残留
   eng[0] 状态。每次卸载把污染固化一次。

save 单发 vs load 扇出的不对称是本缺陷的核心；v3.3 撤除「全部」后，-1 路在 VB
下不再是合法路，两条回落路径都成了语义孤儿。

**修复**（audio_isolate.dart）：`pluginSlotSavePresetG` / `pluginSlotLoadPresetG` /
`pluginSlotSetChannels` 三个 case，当 `pb != null && group < 0` 时——
桥支持 `_g` 导出（`hasPresetG` / `hasSetChannelsG`，VB 新桥为真）走**单组 0**
语义（`savePresetG(slot,0,…)` / `loadPresetG(slot,0,…)` / `setChannelsG(slot,0,…)`），
与 save 侧对称、无扇出；老桥（无 `_g`，ASIO/VAIO 单引擎桥亦然）保持原回落，
行为不变。配套 `BridgePluginFfi` 新增两个能力 getter。

**残余语义**（记档 C6）：VB 下 -1 路预设仍会被写（= eng[0] 备份，内容与 route 0
预设重复），还原时单组 0 载入——不再污染其它组，属可接受冗余。

### A2（中）非 VB 轮询解锁不落盘

**现象**：ASIO/VAIO/WASAPI 单引擎模式下，用户打开插件界面调音，点**插件自带的
关闭按钮**（而非宿主「关闭界面」）——status 轮询检测到编辑器关闭，但该次调音
不落盘；之后卸载/切模式重挂，调音丢失。

**根因**：`onSlotEditorOpenPolled` 的落盘分支被 `if (_editorRoute[slot] >= 0)`
包裹——只覆盖 VB 各路（group>=0）；非 VB 单路（group=-1）被跳过。而 close
回执路径 `onPluginSlotEditorResult` 的口径是 `r >= 0 ? r : -1`（含 -1）——
两条解锁路径口径不一致（v3.3 修 VB 侧时漏了非 VB 侧）。

**修复**：轮询路径与 close 回执同口径——`autoSaveAb(slot, group: r >= 0 ? r : -1)`
+ 重置 `_editorRoute`。双路径不会双写：close 回执先把 `_slotEditorOpen` 置 false，
轮询的 `!= open` 守卫随之短路。

### A3（中）模式切换时开着的编辑器若从未落盘 → 调音丢失

**现象**：新挂插件 → 打开界面调音 → **不关界面**直接切驱动模式——该路调音随
引擎重建丢失（旧实现只存 -1 路与「meta 里已有记录的路」，新开未存的路不在列）。

**修复**：`onAudioModeSwitching` 循环内增加 `if (_editorRoute[s] >= 0)
autoSaveAb(s, group: _editorRoute[s]);`——开过的路必存（autoSaveAb 幂等）。

### A4（低）setChannels 回执不携带 group，污染 -1 路 Ch 记忆

**根因**：`onPluginSlotChannels(slot, mask, rc)` 无路由信息，恒写
`_slotChannels[slot]`（-1 路记忆）。VB 下任一路的 Ch 回执都覆写 -1 路记忆，
而 `autoSaveAb(group:-1)` 的 chMask 快照读的正是它。

**修复**：isolate `pluginSlotChannels` 事件增加 `group` 字段 → state 转发 →
manager 按 group 分流（`>=0 → _routeChannels[s][g]`，else `_slotChannels[s]`），
与 `setSlotChannels` 的乐观写入归一位一致。rc != 1 仍不改写。

## 3. UI 显示遗漏与卫生

### A5（低）VB 无有效路时 A/B 条与 Ch strip 仍可操作

**现象**：VB 下把某组「通道处理开关」或「插件复选框」全部关掉（routeMask==0）——
路由下拉正确禁用并显示「旁路」提示，但 Hero 卡下方 **A/B 预设条与 Ch strip 仍
以 group=-1 存活**：A/B 点击会对 -1 路（eng[0]）切预设，Ch strip 改动经
set_channels 落到单组 0——与「无可操作路」的展示自相矛盾。冷启动进 VB 未选路时
（`vbPluginEditorGroup` 还是 -2 哨兵）同样落入此态。

**修复**（双管）：
1. plugins_hero.dart：`noRoute = isVb && openGroup < 0` 折进 `locked`——
   A/B 条全禁 + Ch strip 全灰（chInteractive 置 0）；「打开界面」按钮原有
   `openGroup < 0` 禁用不变。
2. state.dart：`vbstatus` 上升沿（进桥成功）调 `_fallbackVbPluginEditorGroup()`
   ——自动落最低有效路，压缩无路态窗口（用户显式全关的路由仍保持禁用态，
   由 1 兜底诚实展示）。

### A6（卫生）state.dart 两方法零缩进

`setVbPluginEditorGroup` / `_fallbackVbPluginEditorGroup` 曾以零缩进写在类内
（Dart 不在意缩进故能编译，dart format 漏网）。本轮 `dart format` 归位，
diff 仅涉目标两处。

## 5. 操作冲突矩阵核查结论

对全部会触达插件实例的操作两两组合核对守卫覆盖（busy 全锁 / locked 路由锁 /
per-slot 忙态 / 引擎侧拒绝 / 轮询兜底五道防线）：

| 组合 | 守卫 | 结论 |
|------|------|------|
| 加载中再加载（同槽） | `_slotBusy` 前置拦截 + UI 禁用 | 覆盖 |
| 加载中卸载（同槽） | 同上 | 覆盖 |
| 卸载中加载（同槽） | 同上 | 覆盖 |
| 卸载宽限 150ms 内切路由 | busy 不禁路由（刻意：可先看各路）→ autoSaveAb 落旧实例后卸载 | 无害（C5 记档） |
| 编辑器开着切路由 / A/B / Ch / 复原 | locked（事件 + 轮询双通道）全禁 | 覆盖 |
| 编辑器开着重复点「打开界面」 | 引擎 showEditor 幂等（VST3/CLAP 均已开→前置窗口返回 true） | 无害 |
| 编辑器开着卸载 | busy 锁禁卸载按钮；onAudioModeSwitching/unload 均先 autoSaveAb | 覆盖 |
| 模式切换中加载 | onAudioModeSwitching 收尾落盘 + 引擎重建后 mirror 回放 | 覆盖 |
| 多槽并发加载大插件 | per-slot busy + isolate 串行 + 桥线程 BELOW_NORMAL + scratch VirtualLock | 覆盖（既有措施） |
| 无有效路时打开界面 / A/B / Ch | A5 修复后全禁 | 覆盖（本轮补齐） |
| A/B 切换中（inherit 复制）编辑器状态 | UI locked 禁；Dart 层无锁（C3 记档，风险低） | 记档 |
| 复原进行中切槽 | per-slot 状态互不影响 | 覆盖 |
| 加载失败后重试 | busy 终态清除 + _lastError 可见 + 不兼容前置拦截 | 覆盖 |
| 32 位/损坏插件加载 | Dart+引擎双保险 + 精确 errorMessage | 覆盖 |
| 崩溃隔离插件打开 | notice 提示 + close teardown 隔离（不阻止） | 覆盖 |
| 最小化时轮询暂停/恢复 | WidgetsBindingObserver 生命周期 | 覆盖 |

**矩阵结论：无新增缺陷；A5 为矩阵中唯一实际漏洞（已修）。**

## 6. 测试基建发现：S1 smoke 假绿（本轮订正）

**现象**：本轮刷新 `test/` 部署点（桥 + 引擎 DLL 同步到当日构建）后重跑
`smoke_vm_bridge`，唯一 FAIL 项 = `editor_g empty slot close==0 (rc=1)`。

**根因**（跨两层核对）：
- 引擎 ABI 契约：`auradsp_plugin_slot_close_editor` 对**合法槽恒返回 1**
  （`closeEditorSlot` 空槽 = 幂等空成功，仅 slot 越界返 0）——自 P3 起未变；
- 此前该项"通过"，是因为 `test/auradsp_engine.dll` 停留在 10-20 旧构建，
  桥加载后插件 ABI 未解析（`Fns::Ready()==false`），所有 editor_g 调用
  都从 `!Ready()` 守卫返 0——show/is_open/close 三项断言全部空转，构成
  **假绿**；bypass 等项的 rc=0 期望值同样被该守卫"喂饱"。

**订正**：断言改为契约口径 `close==1`，并在注释中明示其双重身份——
「空槽 close 幂等成功」+「桥-引擎插件 ABI 已解析」的活性探针。刷新
test/ 部署点后复跑全绿（该项 rc=1 实锤 ABI 活着）。

**教训**：冒烟断言"通过"必须区分「契约命中」与「守卫短路」——当被测路径
存在多层前置守卫（!running / !Ready / !e）时，期望值要能穿透守卫触达
真实契约，否则旧部署点会周期性制造假绿。test/ 目录 DLL 与构建产物的
同步列为每轮部署检查项（本轮已补同步：桥 19:07 + 引擎 18:34）。

## 7. 记档待办（本轮不修）

- **C1 老桥 DLL 回落静默错组**：VB 桥缺 `_g` 导出时（部署陈旧），`savePresetG`
  回落 eng[0]、editor `_g` 回落单路——per-route 预设与编辑器路由静默错位。
  建议后续：桥 start 时若 `prefix==vb && _savePresetG==null`，Dart 侧弹一次
  「桥 DLL 过旧」notice。属二进制陈旧场景，dist/runner 双部署同步后不可达。
- **C2 遥测行重复**：Hero 卡内 `in/out/Δmax/calls/remote` 行与
  `proc/in/out/Δ` 行信息重叠，建议合并为一行（UI 精简，下轮处理）。
- **C3 selectAb/resetAb 无 Dart 层 locked 守卫**：当前仅 UI 层禁用；建议后续
  在 manager 入口加 `_slotEditorOpen` 断言（纵深防御）。
- **C4 showEditor 失败后 `_editorRoute` 残留**：失败回执不清路由，陈旧值会
  被下次 show/unload 前的 autoSaveAb 用到——保存的是该组真实状态，无害；
  建议失败回执也重置 -1。
- **C5 卸载宽限内切路由**：向即将销毁的旧实例 autoSaveAb——语义正确（存的
  // 就是旧实例最后状态），无需处理。
- **C6 VB -1 路预设冗余**：A1 修复后 -1 路 = eng[0] 备份，与 route 0 预设
  内容重复；更彻底的方案是 VB 下完全跳过 -1 路（需 manager 获知 VB 态），
  留待后续。
