## 1. 背景与核心目标

AuraDSP 目前基于用户态 WASAPI Loopback 环回与独占音频泵运行。尽管在常规桌面音乐重放上表现优秀，但在系统级全局接管、极低延迟专业监听、跨应用音频路由及话筒/游戏分流等场景下，存在以下根本性受限：
1. **无法原生暴露为多设备端点**：无法像独立物理声卡那样让第三方软件（如播放器、语音软件、游戏、DAW）分别选择不同的虚拟输入与输出通道；
2. **延迟受限于 Windows 共享混音器**：WASAPI 共享模式最小缓冲通常在 10ms~20ms，无法胜任专业乐器监听与电竞超低延迟需求；
3. **缺乏底层驱动接管通道**：无法像 EqualizerAPO、Voicemeeter 或 ASIO 驱动一样，在音频到达硬件之前进行全局第一道或最后一道隐形无损处理。

本方案旨在设计一套**Windows 通用底层驱动与音频中间件套件**，构建**四套完全解耦、互为补充的工作模式**，并为未来 Android 等其他平台的拓展提供清晰的架构分层。

### 模式 1：虚拟声卡驱动模式 (Virtual Audio Device / AuraVAIO)

#### 1.1 业务拓扑与数据流向
虚拟驱动模式允许在 Windows 设备管理器中注册一组虚拟物理声卡端点。
- **虚拟播放端点 (Virtual Playback Endpoints - 系统输出，AuraDSP 的输入)**：
  - `AuraVAIO-VA1 (Line In 1 / Main)`：系统默认输出，接收音乐、浏览器声音；
  - `AuraVAIO-VA2 (Line In 2 / Aux)`：辅助音频流，用于游戏音效或播放器分流；
  - 每个端点均支持最高 **7.1 声道（8 通道，32-bit float / 24-bit PCM，44.1k/48k/96k/192kHz）**。
- **虚拟采集端点 (Virtual Recording Endpoints - 系统输入，AuraDSP 的输出)**：
  - `AuraVAIO-Out1 (Line Out 1)`：经过 AuraDSP 调音后的全局音频流（可供 OBS 录制）；
  - `AuraVAIO-Mic (Processed Mic)`：经过 AuraDSP 降噪、门控、电子管话放处理后的话筒声音，供 Discord/腾讯会议/游戏当作真实麦克风使用。

#### 1.2 内核驱动架构选型：KMDF + PortCls WaveRT
针对 Windows 7 至 Windows 11 的通用性要求，驱动采用微软标准 **WaveRT (Wave Real-Time)** 迷你端口架构构建：
1. **微端口对象 (`IMiniportWaveRT`)**：
   - 彻底摒弃已淘汰的 WaveCyclic 与 WavePci 模式；
   - WaveRT 原生支持事件驱动型缓冲区通知 (`IMiniportWaveRTStreamNotification`)，允许应用程序在缓冲区半满/全满时被直接通知，将缓冲区延迟降至 1~3ms。
2. **高精度虚拟时钟模拟器 (Virtual Drift-Free Clock)**：
   - 虚拟驱动没有物理晶振中断，必须自己推进采样时钟。
   - 实现方案：在内核驱动中使用 `KeSetTimerEx` 配合微秒级高性能计数器 (`KeQueryPerformanceCounter`)，维持一个高精度递增累加器：
     $$\text{Position} = \left(\frac{\Delta t \times \text{SampleRate}}{10^7}\right) \times \text{BlockAlign} \pmod{\text{BufferSize}}$$
   - 在 `GetPosition()` 与 `GetClockRegister()` 中准确汇报播放头位置，**彻底防止时钟抖动引发爆音或音画不同步**。
3. **零拷贝跨环共享内存 (Zero-Copy Inter-Ring IPC)**：
   - 内核在驱动初始化时分配固定非分页物理内存池 (`MmAllocatePagesForMdlEx`)；
   - 驱动通过 IOCTL `IOCTL_AURAVAIO_MAP_SHARED_RING` 将该内存映射至用户态服务空间 (`MmMapLockedPagesSpecifyCache`，用户态拥有只读/读写权限)；
   - 用户态 AuraDSP 引擎与内核驱动之间通过**无锁 SPSC (单生产者单消费者) 环形缓冲区**直接交换原始浮点 PCM 数据，**CPU 零拷贝，上下文切换开销趋近于零**。

#### 1.3 7.1 环绕声与扬声器掩码配置（前瞻设计；现状见注）
> **现状注**：当前引擎多声道为 ADR-003 Phase A（矩阵包络，LFE 直通），**不是**
> 下述逐声道实例化；“8 通道下 3D 串扰/环绕自动激活”尚未实现，Phase B 才评估。
> 以下掩码设计在驱动实施时仍有效，前提是引擎先完成 Phase B。
在驱动的 `KSDATARANGE_AUDIO` 与 `WAVEFORMATEXTENSIBLE` 规范中声明完整的通道掩码：
- 2.0 声道：`KSAUDIO_SPEAKER_STEREO` (`0x00000003`)
- 5.1 声道：`KSAUDIO_SPEAKER_5POINT1_SURROUND` (`0x0000003F`)
- 7.1 声道：`KSAUDIO_SPEAKER_7POINT1_SURROUND` (`0x000000FF`)
支持动态格式协商，第三方播放器切换为 7.1 电影音轨时，驱动无缝扩展通道拓扑，AuraDSP 内部的 3D 串扰消除与环绕声自动按 8 通道模式激活。

### 模式 2：Voicemeeter VB-Callback 模式 (深度对接与自省)

#### 2.1 彻底根治 EqualizerAPO 识别版本脆弱的历史硬伤
EqualizerAPO 的经典设计缺陷在于：在配置工具中通过分析安装包名称（`voicemeeterprosetup.exe` / `voicemeeter8setup.exe`）来判断当前版本，这极度脆弱。

AuraDSP 设计了**三级精准自省状态机 (Three-Tier Introspection Engine)**：

```
[步骤 1: 注册表安全寻址]
  - 检索 HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall\VB:Voicemeeter {17359A74-1236-5467}
  - 及 32位重定向键 Wow6432Node
  - 读取 InstallDir / UninstallString 并提取官方安装基目录

[步骤 2: 动态原生 API 自省 (主轨道，100% 准确)]
  - 动态载入 VoicemeeterRemote64.dll (32位则为 VoicemeeterRemote.dll)
  - VBVMR_Login() 登录 API
  - 调用 VBVMR_GetVoicemeeterType(&vmType)
      1 -> Voicemeeter Standard (物理输入*2, 虚拟输入*1, 物理输出*2, 虚拟输出*1)
      2 -> Voicemeeter Banana   (物理输入*3, 虚拟输入*2, 物理输出*3, 虚拟输出*2)
      3 -> Voicemeeter Potato   (物理输入*5, 虚拟输入*3, 物理输出*5, 虚拟输出*3)
  - 调用 VBVMR_GetVoicemeeterVersion(&vmVersion)
      提取高低 16 位，格式化为真实内部构建版本号 (如 v3.1.8.2)

[步骤 3: 二进制 PE 版本元数据自省 (备选静态校验)]
  - 若 Voicemeeter 服务未启动导致 API 超时，直接对主目录二进制文件进行 PE 自检：
      Voicemeeter8.exe   -> Potato
      VoicemeeterPro.exe -> Banana
      Voicemeeter.exe    -> Standard
  - 解析 VS_FIXEDFILEINFO 结构体中的 FileVersionMS / FileVersionLS，获取底层真实签名
```

#### 2.2 回调流处理与 8 通道平铺浮点转换（前瞻设计；现状见注）
> **现状注**：①“AVX2/SSE2 优化”修正——当前引擎为标量 DF2T 处理，
> 仅用 `xmmintrin` 做 FTZ/DAZ，无 SIMD 处理 intrinsics；
> ②“独立每总线 DSP 配置下发”修正——当前为 Phase A 矩阵（M→2 进链），
> 不存在逐总线 DSP 实例，对接时只能下发统一链配置。
- 注册输出插入点：`VBVMR_AudioCallbackRegister(VBVMR_AUDIOCALLBACK_OUT, AuraVBCallback, pContext, "AuraDSP")`；
- Voicemeeter 提供的是**平铺多声道浮点数组 (Planar Float Arrays)**：
  - `audiobuffer_r[ch][sample]`，每个通道对应独立一维 float 数组；
- **SIMD 批量转换与通道映射**：
  - AuraDSP 内部支持 AVX2 / SSE2 优化将 Planar 浮点流直接交织或分发给 16 Stage DSP 链；
  - 支持对 Banana 的 A1~A3、Potato 的 A1~A5 进行**独立每总线 DSP 配置下发**。
- **智能静音空转检测 (Silent Bypass)**：
  - 维护静音帧计数器 `m_silentFrames`；
  - 当连续 2 秒所有通道输入均低于 $-96\text{ dBFS}$（$|x| < 10^{-5}$）时，自动转入空转待机状态，直接做指针透传（Bypass memcpy），**CPU 消耗归零**。

### 模式 3：Windows 原生 APO 模式 (Audio Processing Object)

#### 3.1 彻底解决“假装处理（UI 显示生效但实际无声音变化）”的四大根因

很多用户在 Windows 下使用 EqualizerAPO、ViPER4Windows 时，经常遇到“软件界面显示开启、滑块能拖动，但声音根本没有任何音效”的致命痛点。本方案针对底层机理实施精确打击：

```
+-------------------+-----------------------------------+---------------------------------+
```

#### 3.2 Win7 sAPO 与 Win10/11 APO 2.0 的统一兼容架构
Windows 7 与 Windows 10/11 的 APO 架构存在代际割裂：
- **Windows 7 / 8.1 目标 (sAPO)**：
  - 注册接口：`IAudioProcessingObject`、`IAudioProcessingObjectRT`、`IAudioProcessingObjectConfiguration`；
  - 拓扑挂载：注册为 **LFX (Local Effects)** 或 **GFX (Global Effects)**；
  - 注册表路径：
    `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\MMDevices\Audio\Render\{EndpointID}\FxProperties`
    - `{d04e05a5-593b-4d4c-b109-b16f219c795c},0` (PKEY_AudioEndpoint_LocalEffectsCLSID)
    - `{d04e05a5-593b-4d4c-b109-b16f219c795c},1` (PKEY_AudioEndpoint_GlobalEffectsCLSID)
- **Windows 10 / 11 目标 (APO 2.0 / DCHU 模式)**：
  - 升级为三级分层：**SFX (Stream Effects)**、**MFX (Mode Effects)**、**EFX (Endpoint Effects)**；
  - 注册表路径：
    - `{d3993a3f-99ac-42d4-a823-4903332c32f4},5` (PKEY_FX_StreamEffectClsid)
    - `{d3993a3f-99ac-42d4-a823-4903332c32f4},6` (PKEY_FX_ModeEffectClsid)
    - `{d3993a3f-99ac-42d4-a823-4903332c32f4},7` (PKEY_FX_EndpointEffectClsid)
- **AuraApoConfigurator 自动化安装工具**：
  - 采用 C++ 原生实现，自动调用 `RtlGetVersion` 检测当前宿主内核版本；
  - Win7 下自动写入 LFX/GFX 映射，Win10/Win11 下自动写入 SFX/MFX/EFX 现代映射；
  - 具备**原子备份与一键自愈 (Restore to Default)** 能力：安装前对原始驱动注册表进行镜像快照，若系统音频服务崩溃或发生冲突，可在安全模式或一键恢复按钮下瞬间复原声卡原始状态，绝不损坏系统音频。

### 模式 4：ASIO 驱动与超低延迟模式

#### 4.1 双向架构：ASIO Host 与 Virtual ASIO Driver
ASIO（Audio Stream Input/Output）是专业音频领域的工业标准。AuraDSP 在 Windows 下提供**双向全功能支持**：

1. **AuraDSP 作为 ASIO Host (接管物理专业声卡)**：
   - 目标：专业音频制作人、高端外置声卡用户（RME, Universal Audio, Focusrite, Moto 等）；
   - 实现：集成 Steinberg ASIO SDK 2.3 宿主规范；
   - 性能指标：直接对接硬件声卡官方 ASIO 驱动，绕过 Windows 系统所有中间层，在 **96kHz / 64 samples** 条件下实现端到端硬件延迟 **$< 3.0\text{ ms}$**；
   - 线程调度：调用 Windows 多媒体类计划程序服务 (MMCSS)，将音频泵线程注册为 `Pro Audio` 特性 (`AvSetMmThreadCharacteristicsW(L"Pro Audio", &taskIndex)`)，享有与硬件中断同级的调度优先级，杜绝爆音。

2. **AuraDSP 作为虚拟 ASIO 驱动 (供专业宿主 DAW / 播放器调用)**：
   - 目标：Cubase、Studio One、Reaper、Ableton Live、FL Studio 以及 Foobar2000 (ASIO 输出插件)；
   - 实现：实现符合 ASIO COM 接口规范的 `AuraAsioDriver.dll`：
     - 在注册表 `HKLM\SOFTWARE\ASIO\AuraDSP ASIO Driver` 注册；
     - 导出标准 COM 类对象，实现 `IASIO` 接口：
       ```cpp
       class AuraAsioCom : public IASIO {
           ASIOBool init(void* sysHandle) override;
           void getDriverName(char* name) override; // "AuraDSP ASIO Driver"
           long getDriverVersion() override;
           ASIOError getChannels(long* numInputChannels, long* numOutputChannels) override;
           ASIOError getBufferSize(long* minSize, long* maxSize, long* preferredSize, long* granularity) override;
           ASIOError getSampleRate(ASIOSampleRate* sampleRate) override;
           ASIOError createBuffers(ASIOBufferInfo* bufferInfos, long numChannels, long bufferSize, ASIOCallbacks* callbacks) override;
           ASIOError start() override;
           ASIOError stop() override;
           // ...
       };
       ```
   - 数据通路：DAW 启动时加载该 DLL，DAW 输出的极低延迟音频流直接泵入 AuraDSP 核心处理引擎，处理完成后再由 AuraDSP 路由至当前选定的物理输出设备。

## 3. 跨平台目录树与工程解耦方案

Windows 底层驱动套件是一个极其专业且独立的体系（包含内核驱动 SYS、INF、APO COM DLL、Voicemeeter Client、ASIO COM DLL 及配置安装工具），必须与核心 DSP 算法及其他操作系统（如 Android）保持严格的解耦与清晰的物理边界。

### 3.1 目录树布局设计

```
AuraDSP/
├── engine/                              # [★ P3a 上移] 核心 DSP 引擎（原 core/desktop/engine_api）
│   ├── auradsp_engine.h/.cpp/.def       #   C ABI 契约 —— 驱动层唯一入口
```

### 3.2 跨平台隔离与核心算法复用契约
1. **算法单点真相源**：
   无论是哪种模式（AuraVAIO、Voicemeeter、APO、ASIO），捕获到的原始 PCM 音频帧最终均进入同一个 `AuraEngine`（**P3a 后位于 `engine/`，原 `core/desktop/engine_api/`**）；驱动层**只做传输与格式搬运，不承载任何具体音效算法**。
2. **纯粹解耦**：
   `core/desktop/windows-drivers/`（注意不是 `core/windows-drivers/`）下的代码
   完全不包含任何 Android、Linux 相关代码，仅依赖 Windows SDK / WDK；Android 端的
   开发与日常构建完全不受此目录影响，保证极速构建与零污染。

## 5. 总结

本方案不仅完整覆盖了用户提出的四套核心模式，更从底层原理层面彻底攻克了传统软件的痛点：
- **终结 Voicemeeter 识别脆弱性**：采用动态 API 探测 + PE 二进制自检的三级自省体系，彻底摒弃安装包名称猜测；
- **终结 APO“假装处理”**：采用全格式宽容协商（`PreferredFormatSupport`）+ 沙箱穿透 DACL + 双向原子心跳探针，构建绝对真实的生效闭环；
- **内核级多通道虚拟化**：采用基于 WaveRT 现代架构的虚拟驱动，全系兼容 Windows 7 至 Windows 11；
- **目录物理隔离**：建立独立的 `core/desktop/windows-drivers/` 子系统（未建），实现了专业 Windows 系统级音频基础设施与跨平台核心引擎的完美平衡。
