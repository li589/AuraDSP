## 1. 品牌与命名体系

| 名称 | 层级 | 说明 |
|---|---|---|
| **AuraDSP** | 项目 + 应用总品牌 | 所有平台的应用统一叫 **AuraDSP**（手机 / PC 同名，用户只认一个名字） |
| **AuraDSP Engines** | 引擎族总称 | 底层适配硬件与系统的驱动 + DSP 算法等核心组件的统称 |
| **AuraDSP Engines (Root)** | Android 引擎形态一 | KSU/Magisk 模块，AIDL effects HAL 注入，**系统级全局**。模块 id 保持 `auradsp_jdsp`，显示名 `AuraDSP Engines (Root)` |
| **AuraDSP Engines (Rootless)** | Android 引擎形态二 | 打包在 APK 内的引擎（无 root 兜底），**会话级**处理 |
| **AuraDSP Engines (Desktop)** | PC 引擎形态 | Windows / Linux 引擎（自研 APO/WASAPI、PipeWire 胶水 + DSP 核心） |
| **AuraDSP UI** | 界面主体框架 | Flutter 一码多端，多语言、多声道、可视化 |

命名规则：

1. **用户可见处一律 `AuraDSP*`**（应用名、模块显示名、预设格式名）；代码 / 目录 / 包名保持 snake_case 现状。
2. 上游引擎 **libjamesdsp 不改名**（尊重上游、便于 diff 升级）；我们包装后的成品才使用 AuraDSP Engines 品牌。
3. EffectRegistrar（`core/android/registrar/`）是**工程资产名**，不面向用户宣传；对外统一归属 AuraDSP Engines。

## 2. 应用构成：APP = AuraDSP Engines + UI 主体框架

每个平台的 AuraDSP 应用都由两部分组成：

```
┌─────────────────────────────────────────────────────────┐
│                AuraDSP APP（各平台统一名）                │
│                                                         │
│  ┌───────────────────────┐  ┌─────────────────────────┐ │
│  │  AuraDSP UI（Flutter） │  │  AuraDSP Engines        │ │
│  │  多语言 / 多声道 / 可视化│  │  DSP 核心 + 平台适配驱动  │ │
│  └───────────────────────┘  └─────────────────────────┘ │
│            ▲  统一控制协议 Control API ▼                 │
└─────────────────────────────────────────────────────────┘
```

- **Android APK** = Flutter UI + Rootless 引擎（内置 .so）+ 控制桥接层。装了 Root 模块的设备，APK 通过控制协议接管全局引擎。
- **Windows / Linux** = Flutter UI + Desktop 引擎（服务 / 库形态，系统级注入）。
- UI 与引擎**永远通过统一控制协议解耦**，UI 不直接关心引擎在哪个进程、哪个形态。

## 4. Android 引擎拆分：Root 模块与 Rootless 引擎

Android 上 AuraDSP Engines 拆成两半，**共享同一套 DSP 核心与预设格式**：

### 4.1 AuraDSP Engines (Root) —— KSU/Magisk 模块（已完成 v0.4.0）

- **载体**：KSU/Magisk 模块（id `auradsp_jdsp`），安装于 `/data/adb/modules/`。
- **注入链**（每次开机自动重放）：tmpfs overlay 盖 `/vendor/lib64/soundfx` → 回填原厂库 + libjdsp.so → bind-mount 补丁版 `audio_effects_config.xml` 到 `/odm/etc` → ksud 注入 9 条 sepolicy 规则（Enforcing 下 FMQ memfd 跨域共享最小集）→ audioserver 启动时 HAL 自动 dlopen。
- **引擎栈**：libjamesdsp（C）→ JamesDspEngine（IAudioEngine 适配）→ EffectRegistrar（AIDL/FMQ/状态机）→ effects HAL 进程。
- **参数通道**：标准 AIDL Parameter（bassBoost / presetReverb / equalizer band0）→ VendorParamId → JamesDSP API；`kPostGainDb` 预留给控制 APP 独立使用；volumeStereo 实测为 framework 侧增益，**永久只 log 不路由**（防止双重衰减）。
- 模块结构与开机时序详见 `core/android/registrar/examples/jamesdsp_engine/deploy/ksu_module/`。

### 4.2 AuraDSP Engines (Rootless) —— APK 内置引擎（设计方向）

- **场景**：无 root 设备的兜底路线。
- **方式**：会话级处理（Android AudioEffect / DynamicsProcessing 挂到 audio session），引擎核心编译进 APK，进程内 dart:ffi 直调。
- **必须吸收的旧路线教训**（RootlessJamesDSP 实测痛点，见项目初衷 §2.1）：前台服务 + 守护重启防保活失败；单实例互斥防双重声音；版本适配层处理 12~16 政策差异；崩溃隔离。

### 4.3 一致性原则

- 同一 DSP 核心（libjamesdsp）、同一预设格式、同一参数语义。
- APP 启动时能力探测：检测到 Root 模块 → 全局引擎优先；否则自动落 Rootless，**UI 无感知切换**。

## 5. 控制通道（AuraDSP APP ↔ Engines）

| 场景 | 通道 |
|---|---|
| Android（Root） | APP 使用标准 `android.media.audiofx.AudioEffect`（按 effect UUID attach）→ framework → HAL → `setParameterSpecific`（bassBoost/reverb/EQ 通路已实测验证） |
| Android（Rootless） | 进程内 dart:ffi 直调引擎 |
| Desktop | **进程内 dart:ffi 直调 `auradsp_engine.dll`**（音频 isolate + 独占 handle + WASAPI pump）；VAIO/VM/APO/ASIO 模式经各自桥接层复用同一 C ABI |
| 可视化数据 | 引擎侧 FFT/电平 → 64 槽 lock-free SPSC 环（536B `auradsp_viz_frame`）→ UI 30fps 拉取 |

## 6. UI 主体框架（Flutter）规范

- **一码多端**：Android / Windows / Linux（macOS 后续）共用一套 Flutter 代码。
- **三大支柱**（用户点名的硬需求）：
  1. **多语言**：中文优先，ARB 资源 i18n，预设 / 效果名统一走翻译表；
  2. **多声道**：立体声 ~ 5.1/7.1 的直通 / 下混 / 声道映射 UI；引擎侧已落地 ADR-003 Phase A（矩阵下混/上混，LFE 直通）与 Phase B（Category A 效果器 8 声道独立位掩码），Category B 跨声道效果仍只作用前置 FL/FR；空间音效已支持 6/8ch→双耳立体声虚拟环绕（B1 引擎/VAIO、B2a VM、B2b 本地播放、B2c ASIO 双线 2/4/6/8 档多声道传输），Category B 空间族仍只作用前置（见空间音效升级方案）；
  3. **可视化**：播放流 / 波形 / 频谱 / 声谱（CustomPaint / Texture + 引擎推送 FFT 数据）。
- **状态明示**：处理中 / 旁路 / 失效三态常显（直击"静默失效"痛点，项目初衷 §3）。
- 与引擎只经 Control API 通信，UI 不感知引擎所在进程与形态。
