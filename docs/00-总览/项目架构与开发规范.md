## 1. 项目定位

基于 JamesDSP 引擎的**跨平台全局音频效果软件**，覆盖 Windows / macOS / Linux / Android。Android 路线已验证：以 **AIDL VINTF 效果 HAL（`android.hardware.audio.effect`）** 形式注入系统音频链路，通过 EffectRegistrar 框架挂载 DSP 引擎。

**品牌与命名体系**（详见 `docs/产品架构总览.md` §1）：应用统一叫 **AuraDSP**（PC/手机同名）；引擎族叫 **AuraDSP Engines**，Android 上拆分为 **(Root)**（KSU 模块，系统全局）与 **(Rootless)**（APK 内置，会话级）两种形态；UI 主体框架基于 Flutter（多语言/多声道/可视化）。APP = AuraDSP Engines + UI 主体框架。

## 3. source/ 整合铁律

1. **禁止使用预编译包**：第三方能力一律从 `source/` 的源码整合进 `core/` 编译体系。唯一例外：NDK 工具链本身。
2. **来源可追溯**：每个从 `source/` 提取的源码子集，必须在 `core/android/vendor-src/ORIGIN.md` 登记上游仓库、分支、提取路径范围、用途、提取日期。
3. **vendor-src 内不改上游逻辑**：如确需补丁（如 libfmq 的 file-backed FMQ 场景），补丁写在调用侧或独立 shim，vendor-src 保持与上游逐字节可 diff；若必须改动，在 ORIGIN.md 中标注 `[PATCHED]` 并说明 diff。
4. **升级路径**：上游更新时重新从 `source/` 提取覆盖 vendor-src 对应目录，ORIGIN.md 更新版本号即可，无历史包袱。

## 4. core/android/ 分层架构

```
┌─────────────────────────────────────────────────────┐
│  examples/ (SpikeEqEngine 等) + 未来 libjamesdsp 引擎 │  ← 引擎层
│  实现 IAudioEngine 接口，纯 DSP，不知道 binder 存在     │
├─────────────────────────────────────────────────────┤
│  registrar/ (AidlEffectBase + Exports)               │  ← 框架层
│  状态机 / FMQ / worker 线程 / extern "C" 三导出       │
├─────────────────────────────────────────────────────┤
│  aidl-gen/ + vendor-src/(libfmq, binder-ndk, ...)    │  ← 平台源码层
├─────────────────────────────────────────────────────┤
│  stubs/ (cutils/libbase/libutils 自写替代)            │  ← shim 层
└─────────────────────────────────────────────────────┘
```

**依赖方向严格自上而下**：引擎只依赖 registrar 的 `Engine.h`；registrar 只依赖 aidl-gen/vendor-src/stubs；stubs 不依赖任何人。禁止跨层反向 include。

### 4.1 关键接口契约（registrar/Engine.h）

```cpp
class IAudioEngine {
    // open/process/reset/close/name()
    // process() 为 RT-safe：禁止 malloc/锁/IO/日志
};
```

- 引擎实现方 **不需要** 了解 AIDL/FMQ/binder；框架负责全部 IPC 细节。
- 新引擎接入三步：① 实现 IAudioEngine；② 构造 RegistrarEntry（uuid + Descriptor + factory）；③ 在 Exports.cpp 注册。

### 4.2 spike-global-effect 的定位

保留为：① 端到端回归参考（Spike2 全链路已验证）；② `deploy/` 部署工具集（KSU 模块打包、MiniAttach 测试器）。**新代码禁止放入**，新工作一律进 `core/android/<新模块>`。

## 5. core/desktop/ 桌面引擎架构（Windows）

### 5.1 分层

```
Flutter UI (app/auradsp_app)  ──dart:ffi──▶  auradsp_engine.dll (engine)
   │                                              │
   │ 控制通道（SendPort，跨 isolate）                │  auradsp_process (RT 线程)
   ▼                                              ▼
音频 isolate（独占 handle + WASAPI pump） ──▶ gate → deesser → filter → bassmono
                                                  → 心理声学低音 basspsycho
                                                  → Stage 0 Pre-DSP (插件)
                                                  → M5-b 低频搁架 shelf → dyneq 三段动态 EQ
                                                  → Stage 1 Pre-Vendor (插件)
                                                  → engine/legacy 12 级效果链（P-004 表驱动）
                                                  → Stage 2 Post-Vendor (插件)
                                                  → Haas 差分环绕 → Spatial L1 → Exciter → M5-c Freeverb
                                                  → Stage 3 Post-Reverb (插件，默认)
                                                  → Loudness 等响度补偿
                                                  → Modern Lookahead Limiter (0ms / 1.5ms 可选)
                                                  → NaN/Inf 清洗 + ±10.0 钳位
                                                  → Stage 4 Post-Limiter (插件)
                                                  → viz_write → SPSC 无锁环 → UI (30fps)
```

- **唯一边界**：`auradsp_engine.h` 是 UI ↔ 驱动之间**唯一**的 C ABI（v1.0，单调向后兼容）。任何新引擎能力都必须先在此加符号，再在 `auradsp_engine.def` 登记导出。
- **插件宿主**：`engine/host/auradsp_plugin_host.cpp`（公共头 `auradsp_plugin_host.h` 在 `engine/` 根）进程内 64 位 VST3 + CLAP 宿主，**四插槽**（`kMaxPluginSlots = 4`，ADR-004 立项时为双插槽，后扩至 4）+ 五级阶段插入（Stage 0~4）。决策与取舍见 [ADR-004](../adr/ADR-004-plugin-multi-slot-and-stage-topology.md)。
- **Windows 驱动套件**（`core/desktop/windows-drivers/`，与 `engine/` 解耦，独立 CMake）：`01_vaio_driver/`（AuraVAIO PortCls/WaveRT 虚拟声卡，modern WDK 28000 + Win7 legacy EWDK 19041 双轨，4.0/5.1/7.1 DataRanges + `KSPROPERTY_AUDIO_CHANNEL_CONFIG`）、`02_voicemeeter_client/`（VM 回调泵：三级自省检测 + OUTPUT INSERT 回调 + 多总线逐对处理 + CHANGE 触发引擎重建）、`03_system_apo/`（自研 APO `AuraApo.dll`：裸 COM 聚合 + 自注册 + 透传 + 心跳 + SILENT 清零；Configurator 安装/备份/卸载 + selftest + tone_play + COM/CLSID 诊断探针）、`04_asio_client/` + `04_asio_driver/`（ASIO 宿主与虚拟驱动双线）、`bridge/`（无编号 FFI 桥：`vm_bridge/` + `asio_bridge/` + `vaio_bridge/`）。属 Phase 7 系统级链路的前置探索，**不改变 ADR-001 进程内为主力形态的结论**。现状与构建见该目录 README。
- **legacy 不可变**：`engine/legacy` 与上游 libjamesdsp 逐字节一致（补丁除外）；MSVC 兼容问题走 `/FI auradsp_msvc_shim.h` 强制包含层解决，功能性改动一律登记到 `engine/legacy/PATCHES.md`（P-001~P-014）。engine 侧引用 legacy 头须写 `legacy/jdsp/...`。
- **wrapper 自研区**（不碰 legacy）：低频搁架 biquad、Freeverb、Spatial L1、viz 4096-FFT、IR FileGate 六道门卫。

### 5.2 RT-Safe 铁律（音频线程绝对禁区）

1. 禁止 `malloc/free/new/delete`、禁止 `std::mutex` 竞态、禁止 IO/打印/系统调用。
2. 插件 stage 匹配只读 `std::atomic`；`ctrl_mutex` 存在但**在 `auradsp_process` 中绝不加锁**。
3. 可视化走 64 槽 SPSC 无锁环（536 字节定长 `auradsp_viz_frame`：整链输出频谱 + **EQ 输入频谱** + 总峰值 + 32 槽 per-stage 电平/GR，已用 0..20），写失败不影响音频路径。
   - `spectrum` 是**整条链的最终输出**（EQ 之后的混响/卷积/Freeverb/插件全在内），只用于首页与可视化页。
   - `eq_in_spectrum` 取自 `processFloatMultiplexd` **之前**（vendor 链入口 = EQ 输入），供均衡器面板使用。
     EQ 在 libjamesdsp 单体链内部拿不到输出 tap，故由 UI 按 `|Y(f)| = |X(f)|·|H_eq(f)|`
     合成输出谱（见 `AppModel.composeEqOutputSpectrum`）——这是 LTI 系统幅度谱乘法定理，是精确值。
   - 两条 tap 的环形历史与 DC blocker 状态必须各自独立，否则会互相插值，两条谱都不再可信。
   - **`stage_levels_l/r[32]` 物理槽位分配契约（ABI v2）**：
     - 槽位 0..11（12 槽）：严格对应 Legacy 12 级链各阶段自身处理后的**真实输出峰值**（`tmpBuffer` 就地扫描，与 `stageIdx` 静态绑定，重排不漂移）；
     - 槽位 12（1 槽）：Gate 输入前测点 IN 电平（`input_lvl_in`）；
     - 槽位 13（1 槽）：Gate 处理后输出 OUT 电平（`input_lvl_out`）；
     - 槽位 14（1 槽）：动态均衡器 Dynamic EQ 真实输出峰值（`dyneq`）；
     - 槽位 15（1 槽）：独立滤波器 Filter 真实输出峰值（`filter`）；
     - 槽位 16（1 槽）：低音单声道化 BassMono 真实输出峰值（`bassmono`）；
     - 槽位 17（1 槽）：哈斯环绕 Haas Surround 真实输出峰值（`haas`）；
     - 槽位 18（1 槽）：激励器 Exciter 真实输出峰值（`exciter`）；
     - 槽位 19（1 槽）：等响度补偿 Loudness 真实输出峰值（`loudness`）；
     - 槽位 20（1 槽）：空间音效 Spatial 真实输出峰值（`spatial`）；
     - 槽位 21..23（3 槽）：预留位/扩展插件槽（恒置 -120 dBFS）；
     - 槽位 24..29（6 槽）：GR 计量（limiter / comp / gate / dyneq low / mid / high，dB ≥ 0）；
     - 槽位 30..31（2 槽）：预留位（恒置 -120 dBFS）；
     - 全 21 个已用槽位（0..20）均拥有真实实时双声道输出电平采样，Dart 侧 `stageMeterIndex` 静态映射到对应槽位，UI 渲染合成器级硬件 LED 电平阶梯；
     - **多声道约定**：`channels.mode=0`（ADR-003 Phase A）下混后链内节点处理 2 声道核心，电平表反映核心包络；`channels.mode=1`（Phase B）下 Category A 节点逐声道独立处理，per-stage 电平尚未逐声道展开（仍为立体声包络口径），UI 点阵表原生支持 `channelsDb` 多列扩展。
   - 改这个结构体时，**所有** ctypes 镜像（Dart `VizFrame` + `test/smoke/*.py`、`tools/*.py`）必须同步，
     否则 `auradsp_viz_read` 会越界写坏堆（`STATUS_HEAP_CORRUPTION`）。`sizeof == 536` 断言就是为此存在的。
4. 高频 viz 数据**不得**触发 Dart 根级 `notifyListeners`，一律走独立 `ValueNotifier` 局部重绘。
5. 延迟是**测量量不是准入闸门**（[ADR-006](../adr/ADR-006-remove-latency-tier-gating.md) 取代 ADR-002）：引擎按启用组合如实上报 `auradsp_get_latency_ms()`，任何效果都可自由使能；**不存在**「因延迟拒绝使能」的失败路径。

  即是子集；完整字体约 1.6MB）。禁用后包体 +1.6MB（桌面端可接受），一劳永逸。

## 6. 构建规范（Android）

- **工具链**：NDK 30 `clang++.exe` 直调（不用 `.cmd` wrapper），`--target=aarch64-linux-android34 --sysroot`。
- **C++ 标准**：`-std=c++20`（libfmq 依赖 std::format）；libjamesdsp 为纯 C，单独按 C99 编。
- **链接**：`-Wl,-z,max-page-size=16384`（16KB page 强制）。
- **符号控制**：`version_script.txt` 只导出 `createEffect`/`queryEffect`/`destroyEffect` 三个 extern "C" 符号；所有 C++ 符号 `-fvisibility=hidden`。禁止向进程空间泄漏任何其它符号（防 VNDK 冲突）。
- **构建入口**：每模块一个 `build.sh`（Git Bash 运行），输出到 `out/`（gitignore）。路径处理用 POSIX 变量 + `pwd -W`，禁止在 xargs/子 shell 内嵌套 `cygpath`（会触发引号地狱）。
- **共享中间产物**：aidl-gen、vendor-src、stubs 由各模块 build.sh 直接引用同一份源码，不复制副本。

## 7. 已验证的技术决策（不要回退）

| 决策 | 结论 | 依据 |
|---|---|---|
| FMQ 共享内存 | **file-backed**（`/data/vendor/audio/.spike_fmq_*`） | Oplus Android 16 上 hal_audio_default 域 memfd ftruncate / ashmem EACCES；普通文件 MAP_SHARED fd 可过 binder |
| HAL 形式 | AIDL VINTF 效果库 .so，extern "C" 三函数导出 | Spike2 全链路验证（create→FMQ→biquad→START→close） |
| 符号导出 | version script 白名单 3 符号 | 与进程内 VNDK 零冲突 |
| C++ std | C++20 | libfmq std::format 依赖 |

## 8. 代码风格与提交规范

- 项目代号：**AuraDSP**（仓库/文档/产物命名统一使用；上游引擎仍称 libjamesdsp 不改名）。
- 用户可见命名：应用名 **AuraDSP**；KSU 模块显示名 **AuraDSP Engines (Root)**（模块 id 保持 `auradsp_jdsp`）。命名体系详见 `docs/产品架构总览.md` §1，新增用户可见名称前先对照该节。
- 语言：核心 C++20；引擎若整合上游纯 C 代码保持 C 原样，wrapper 层用 C++。
- 命名：目录/文件 snake_case；类 PascalCase；成员 `m_` 前缀；namespace `jamesdsp::registrar`。
- 注释：接口契约（RT-safe、线程、生命周期）必须写在头文件；中文注释优先。
- Git：主分支 `main`；提交信息 `模块: 动作` 格式（如 `registrar: add SpikeEqEngine example`）；禁止 `git stash`（沙箱拦截且易丢数据），用 commit 或显式补丁文件。vendor-src 子目录禁止携带嵌套 `.git`（提取后删除，来源靠 ORIGIN.md）。
- 工具：写代码/检索代码结构时优先使用 **codegraph**（项目根有 `.codegraph/` 索引），大型重构前先查调用关系再动手。
- 文档：每个 spike/phase 结束输出一份 `docs/<Phase>-<主题>报告.md`。
