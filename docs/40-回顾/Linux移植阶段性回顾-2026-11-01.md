## 2. 关键裁定与实测结论

1. **ELF 导出靠 version script 单点收口**：Linux `auradsp_core` 必须
   OBJECT 而非 STATIC（ELF 不像 MSVC `.def` 那样强制归档抽取）；
   且**不能**叠 `-fvisibility=hidden`——ABI 头无 visibility 宏，叠了
   会把 56 个导出全部藏掉。最终 `.so`（2.1MB）导出集与 `.def` 恒等，
   现由 `smoke_linux_engine_exports` 纯 Python 解析 dynsym 常驻把守。
2. **GCC 垫片层**：legacy/core 源码零改动，靠前置 shim（镜像 MSVC
   `/FI` 范式）解决模板头进 `extern "C"`、EEL 宏与 libstdc++ 冲突等
   问题；C 源 `-include stdint.h`。
3. **GCC 14 诊断晋升**：CI 的 ubuntu-latest 已是 GCC 14，五条 C 诊断
   （incompatible-pointer-types 等）由警告升默认错误，冻结的 legacy
   三个文件（crossfeed / nseel-compiler / jdspController）中招。处理
   方式仍是垫片：Linux CMake 里带 `VERSION>=14` 守卫的 `-Wno-error=`
   整组降回警告，不动 legacy 源码。本地以四条可验诊断对全部 85 个
   C 文件加严普查，违规集合与垫片覆盖精确对齐才推送。
