# 插件体系健壮性治理与多通道拓扑优化回顾（2026-11-05）

## 1. 背景与问题定义

在跨平台（Windows / Linux）真实第三方插件（包括 IEM 空间音频全系、FabFilter 肥波全系、DPF 系列、GVST 系列等）实机测试中，暴露了以下关键故障与架构缺陷：

1. **高阶 Ambisonics / 多声道插件崩溃与音频死循环**：
   - 挂载 IEM `CoordinateConverter` 等 7 阶 Ambisonics（64 通道）插件时，音频陷入最后 1 秒死循环，卸载槽位仍无法恢复。
   - 根因分析：原 VST2 宿主仅静态分配了最多 8 个通道的输入/输出指针数组。当 64 通道插件写入 `outputs[2..63]` 时，触发严重的栈帧越界与空指针解引用，导致宿主音频回调崩溃，WASAPI/PulseAudio 驱动层死循环重放 DMA 环形缓冲区。
2. **异常插件毒化宿主音频管线导致永久静音**：
   - 部分插件由于许可证未激活、内部空指针或为纯合成乐器无音频输入，在处理时产生非数（`NaN`）或无穷大（`Inf`）。
   - 根因分析：下游 JamesDSP 的各类 IIR 递归滤波器（EQ、动态EQ、低音强化、混响）一旦吸入 `NaN`，反馈延迟线状态寄存器将永久中毒（NaN + x = NaN），导致后续即使用户将插件旁路（Bypass）或卸载，宿主依然无法输出任何声音，必须彻底重置引擎。
3. **VST2 插件窗口尺寸裁剪与不可调整**：
   - IEM 等 JUCE 系插件在 `effEditOpen` 打开前后尺寸不一致（如预备尺寸与实际尺寸不同），且宿主未支持 VST2 动态调尺操作码（`audioMasterSizeWindow` / opcode 15），窗口无缩放边框（缺少 `WS_THICKFRAME`），导致右半部分或底部被严重裁剪且无法拖动改变大小。
4. **Linux CLAP 插件打开界面黑屏**：
   - Linux X11 环境下打开 CLAP 插件 GUI 时全黑不刷新。
   - 根因分析：CLAP GUI 规范中，GUI 动画与重绘高度依赖宿主提供的定时器支持扩展（`clap_plugin_timer_support_t`）。原 Linux X11 事件分发层忽略了定时器消息向插件实例的分发，导致插件的 `on_timer` 回调从未被执行，UI 永远停留在未完成初次重绘的黑色背景。
5. **纯算法插件（Headless）无界面友好提示**：
   - 部分插件（如 DPF 的 `MaFreeverb`）本身无原生图形界面。点击界面按钮时触发失败提示，易造成用户误解。
6. **Linux 32 位位桥打包路径搜索失败**：
   - Linux 打包后插件宿主目录结构为 `bundle/lib/`，原代码只搜索同级目录，导致无法找到位桥进程 `plugin_host_x86`，提示 32 位无法加载。
7. **硬编码与隔离黑名单机制割裂**：
   - 旧代码中存在个别针对特定插件的硬编码判断，且隔离黑名单只在个别格式中分散实现，未形成跨 VST2 / VST3 / CLAP 的统一防护网。

## 2. 治理与重构实施方案

### 2.1 64 通道安全缓冲与丢弃通道（Multichannel Safe Scratch）
- 在 `Vst2Instance` 中将最大通道上限定义为 `kMaxPluginChannels = 64`。
- 引入静态保护全 0 缓冲 `m_zeroBuffer` 与丢弃缓冲区 `m_discardBuffer`。
- 当插件声道数超过当前处理流输入声道时，空余通道安全垫入 `m_zeroBuffer`；当插件声道数超过输出声道时，多余通道安全连接到 `m_discardBuffer`，彻底阻断越界写入。

### 2.2 全通道直通与 NaN/Inf 毒化防护网（Audio Sanitization & Clamping）
- 在 `PluginHostManager::processSlot` 中：
  - **旁路态与崩溃态**：无条件按声道提示 `chHint`（最高 64 通道）完整执行 `std::memcpy(out, in)`，消除历史残留的硬编码 2 通道限制。
  - **非有限值清洗**：音频流过插件后，对所有输出声道执行 `std::isfinite` 检测，若检测到 `NaN` 或 `Inf` 立即清洗置 0，并对正常样本强制施加 `[-10.0f, +10.0f]` 硬极值钳位，杜绝下游滤波器寄存器中毒。

### 2.3 VST2 自适应窗口与 Opcode 15 动态缩放
- 宿主窗口样式补齐 `WS_THICKFRAME | WS_MAXIMIZEBOX`，支持鼠标拖拽边框调整。
- `effEditOpen` 之后重新执行 `effEditGetRect` 二次尺寸校准，并设立稳定化延时检查 `kSizeSettleTimerId`。
- 宿主回调中完整实现 `VST_HOST_OPCODE_EDITOR_RESIZE`（opcode 15），动态同步父容器与子窗口，修复 IEM 全系及第三方插件的裁剪缺陷。

### 2.4 Linux CLAP 定时器派发接入
- `IPluginInstance` 抽象增加 `virtual void onTimer(uint32_t timerId)`。
- 在 `ClapInstance` 中实现 `onTimer`，查找注册的定时器 ID 并分发给插件扩展 `m_timer->on_timer(plugin, timer_id)`。
- `plugin_gui_x11.cpp` 的 `guiX11Dispatch` 循环中，捕获定时器事件并派发给对应实例，恢复 Linux CLAP 界面流畅重绘。

### 2.5 纯算法（Headless）元数据感知
- 在 VST2/VST3/CLAP 各格式实例与元数据探测层中，探测是否具备原生 UI（`hasEditor`）。
- 将 `hasEditor` 字段纳入元数据协议与 JSON 序列化，Flutter 前端拦截无界面的点击操作并友好提示：*“纯算法效果器 (Headless)，无原生图形界面”*。

### 2.6 多级位桥宿主定位策略
- `PluginHostClient` 在 Windows 与 Linux (POSIX) 下均支持多级候选探测路径：
  1. 同级目录 `dir/plugin_host_*`
  2. 父级目录 `dir/../plugin_host_*`
  3. `dir/../bin/plugin_host_*`
  4. `dir/bin/plugin_host_*`
  5. `dir/lib/plugin_host_*`
- 彻底兼容开发目录、Release 目录及 Flutter Bundle 打包结构。

### 2.7 跨格式统一隔离黑名单
- 抽象统一隔离接口：`pluginSetEditorQuarantineList` 与 `editorQuarantineMatch`。
- 移除非通用硬编码特判，通过统一模式匹配保护 VST2、VST3 与 CLAP 在析构或销毁异常插件界面时的宿主进程稳定性。
