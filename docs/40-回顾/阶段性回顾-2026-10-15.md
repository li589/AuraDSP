## 2. 核心事件：FL Studio ASIO 桥宿主必崩——根因是我们自己的 bug

**现象**：`asio_tone.exe` 直连 FL Studio ASIO 完全正常；经 `auraasio_bridge.dll`
（DLL 宿主，exe/python 均验）`ASIOStart` 后 10ms 内驱动自有线程必崩
（首次 `bufferSwitch` 之前，垃圾 RIP）。

**排除法矩阵**（对偶实验，全部实测）：死亡与桥 DLL 化、引擎加载、输入缓冲、
query_caps、sink、VEH、快照、SetErrorMode、轮询、stdio、环境变量、exe 命名
均无关；崩溃线程 = 驱动 RT 线程（start = ilwasapi2asio+0x7700），崩溃点 =
RT 助手函数 `sub_32E0` 内 `jmp [rax]`（rax = 驱动从引擎对象 `+0xd0` 读出的
`ASIOCallbacks*`）。

**根因**：初版 `AsioHost` 把**栈局部 `ASIOCallbacks cb` 的地址**传给
`ASIOCreateBuffers`。驱动按 ASIO 契约长期持有该指针（反汇编确认 FL Studio
ASIO 在 `ASIOCreateBuffers` 末尾存入引擎对象 `+0xd0`，RT 线程每帧经它尾调用
`bufferSwitch`）。栈局部在 `create_*` 返回后失效并被后续调用覆写 → 驱动首次
回调即跳垃圾指针（NX 崩溃）。**"tone 侥幸存活、桥宿主必崩"的对偶真相**：tone
后续调用链浅、该栈槽未被覆写纯属运气；任何更深调用链必覆写。

**修复**：回调结构体改**类级静态**（`AsioHost::s_cb`，单实例约束下安全），
`create_output_stereo`/`create_stereo_io` 两条路径均已切换。

**排查手法**（跳板式 hook，.workbuddy/tmp 工具链，不入库）：hook 驱动
`createBuffers(0x3570)` 与 `sub_32E0(0x32e0)`，记录实参、`[E+0x28]`（x64
第 5 栈参）、`+0xd0`、调用栈；trampoline 跳板（驱动函数前 16 字节指令不对齐，
"恢复 16 字节重执行"会截断指令，必须整条指令复制 + 跳回）。

**顺带定罪的两条驱动兼容性铁律**（详见 Spec §Phase 2 落地偏差记录）：

1. 引擎 DLL 必须在 `host.open` 之前加载——驱动 `ASIOInit`~`ASIOCreateBuffers`
   窗口内启动 RT 线程，此窗口内的 `LoadLibrary` 与其争抢 loader lock，轻则
   回调永久静默、重则驱动看门狗 `ExitProcess(0)` 干净杀宿主（无转储无段错误，
   曾长期被误判"玄学崩"）。
2. FL Studio ASIO 对 `ASIOInit` 的 `sysRef=nullptr` 敏感（给宿主派发终止），
   必须传真实窗口句柄（`GetConsoleWindow()` / GUI 宿主主窗口）。

`smoke_vm_pump` 一次实时性断言失败（`change run frames real-time`）为
**负载敏感型 flaky**：单跑全 PASS、复跑即过；其二进制（auravm）不链
`auraasio_host`，与本次改动无因果关系。

> **2026-10-17 根因补记（重要环境诊断）**：`smoke_vm_pump` 报
> `frames=0 / groups=0 / note=no-buffers-timeout` **不一定是负载抖动**——
> 最常是 **Voicemeeter A1 输出设备不可用**（如蓝牙耳机没电飘红），VM 整机
> 无活跃回调。排查顺序：① 看 VB 面板 A1 是否飘红/有无音频在放；② 移除
> 不可用输出设备后复跑；③ 仍挂再看负载（与 flutter test 并行争抢 CPU）。
> 判定代码回归前务必排除此环境态。
