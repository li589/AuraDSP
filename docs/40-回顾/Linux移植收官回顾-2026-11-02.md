## 2. 真机轮次抓到的问题（本期最有价值的部分）

无头 VM 与 CI 的共同盲区是「真实声卡 + 真实桌面」：延迟模型、内核
模块枚举、面板行为、软件渲染都与真机不同。本轮五项全部源于此：

1. **输出泵饿死**（`0d79cd3`）：真机 `pa_simple_get_latency` 含设备
   侧缓冲（实测 ~10.4k 帧 @48k），远超本地 tlength 2048，泵按
   `bufferFrames − padding` 算出的可用帧恒为负 → 永不写入 → 无声。
   VM 的 null-sink 延迟小，永远复现不出。修复：padding 钳到半缓冲，
   节流交回阻塞写。教训：**基于 latency 的泵模型必须按「服务端可
   报告任意大延迟」设计**。
2. **driver 回环源选错**（`76e8c14`）：snd-aloop 写入回环 sink 后，
   只有其同名 `.monitor` 能采到信号（RMS 0.203），`alsa_input.*`
   恒为 0；且 `modprobe snd-aloop enable=1,1` 会建两张卡、PA 枚举
   顺序与 `index=2` 不一致。修复：源选择优先 `.monitor`
   （`pickLoopbackSource`），推荐命令改单卡 `enable=1`，新增真机
   门禁 `smoke_linux_driver_loopback`。
3. **Impeller 软件 OpenGL 重绘损坏**（`080beb0`）：llvmpipe/VMware
   SVGA3d 下 Impeller GLES(SDF) 后端首帧后整窗损坏（描边消失、文字
   纯色、控件错位、对话框异常色扇形）。Linux runner 关闭 Impeller
   改走 Skia GL。
4. **门禁在真机误红**（`4bc9d38`）：`smoke_linux_pulse_output` 在
   默认实体设备上被硬件缓冲撑高 latency 而误判；改用自建私有
   null-sink 并显式指定 dev，与 CI J3 同条件。
5. **频谱门漏认 PA 采集**（`476fb8e`）：virtual/driver 由采集供流、
   不置 `playing`，主页频谱与可视化舞台误判空闲；门控纳入
   `linuxCaptureActive`（Windows 该值恒 false，零行为变化）。
   另同轮补了设置页设备卡的 Linux 分支，不再落到 Windows 三层
   管线 UI。

托盘亦在本轮定案：XFCE 实测 SNI 注册正常（Status=Active、
ItemIsMenu=false），Activate 可恢复窗口；systray 的
`menu-is-primary` 会让左键弹菜单，菜单「显示主窗口」是 XFCE 上的
可靠路径，GNOME/KDE 按 Activate 走左键恢复。
