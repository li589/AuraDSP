# ADR-002 — 三档延迟模式为硬约束，引擎侧守卫

> **⚠️ 已被 [ADR-006](ADR-006-remove-latency-tier-gating.md) 取代（2026-10-12）。**
> 三档硬约束、引擎侧守卫、`AURADSP_E_LATENCY_GUARD` 全部撤销。
> 本文按项目约定**原文保留不改写**，仅作历史留档；一切实现以 ADR-006 为准。
> 取代理由：切档静默回滚导致选项不可用、且与效果使能互相锁死（详见 ADR-006 §1）。

- 状态：**已被取代**（2026-10-12，见 ADR-006）；原接受于 2026-10-09
- 背景：libjamesdsp 的 Compressor（FFTCompander）使用 FFTSIZE_DRS=8192 的重叠相加（jdsp_header.h），48kHz 下理论附加延迟 ~85–170ms，与"商业水平延迟"直接冲突；Convolver/Reverb 延迟 = IR 长度 / 预延迟，同样不可控。
- 决策：
  1. 延迟档位三档：**实时 ≤10ms（仅 T0 效果）**、**音乐 ≤30ms（T0+T1）**、**品质不限（T0~T2）**；
  2. 每个效果标注延迟档位（见方案 §4 表），引擎按启用组合实时计算 `get_latency_ms()`；
  3. **守卫逻辑放引擎侧**：超档启用请求返回错误码，UI 置灰并标注原因——UI 不能绕过；
  4. Compressor 在实时/音乐档被引擎强制排除。
- 后果：预设保存/载入必须携带档位元数据；跨档载入时降级并提示。
