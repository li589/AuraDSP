## 2. 架构现状

```
Flutter UI（六页）
   │
   ├─ 控制面：dart:ffi ──▶ auradsp_engine.dll ── Control API（SendPort，音频 isolate 独占 handle）
   │                        └─ PluginHostManager（双插槽 · VST3 + CLAP 64 位进程内）
   └─ 数据面：viz 30fps ← 64 槽 SPSC 无锁环 ← RT 线程
                              │
   auradsp_process 链：  Stage0 Pre-DSP ▸ 低频搁架 ▸ Stage1 Pre-Vendor ▸ vendor 12 级(P-004 表驱动)
                        ▸ Stage2 Post-Vendor ▸ Freeverb ▸ Stage3 Post-Reverb ▸ NaN/Inf 清洗+钳位
                        ▸ Stage4 Post-Limiter
```

本轮的核心结构性变化：**第三方插件从"链外固定点"变成"链内五级锚点"**，与 vendor 12 级的表驱动重排（P-004）在同一张拓扑图上共存，解决了此前"内部可重排、外部不可插"的割裂。

## 3. 本轮关键决策

| 决策 | 结论 | 落点 |
|---|---|---|
| 宿主形态 | **进程内**，不用桥进程 | [ADR-004](adr/ADR-004-plugin-multi-slot-and-stage-topology.md) |
| 插槽数 | **固定 2 路**，编译期常量，不做动态增删 | `PluginHostManager::kMaxPluginSlots` |
| 插入点 | Stage 0~4 五个锚点，**默认 Stage 3**（与旧单插槽固定点行为一致） | `PluginSlot::insertStage` |
| ABI 演进 | 新增 13 个 `auradsp_plugin_slot_*`，**旧符号全部保留**转发 slot 0 | `auradsp_engine.h/.def` |
| 预设落盘 | 引擎只做 `getState/setState` 流序列化；**路径与命名归 Dart** | `%APPDATA%/AuraDSP/plugin_presets/<插件名>/*.aurapreset` |

**诚实记录**：ADR-004 接受了"插件崩溃会带崩宿主进程"这一代价，未达成《扩展规划》§2.1 "崩溃不拖垮 APP" 的目标。这是明示取舍，非遗漏。

## 4. 技术债与风险（诚实清单）

| 项 | 等级 | 说明 |
|---|---|---|
| 插件崩溃无隔离 | 高 | 进程内固有代价；桥进程化推迟至 Phase 7，**当前无崩溃采集口径**——需先补齐 |
| 插件重排后状态失效 | 中 | 部分插件（Auto-Tune 等带内部状态机）换插入点后可能需重新初始化才正确，未做深度验证 |
| 双槽延迟累加无补偿 | 中 | 两插件串联延迟超阈值时仅 UI 标注，未自动降级 |
| Stage 数为编译期常量 | 低 | 用户无法把插件拖到任意两个 vendor stage 之间；扩展需再开 ADR |
| `eq.curve` 无 get 回读 | 低 | 状态在 vendor 内部；UI 持镜像，重启后曲线不恢复（预设可存） |
| vendor 输出限幅恒开（threshold=1.0） | 中 | 强正增益会被钳到 1.0；UI 已注明，长期可暴露 threshold 参数 |
| 硬编码绝对路径 | 低 | `auradsp_ffi.dart` 开发期回退路径、smoke 测试 DLL 路径均写死 `D:\temp_desktop\Proj\JamesDSP` |
| `docs/forensics/` 34MB 原始日志入库 | 低 | 用户裁定保留为审计证据（2026-10-10），不清理 |
