## 4. Win7 APO 全闭环（本轮补完）

### 4.1 挂载与还原

Win7 端点命名与 Win10 不同（无 Theater/Definition 友好名），且按名称子串匹配撞上 render/capture 同名歧义（扬声器/Microphone 均「(High Definition Audio Device)」结尾）。最终改用**端点 ID 子串**匹配：render 物理端点 `{0.0.0...}{864efafa-...}` → `install 864efafa --force`。

- 挂载模式自动切换为 `win7-sapo`（Win7 sAPO 规范：,1 = LFX、,2 = GFX 双槽），备份 `apo-backups/fx__864efafa_c055_4_20261024_214022.reg`，音频服务重启成功。
- `start /b tone_play Definition 8 440` + 3 秒后心跳：**alive，seq=340，frames=152,320，sr=44100，nbs=448，pid=1016**。
- `uninstall 864efafa`：还原成功，`remaining_count=0`（Win7 全干净）。

### 4.2 新增工具：test/vm/apo_runner.py

ssh 命令行传中文参数会被码页损坏（UTF-8 → GBK 乱码），直接导致「扬声器」等子串失配。新增 ASCII-safe 包装：

- 参数与输出全程 ASCII：子串以 `\uXXXX` 转义传入（内部 `unicode_escape` 还原为真 Unicode），输出经 `backslashreplace` 转义。
- 动词：`endpoints` / `install` / `uninstall` / `heartbeat`，直接调用 `apo_config` 的对应函数。

### 4.3 过程中发现：apo_inspect.exe 输出码页损坏

`apo_inspect.exe` 输出 UTF-8 字节，被 python `subprocess(text=True)` 按 cp936 解码后，**VM 内部拿到的端点 name/friendlyName 本身就是乱码字符串**——不仅 ssh 传输会坏，VM 内的 Unicode 子串匹配也对不上乱码数据。因此 Win7 侧的可靠匹配键是端点 `id`（纯 ASCII）。

此问题同样解释了为何 `install High` 会 ambiguous（render/capture 名字中的 ASCII 段相同）。Win10 侧未触发是因为其友好名（Home Theater）与捕获端不重叠且本身为 ASCII。

> 备忘：若后续要在 VM 上按名称匹配，正确修法是让 apo_inspect.exe 输出强制 UTF-8 并在 python 侧显式 `encoding='utf-8'` 解码，而非依赖 locale。本轮以 ID 子串绕过，未改 exe。

## 5. 引擎副本漂移发现与修复（tools/sync_artifacts.ps1）

首轮 VM 检查中 Win10 侧 `vm_abi_check` 报引擎 ABI=1（假绿风险）。排查：`core/desktop/windows-drivers/out/Release/auradsp_engine.dll` 是 **10-17 旧副本（ABI 1）**，而真相源 `core/desktop/windows/out/Release` 已是 ABI 2；`sync_artifacts.ps1` 原目标清单不覆盖 windows-drivers\out\Release，导致桥/探针从旁边加载的引擎长期陈旧。

修复：主循环后追加**定向分发块**——`auradsp_engine.dll → windows-drivers\out\Release`（-Force 覆盖，含计数与失败告警）。重推后两台 VM 全绿。该修复随本报告提交入库。

## 6. 测试方法论记档（复用价值）

- **心跳须在发声进行中查验**：audiodg 空闲时 AuraAPO 卸载，心跳 dead 是正常现象不是失败。正确序列 = 后台发声 → 延迟 3 秒 → verify-heartbeat。
- **vaio_multichannel_probe 在 ssh 会话挂起是探针假象**：其「扬声器向导」步需要 GUI 会话；驱动本身由 tone_play `played:true` 实证，不作为失败依据。
- **中文参数禁走 ssh 命令行**：一律 ASCII 子串或端点 ID；必要时用 `apo_runner.py` 的 `\uXXXX` 通道。
- **Win7 VM 中途干净关机（VMX exit 0）+ 陈旧锁恢复**：空 `M46275.lck` 等待后重启即可；vmx/vmdk/vmem.lck 出现 = 启动进行中，勿强制清锁。
