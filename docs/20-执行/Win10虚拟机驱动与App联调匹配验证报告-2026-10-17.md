## 2. 关键突破与底层问题攻关详情

### 2.1 Mode 3 (System APO) audiodg 载入与权限隔离深度攻关

在 Win10 虚拟机实机联调中，定位并彻底解决了影响 APO 载入的两个关键问题：

1. **COM 聚合规约与递归崩溃防范**：
   - 彻底修复 `audiodg!CSystemEffectWrapper` 调用 COM 聚合时的递归崩溃陷阱，采用 Nested Class 实现了完全合规的 `IUnknown` 聚合委托机制。
   - `apo_selftest.exe` 20 项断言在 Win10 虚拟机上 100% 通过。
2. **LPAC 沙箱与文件系统 ACL 隔离突破**：
   - **现象**：当 `AuraApo.dll` 注册在桌面用户目录（`C:\Users\li\Desktop\...`）时，`audiodg.exe`（运行在 `NT AUTHORITY\LOCAL SERVICE` 与 LPAC 沙箱下）因无权读取用户目录报 `0x80070005` (Access Denied)。
   - **方案**：将 `AuraApo.dll` 部署至系统目录 `C:\Windows\System32\`，天然继承沙箱与系统服务的读取与执行权限；
   - **心跳穿透**：通过 SDDL `D:(A;;GA;;;WD)(A;;GA;;;AC)(A;;GA;;;S-1-15-2-1)(A;;GA;;;S-1-15-2-2)` 为 `Global\AuraAPO_Heartbeat` 显式注入 LPAC 权限，成功实现实时双向心跳。
3. **注册表 FxProperties 精确权限适配**：
   - Windows MMDevices 注册表项由 `TrustedInstaller` 拥有，管理员仅具备 `KEY_SET_VALUE | KEY_QUERY_VALUE`，常规 `CreateKey`（含 `KEY_CREATE_SUB_KEY`）会触发权限拒绝。
   - 改造 `apo_config.py`，采用精确权限 `CreateKeyEx(..., KEY_SET_VALUE | KEY_QUERY_VALUE)` 操作已存在属性，保证在不触碰系统所有权的前提下安全挂载与还原。
4. **实机播放与心跳验证**：
   - 针对物理扬声器挂载后，通过 WASAPI 发声探针播放音频流：
   - 实测输出：
     ```json
     {"played":true,"endpoint":"扬声器 (High Definition Audio Device)","seconds":4,"freq":440.0}
     HB: {'alive': True, 'seq': 123, 'frames': 59040, 'sr': 48000, 'nbs': 480, 'pid': 8472}
     ```
   - 证实 `audiodg.exe` (PID 8472) 正常装载 `C:\Windows\System32\AuraApo.dll`，累计实时处理 59,040 帧音频，无任何爆音、杂音与崩溃。
   - 执行 `uninstall` 后，100% 精确还原原有厂商配置（`WMALFXGFXDSP.dll`），零残留。
