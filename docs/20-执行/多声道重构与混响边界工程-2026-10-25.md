## 0. 结论摘要（先看这里）

### 0.1 对“A+C / 去掉 spatial.fdn / LFE 可选”的评估

| 决策 | 结论 | 关键理由 / 代价 |
|---|---|---|
| **A：vendor reverb 做立体声，MC FDN 做多声道** | **可行，推荐** | 两条路径的最终输出形态不同：矩阵/双耳最终是 2ch，离散 MC 是 Nch。按路径选引擎可以从结构上消灭“双混响叠加”。 |
| **C：立体声自定义暴露 vendor 原生参数** | **可行，但不是“已有 API 直接暴露”** | `reverb.c` 只有 `Reverb_SetParam(jdsp, preset)`；`sf_advancereverb()` 虽接受 18 个参数，但会**整体重建约 1MB 的 `sf_reverb_state_st`**。直接在 RT 线程调会卡音频，在控制线程反复调会与 RT 竞争。必须新增 legacy API + 影子槽/原子换指针（与 P-018 comp 同范式）。 |
| **去掉 `spatial.fdn` / `spatial.late` 开关** | **正确** | 晚期混响应由混响卡统一负责；spatial 卡只做声场化/早期反射。否则同一张 spatial 卡里又藏一个“第二混响”，边界再次模糊。 |
| **LFE 可选入混响（默认关）** | **正确，低风险** | 默认遵守 ADR-003 的 LFE 直通；开启时先 120Hz 低通再按 -6dB 送入 FDN，避免低频把尾音搅浑。立体声路径忽略该开关。 |
| **comp/eq 逐声道** | **EQ 低风险；comp 是本期最高成本项** | EQ 可复用 arbmag 的 8×`FFTConvolver1x1` 池；comp 每个 `FFTCompander` 约 1MB 级，8 声道 + 影子槽在 VB 8×8 下需要实测预算，必要时降级为逐对（见 §6、Q2）。 |
| **bassmono 多对选择（标准四对）** | **可行，但现有 UI 必须整体重做** | 标准四对（FL/FR、C/LFE、SL/SR、BL/BR）位掩码 + 合并方式（每对独立 / 全部合并），默认仅 FL/FR。现有卡片是“3 个滑块 + 一个搁架路由”，既没有 bassmono 独立开关，也没有声道对概念——无法靠加两个 chip 修补。UI 方案见 §3.9。 |

**一句话边界**：`reverb.preset` 是唯一混响开关；矩阵/双耳路径只跑 vendor reverb，离散 MC 路径只跑 MC FDN；Freeverb 退役；`spatial` 卡不再产生晚期混响。

## 1. 现状证据（只列与本工程直接相关的）

### 1.1 双混响是“同时开”，不是“二选一”

- vendor reverb：`engine/legacy/jdsp/Effects/reverb.c`，开关 `reverb.preset >= 0` → `ReverbEnable`，`< 0` → `ReverbDisable`（`engine/chain/engine_chain.cpp` `apply_reverb`）。
- 自研 Freeverb：`engine/dsp/dsp_freeverb.cpp`，开关只看 `freeverb.enable`。
- UI 只有一张 `reverb_card.dart`，但 `state_effects.dart` 的 `selectReverbPreset()` 在预设 0..7 时同时：
  - `setFreeverbEnabled(true)` + 写 6 个 `freeverb.*`；
  - `setReverbPreset(id)` → 发 `reverb.preset=id`。
- 自定义 `-2` 只开 Freeverb，**不发** `reverb.preset=-2`；从预设切自定义时 vendor 仍开着。
- 会话恢复 `state_session.dart` 同样是 `freeverb.enable=1` + `reverb.preset=preset`。
- `compute_latency` 只在 `reverb.preset >= 0` 计 vendor 30ms；自定义态若 vendor 还开着，延迟反而少报。

### 1.2 离散 MC 链的效果作用面（`process_multichannel_chain`）

| 作用面 | 效果 |
|---|---|
| 全声道逐声道 | gate / filter / shelf / dyneq / tube / exciter / loudness / limiter / arbmag / 插件 5 段 |
| 逐对共享单实例 | comp / eq（`p0 = 2,4,6`，C/LFE 被配成一对） |
| 仅 FL/FR | bassmono / basspsycho / vendor 段（bass、convolver、ddc、liveprog、crossfeed、stereo、reverb、output）/ haas / spatial / freeverb |

注意：comp/eq 目前在 **3b 段**（vendor FL/FR 段之后、插件 stage 3 之后）处理，与 vendor 链内 `tube,comp,bass,eq` 的原始顺序不一致；本工程会顺手把顺序对齐（§3.7）。

### 1.3 comp/eq 的实例复用

- `dynamic.c`：`compActive` 单指针，`compSlots[2]` 是“1 活动 + 1 影子”的参数重建机制，不是逐声道实例。
- `multimodalEQ.c`：`mEQ.activeConv` 单实例，2x2 卷积；`MultimodalEqualizerProcess` 只处理 `tmpBuffer[0/1]`。
- MC 的 `3b` 段把每对塞进同一个 vendor 实例：换对时 OLA 尾、包络、卷积 FIFO 全部带上一对的状态（细审 M-1，阻断级）。

### 1.4 bassmono 只处理 L/R

`dsp_bassmono.cpp` 固定 `bm_lp_l/bm_lp_r`，只读写 `io[i*2]` / `io[i*2+1]`。MC 链只把 FL/FR 拷进 `shelf_scratch` 再调用，环绕/LFE 完全不过。

### 1.5 postGain 只作用 FL/FR

vendor `stage_output`（`jdspController.c`）只处理 `tmpBuffer[0/1]`；MC 链又只在 FL/FR vendor 段里带 `output`，所以环绕/LFE 不衰减（细审 M-4）。

### 1.6 VB 8×8 拓扑

`core/desktop/windows-drivers/bridge/vm_bridge/VmBridge.cpp`：`nEng` 个独立引擎句柄，每个句柄独立 `channels.count`；参数由 `MirrorReplay` 广播到各组。逐声道状态只要存在 handle 内 `[8]`，天然按组隔离，不需要跨组共享 DSP 状态。

### 1.7 spatial 卡里的第二混响

`spatial.fdn` / `spatial.late` 在 `engine_param_table.h`、`param_schema.dart`、`spatial_card.dart`、`state_session.dart` 全部可达。`spatial_process()` 里 `fdn_tick(h, 0.5*(inL+inR), ...)` 是 **mono send → stereo**，不是多声道真空间；且 `spatial.fdn=1` 时立体声链会跳过 Freeverb（`engine_chain.cpp`），形成“spatial 卡内置混响”的第三套语义。

## 3. 目标架构

### 3.1 MC 链目标顺序（对齐立体声语义）

**现状核对（2026-10-25 逐行）**：`process_multichannel_chain` 的真实顺序是

```text
gate → filter → plugin0 → shelf → dyneq → tube → plugin1
→ [FL/FR scratch] bassmono → basspsycho
→ vendor "tube,comp,bass,eq"（tube 恒 0；comp/eq 仅当 FL/FR 对选中）
→ arbmag_pool(FL/FR) → vendor "convolver,ddc,liveprog,crossfeed,stereo,reverb,output"
→ plugin2 → haas → spatial → freeverb → plugin3
→ 3b：对 (2,3)(4,5)(6,7) 跑 comp/eq + arbmag
→ exciter → loudness → limiter → clamp → plugin4
```

两处需要更正此前的判断：

1. **`plugin stage 2` 已存在**（`engine_chain.cpp:900`），不是缺失。此前的“补齐 stage 2”作废。
2. comp/eq 不是“全部在 3b”：FL/FR 在 vendor 段内、2..7 在 3b —— 同一效果在两条完全不同的链位置，这才是 M-1/M-2 的根因。`arbmag` 同样是 FL/FR 前置 + 2..7 在 3b 的两段式。

**目标顺序**：

```text
 #   stage                               channels    相对现状
 1   gate_process_mc                     全声道      不变
 2   filter_process_mc                   全声道      不变
 3   plugin stage 0                      全声道      不变
 4   shelf_process_mc                    全声道      不变
 5   dyneq_process_mc                    全声道      不变
 6   tube_process_mc                     全声道      不变
 7   plugin stage 1                      全声道      不变
 8   bassmono_process_mc                 全声道      **扩展**（原仅 FL/FR）
 9   basspsycho（FL/FR scratch）          仅 FL/FR    不变
10   comp_process_mc                     全声道      **新**（逐声道）
11   vendor bass                         仅 FL/FR    从 vendor 段拆出
12   eq_process_mc                       全声道      **新**（逐声道卷积池）
13   arbmag_pool                         全声道      **合并**（原两段式）
14   vendor 段                           仅 FL/FR    convolver,ddc,liveprog,crossfeed,stereo
15   post_gain_process_mc                全声道      **扩展**（原 vendor output 仅 FL/FR）
16   plugin stage 2                      全声道      不变
17   haas                                仅 FL/FR    不变
18   spatial                             仅 FL/FR    移除 FDN/late
19   exciter_process_mc                  全声道      不变
20   mc_reverb_process_mc                全声道      **新**（原 freeverb 仅 FL/FR 且在 exciter 前）
21   plugin stage 3                      全声道      随混响后移
22   loudness_process_mc                 全声道      不变
23   limiter_process_mc                  全声道      不变
24   安全钳位                             全声道      不变
25   plugin stage 4                      全声道      不变
```

要点与理由：

- **bassmono 保持在 tube 之后**（第 8 步），只把作用面从 FL/FR 扩到全声道。不把它挪到链头：立体声链的 bassmono 在 plugin0/shelf 之前，MC 在 tube 之后——这是既有的路径差异，本工程不顺手改（见 §8 R9），避免 FL/FR 音色二次变化。
- **comp → bass → eq** 严格按 vendor 原顺序：comp 在 bass 前、eq 在 bass 后。这样 FL/FR 与 2..7 走同一组位置，只是 bass 对 2..7 不存在（FL/FR-only 效果）。
- **arbmag 合并为单次全声道 pass**，位置保持在 vendor order 的 `eq` 之后、`convolver` 之前。原两段式会让 2..7 的 arbmag 落到混响之后，属于同类错位。
- **混响放在 exciter 后、plugin3/loudness 前**：让 FDN 尾音不再经过 spatial/exciter。旧 MC 是 `freeverb → plugin3 → exciter`，尾音会被 exciter 再处理；本工程修正该顺序（FL/FR 会有可听差异，见 §8 R9）。立体声/矩阵/双耳路径的 vendor 混响位于 vendor 段内（plugin2 前），与 MC 第 20 步位置不同——这是 A+C 两条引擎路径的固有差异，不在本工程统一。
- **post gain 留在 vendor `output` 的原位置**（第 15 步，plugin2 之前），只扩到全声道 + 逐声道 trim（D13）。不挪到链尾，避免改变限幅器输入电平与整体增益级联。
- **vendor 段移除 `reverb,output`**：混响由 MC FDN 接管，postGain 由第 15 步接管，避免 FL/FR 双重处理。
- vendor 段保留 `convolver,ddc,liveprog,crossfeed,stereo`，仍只作用 FL/FR（D10）。
- **3b 整段删除**；`comp/eq` 不再走 `JamesDSPProcessMultiplexedStageSet` 的对循环。

### 3.2 混响边界

| 路径 | 引擎 | 参数来源 | 延迟 | LFE |
|---|---|---|---|---|
| 矩阵（mode=0） | vendor Progenitor2（立体声） | `reverb.preset` 预设 / `freeverb.*` 映射到 vendor 原生参数 | 30ms（`kLatReverb`） | 不适用（下混已含 LFE） |
| 双耳（binaural） | vendor Progenitor2（立体声） | 同上 | 30ms | 不适用（Nch→2ch 已处理） |
| 离散 MC（mode=1） | MC FDN（N 进 N 出） | `reverb.preset` 预设表 / `freeverb.*` 映射到 FDN 参数 | ~0ms | `reverb.lfe` 可选，默认直通 |

**双混响的结构性消失**：

- `apply_reverb()` 在 MC 路径调用 `ReverbDisable()`，在立体声路径按 `reverb.preset` 决定 `ReverbEnable()`（`>=0` 预设或 `-2` 自定义都 enable；只有 `-1` disable）。
- MC 链不再调用 `freeverb_process()`；立体声链也不再调用。
- `freeverb.enable` 变成 `reverb.preset` 的 deprecated 别名（写 1 → 若当前为 -1 则设默认预设；写 0 → -1），UI 不再使用。
- 任何路径都不会同时跑两套混响。

### 3.3 MC FDN 拓扑（N 进 N 出）

```text
ch0 ──┐
ch1 ──┤  (可选 LFE 120Hz LP + -6dB)
 ...  ├──► 预延迟(全局 0..100ms) ──► 输入矩阵 N×8 ──► 8 条延迟线
chN-1─┘                                              │  每线一阶阻尼
                                                     ▼
                                          8×8 Hadamard 反馈（正交归一）
                                                     │
                                                     ▼
                                          输出矩阵 8×N ──► 宽度/干湿 ──► 加到各声道
```

设计约束：

- **8 条延迟线**，基准长度沿用现有 `kMs[8] = {29.7, 37.1, 41.1, 43.7, 53.3, 59.9, 67.7, 73.9}`；现有 `kFdnMax = 16384` 需扩到 **32768**（170.6ms@192k），按 `roomScale` 在 `[0.5, 2.0]` 内缩放，最长 147.8ms < 170.6ms。扩上限是内存从 ~0.5MB 增到 ~1.1MB 的原因，WP1 需在 PATCHES/注释中写明。
- **输入矩阵**：8×8 Hadamard 的前 N 行，按 `1/sqrt(8)` 归一；每个输入声道以唯一符号图样注入 8 条线，形成跨声道扩散。
- **输出矩阵**：同一个 8×8 Hadamard 的前 N 行（转置），按 `1/sqrt(8)` 归一；输出到各声道。LFE 关闭时其输出行置零（只留干声）。
- **反馈**：8 点快速 Hadamard，正交归一；每线乘 `g = 10^(-3 * len / (rt60 * fs))`，clamp 0.995。`rt60` 由 `freeverb.decay` / 预设表给出。
- **阻尼**：每线一阶低通，截止频率由 `freeverb.damp` 映射（18k..1k Hz），系数每块算一次。
- **宽度**：对 FL/FR、SL/SR、BL/BR 三对做 M/S 宽度调整；C/LFE 不做宽度。
- **干湿**：沿用 Freeverb 的等能量归一 `norm = 1/sqrt(max(0.01, dry² + wet²))`，`wetG = wet * 0.7`（校准常数，smoke 校验 RMS）。
- **预延迟**：全局单环，100ms 上限；0 时直通。
- **LFE**：`reverb.lfe=1` 时，LFE 先 120Hz 一阶低通、乘 0.5 再入输入矩阵；输出矩阵的 LFE 行也参与，且 LFE 湿声在加回前再过同一 120Hz 一阶低通（避免其他声道的全频混响串入 LFE）。默认 0：LFE 完全不进 FDN，输出也不加湿。
- **重置**：`mc_reverb_reset()` 清 8 线 + 预延迟 + 平滑状态；通道数/模式/预设切换时调用。
- **内存**：8×32768×4 ≈ 1.0MB + 预延迟 19.2k×4 ≈ 77KB + 状态 ≈ **1.1MB/handle**。
- **CPU**：每样本 8 线读写 + 24 次 Hadamard 加减 + 8 次乘 + N×8 输入/输出矩阵（N=8 时约 128 次乘加），48k 下 < 1% 单核量级；192k 下 < 4%。

**与 spatial 的关系**：spatial 只保留 HRTF/早期反射/头影/ITD；`fdn_tick` 从 `dsp_spatial.cpp` 抽到 `dsp_mc_reverb.cpp`（或复用同一套 FDN 内核的两个实例）。**不要**让 spatial 和 MC reverb 共用同一个 FDN 实例——两者生命周期/输入布局不同，共用会在切换时互相清尾。

### 3.4 立体声 vendor 原生参数（A+C）

现状：`reverb.c` 只有 `Reverb_SetParam(jdsp, preset)`；`sf_advancereverb()` 有 18 个参数，但会重建整个状态。

**新增 legacy API（建议 P-033）**：

```c
typedef struct {
    int   oversamplefactor;  /* 1..2 */
    float ertolate;          /* 0..1 早期反射湿比 */
    float erefwet_db;        /* dB */
    float dry_db;            /* dB */
    float ereffactor;        /* 0.5..2.5 早期反射房间倍数 */
    float erefwidth;         /* 0..1 */
    float width;             /* 0..1 */
    float wet_db;            /* dB */
    float wander;            /* 0..1 */
    float bassb;             /* 0..1 */
    float spin;              /* 0..10 */
    float inputlpf_hz;       /* Hz */
    float basslpf_hz;        /* Hz */
    float damplpf_hz;        /* Hz */
    float outputlpf_hz;      /* Hz */
    float rt60_s;            /* 0.1..30 */
    float delay_s;           /* 0..0.1 */
} AuraReverbNativeParams;

extern void Reverb_SetNative(JamesDSPLib *jdsp,
                             const AuraReverbNativeParams *p);
```

**影子槽（必须）**：

- `JamesDSPLib` 内把单个 `sf_reverb_state_st reverb` 改为 `sf_reverb_state_st reverbSlots[2]` + `sf_reverb_state_st *reverbActive`。
- 控制线程在非活动槽上 `sf_advancereverb()` 全量构建，成功后原子换 `reverbActive`；RT `ReverbProcess()` 块首读一次指针。
- 与 P-018 comp 同范式加 `reverbProcCount` / `reverbInFlight` / `retiredAt`，保证换下的槽在 RT 不再持有后才复用。
- **连续拖动合并**：`freeverb.*` 的 set hook 只置 `reverbCustomDirty` 并记录最新参数，不在每次 setter 里全量重建；控制线程最多每 20–50ms（或每个音频块边界）取一次最新值重建非活动槽。重建期间 RT 继续用旧槽，避免 60Hz 拖动把控制线程打满。预设切换（`Reverb_SetParam`）是一次性事件，不节流。
- `Reverb_SetParam()` 也改走影子槽，顺带修掉“切预设时重建 1MB 状态”的潜在卡顿。
- 内存代价：2×~1MB = **2MB/handle**；VB 8×8 = 16MB。可接受。
- 若不做影子槽，C 只能退化为“预设切换可用、自定义拖动会卡/爆音”，不建议。

**UI 参数 → vendor 原生参数映射**：

| UI 参数 | vendor 原生参数（单位） | 映射 |
|---|---|---|
| `freeverb.roomsize` 0.5..2.5 | `ereffactor` | 直接 |
| `freeverb.decay` 0..1 | `rt60_s` | `0.5 + 9.5*decay`（0.5..10s） |
| `freeverb.damp` 0..1 | `damplpf_hz` | `18000 * (1000/18000)^damp`（18k..1k） |
| `freeverb.wet` 0..1 | `wet_db` | `20*log10(max(0.001, wet))`，clamp -60..0 |
| `freeverb.dry` 0..1 | `dry_db` | `20*log10(max(0.001, dry))`，clamp -60..0 |
| `freeverb.width` 0.2..2.0 | `width` | clamp 0..1（>1 只在 MC FDN 生效） |
| `reverb.predelay` 0..100ms | `delay_s` | `/1000` |
| 固定中性值 | `ertolate=0.3`, `erefwet_db=-9`, `erefwidth=0.7`, `wander=0.2`, `bassb=0.15`, `spin=0.7`, `inputlpf=18000`, `basslpf=500`, `outputlpf=12000`, `oversamplefactor=1` | 后续如需再暴露 |

> 注意：`sf_advancereverb` 的 `wet` / `dry` / `erefwet` 入参是 **dB**（函数内 `db2lin`），`rt60` 单位秒，`delay` 单位秒，滤波截止单位 Hz；表中的 `*_db` / `*_s` / `*_hz` 是单位标注，不是结构体字段名。
>
> 注意：`freeverb.width` 当前上限 2.0 是 Freeverb 的 M/S 加宽语义；vendor `width` 是 0..1 的 wet1/wet2 混合。立体声路径 clamp 到 1，MC 路径保留 0.2..2.0 的宽度语义。UI 需要按路径显示不同的上限说明。

**`reverb.outgain/autogain`**：当前只落在 Freeverb。退役 Freeverb 后，需要在 vendor `stage_reverb` 内加输出增益/自动增益（或在 `ReverbProcess` 后处理），否则立体声路径丢功能。建议在 P-033 一并补 `reverbOutGainDb` / `reverbAutoGain` 字段，`stage_reverb` 处理。若暂不做，UI 在立体声路径隐藏这两项并注明（不推荐）。

|---|---|---|---|
| 大音乐厅 | 5 | LARGEHALL1 | 3.2s / 1.6 / 7000 / 0.45 / 1.0 / 20ms |
| 音乐厅 | 3 | MEDIUMHALL1 | 2.3s / 1.2 / 8000 / 0.40 / 1.0 / 10ms |

- `-1` 关闭。

### 3.7 comp 逐声道

**目标**：`comp.channels` 变成真正的逐声道位掩码；每个选中声道有独立的检测器/包络/OLA 状态；C 与 LFE 不再配对。

**legacy 方案（建议 P-034）**：

- `CompSlot compSlots[AURA_COMP_CHANNELS + 1]`，`AURA_COMP_CHANNELS=8`；0..7 为活动槽，8 为重建影子槽。
- `FFTCompander *compActive[AURA_COMP_CHANNELS]`；控制线程逐声道在影子槽构建，成功后换指针；用 `retiredAt` 保证换下的槽在 RT 块结束后才复用。
- 新增 `CompressorProcessChannel(JamesDSPLib *jdsp, int ch, size_t n, int enabled)`：
  - 取 `compActive[ch]`；
  - 把 mono 输入喂给 `FFTCompanderProcessSamples` 的 L 通道，并增加 `mono` 标志跳过 R 通道 FFT（否则 8 声道等于 16 通道 CPU）；
  - `tfresolution==3` 的时域分支同样只跑 L 的 `Zre/Zim`。
- 参数重建：comp 参数是全局的，8 个实例用同一组参数；控制线程逐声道重建，UI 侧对连续拖动做 30ms 防抖。重建总耗时约 8×单实例，仍在控制线程，不阻塞 RT。
- 内存：`sizeof(FFTCompander)` 约 1.0–1.2MB（FFTSIZE_DRS=8192 的多组数组）；8 活动 + 1 影子 ≈ **9–10MB/handle**；VB 8×8 ≈ 72–80MB。必须实测（§6）。
- CPU：8 声道 mono 化后约为当前 3 对立体声实例的 1.3–1.7 倍；若不做 mono 优化会到 2.7 倍。以 `smoke_vb_8x8_budget.py` 为准。
- 顺序：MC 链第 10 步，在 vendor bass 前；不再走 `3b` 的 `JamesDSPProcessMultiplexedStageSet`。

**回退**：若实测超预算，`comp.mode` 回读 1（逐对降级），UI 显示“性能模式：逐对”，并保留逐声道作为高性能选项。该降级必须诚实显示，不能静默。降级**不是**恢复旧 `3b` 位置：仍在 MC 链第 10 步，用 1 个实例处理一对（4 对 → 4 活动实例 + 1 影子，约 5–6MB/handle），位置与逐声道一致，只减少实例数。`comp.mode` 只接受 0/1，其余拒绝。

**`comp.mode=1` 的掩码语义**：只有一对的两位都置位才处理该对；半选对**不处理**（不静默扩大到另一声道）。UI 仍用逐声道 chip，mode 1 下半选对显示 warning“性能模式需成对选择”，但不改写 `comp.channels` 的存储值；切回 mode 0 时原逐声道选择仍在。smoke 必须覆盖“半选对在 mode 1 不处理、mode 0 只处理选中声道”。

### 3.8 EQ 逐声道

**目标**：`eq.channels` 逐声道位掩码；每声道独立卷积状态；MC 路径的 IR 按**设备率**设计，修复 S-6 类问题。

**方案（建议 P-035，尽量少改 legacy）**：

- 新增 `EqPool`（与 `arbmag_pool` 同范式）：
  - `FFTConvolver1x1 *conv[8]`、`loaded`、`loaded_block`、`ir_rate`；
  - 控制线程 `eq_pool_reload()`：用 `mEQ.instance.coeffGen.GetFilter(&..., h->sample_rate)` 取 IR（FILTERLEN=8192），逐个 Load；
  - RT 线程 `eq_pool_process_strided(h, io, frames, ch, ch_idx)`：按 `eq.channels` 位抽 mono 到 `shelf_scratch`，卷积，写回。
- MC 链第 12 步，在 vendor bass 后、arbmag 前；vendor EQ 在 MC 路径 gate 掉（`g.eq=0`），不再走 `3b`。
- 立体声路径保持 vendor `MultimodalEqualizer` 不变（工作率/ASRC 内自洽）。
- `operatingMode==1`（时域 IIR）时：
  - 本批 MC 路径**只支持卷积模式**；UI 不暴露该模式（当前 UI 也没有入口），文档标注为内部限制；
  - 若未来暴露，再补逐声道 IIR 状态。
- 内存：`FFTConvolver1x1` 在 block≈1024、IR=8192 时约 0.25–0.35MB/声道；8 声道 ≈ **2–3MB/handle**；VB 8×8 ≈ 16–24MB。
- EQ 频率钳制（S-5）：`eq.freq` 上限改用 `jdsp.fs`（工作率）而非 `h->sample_rate`；UI 轴保持 20Hz–20kHz，不因 96k 设备放宽到 30k。

### 3.9 低频单声道化（BassMono）：引擎语义 + UI 重规划

> 本节是 Q1/Q4 定案后的完整方案。结论：**现有 UI 不能靠加两个 chip 修补，必须重做卡片**。

#### 3.9.1 为什么现有 UI 不成立

| 现状 | 问题 |
|---|---|
| 卡片只有 3 个滑块（shelf.freq / shelf.gain / bassmono.freq）+ 1 个 `shelf.channels` 路由 | 没有声道对概念，无法表达“选哪几对” |
| `bassmono.enable` 参数存在，但卡片里**没有开关** | 用户无法单独开关单声道化 |
| 卡片总开关 `setBassShapingEnabled()` 同时写 `shelf.enable` 与 `bassmono.enable` | 总开关语义不透明；关一个等于关两个 |
| 链页 `isStageEnabled('bassmono')` 也返回 `bassShapingOn`，`toggleStage('bassmono')` 调 `setBassShapingEnabled` | 链页关 BassMono 会把搁架一起关（假开关） |
| `isSectionEnabled('shelf')` / `'bassmono'` 同样返回 `bassShapingOn` | 只开 bassmono 时搁架滑块仍显示 enabled，模块开关语义失真 |
| `ChannelRoutingSelector(pairSemantics: true)` 是 comp/eq 旧配对语义的补丁 | 复用它会把“半选无效”的陷阱带到 bassmono；且它按 8 个单声道 chip 表达，不是“对” |
| `test/bass_shaping_test.dart` 把“恰好 3 个滑块、无 AdvancedSection”钉成契约 | 重做 UI 必须同步改写该测试 |

#### 3.9.2 引擎语义（定案）

**参数**

| 参数 | 类型 | 范围 | 默认 | 说明 |
|---|---|---|---|---|
| `bassmono.enable` | bool | 0/1 | 0 | 模块开关（已有） |
| `bassmono.freq` | f32 | 20..300 Hz | 120 | 分频点（已有） |
| `bassmono.pairs` | i32 | 0..15 | `0x01` | bit0 FL/FR、bit1 C/LFE、bit2 SL/SR、bit3 BL/BR |
| `bassmono.merge` | i32 | 0/1 | 0 | 0=每对独立平均；1=所有选中声道全局平均 |

- `bassmono.pairs` 越界（<0 或 >15）**拒绝**并返回 `AURADSP_E_PARAM`，错误文案 `bassmono.pairs: out of range (0..15)`；不做静默截断。
- `bassmono.merge` 只接受 0/1，其余拒绝。

**处理式**（每声道独立一阶低通；`fs = h->sample_rate`，设备率）

```text
a       = 1 - exp(-2π·fc/fs)
lp[c]  += a · (x[c] - lp[c])                    // c ∈ S（选中且存在），状态常驻
per-pair: avg = 0.5·(lp[a] + lp[b])             // 对 (a,b)
          y[c] = x[c] + (avg - lp[c])           // = 高通 + 单声道低频
global:   avg = (Σ_{c∈S} lp[c]) / |S|           // S = 选中且存在的声道集合
          y[c] = x[c] + (avg - lp[c])  ∀ c∈S
```

- 未选中的声道**逐样本直通**（不读写其 `lp`，保证 bit-exact）。
- `|S| < 2` 时整段 no-op（没有可合并的对象）。
- **掩码/合并方式切换的瞬态**：`bassmono.pairs` 或 `bassmono.merge` 变化时，控制线程置 `bm_reinit=1`；RT 下一块对所有**选中且存在**的声道用该块首样本初始化 `lp[c] = x[c][0]`，再进入正常递推。理由：未选中声道的 `lp` 是陈旧值，直接启用会产生 `avg - lp` 的大跳变；用首样本初始化可让首块修正量接近 0。未选中声道仍不初始化。
- 每块末对**选中声道**的 `lp[c]` 做 denormal 归零（沿用现有 `fabsf < 1e-18 → 0`）；未选中声道不读写其 `lp`。
- 状态：`float bm_lp[8]`；由 `reset_channel_state()` 清零；`bm_reinit` 为一次性标志。
- 延迟：0 ms。

**声道对可用性**（由 `layout_for(ch)` 决定，WP8）

| 输出声道 | 可用对 |
|---|---|
| 2ch | FL/FR |
| 4ch（Quad = FL/FR/BL/BR） | FL/FR、BL/BR |
| 6ch | FL/FR、C/LFE、SL/SR |
| 8ch | 全部四对 |

- **对索引由 `layout_for(ch)` 解析，不是固定 0/1、2/3、4/5、6/7**：
  - 2ch：FL/FR=(0,1)；
  - 4ch（Quad）：FL/FR=(0,1)、BL/BR=(**2,3**)；
  - 6ch：FL/FR=(0,1)、C/LFE=(2,3)、SL/SR=(4,5)；
  - 8ch：FL/FR=(0,1)、C/LFE=(2,3)、SL/SR=(4,5)、BL/BR=(6,7)。
  - `bassmono.pairs` 的 bit 是**逻辑对**，不是物理声道索引；4ch 的 bit3 必须落到 2/3，不能读 6/7（越界）。
- **不存在的对被忽略，但不改写 `bassmono.pairs`**：用户从 8ch 切到 4ch 再切回，原选择应恢复。UI 只显示“已忽略 N 对”。
- 立体声/矩阵/双耳路径（以及 `channels.count=2` 的 MC 链）：只有 L/R 有效（2ch 包装或 2 进 2 出的 `bassmono_process_mc`），bit1..3 无意义。UI 按**路径**（而非只看 `channels.count`）只启用 FL/FR，并显示 `bassMonoStereoPathHint`；合并方式行隐藏。

**与 basspsycho 的关系**：本批 basspsycho 保持 FL/FR 不变，且仍在 bassmono 之后（顺序不变）。

层级规则：

1. **卡片总开关**（`SectionCard.trailing`）是唯一控制折叠的开关，语义 = “本卡是否在工作”。
   - `bassShapingOn = shelfOn || bassmonoOn`（派生，不新增引擎参数）。
   - 打开：恢复上一次的模块组合（Dart 侧记住 `_wantedShelf` / `_wantedBassmono`，默认都为 true）；若上次两个都关，则两个都开。
   - 关闭：两个模块都关，记住当前组合。
   - 两个模块都关时 `bassShapingOn=false` → 卡片折叠、总开关显示 off（诚实：确实没有处理）。
2. **模块开关**只写自己的参数：搁架 → `setShelfEnabled`，单声道化 → `setBassmonoEnabled`。互不牵连。
3. **模块标题行**统一结构：`Icon(16, p.accent) + 标题(13/w600) + InfoBadge + Spacer + AuraSwitch`。与 `spatial_card.dart` 的子效果行同构。
4. **模块之间**用 `Divider(height: 1, thickness: 0.5, color: p.hairline)` + 上下 `AuraSpace.md`，与 `ChannelRoutingSelector` 内部一致。
5. 模块关闭时，模块内控件 `enabled: false`（`ParamSlider` / `ValueSlider` 会走 `p.textDim`），而不是隐藏——用户仍能看到自己的参数。
6. **搁架的作用声道**沿用现有 `ChannelRoutingSelector(paramKey: 'shelf.channels')`（WP3 删除 `pairSemantics` 后不再传该参数），直接放在搁架模块内（它自带折叠摘要，**不要**再套 `AdvancedSection`）；summary 显示“全部 8 声道”/“已选 N 声道”。这是 8 个单声道位，和 bassmono 的“对”是两种语义，**不要**合并成一个选择器；默认 `shelf.channels=0xFF`。矩阵/双耳路径下该掩码不生效，摘要追加“（矩阵/双耳：仅 L/R）”。

#### 3.9.5 合并方式控件

- 参数：`bassmono.merge`（0=每对独立，1=全部合并）。

  - 卡片宽 ≥ 420：`Row(标签 140px + InfoBadge + Expanded(AuraSegmented))`，与 `ValueSlider` 的 140px 标签列对齐。
  - 卡片宽 < 420：标签独占一行，`AuraSegmented` 下一行通栏（`LayoutBuilder` 分支）。

### 3.10 output 逐声道（M-4，D13）

**决策**：`post.gain` **保持在现有链位置**（MC 链里 vendor `output` 所在点，目标顺序第 15 步），只做两件事：

1. 作用面从 FL/FR 扩到**全声道**；
2. 增加 `post.gain.c0..c7` **逐声道补偿**。

**不挪到链尾**：链尾挪动会改变 plugin2/haas/spatial/exciter/混响/loudness 的输入电平，也会改变限幅器看到的总增益，属于超出 M-4 的行为变更。保持原位可让旧会话的 FL/FR 增益级联逐位不变。

- 参数：
  - `post.gain`（既有主增益，dB）；
  - `post.gain.c0..c7`（新增，dB，-15..+15，默认 0）。
- MC 链第 15 步 `post_gain_process_mc()`：
  ```text
  g[c] = 10^((post_gain + post_gain_ch[c]) / 20)
  ```
  - 每声道一阶平滑（约 10ms），避免拖动 zipper；
  - `g[c]` 在块内常量，逐样本乘；
  - 未启用/全 0 时直接返回（bit-exact）。
- 立体声路径：
  - vendor `output` stage 继续应用 `post.gain`（既有行为，不动）；
  - 为让 c0/c1 与主增益在**同一级**、vendor limiter 看到最终电平，给 `JamesDSPLib` 增加 `float postGainCh[2]`（默认 1.0）与 `JamesDSPSetPostGainCh(jdsp, ch, dB)`（控制线程调用，与现有 `JamesDSPSetPostGain` 同范式），`stage_output` 改为 `tmpBuffer[c][i] * postGain * postGainCh[c]`；这是 WP5 的唯一 legacy 补丁（P-037），只影响 stereo/matrix/binaural 路径；
  - 若评审认为不值得动 legacy：退化为在 `processFloatMultiplexd` 返回后、plugin2 前乘 c0/c1；此时 vendor 内部 limiter 只看到主增益，最终 `limiter_process_mc` 仍会兜住 trim 后的峰值——必须在文档与 smoke 中标注该差异。
- MC 链 vendor 段**移除 `output`**，避免 FL/FR 双重增益；MC 的 limiter 仍由链尾 `limiter_process_mc` 承担。
- 已知路径差异（写入 §8 R9）：**bassmono** 在立体声链位于 plugin0 之前，在 MC 链位于 tube 之后。这是既有差异，D13 明确不在本工程统一。post gain 在两条路径都位于 plugin2 之前（stereo 在 vendor `output` 内，MC 在第 15 步），位置一致。
- UI：`post_card.dart` 在主增益下加“逐声道输出补偿”折叠区，按当前有效声道数显示 2/4/6/8 个 slider（声道数来源同 §3.9.4：`vizChannelCount`，WP9 后切 `channels.count`）；带“全部归零”；LFE 也显示（M-4 的核心就是 LFE 不再漏掉）。顺手修正 `isSectionEnabled('post')` 只返回 `limiterOn` 导致“限幅器关时主增益滑块被禁用”的旧问题：`isSectionEnabled('post')` 改为恒 `true`，limiter 控件各自显式 `enabled: limiterOn`，主增益/逐声道 trim 恒可用；limiter 关时延迟徽标显示 0ms。

### 3.11 统一 reset 与延迟（M-6/M-7）

新增 `reset_channel_state(auradsp_handle h)`（控制线程），按模块清理：

| 模块 | 需要重置的状态 |
|---|---|
| gate | `gate_gain/state/hold/env/ds_lp/ds_env` |
| filter / shelf | `z1/z2[8]` |
| dyneq | 3 段 `det_z1/det_z2/env/z1/z2` |
| tube | 逐声道状态（`tube_process_mc` 内部数组） |
| exciter / loudness | 逐声道 one-pole / 包络 |
| limiter | `mc_limiter_*` 环/包络/deque |
| bassmono / basspsycho | `bm_lp[8]` / `psy_*` |
| haas | `haas_ring` |
| spatial | `spatial_reset` |
| MC reverb | `mc_reverb_reset` |
| comp/eq/arbmag 池 | 逐声道实例 reset（卷积 FIFO 清零） |
| vendor 段 | `apply_reverb` + 必要的 vendor refresh |

调用点：

- `set_channels_mode`（已有 `spatial_reset`，替换为全量 reset）
- `set_channels_count`（同上）
- `hook_spatial_binaural`（新增）
- `hook_spatial_enable`（现有 `spatial_reset`，补全量 reset + `apply_reverb`）
- `set_reverb_preset`：只重置混响状态（MC FDN / vendor 影子槽），不全量 reset
- `compute_latency` 在以上所有拓扑变化后调用（M-7）
- 若 vendor 段需要新增显式 reset 入口（如 `JamesDSPResetVendorState`），登记为预留的 P-036；否则该号保留不用。

**防爆音**：`channels.count` 变化通常伴随流重启，可硬重置；`channels.mode` / `spatial.binaural` 是直播切换，建议 5ms 淡出→重置→5ms 淡入。若实现成本高，至少在 smoke 中测“切换无 > -60dBFS 的瞬态”，并把硬重置标为已知限制。

### 3.12 布局常量 / viz（M-8/M-10/M-11）

- 新增 `SpeakerLayout`（`engine_internal.h` 或 `engine/chain/speaker_layout.h`）：
  ```c
  struct SpeakerLayout {
      int count;
      int fl, fr, c, lfe, sl, sr, bl, br; // -1 = 不存在
  };
  SpeakerLayout layout_for(int ch);
  ```
  - 2ch：FL/FR
  - 4ch：FL/FR/BL/BR（Quad，沿用 ADR-003）

## 4. 参数、预设、会话迁移

### 4.1 参数表

| 参数 | 类型 | 默认 | 状态 | 说明 |
|---|---|---|---|---|
| `reverb.preset` | i32 | -1 | 语义扩展 | 唯一混响开关：-1 关、-2 自定义、0..18 预设；路径决定引擎 |
| `freeverb.enable` | bool | 0 | deprecated | 写 1 → 若 -1 则设默认预设；写 0 → -1；UI 不再使用 |
| `freeverb.decay/damp/wet/dry/roomsize/width` | f32 | 保持 | 语义扩展 | 统一“混响自定义参数”；立体声映射 vendor 原生，MC 映射 FDN |
| `reverb.predelay` | f32 | 0 | 新增 | 0..100ms，两引擎共用 |
| `reverb.lfe` | bool | 0 | 新增 | 仅 MC：LFE 入混响（120Hz LP + -6dB） |
| `reverb.engine` | i32 | — | 新增 get-only | 0=vendor stereo、1=MC FDN、-1=off（调试/诚实显示） |
| `spatial.fdn` | bool | 0 | deprecated | 写 1 → 若混响关则开默认预设；不读回；UI 移除 |
| `spatial.late` | f32 | 0.25 | deprecated | 写 → 若 `freeverb.wet` 为默认则写入；不读回；UI 移除 |
| `bassmono.pairs` | i32 | 0x01 | 新增 | 标准四对位掩码（bit0 FL/FR、bit1 C/LFE、bit2 SL/SR、bit3 BL/BR） |
| `bassmono.merge` | i32 | 0 | 新增 | 0=每对独立平均；1=所有选中声道全局平均；仅 0/1 |
| `post.gain.c0..c7` | f32 | 0 | 新增 | 逐声道输出补偿 dB |
| `comp.channels` | i32 | 0xFF | 语义变更 | 真逐声道位掩码；C/LFE 不再配对 |
| `comp.mode` | i32 | 0 | 新增 | 0=逐声道（默认）；1=逐对降级（性能模式，1 实例/对）；仅 0/1 |
| `eq.channels` | i32 | 0xFF | 语义变更 | 真逐声道位掩码 |
| `channels.countMode` | i32 | 0 | 新增（纯状态） | 0=自动、1=手动；isolate 读取，不参与 DSP |
| `channels.count` | i32 | 2 | 已有 | 2/4/6/8；U-1 手动入口 |

> `channels.countMode` 走“纯状态载体参数”模式（与 `bass.mode` 同），避免新增 IPC 消息；引擎只存值，isolate 通过参数镜像读取。
>
> `reverb.engine` 是只读诊断参数：写入直接拒绝（`AURADSP_E_PARAM`），UI 只读；值在 `apply_reverb()` / 路径切换后更新，供“当前引擎”徽标与 smoke 断言使用。

### 4.2 预设迁移

- 旧会话的 `reverb.preset=0..18`：立体声路径保持 vendor 原预设；UI 若不在 curated 集合，显示“旧预设”。
- 旧会话的 `freeverb.enable=1` + `reverb.preset>=0`：加载时以 `reverb.preset` 为准，`freeverb.enable` 忽略（不再双开）。
- 旧会话的 `freeverb.enable=1` + `reverb.preset=-1`：视为旧“自定义”态，加载时设 `reverb.preset=-2`，并把 `freeverb.*` 映射到 vendor 原生 / FDN；否则用户的 Freeverb 自定义会变成完全关闭。
- 旧会话的 `reverb.preset=-2`：保持自定义；立体声用 vendor 原生映射，MC 用 FDN。
- 旧会话的 `spatial.fdn=1`：加载时若 `reverb.preset==-1`，设 `reverb.preset=5`（大音乐厅）并把 `spatial.late` 写入 `freeverb.wet`；`spatial.fdn/late` 之后忽略。
- `bassmono.pairs` 缺省 → 0x01（FL/FR），与旧行为一致。
- `bassmono.merge` 缺省 → 0（每对独立）；旧会话没有该参数时行为与旧版 L/R 平均完全一致。
- `post.gain.c*` 缺省 → 0，与旧行为一致。
- comp/eq 旧掩码（如 0x3F、0x33）原样保留；逐声道语义下 C/LFE 不再联动，属于预期行为变化，release notes 说明。

### 4.3 ABI / 兼容

- 不改变 `auradsp_viz_frame` / `AURADSP_ABI`；`channels.count` 已是 custom 参数。
- 新增参数走 `auradsp_set_param` 字符串路径；老客户端不感知。
- `spatial.fdn/late` 保留注册为 deprecated 写别名，至少保留一个发布周期；之后可移除。
- `freeverb.enable` 保留注册为 deprecated 别名，不读回。
- legacy 结构体内部布局可变（`reverbSlots`、`compActive[8]`），不对外暴露 ABI。

## 6. VB 8×8 预算

### 6.1 拓扑

- `nEng` 个独立 handle；每个 handle 独立 `channels.count`；参数 `MirrorReplay` 广播。
- 逐声道状态在 handle 内 `[8]`，天然按组隔离；**不要**跨 handle 共享 FDN/comp/EQ 实例。
- 8 组 × 8 声道 = 64 声道总处理量；实际是否同时 8 组由 VB 拓扑决定，但预算按最坏情况算。

### 6.2 内存（每 handle，估算，需实测）

| 项 | 估算 | 备注 |
|---|---|---|
| MC FDN | ~1.1MB | 8×32768×4 + 预延迟 |
| comp 逐声道 | ~9–10MB | 8 活动 + 1 影子，`sizeof(FFTCompander)` 实测 |
| EQ 池 | ~2–3MB | 8×FFTConvolver1x1，IR 8192 |
| arbmag 池 | 既有 | 以现有实测为准 |
| vendor reverb 双槽 | ~2MB | 立体声/双耳路径 |
| vendor comp 双槽 | 既有 | 立体声路径 |
| **合计** | **~15–18MB** | 不含插件/卷积 IR |
| **VB 8×8** | **~120–144MB** | 加上插件后可能 200MB+ |

### 6.3 CPU（每 handle，48k，估算与实测）

| 项 | 估算 | 实测（`smoke_vb_8x8_budget.py`） | 说明 |
|---|---|---|---|
| MC FDN 8ch | <1% 单核 | 约 0.3% | 每样本 ~128 乘加 |
| bassmono 8ch | <1% 单核 | <0.1% | 8×one-pole + 每样本约 4 次加乘；可忽略 |
| EQ 池 8ch | 2–4% | 约 2.1% | 8×`FFTConvolver1x1` 分区卷积 |
| comp 8ch（mono 优化） | 15–25% | **10.14%** | 8×FFT 8192，mono-aware 优化后远低于 25% 预算门限 |
| 其他逐声道 | 5–10% | 约 1.5% | gate/filter/dyneq/tube/exciter/loudness/limiter |
| **合计（全栈全开）** | **<40% 单核** | **13.98% 单核** | 远低于 40% 预算门限，8 组在现代多核处理器上开销平稳 |
| **8 Handle 活跃 RSS 增量** | **<150MB** | **0.00MB（<1MB）** | 预分配内存充足，无堆颠簸 |

> **WP3 实测定案结论**：`smoke_vb_8x8_budget.py` 门禁全绿（单 handle 全开仅 13.98% 单核、comp 8ch 仅 10.14% 单核、内存增量 < 150MB、反向验证开/关比达 14x 证明非空转）。因此 **无需强制降级为逐对**，系统默认安全维持 `comp.mode=0` 逐声道独立处理；`comp.mode=1` 作为手动切换的高效对模式回退选项保留。

### 6.4 降级策略

- comp：
  - 默认逐声道；若 `smoke_vb_8x8_budget.py` 超预算，`comp.mode=1` 逐对降级，UI 显示“性能模式：逐对”。
  - 逐声道仍作为“高性能”选项保留；不静默降级。
- EQ：8×卷积池成本可控，不设降级；若 IR 过长导致内存超限，限制 MC EQ 为 6ch 或提示用户关闭。
- MC FDN：固定 8 线，不做通道数降级；N<8 时矩阵规模自然减小。

### 6.5 测量方法

新增 `test/smoke/smoke_vb_8x8_budget.py`：

- 创建 8 个 handle，`channels.count=8`、`channels.mode=1`；
- 开启 gate/filter/shelf/dyneq/tube/bassmono/comp/eq/loudness/limiter/reverb；
- 8ch 粉噪，480 帧块，跑 60s 音频；
- 记录 wall time / audio time、峰值 RSS、每 handle 的 comp/EQ/FDN 分段耗时（可在 engine 侧加 `std::chrono` 临时计点，或只测总墙钟）；
- 阈值：单 handle 总 CPU < 40% 单核@48k；8 handle 峰值 RSS 增量 < 150MB；comp 8ch < 25% 单核；
- 反向验证：临时把 comp 改回逐对，确认逐声道耗时明显更高，证明测量非空转。

### 10.1 Q1 的追加要求（UI 整体重规划）

现有 `bass_shaping_card.dart` 是“3 个滑块 + 一个搁架路由”，无法表达声道对、没有 bassmono 独立开关，且总开关会同时写两个 `enable`。定案：

- 拆成**低频搁架 / 低频单声道化**两个模块，各自 `AuraSwitch`；
- 新增专用 `PairRouteSelector`（4 个对 chip），不复用 `ChannelRoutingSelector`、不恢复 `pairSemantics`；
- 卡片总开关派生 `bassShapingOn = shelfOn || bassmonoOn`，并记住上次模块组合；
- `isStageEnabled` 的 `shelf` 只看搁架、`bassmono` 只看单声道化、`bass_shaping` 为两者 OR；链页现有 `bassmono` 行只切单声道化（`shelf`/`bass_shaping` 当前没有独立链页行，只服务卡片与延迟探针）；
- 三主题（`auraDark/auraLight/aurora`）、三语（zh/en/ja）、响应式与可访问性按 §3.9.7–§3.9.9 执行。
