## 1. 架构裁定：两段式（引导壳 + Flutter 向导）

02 号文档在 C++（方案 A）与 Flutter（方案 B）之间推荐 B，并留了
「C++ 极简解压壳驱动」作为封装形态。本实施采用两者的咬合：

| 组件 | 技术 | 职责 | 规模目标 |
| :--- | :--- | :--- | :--- |
| **引导壳 bootstrapper** | C++ Win32（单文件 `bootstrapper.cpp`，零第三方依赖） | 校验并解出内嵌的向导运行时到 %TEMP%，透传参数启动向导，退出 | ≤600 行，原生面最小化 |
| **安装向导 wizard** | 独立 Flutter Windows 工程 | 全部 UI、安装/卸载引擎、系统集成（注册表/COM/快捷方式/驱动脚本编排） | 与主应用同一设计体系 |

裁定理由：
1. **视觉**：用户要求「高级且与众不同、完全自定义」——向导直接复用
   主应用的极光（aurora）设计语言（色板见 §4.2）、字体与动效，成品
   与主程序浑然一体；手写 D2D 界面无法在无本地 Windows 编译/渲染
   验证的条件下保证同等完成度。
2. **可验证性**：向导的 Dart 代码可在任意平台过 analyze 与单测；
   原生代码只剩引导壳的解压与进程启动（保守 API），由 CI 在
   windows-latest 上编译验证（见 §7）。
3. **单体分发**：最终仍是一个 `AuraDSP-Setup-x64-v<ver>.exe`
   （02 §5 的单体结构），引导壳即其 PE 本体。

## 2. 单体 Setup EXE 文件格式

```text
+----------------------------------------------------------+
| PE：引导壳（bootstrapper.exe 本体，含图标/版本资源）        |
+----------------------------------------------------------+
| ZIP-W：向导运行时（wizard 构建产物：auradsp_setup.exe、    |
|         flutter_windows.dll、data/ 等，ZIP-STORED 不压缩） |
+----------------------------------------------------------+
| ZIP-P：产品载荷（payload/ 前缀目录，deflate）               |
+----------------------------------------------------------+
| 尾部元数据块（80 字节，小端，布局见下）                    |
+----------------------------------------------------------+
```

- 元数据块定长 **80 字节**：magic(8) + fmtVer(4) + flags(4) +
  offW(8) + lenW(8) + offP(8) + lenP(8) + sha256P(32)。
  sha256 只覆盖 ZIP-P（产品载荷，用户资产完整性关键面）；
  ZIP-W 的完整性由其内 `wizard_manifest.json`（向导文件清单及
  各文件 SHA256）二级校验，向导启动时自检。fmtVer=1。
- pack.py 负责拼装（append 两个 zip + 写尾块），并提供
  `--verify` 自检模式解析尾块回读校验（CI 与本地逻辑测试共用）。
- 引导壳只读尾块 → 按 offW/lenW 解出 ZIP-W 到
  `%TEMP%\AuraDSP-Setup\<tag>-<pid>\wizard\`，校验 ZIP-P 的
  SHA256（流式，边读边算，失败即中止并报错），把
  `--payload-exe <自身路径> --payload-off <offP> --payload-len <lenP>`
  等参数透传给向导后退出。**引导壳不解压产品载荷**（由向导按
  组件选择解压，避免双倍 IO）。
- 向导解压 ZIP-P 时以 offP/lenP 切出字节段落盘为临时 zip 再用
  `archive` 包解压（纯 Dart，跨平台可测）。

## 3. 引导壳规格（bootstrapper/）

- 入口 `wWinMain`，无窗口（失败时 MessageBox 报错）；Per-Monitor
  V2 DPI 与 `requireAdministrator=false`（asInvoker）清单——
  提权由向导在需要时按 §5.6 协议自提权，引导壳保持普通权限，
  SmartScreen 姿态更友好。
- 解压安全：条目路径规范化后必须仍在目标目录内（防 `../` 穿越），
  拒绝符号链接/设备文件条目，单文件与总量上限取自 zip 头并做
  合理性校验（>4GB 拒绝）。
- 参数透传：自身收到的全部参数原样转发给向导，并追加
  `--setup-exe <path>` 与载荷定位参数；若 argv[0] 文件名为
  `uninstall.exe`（不区分大小写）或参数含 `--uninstall`，
  自动追加 `--mode uninstall`。
- 向导进程结束后不阻塞（引导壳先退，临时目录由向导在结束时
  自清理；异常残留由下次启动时按 tag 前缀清扫）。
- 构建：独立 `CMakeLists.txt`（target `auradsp_bootstrapper`，
  产物名 `bootstrapper.exe`），链接 `shell32/shlwapi/bcrypt`
  （SHA256 用 BCrypt 流式计算，避免自带实现）。
- **解压零依赖（2026-11-06 修订）**：ZIP-W 固定为 **ZIP-STORED
  不压缩**，引导壳手写 stored 条目解包器（中央目录解析 + 路径
  穿越防护，约 150 行），不引入任何第三方解压代码——引导壳是
  整条信任链的第一环，攻击面最小化优先；代价是向导段约多
  10MB（flutter 运行时未压缩），可接受。ZIP-P 仍为 deflate，
  由向导的 `archive` 包解压。若未来体积敏感，再评估以 vendored
  miniz 换回 deflate 并同步修订本条。

## 4. 向导规格（wizard/）

### 4.1 工程与窗口

- Flutter 工程：`installer/windows/custom_installer/wizard/`，
  包名 `auradsp_setup`，可执行名 `auradsp_setup.exe`。
- 窗口：固定 920×600 逻辑像素、无边框（`window_manager`，与主
  应用同款插件），自绘标题栏（拖拽/最小化/关闭），圆角 +
  DWM 阴影；不支持缩放。
- 依赖：`window_manager`、`archive`（zip 解压）、`win32` +
  `ffi`（系统集成 FFI）、`path`、`crypto`（清单哈希校验）。
  版本以 `pubspec.yaml` 锁定、CI 复现为准。

### 4.2 视觉设计（极光主题，取自主应用 tokens.g.dart 实值）

- 底色 `auroraBg #070B14`，面板 `#0E1626` 系半透明玻璃层，
  主强调 `auroraAccent #64F0DC`（青），次强调沿用主应用荧光绿
  `#D4FF3F`（成功态）与橙 `#FF6B35`（警告态）。
- 背景：全窗 CustomPainter 极光层——3 条缓慢漂移的高斯径向
  光斑（青/蓝紫/绿）+ 细噪点网格，60fps 以外的低频重绘（2s
  缓动周期驱动，避免耗电与风扇噪声）。
- 版式：左侧 300px 品牌区（Logo、产品名、版本号、竖排步骤
  指示器），右侧内容区页面切换（淡入 + 8px 位移，240ms
  easeOutCubic）。
- 进度页：极光渐变进度轨 + 流光高光、当前操作文案实时滚动
  （安装引擎事件流驱动），可展开「详情」看逐文件日志。
- 完成页：对勾描画动画（CustomPainter 路径生长 600ms）+
  极光光晕扩散一次。
- 字体：跟随系统（Segoe UI / 微软雅黑回退链），标题 28px
  半粗，正文 13.5px——与主应用字阶同源。

### 4.3 页面状态机（对齐 02 §2，含卸载流）

```text
安装流：CheckEnv（进程冲突门）→ Welcome（许可勾选）
        → Options（目录/组件/快捷方式/自启；全用户模式开关）
        → Progress（引擎事件流）→ Finish（启动应用/声音设置）
卸载流：UninstallConfirm（保留数据选项）→ Progress → Finish
异常：Progress 任一关键步失败 → Rollback 执行 → Error 页（错误码+日志路径）
```

### 4.4 文案与多语言

`lib/l10n/` 放 zh/en/ja 三套 arb（安装域字符串子集，自维护，
不与主应用 arb 耦合）；默认跟随系统语言，标题栏可切换。

## 5. 安装引擎规格（wizard/lib/engine/，纯 Dart 服务层）

| 服务 | 职责与关键口径 |
| :--- | :--- |
| `ProcessGuard` | Toolhelp 快照枚举 `auradsp_app.exe` / `plugin_host_x64.exe` / `plugin_host_x86.exe`；命中先 `WM_CLOSE` 优雅退出（等 3s），未退则 TerminateProcess。DAW 宿主不杀，只提示 |
| `PayloadExtractor` | 按组件选择解压 ZIP-P 子集到安装目录，逐文件记录 `{path, size, sha256}` 生成安装清单；解压失败即抛错走回滚 |
| `RegistryManager` | 写卸载项（§5.5 字段表）；写 `HKCU/HKLM\Software\AuraDSP`（InstallDir/Version）；自启项 `HKCU\...\Run\AuraDSP`（可选） |
| `AsioRegistrar` | FFI 加载安装目录内 `auraasio_driver.dll` 调 `DllRegisterServer`/`DllUnregisterServer`。事实依据：驱动源码 `AuraAsioDriverMain.cpp`——CLSID `{4B617572-6144-5350-4153-494F44727631}`、ASIO 名 `AuraDSP Driver`，其注册函数自带 HKLM 主写 + HKCU 兜底；提权时全量生效，未提权时降级 HKCU 并回报「DAW 可见性受限」警告 |
| `VaioDriverInstaller` | 仅当「VAIO 驱动」组件勾选且已提权：对载荷 `driver/` 子目录执行 `install_driver.ps1`（该脚本内建 DRV 规约残留清理）；捕获退出码与输出尾部进日志；失败记警告**不回滚**（应用本体可用，驱动可事后重装），Finish 页明示 |
| `ShortcutManager` | `win32` 包 COM `IShellLink` 建桌面/开始菜单 `.lnk`（目标 auradsp_app.exe，工作目录=安装目录，图标同 exe,0）；卸载按清单删 |
| `UninstallerEmitter` | 把 Setup 本体复制为安装目录 `uninstall.exe`（即单体 exe，靠 argv[0] 识别卸载模式），写 `install_manifest.json`（版本/模式/ hive/组件/文件清单/快捷方式清单） |
| `ElevationManager` | Options 选全用户模式或 VAIO/ASIO 全量注册时：向导以 `ShellExecute(runas)` 自重启并追加 `--elevated --resume-options <临时状态文件>`，原进程退出；状态文件位于 %TEMP% 且用后即删 |
| `RollbackManager` | Progress 关键步失败：按已执行步逆序撤销（删已解压文件、注销已写注册表/快捷方式），保留日志，展示 Error 页 |

### 5.5 卸载注册表项字段（02 §4.3 落实，修正其示例错误）

键：Per-User `HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\AuraDSP`；
All-Users 同路径 HKLM。字段：DisplayName=`AuraDSP`、
DisplayVersion=`<FULL_VERSION>`（如 0.1.0.1）、Publisher=`li589`、
DisplayIcon=`<InstallDir>\auradsp_app.exe,0`、InstallLocation、
UninstallString=`"<InstallDir>\uninstall.exe"`、
QuietUninstallString=`"<InstallDir>\uninstall.exe" /silent`、
EstimatedSize（KB，实测汇总）、NoModify=1、NoRepair=1、
URLInfoAbout=`https://github.com/li589/AuraDSP`
（02 示例中的 `github.com/AuraDSP/AuraDSP` 为占位错误，一并修正）。

### 5.6 载荷构成（ZIP-P 的 payload/ 目录）

| 内容 | 来源 | 备注 |
| :--- | :--- | :--- |
| 主程序全套（auradsp_app.exe、*.dll、data/） | staging `dist/AuraDSP-Windows-x64/` | build_windows.ps1 产物，含引擎/三桥/双宿主 |
| `auraasio_driver.dll` | **收集项**：pack.py 从 `core/desktop/windows-drivers` 产物目录定位 | **缺口登记**：当前 staging 不含 ASIO 驱动本体（只有客户端桥 auraasio_bridge.dll）；setup 模式缺此文件直接报错，portable 模式仅警告。**（2026-11-07 已修）** 根因有二：build_windows.ps1 从未构建 auraasio_driver 目标；安装器侧文件名口径误写作 AuraAsioDriver.dll，与 ADR-008 的规范名 auraasio_driver.dll 不一致（带下划线，按名查找永远落空）。修复：ps1 Step 3 补建该目标并做就绪检查；pack.py 发现逻辑以规范名为准、别名兼容发现、入包一律归一化为规范名；向导 asioDllPath 同口径（规范名优先、别名回退）；fixture 新增别名归一化与 ZIP-P 载荷断言 |
| `driver/`（VAIO 驱动 .sys/.inf/.cat + `install_driver.ps1` + 测试证书） | pack.py 从 `01_vaio_driver` 构建产物与源码目录组装 | 见 pack.py `--driver-dir` |
| `resources/` | 按 `--resources` 策略（§6） | core/full/none/addons-merged |
| `build-info.txt` | dist_manifest 生成 | 随包可追溯 |

## 6. pack.py 规格（installer/windows/pack.py，全量可传参）

定位：**Windows 发行的唯一打包入口**（01 §5 的 `package-windows`
落点）。纯 Python（pathlib/zipfile/hashlib），逻辑层与平台无关，
可在 Linux 上以 fixture staging 做全模式逻辑自测；Windows 专属
动作（签名、真实 staging 构建调用）以参数开关隔离。

### 6.1 参数表

| 参数 | 默认 | 说明 |
| :--- | :--- | :--- |
| `--mode` | `all` | 逗号分隔：`driver,portable,setup` 或 `all` |
| `--resources` | `core` | `core`（staging 自带）/ `full`（合并 full 资源包）/ `addons`（合并 core+full+全部 addon 包）/ `none`（剔除 resources） |
| `--rebuild-resource-packs` | 关 | 先跑 `tools/resource_pipeline/build_packages.py` 重建 `dist/resources/*.zip` 再合并 |
| `--staging` | `dist/AuraDSP-Windows-x64` | 主程序 staging 目录 |
| `--build-staging` | 关 | 先调 `tools/windows/build_windows.ps1`（透传 `--build-type`、`--skip-drivers` 等）生成 staging |
| `--driver-dir` | 自动探测 | VAIO 驱动产物目录（含 .sys/.inf/.cat） |
| `--asio-driver` | 自动探测 | auraasio_driver.dll 路径 |
| `--installer-build-dir` | 自动 | 引导壳 + 向导已构建产物目录；`--build-installer` 时先行构建 |
| `--build-installer` | 关 | cmake 构建 bootstrapper + `flutter build windows` 构建 wizard |
| `--version` | pubspec | 覆盖版本号（仍过 version_resolver 格式校验） |
| `--out` | `dist/` | 产物输出目录 |
| `--zip-level` | `6` | zip 压缩等级 0–9（便携包/载荷共用） |
| `--sign` | 关 | 对 Setup exe 与驱动包内 .sys/.cat 之外的 exe/dll 调 signtool（`--signtool`、`--cert-thumbprint` 或环境变量 `AURADSP_SIGN_PFX`/`AURADSP_SIGN_PASS`）；未配置证书时警告跳过（当前驱动为测试签名，正式签名属 05 号规划风险项） |
| `--clean` | 关 | 构建前清理 `--out` 中同名旧产物 |
| `--what-if` | 关 | 只打印计划与输入校验结果，不写任何文件 |
| `--verify` | — | 对已生成的 Setup exe 解析尾块并校验双 zip 与 SHA256 后退出 |

### 6.2 各模式产出

```text
driver   → AuraDSP-Driver-x64-v<ver>.zip
           （driver/ 全套 + install_driver.ps1 + auraasio_driver.dll
             + 注册脚本 register_asio.ps1（pack.py 生成，封装
             regsvr32 静默注册/反注册，供绿色场景手动集成））
portable → AuraDSP-Windows-x64-v<ver>.zip（staging 按 resources
             策略加工后的整目录，含 build-info.txt 刷新）
setup    → AuraDSP-Setup-x64-v<ver>.exe（§2 单体格式）
共通     → 刷新 staging 的 build-info.txt（dist_manifest）；
             --sha256sums 时生成/更新 dist/SHA256SUMS.txt
```

### 6.3 资源合并语义（--resources full/addons）

资源包（`dist/resources/auradsp-resource-*.zip`、
`auradsp-addon-*.zip`）的 zip 根即 resources 内容布局
（build_packages.py 已演练验证：相对路径确定性统一、覆盖幂等、
`user_data/` 隔离）。合并 = 在 staging 的**临时副本**上按
core → full → addons（按文件名序）依次解开覆盖 `resources/`，
不污染原 staging；`none` = 副本中删除 `resources/`（保留空壳
目录与 manifest.json 占位说明）。合并后在 build-info 追加
`resources-mode` 与各包 SHA256 记录。

## 7. CI 规格（新增独立工作流，不动现有 ci.yml）

`.github/workflows/windows-installer.yml`（windows-latest；
push 到 feature/linux 且路径命中 installer/windows/**、
tools/resource_pipeline/**、本工作流，或手动 dispatch）：

1. 检出 + Flutter 3.47.9（subosito/flutter-action，与主 CI 同钉版）。
2. 构建向导：`flutter pub get` + `flutter build windows --release`
   于 wizard/；`flutter analyze` 先行把关。
3. 构建引导壳：cmake 配置/构建 bootstrapper/（MSVC，windows-latest
   自带），产物校验存在。
4. fixture staging：脚本生成最小假 staging（占位 exe/dll/driver
   文件 + resources 骨架 + 真实 install_driver.ps1 拷贝），另以
   本仓真实 `auraasio_driver.dll` 缺失场景验证 setup 报错路径、
   以占位 dll 验证成功路径。
5. 跑 pack.py 全模式（driver/portable/setup，resources=core 与
   addons 各一次）+ `--verify` 校验 Setup exe。
6. 上传 artifacts：Setup exe、三包 zip、pack 日志（保留 14 天）。

## 9. 已知风险与取舍

1. **驱动签名**：VAIO 驱动当前测试签名——Setup 即便完美，目标机
   未开测试模式时驱动仍装不上；属 05 号规划已登记的外部风险，
   不在本实施范围，向导在驱动步失败时按 §5 口径降级警告。
2. **win32 包 COM 绑定**：IShellLink 等接口以 `win32` 包当前
