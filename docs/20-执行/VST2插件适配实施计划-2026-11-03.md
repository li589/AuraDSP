## 3. 关键决策

### D-1 编译头：收编 Xaymar 净室 `vst.h`，退役仓库内 LSP 头

- **现状核查（2026-11-03）**：`vendor/plugin-api/steinberg/vst2.h` 的 Doxygen 注释与 Steinberg 官方 `source/vst2sdk/vstsdk2.4/pluginterfaces/vst2.x/aeffect.h` **逐字相同**（例如「The magic number that allows to identify VST 2.x effect」），只把版权头替换为 LSP 的 ISC 声明。这不是净室重建，存在许可瑕疵；
- **合规源**：`source/vst2sdk/vst2sdk/include/vst.h`（Xaymar，BSD-3-Clause，3161 行）是审计报告 §2.11 明确指定的唯一合法编译源，已被 DPF / OBS / DISTRHO 等采用；
- **处置**：
  1. 把 `vst.h` 与 `LICENSE` 收编到 `vendor/plugin-api/vst2/`（只读、原样、保留版权头）；
  2. **删除** `vendor/plugin-api/steinberg/vst2.h`、`vst2main.h`、`vst2_keytable.h`（当前全仓无引用；git 可回溯；删除即消除误用风险）；
  3. Steinberg 官方 2.4 归档继续只读隔离在 `source/vst2sdk/vstsdk2.4/`，仅用于 Dispatcher 语义对照，**不进 `vendor/`、不进 git、不进 Release**；
- **API 适配**：Xaymar 的命名是 `vst_effect_t` / `vst_effect_control_t` / `VST_EFFECT_OPCODE_*` / `VST_HOST_OPCODE_*`。驱动内可用 `using` 别名映射到熟悉的名字（`using AEffect = vst_effect_t;`），但**结构体定义只允许来自 `vst2/vst.h`**。

### D-1a 32 位回调 ABI 陷阱（必须按此实现）

Xaymar 头把宿主回调声明为：

```c
typedef intptr_t (VST_FUNCTION_INTERFACE *vst_host_callback_t)(
    vst_effect_t* plugin, int32_t opcode, int32_t p_int1,
    int64_t p_int2, const char* p_str, float p_float);
```

其中 `p_int2` 是 **`int64_t`**，而官方 VST2 ABI 的 `VstIntPtr` 在 32 位下是 **4 字节**。若宿主按该 typedef 实现回调，32 位插件调用时 `p_str` / `p_float` 会整体错位 4 字节，表现为指针乱码或崩溃。因此：

- 宿主侧**自定义**回调签名，`value` 用 `intptr_t`：

```c
static intptr_t VST_FUNCTION_INTERFACE hostCallback(
    vst_effect_t* effect, int32_t opcode, int32_t index,
    intptr_t value, void* ptr, float opt);
```

- 传给 `VSTPluginMain` 时再 `reinterpret_cast<vst_host_callback_t>`（两者在 64 位下等价，32 位下以我们的 `intptr_t` 为准）；
- 门禁：32 位探针必须验证 `audioMasterVersion` / `audioMasterGetSampleRate` 返回值正确，且编辑器/音频无崩溃。

### D-2 宿主路由：64 位进程内默认，32 位强制位桥

| 位数 | 默认路径 | 例外 |
|---|---|---|
| 64 位 VST2 | 引擎进程内（`Vst2Instance` 直接 `LoadLibrary`） | `AURA_PLUGIN_HOST_MODE=process` 时转 `plugin_host_x64` 沙箱 |
| 32 位 VST2 | `plugin_host_x86.exe` 位桥（现有 `remoteClientFor` 自动分派） | 进程内模式不具备加载 32 位的能力，仍走桥；桥缺位则报错，不退化 |

理由：64 位进程内是零拷贝、最低延迟路径，与现有 VST3/CLAP 默认一致；32 位没有选择，必须跨进程。

### D-3 扫描：PE 导出表廉价判定 + 32 位远程深扫

VST2 没有 bundle，扫描目录下每个 `.dll` 都可能是插件，也可能是依赖库。策略：

1. 新增 `peHasVst2Entry(path)`：解析 PE 导出表，检查 `VSTPluginMain` 或旧式 `main`，**不 `LoadLibrary`**；
2. `matchesPath` 只认 `.dll`；`resolveBinary` 对文件返回路径**前提是导出表命中**，否则返回空 → 枚举阶段直接过滤掉非插件 DLL；
3. 快扫：PE 版本资源（公司/产品/版本）+ 文件名 stem，`is64Bit` 由 PE 头判定；
4. 深扫：
   - **64 位（进程内）**：**不做 `LoadLibrary`，只保留 PE 快扫**。实测 `C:\Program Files\VstPlugins` 下 Blue Cat PatchWork / FabFilter 等真实 VST2 在 `VSTPluginMain`/`effOpen` 阶段直接 `0xC0000005`，整进程崩溃；扫描阶段加载未知厂商 VST2 不可接受。真实元数据由**加载路**补齐（用户显式挂载时才实例化，仍受异步超时/隔离区保护）；
   - **32 位**：x64 进程无法加载，改由 **`plugin_host_x86` 远程深扫**。新增 IPC `Op::QueryMetadata`，复用既有 `ipc::RemotePluginInfo` 定长结构（已含 name/vendor/version/category/description/format/is64Bit 等字段）。宿主侧临时 `createInstance → load → 读元数据 → unload`，不占用槽位、不激活；
   - **进程外模式（`AURA_PLUGIN_HOST_MODE=process`）**：整套扫描委托给 `plugin_host_x64`，宿主进程内允许 VST2 深扫（崩溃只杀宿主，客户端下次自动重启）。代价是 32 位条目**只有宿主快扫元数据**——宿主没有 x86 桥客户端，无法代查 32 位 DLL；音频/编辑器/预设不受影响（加载仍由引擎 `remoteClientFor` 路由到 `plugin_host_x86`）。
   - 远程查询失败/超时（2500ms，与进程内深扫同口径）→ 回退快扫元数据，并写 `errorMessage`；扫描继续推进；
5. 32 位条目的 `isCompatible=false` 仍由现有扫描路径写入，Dart `isSupported` 已按「Windows 32 位可用」放行；加载时由 `remoteClientFor` 分派到桥宿主。

### D-4 线程模型：dispatcher 走模块泵，process 走音频线程

| 调用 | 线程 | 说明 |
|---|---|---|
| `VSTPluginMain` / `effOpen` / `effSetSampleRate` / `effSetBlockSize` / `effMainsChanged` / `effGetChunk` / `effSetChunk` / `effEditOpen` / `effEditClose` | `ModulePumpThread`（按规范化模块路径共享） | 与 VST3 的 B3 决策同构，避免插件 MessageManager 归属错线程 |
| `processReplacing` | 音频线程直接调用 | 不跨线程排队，避免额外延迟 |
| `effEditIdle` | 编辑器窗口 `WM_TIMER`（约 30ms） | 新增 `IPluginInstance::onEditorIdle()` 默认空实现，容器窗口定时回调 |
| `audioMaster` 回调 | 可能在音频线程或 GUI 线程 | 只读原子/常量，不加锁、不分配、不做 IO |

### D-5 回调上下文：宿主保留字段存实例指针

插件回调只给 `vst_effect_t*`，宿主需要反查实例。按 VST2 规范，`reserved1/reserved2`（Xaymar 命名 `_unknown_00/_unknown_01`）**明确留给宿主**，插件不得读写。实现：

- 创建后写 `effect->_unknown_00 = reinterpret_cast<void*>(this)`；
- 回调优先读 `_unknown_00`，为空再读 `host_internal`（宿主自有指针）；
- 不使用 `effect_internal`（插件私有），不引入全局 map，音频线程无锁。

### D-6 预设：自描述头 + chunk，兼容读取 `.fxp`

- 保存：优先 `effGetChunk(isProgram=1)`，失败回退 `isProgram=0`；写 `AUR2` 头（magic + 版本 + uniqueID + 字节数）+ 原始 chunk；
- 无 `effFlagsProgramChunks` 的插件：退化为 `numParams` 个 float（`getParameter`）；
- 读取：识别 `AUR2` 与标准 `.fxp`（`CcnK`）两种头；`.fxp` 只取 chunk 段；
- 与现有 VST3/CLAP 的 preset 路径保持同一 FFI 入口，不改 Dart 预设系统。

### D-7 平台范围：本期只做 Windows

- 驱动注册用 `#if defined(_WIN32)` 包裹；VST2 源文件只进 Windows CMake 源表；
- Linux 侧继续只支持 VST3/CLAP，避免把 `.so` VST2 的扫描噪声与验证面带进当前 `feature/linux` 收尾；
- `PluginFormat::VST2` 枚举全平台可见，序列化字符串固定为 `VST2`。

## 4. 数据流

### 4.1 64 位（进程内）

```
UI 选择插件
  └─ FFI slot_load(path)
      └─ PluginHostManager::loadPluginSlot
          ├─ remoteClientFor(path) → 64 位且非 process 模式 → 不命中远程
          ├─ PluginDriverRegistry::findForPath(path) → Vst2Driver
          ├─ prepareInstance → Vst2Instance::load
          │    ├─ setupPluginDllDirectories(path)   // 依赖 DLL 同目录
          │    ├─ LoadLibraryExW
          │    ├─ GetProcAddress("VSTPluginMain") → 回退 "main"
          │    ├─ VSTPluginMain(audioMasterCallback)
          │    ├─ 校验 magic == 'VstP'、processReplacing != null
          │    └─ pump: effOpen → effSetSampleRate → effSetBlockSize
          ├─ activate → pump: effMainsChanged(1)、读 initialDelay
          └─ commitInstanceLocked（挂载即旁路）
音频线程 → processSlot → Vst2Instance::process → processReplacing
```

### 4.2 32 位（位桥）

```
UI slot_load(path)
  └─ remoteClientFor(path)
      ├─ driver->resolveBinary → .dll 本身
      ├─ pluginBinaryBitness == 32
      └─ m_remoteClientX86 → ProcessPluginProxy
          └─ IPC Op::Load → plugin_host_x86.exe
              └─ 32 位进程内 Vst2Instance（同 4.1）
音频线程 → 共享内存 SPSC 环 → x86 宿主 processReplacing → 环回
```

### 4.3 扫描

```
enumerate(dir)
  └─ findForPath(.dll) → Vst2Driver::matchesPath
      └─ resolveBinary(file) → peHasVst2Entry ? path : ""   // 非插件 DLL 直接跳过
快扫 → makeQuickMeta（PE 版本资源，is64Bit 由 PE 头）
深扫 → 64 位：进程内 LoadLibrary + VSTPluginMain
       32 位：IPC Op::QueryMetadata → plugin_host_x86 临时加载查询
       远程失败 → 回退快扫，errorMessage 标注
```

## 8. 风险与回退

| 风险 | 影响 | 缓解 |
|---|---|---|
| VST2 插件在 `VSTPluginMain`/`effOpen` 崩溃 | 进程内深扫整进程 AV（实测 Blue Cat/FabFilter） | 64 位进程内只做 PE 快扫；深扫仅在进程外宿主；32 位走位桥；加载路仍有异步超时 + 隔离区 |
| 插件依赖 DLL 找不到 | 加载失败 | `setupPluginDllDirectories(path)` + 既有 F1 cookie 记账 |
| `FreeLibrary` 时插件线程未退 | 退出崩溃 | 沿用 `ModulePumpThread` 与 `abandoned` 隔离区，绝不强释放 |
| 普通 DLL 被误当插件 | 列表噪声/崩溃 | PE 导出表前置判定；无 `VSTPluginMain`/`main` 直接跳过 |
| 32 位远程深扫失败/超时 | 元数据退化为文件名 | 2500ms 超时 + 快扫回退 + `errorMessage` 标注；不阻塞扫描队列 |
| 32 位回调 ABI 错位 | 插件调用即崩溃 | 宿主回调必须用 `intptr_t` 自定义签名（见 D-1a），不得直接照抄 `vst_host_callback_t` 的 `int64_t` |
| 进程外模式下 32 位元数据降级 | 进程外模式 32 位 VST2 只有宿主快扫元数据（无真实 vendor/category/uniqueID） | 已接受：加载/音频/编辑器/预设不受影响；要对齐需给 `plugin_host_x64` 挂 x86 桥客户端（后续项） |
| VST2 GUI 不刷新 | 编辑器假死 | 30ms `effEditIdle` 定时器；探针可断言 idle 计数 |
| 许可证污染 | 合规事故 | 只用 vendor 净室头；Steinberg 官方文件仅 `source/` 只读 |

**回退**：VST2 驱动以独立源文件与注册开关隔离，回退只需移除注册与 UI 药丸，不影响 VST3/CLAP；`PluginFormat::VST2` 枚举可保留（Dart 已预留）。
