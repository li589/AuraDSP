**三个关键结论**（下文设计的事实基础）：

1. busMask 关时插件**本来就不跑**（泵层 continue，零 CPU）——「插件无需运行」
   已是现状，缺的只是 UI 联动。
2. **不存在「重开开关要等 5-6s」**：插件实例常驻内存（busMask 不卸载实例），

3. 参数层无跨组同步能力：全库无 `IComponentHandler/performEdit` 实现
   （grep 0 命中）——GUI 调参宿主收不到变化通知，这是「全部」方案的
   核心缺口。

## 一、问题 1：通道处理开关 × 插件复选框联动

### 设计定案：灰显保留勾选，不卸载实例（否决「关=卸载」）

**规则**：
1. 右侧通道处理开关（`vbBusMask` bit g）关 → 左侧插件复选框
   `onChanged: null`（Material 灰显）**保留勾选状态**，不可点。
2. 插件不运行 = 泵层已实现（整组直通），**无需任何额外动作**。
3. 开关重开 → 复选框立即恢复可点，该组处理立即恢复（链开关状态原样），
   **零等待**。

**为什么否决「关开关 = 卸载插件」**：
- 用户担忧的「重开等待 5-6s/通道 × 8 组 ≈ 40s」只在这个方案下成立；
- 卸载丢失插件内部状态（含未保存调音），代价远大于内存收益；
- 保活常驻（当前）内存占用 = 8 组 × N 槽实例，与「全部」联动方案（问题 2）
  的实例数相同，不构成额外压力。

**待定项的结论**：无需待定。加载延迟与开关切换解耦——只有首次挂载
（load，全组扇出一次性 8×5-6s 由进度条表达）才有等待；开关/复选框只是
「跑不跑」的门控。

**附带联动**（插件页下拉的选项源收窄）：
- 总线下拉可选路 = `vbBusMask & vbPluginGroupMask`（通道开着 **且** 插件
  勾选才可作为编辑器目标——否则打开界面调的参数不上流，毫无意义）。
- 现有 `_fallbackVbPluginEditorGroup` 回落判据从 `vbPluginGroupMask` 改为
  `vbBusMask & vbPluginGroupMask`。
- 全不可选时下拉显示「旁路（未选路）」，打开界面禁用（沿用 v2 机制）。

**改动面**：settings_page `_VbBusRow`（Checkbox 灰显 + Tooltip 文案更新）、
state 回落判据、插件页下拉选项源、l10n 两串。约 1 小时工作量。

## 二、问题 2：「全部」选项

### 语义定案：「全部」= 参数联动模式（多实例 + 同步），不是第二条链

**两条候选路线的取舍**：

| | 路线 A：多实例 + 参数同步（**采纳**） | 路线 B：单实例 + 音频应用于全部通道（**否决**） |
|---|---|---|
| 实例数 | 每组一份（现状，433963a 已如此） | 全局 1 份 |
| CPU | 8 × 插件 | 1 × 插件（诱人） |
| 可行性 | 可行，缺参数同步钩子（见下） | **不可行**：① 插件 process 绑定固定总线布局，8 路 8ch 流无法塞进单实例；② 分时复用会跨路污染插件内部状态（混响尾音/压缩包络/延迟线互相串）；③ 各组引擎独立 handle 架构（VM 每总线独立）无法共享实例 |
| 状态一致性 | 同步后一致，各路可独立偏离 | 天然一致 |

**「全部也是单独的记忆模式」的落地语义**：
- 下拉选项顺序：`全部 | A1 | A2 | …`（`全部` = 会话级虚拟路由 `kAllRoutes=-2`）。
- 选「全部」打开界面 = 打开**主实例**（`vbBusMask & vbPluginGroupMask` 内
  最低组）的 GUI；此时参数改动**广播到全部勾选组的同槽实例**。
- 选某路（A1…）打开界面 = 打开该路实例，调参**只作用该路**（现状 v2 语义）。
- 「独立记忆」：每路实例的参数状态本就独立（VST3/CLAP state per instance）；
  「全部」调参会覆盖各路当前值（统一化），此后各路仍可单独偏离。
  切换下拉不改动任何实例参数——「记忆」就是各实例的实际状态本身，
  不存在第 9 套隐藏配置（避免「全部」与「单路」两套状态互相打架）。
- 配置层（挂载/卸载/旁路/阶段/Ch mask）维持全组同步（现状不变）——
  「全部」与「单路」的区别**仅在参数联动**。

### 参数同步机制（核心缺口的补齐方案）

现状全库无 `IComponentHandler`——GUI 调参宿主无感知。补齐方案（双轨）：

**主轨：变化钩子（实时同步）**
- VST3：宿主实现 `IComponentHandler::beginEdit/performEdit/endEdit`，
  GUI 每改一个参数 → `performEdit(id, value)` 回调 → 桥把该参数
  `setParam` 到其余组同槽实例（`IEditController::setParamNormalized`）。
  覆盖绝大多数插件（VST3 SDK 交互 UI 均走此通道）。
- CLAP：`clap_plugin_params` 的 `flush()` 事件通道（GUI 线程写事件 →
  process 前 flush 消费），同式广播。
- 仅「全部」模式开启钩子广播；单路模式钩子只记日志不广播（零开销）。

**兜底轨：手动全量同步（覆盖不走钩子的插件）**
- 桥新增 `vb_plugin_slot_sync_all(slot)`：主实例 `getState()` 快照 →
  其余组同槽 `setState()`；UI 在「全部」模式的 Hero 卡加
  「同步到全部」按钮（小图标按钮，主轨失效时手动补）。
- 编辑器关闭时若为「全部」模式自动做一次全量同步（收尾对齐）。

**延迟/成本**：performEdit 广播 = 每次参数变化 7 次 setParam（极轻）；
getState/setState 仅手动/收尾触发。

## 三、问题 3：性能与并发 + Ch strip 跨模式语义

### 并发模型现状与卡顿根因假说

**模型**：Voicemeeter **单 RT 回调**内 for 8 组**串行**调
`processInterleavedN`（`VmPumpCore.h` L249-324）。每组一条完整引擎链。
- 挂 2 槽 × 8 组 = **16 个插件实例在同一条 RT 回调里串行跑**。
- FL Studio 20+ 插件不卡 = FL 多线程 mixer（每轨独立线程可选）+ 单处理流；
  本架构是 8 条独立链串行累加——单回调预算（~2.7ms @128/48k）内挤不下
  8× 插件成本时即爆音。

**已有缓解（复核确认有效）**：
1. busMask 关组 → memcpy 直通（零成本）；
2. idle 10s 静音组 → 跳过 process；
3. 链开关关 → 纯直通早退；
4. 空槽 → 零成本跳过。

**卡顿定位步骤（实施前必做，避免盲优化）**：
- `maxCbTicks` 已有（回调总耗时峰值）；补**每组 process 耗时直方图**
  （QPC 打点进 status JSON），确认爆音块的组分布；
- 分离「加载期间卡顿」（load 是控制线程同步执行，8×5-6s 期间系统内存
  分配抖动可能波及 RT）与「加载后持续卡顿」（CPU 不足）——两者对策不同。

### 优化清单（分级排期）

| 级 | 措施 | 预期 | 成本 |
|----|------|------|------|
| L0 | 每组 process 耗时直方图 + 爆音块关联 | 定位真凶 | 低（打点） |
| L1a | 桥层「无插件组」短路（不经 process，直通 memcpy） | 空组省链遍历 | 低 |
| L1b | idle 阈值 10s → 可配（默认 3s） | 无声组更快休眠 | 低 |
| L1c | 槽位 channels mask==0 跳过插件 | 用户关全部通道即零成本 | 低 |
| L2 | **组级 worker 线程池**：RT 回调只做拷贝+唤醒，8 组并行 process | 8× 成本摊到 8 核，质变 | 高（线程同步/优先级/唤醒抖动） |
| L3 | 无声组插件实例休眠（卸载→有声重载） | 内存收益 | 高（重载 5-6s 有声感知，慎做） |

FL Studio 对标：L2 做到后单回调成本 ≈ max(单组) 而非 Σ(8 组)，与 FL
多轨并行同级——这是「20+ 插件 OK」的结构性答案。L1 先行验证收益。

**内存**：16 实例（Ozone 级插件可达数百 MB）压力记档；「全部」方案采纳
路线 A 后实例数不变（不做 B 不减实例、也不增）。L3 作为后续可选。

### Ch strip（L/R/C/LFE/Ls/Rs/Lr/Rr）跨模式语义定案

**现状缺陷**：Ch strip 恒显示 8 chip，但泵层非双耳模式下每组**只有 L/R
进引擎**（其余 6ch 透传不进链）——VB 非双耳时 C/LFE/… chip 是死控件
（点了不上流）。

**定案**：

| 模式 | Ch strip 行为 |
|------|---------------|
| VAIO / ASIO / WASAPI / 进程内 | 8ch 全语义（现状保持，引擎单 8ch 链） |
| VB 非双耳 | **仅 L/R 可点**，其余 6 chip 灰显 + Tooltip「本模式每通道仅立体声进插件链」 |
| VB 双耳（binaural） | 8ch 全语义（泵 L340 起 8ch 全进） |
| 「全部」模式 | Ch mask 仍是**配置层全组同步**（与「打开界面」路由正交——见下） |

**「打开界面路由（下拉）× Ch strip」的关系澄清**（回应用户第三问后半）：
- 下拉（A1/…/全部）= **编辑器路由**（打开哪组实例的 GUI、参数是否联动）；
- Ch strip = **配置**（该槽位插件处理哪些声道），写操作全组扇出，
  **不随**下拉选路变化；
- 二者正交：任何路由下改 Ch strip 都是改全局配置（VB 下实际只有 L/R
  有意义）。若未来要做 per-route Ch mask，需另立需求——当前无此必要
  （VB 每路仅主对进链）。

**改动面（问题 3）**：L0 打点 + L1 三项桥层短路 + Ch strip 三态
（全开/仅 L/R/灰显）+ l10n。L2 线程池单独立项。

## 一、新增：路由切换锁定（冲突点治理）

**用户原话**：「如果不关界面直接选 A2 或者『全部』，这里应该要处理成在插件

# v3.2 补充：「全部」的继承 / 不继承双选项（2026-10-22 14:19）

**用户原话**：「参数除了继承，也可以选择不继承。」

## 语义定案：「全部」= 独立记忆模式，切换时二选一

「全部」持有**自己的第 9 套记忆**（state + Ch 选择），与各路隔离记忆并列。
切到「全部」时**弹出轻量二选一**（菜单式，非模态）：

| 选项 | 动作 | 右侧标注 |
|------|------|----------|
| **继承自 {A1}**（A1 = lastEditedRoute） | 来源路当前 state+Ch 写入「全部」记忆，再应用到全部有效组（统一） | 「参数继承自 A1」 |
| **不继承（使用『全部』自有状态）** | 用「全部」记忆（上次「全部」态）应用到全部有效组；**从未有过「全部」记忆时不动作**（各组保持现状） | 「『全部』自有状态」 |

**关键规则**：
1. 两种入口都保证「全部」模式下各组**参数统一**（继承=统一为来源值；
   不继承=统一为「全部」记忆值）——「全部」的意义就是全通道一致。
2. 「全部」下开界面调参/调 Ch → 广播全部组 **并更新「全部」记忆**
   （关闭界面时收尾同步）。
3. 各路独立记忆**永不丢失**：「全部」写入各组是覆盖执行，但各路记忆槽
   （manager 侧 per-route 快照）在该路被覆盖前保留；切回单路时显示该路
   当前实例实际值（被「全部」覆盖后即统一值——诚实显示现状）。
   *注：若需「恢复覆盖前的值」属撤销功能，不在本期。*
4. 继承来源 = `lastEditedRoute`（最后关闭编辑器的路由）；从未编辑过时
   继承选项灰显（无可继承来源），只剩「不继承」。
5. 选择发生在**切换时刻**（下拉选「全部」→ 弹选择）；重复选「全部」
   时再弹（幂等无害）。也可在「全部」态下通过右侧标注旁的小按钮
   **手动重新触发继承**（「重新继承自 A1」快捷键位）。

## UI 形态

- 下拉选「全部」→ 菜单（`showMenu`/`DropdownMenu` 风格，主题化）：
  ```
  ○ 继承自 A1        （灰显=无 lastEditedRoute 时禁用）
  ○ 使用『全部』自有状态
  ```

  - 非「全部」路由：空白

# v3.3 预设系统重设计：A/B 记录槽（2026-10-22 15:51，用户三答定案）

用户否决 v3.2 的「全部」继承/不继承菜单交互，改为 **A/B 预设槽**体系。
本节**替代** v3.1 §二「全部」语义与 v3.2 全部内容（「全部」下拉选项撤除）。

## 一、语义定案（用户三答原话落地）

### A/B 记录槽（所有驱动模式）
- 每个「插件（路径+文件）- 槽位」两套预设 **A / B**，内容 = 插件 state +
  声道选择（Ch mask），**持久化**（按插件-槽位保存，重启仍在）。
- 插件加载后**默认激活 A**；用户调音**自动记录**到激活槽（无需确认）。
- A 按钮**始终显示「A」**。VB 模式下**点击 A/B 才展开下拉**：
  1. 自动保存（= 自定义，首选项）
  2. 继承自 X-A / X-B …（排除**自身**槽；源可为任意其它 route×AB）
- 切换到 B（VB：下拉选「自动保存」；非 VB：直接点 B）：
  - B 为空 → 插件保持当前参数，B 开始自动记录（「空预设」语义）；
  - B 选了「继承自 X」→ **一次性复制** X 的 state+Ch 到 B 并应用，
    之后用户一调参 B 自动变回「自定义」（**无引用跟随**——用户：
    「继承后就跟之前的无关了」，循环继承问题自然消解，仅需排除自身）。
- **编辑器打开时**：A/B 按钮、继承下拉、Ch strip、路由下拉**全部禁用**
  （用户：「禁止切换A/B按钮，也禁止模式修改和声道选择」）。
- **复原按钮**（最右）：清除当前激活槽的预设（回到空；继承来的父预设
  不动——复制语义下本就无关）。

### VB per-route 细分
- A/B 按（slot × route）细分：A1-A、A1-B、A2-A、A2-B…（切路由即切
  该路的 A/B 视图）。
- 继承下拉选项 = 全部**其它** route×AB 组合 + 自身 route 的另一槽
  （如 A1-A 可继承 A1-B？——**排除自身槽**即可，A1-B 作为 A1-A 的源
  合法；复制语义无环）。

### 非 VB（VAIO/ASIO/WASAPI/进程内）
- A/B 直接点按切换（无下拉、无继承——「无可继承」）；复原同 VB。

### 「全部」撤除
- 总线下拉不再有「全部」；v3.2 的继承菜单、来源标注、第 9 套记忆、
  关闭界面收尾 sync_all 全部撤除（职责由「预设继承」替代：
  B2-A 继承 A1-A 即可让 B2 用上 A1 的调音）。

## 二、存储设计

```
plugin_presets/.ab/<pluginId>/          pluginId = hash(路径+文件名)
  s{slot}_r{route}_A.aurapreset         state 快照（引擎 preset 格式）
  s{slot}_r{route}_B.aurapreset
  meta.json                             每槽: {chMask, source, hasState}
                                        source: "custom" | "inherit:r{route}:{A|B}"
                                        每 (slot,route): {active: "A"|"B"}
```
- route：VB 0-7；非 VB = -1。
- 自动保存时机（用户感知「自动记录」）：编辑器关闭 / 切换 A-B /
  切换路由 / 切换 A-B 的继承项——统一「离开当前状态前存回激活槽」。
  （实时逐参数存盘无必要：状态在插件实例里，存盘只是持久化。）
- 「调参后变自定义」：保存时 source 归 "custom"（非显式继承加载即自定义）。

## 三、桥接口（P2-1）

- `vb_plugin_slot_save_preset_g(slot, group, path)`：per-group getState
  存文件（现有 save_preset 恒 eng[0]，per-route 存储需要 _g）。
- `vb_plugin_slot_load_preset_g(slot, group, path)`：per-group setState
  （现有 load_preset 全组扇出——预设激活只作用当前路由的组）。
- 继承复制 = 读源文件 → 写目标文件（Dart 文件级拷贝）+ load_preset_g
  应用到当前组；**不经过引擎**做复制。

## 四、UI（P2-3）

```
VB:      [A▾] [B▾] [复原]        点 A/B 弹下拉（自动保存/继承项）
非 VB:   [A]  [B]  [复原]        直接切换
```
- 激活槽高亮（accent）；有内容未激活的槽正常色；空槽 textDim。
- 继承来源以 Tooltip/下拉项勾选态表达（不再有「参数继承自 xxx」行）。
- 原 plugRtNote 位整体让位给 A/B 行（移到 stage Row 右侧原位）。
- 锁定：编辑器打开时 A/B/复原/Ch/路由全禁（p.textDim 灰显）。
