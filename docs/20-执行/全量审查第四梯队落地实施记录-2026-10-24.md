## 2. P-028：§7-2 三桥 ABI 协商（`f4638ec`，21 files / 411+）

审查 §7-2 原话：「三桥增加 `*_abi()` 导出或给 `viz_read` 加 `frame_bytes` 入参；桥加载引擎后校验 `auradsp_abi()`（当前三桥全目录无 `auradsp_abi` 调用）」。选**新增导出**路线（加法不改既有签名）。

### 2.1 实现面

- **C 侧强校验**：`VmPumpCore.h` 增 `FnEngAbi` + `kEngineAbiExpected(=2)`；三桥 `TryLoadEngine` 成功后解析 `auradsp_abi` 并强比对——ASIO/VAIO 硬失败（rc -5/-3，`note=engine-abi-mismatch: bridge=2 engine=N`，发生在驱动 open 之前）；VM 桥降级透传（无引擎本就合法，不比 ASIO/VAIO 硬失败）。
- **新增导出**：`asio_abi` / `vaio_abi` / `vb_abi` 返回桥编译所依据的 viz 帧布局代际；三 .def / .h / .cpp 同步。
- **门禁扩面**：`abi_consistency.py` 增 **B4**（`kEngineAbiExpected` ↔ `engine_internal.h AURADSP_ABI` 联动，引擎升版忘改桥即红）与 **B5**（三桥 cpp 必须引用 `auradsp_abi`，防「清单齐了、校验没了」）。
- **Dart 侧**：`bridge_plugin_ffi.dart` 增 `${prefix}_abi` 可选绑定（`_g` 同款具名 helper，老桥回落 null）+ `assertBridgeAbi`（不符抛 StateError）；三桥 `load()` 接线（open 失败循环语义保持，ABI 错误不受 catch 吞并）。
- **顺手项**：`viz_read` 形参名 out408/out536 纠偏 out1600（§6 C1 注释遗留）。

### 2.2 反向验证（核心断言红证明）

g++ 合成**假引擎 DLL**（纯 C、`-static` 零运行时依赖；桩 create/process/destroy/set_param/get_param/viz_read，仅 `auradsp_abi` 返回值可控；hint 绝对路径 `TryLoadEngine` 直载）：

- **ABI=999** → post-fix 桥 `asio_start` 返回 -5，note 精确为 `engine-abi-mismatch: bridge=2 engine=999`；
- **ABI=2** → 引擎门放行（本机驱动 0 输入声道在后续 buffers 阶段报 -4，与 ABI 无关）——证明拒绝确由 ABI 门触发，而非「假 DLL 一律拒」；
- **还原 pre-fix**（4 cpp/h + 3 def/h 共 10 文件回退重建）→ C1 note 断言**判红**：假引擎穿过引擎门一路进到驱动 open（rc=-4 buffers-failed），门禁 B5 同步红。恢复重建后全绿。
