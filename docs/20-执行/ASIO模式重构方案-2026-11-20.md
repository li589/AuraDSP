# ASIO 模式重构方案（2026-11-20）

状态：**方案待业主确认，未开工。**
业主裁定（2026-11-20 22:28）：主卡处理范式改为「附加模式 / 普通管线模式 /
ASIO 模式」三段；ASIO 模式下直接以切换卡二选一「虚拟 ASIO / ASIO Client」，
不再出现输入/输出端选择；ASIO 模式下的 I/O 配置整卡按新语义重画，不受旧
输入/输出框架约束；此前定罪的 Driver 线问题一并处理。先落实方案再开工。

## 一、为什么要改（问题定罪回顾）

1. **ASIO 被塞进管线的输入/输出交叉组合，是全部别扭的根源。** ASIO 是
   全双工单设备协议，却被拆成「输入=ASIO 驱动」「输出=ASIO Client」两个
   选择器，再靠 composeChain 的接管规则拼回去：选一侧 ASIO、另一侧置灰。
   这套置灰语义修了两轮（r57 P2 立、被业主指出过宽、r58 收窄为仅 asio 链），
   本质是模型错位——不该用两个端点选择器表达一个设备连接。
2. **Driver 线（虚拟 ASIO）三根跨进程线从未接合**（规划 P3「App 后端路由
   接合」长期进行中）：
   - 汇端点：`AuraAsioWasapiSink` 写死系统默认端点，不认 App 选定的物理
     输出。2026-11-20 宾机定罪：REAPER 电平表在跳、处理链在跑，声音被汇
     送进默认端点 AuraVAIO（当时无人转送物理扬声器）→ 无声。
   - 参数：App 在自己进程里另开一个同名驱动空实例发参数，真正发声的
     DAW 侧实例收不到；DAW 侧引擎实际跑默认参数。
   - 遥测：DAW 侧实例的电平/频谱没有任何通道回 App，App 量的是空实例
     的回路 → 可视化恒平。
3. **汇格式潜伏雷**：汇只认 float 与 16 位整数，其余格式（24 位紧缩、
   32 位容器装 24 位、32 位整数）走写零分支。宾机 Voicemeeter 端点群
   皆 24 位，默认端点一旦落到其上即全静音。

## 二、目标形态

### 2.1 顶层范式三段（修订 ADR-009 的两分法，另立 ADR 登记）

| 范式 | 子项 | 处理位置 |
|---|---|---|
| 附加模式 | sysapo / voicemeeter_api（不变） | audiodg 内 APO |
| 普通管线模式 | 输入 {WASAPI, VAIO} × 输出 {WASAPI, VAIO} | App 进程内桥链 |
| ASIO 模式 | 虚拟 ASIO / ASIO Client（切换卡二选一） | 见下 |

- 普通管线摘除 ASIO 两项后，composeChain 只剩 vaio / capture 两链，
  `input/outputOverriddenByChain` 在管线内恒 false，**置灰逻辑与对应
  文案整体删除**——管线里不再有「选了不生效」的一侧。
- 每范式独立记忆自己的子状态，切走再切回恢复原选择（非损原则，沿用
  r56 pipelineOutputForMode 的教训）。

### 2.2 ASIO Client（App 是宿主，向下接设备）

语义：App 打开一个第三方 ASIO 驱动，输入输出同属该设备、同一时钟域，
App 只定连接参数并在回调里处理音频（与 VB 回调同姿势）。

I/O 配置卡（整卡新画）：
- 驱动选择下拉（被占用时让路提示，沿用既有口径）
- 缓冲档选择；协商结果只读显示：采样率 / 实际缓冲 / ioCh / srMismatch 提示
- 输入通道范围、输出起始声道对（**设备内通道选择，不是端点选择**）
- 本地监听镜像：开关 + 监听端点（旁路监听口，文案明示其性质）
- 运行状态行 + 测试源（既有 test 注入保留）

音频通路本身不动（asio_bridge 回调 → 引擎 → 写回设备输出）。

### 2.3 虚拟 ASIO（我们是驱动，向上接 DAW）

语义：DAW 打开 `AuraDSP Driver`，驱动自带时钟泵，引擎在 DAW 进程内
处理；App 只是控制台。**此模式下 App 本地音频链全停**（不起任何桥、
不开自家驱动空实例），只保留控制面与遥测面。

I/O 配置卡（整卡新画）：
- 驱动状态行：注册状态（已注册/未注册，可查注册表对账）
- 声道档位：2 / 4 / 6 / 8（写注册表 `AsioDriver\Channels`，既有通道，
  DAW 下次打开驱动时生效，文案明示）
- **后端输出端点选择**（真实端点下拉）——汇按此端点出声（§三 线 1）
- DAW 连接状态：无 DAW / 处理中（共享块心跳判活）+ 协商参数只读显示
  （采样率/缓冲/声道，来自遥测块）
- **实际生效端点 + 汇格式只读显示**（汇回读，杜绝「选了不生效」重演）
- 旁路状态（经参数块下发，状态以遥测回读为准）
- 一行说明：调音台参数经共享块实时下发至 DAW 侧引擎

## 三、三根线一并接上（Driver 线跨进程通道）

先例：APO 已有同款解法（参数共享块 + `Global\AuraDSP_ApoTelemetry`），
本方案照同一纪律复刻，不发明第二套机制。方向不同、分两块：

- **线 1 · 汇端点**：注册表 `HKCU\SOFTWARE\AuraDSP\AsioDriver\`
  新增 `RenderEndpoint`（端点 ID 字符串），App 在虚拟 ASIO 卡选择时
  写入；汇 `Open()` 优先 `IMMDeviceEnumerator::GetDevice(该 ID)`，
  端点失效/缺省时回落 `GetDefaultAudioEndpoint`（现状行为兜底）。
- **线 2 · 参数**：共享块 `Global\AuraDSP_AsioDriverParams`——版本字段 +
  全量参数快照 + 序号 + bypass 位。App 写；驱动泵每块查序号，变化才
  应用到自家引擎（泵线程只读原子快照区，无锁无分配，RT 纪律同
  ApoTelemetry）。App 侧删除「开自家驱动空实例发参数」的假会话路径。
- **线 3 · 遥测**：共享块 `Global\AuraDSP_AsioDriverTelemetry`——驱动
  发布：心跳时间戳、已处理帧数、逐声道峰值（入/出）、频谱帧、协商
  参数、汇实际端点名与格式、bypass 回读。App 在虚拟 ASIO 模式下，
  电平表与频谱改读此块（与 APO 模式读 ApoTelemetry 同构）。
- **线 0 · 汇格式补全**：24 位紧缩、32 位容器（24 有效位）、32 位整数
  全部做真转换，删除写零分支。

## 四、状态模型与旧配置迁移

- config 新增 `paradigm`（attachment/pipeline/asio）与 `asioFlavor`
  （virtual/client）；管线输入/输出字段保留，选项集去掉 ASIO 两项。
- 旧配置读时推导（只推导一次，落盘后以新字段为准）：
  - 旧合成链 == asio → `paradigm=asio`；其中旧输入 == asio_driver →
    `flavor=virtual`；旧输出 == asio_client 且输入非 asio_driver →
    `flavor=client`（两义时以输入为准：DAW 注入是主语义）。
  - sysapo / voicemeeter_api → attachment；其余 → pipeline。
- audio_modes.dart：新增范式常量与分派；composeChain 收窄为管线内部
  合成；删除 ASIO 接管/置灰相关 helper 与文案键（ioAsioOverrideCaption
  等）。引擎模式 id 与范式映射在本节落表：client → asio 桥链真跑；
  virtual → App 本地无链路（引擎模式置空闲/控制态），处理只发生在
  DAW 进程。

## 五、分段实施（每段独立门禁、可单独回滚）

- **S1 状态模型 + 范式三段 UI + 迁移**：行为等价搬家，ASIO 两 flavor
  仍走旧通路。门：迁移矩阵单测全过、runner 全绿、CI 九绿。
- **S2 ASIO 两张 I/O 卡重构**：新卡替换旧输入/输出卡在 ASIO 下的呈现；
  旧卡只服务管线/附加。门：目检 + 置灰文案清零检查。
- **S3 汇接线（出声修复）**：RenderEndpoint 通道 + 汇按 ID 打开 +
  格式补全 + 遥测块最小版（心跳/汇端点/汇格式）。门：宾机 REAPER
  验收——选定端点出声、换端点跟随、端点拔除回落默认。
- **S4 参数块 + 遥测全量 + 去假会话**：App 参数改走共享块；电平/频谱
  改读遥测块；删空实例路径。门：宾机 REAPER 播放时 App 电平/频谱活、
  改 EQ 在 DAW 侧可闻、bypass 生效、停 DAW 后心跳超时显示「无 DAW」。
- **S5 收口**：ADR 登记（范式三分）、本方案与双线规划文档对账、未决
  登记、smoke 补判别（汇端点选择、参数序号应用、遥测判活）。

## 六、宾机验收总表（S3/S4 后一次走完）

1. REAPER 播放 → 虚拟 ASIO 卡选定的物理端点出声（不再进默认端点）
2. 换一个后端端点、REAPER 重开驱动 → 声音跟随；卡上「实际生效端点」
   与选择一致
3. REAPER 播放中：App 电平表/频谱跟随跳动；App 改 EQ/增益，DAW 侧
   可闻变化；bypass 开关生效
4. 关 REAPER → 卡上状态回到「无 DAW」，App 无残留电平
5. ASIO Client：开 Voicemeeter Virtual ASIO，全双工处理与监听镜像
   行为与重构前一致（回归项）
6. 范式互切：附加/管线/ASIO 三段来回切，各自子状态不丢失

## 七、不做项与已知约束

- 不动 Client 线音频通路、不动 APO、不动 VAIO/VB 桥。
- 多个 DAW 同时打开自家驱动：仍为各自独立实例；共享块以最后发布者
  为准、心跳判活只认最新——多 DAW 并发不在本轮承诺内（双线规划
  §5 既有非目标）。
- Linux 无 ASIO，不受影响；范式三分的 UI 在 Linux 的呈现另按平台
  档案处理，不在本方案内。

## 八、待业主确认的三个决定点

- **D1**：虚拟 ASIO 模式下 App 本地音频链全停、只做控制台——即在此
  模式下 App 自己的播放器/测试源不出声（声音只来自 DAW）。（建议：是）
- **D2**：跨进程通道用「参数块 + 遥测块」两块共享内存（方向分离，
  与 APO 先例同构）。（建议：是）
- **D3**：ASIO Client 的驱动下拉里仍允许选到 `AuraDSP Driver`
  （自宿主自测形态）。（建议：保留，不特殊处理）
