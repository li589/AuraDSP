## 2. 逐项细节与执行要点

### 2.1 A2 · UI 收窄保留（仅文档）
- 结论：`comp.granularity/tfresolution`、`dyneq.attack/mid.freq/release` 五条 UI 收窄
  = **刻意设计**，保留白名单登记（`kKnownRangeDivergences` 不动）。
- 依据：收窄是引擎域子集，无拒收回弹风险；产品确认"合理区间优先"。
- 动作：本文档登记 + 未决清单 A2 标记「已确认（产品定案：保留收窄）」。

### 2.2 B2+B3 · 键名统一 + 全预设注册 + 假参数处置
- **B3 键名统一**：spec id `stereo.band.1~5` → **`stereo.band1~5`**（引擎层名称，
  你的裁决）；getter/setter 不变（字段 `stereoBands[i]` / `setStereoBand(i,v)`）；
  5 条 spec 从孤儿挂进 **stereo section** → 预设/会话经 spec 链覆盖。
  - 契约同步：`kOrphanStaticSpecIds` 删 5 条点号 id；`kEngineOnlyIds` 删 5 条引擎 id。
  - 旧预设兼容：stereo section 的 `customSnapshot['bands']` 保留（旧 JSON 仍有 bands 键），
    新旧双轨并存，apply 以 bands 为准。
- **B2 comp 14 动态参数注册**：`compFreqs/compGains`（`List.generate` 14 条）追加进
  **comp section** specs → 预设/会话经 spec 链覆盖；契约 `kEngineOnlyIds` 删对应 id。
- **comp.ratio / comp.threshold**（引擎无对应实现）：核查发现二者是**压缩卡核心滑块 + 传递曲线可视化依赖**（非摆设）。按"现代压限器设计合适→补充引擎"裁决——**保留 UI + spec**，**登记"待引擎补充"排期**：
  - 实现方向：FFTCompander 外围宏控映射——`comp.threshold` 作输入电平偏移（移位压缩触发点）、`comp.ratio` 作各段 gain 的响应标度；需先验证 vendor `CompressorSetGain`/FFTCompander 内部语义 + 听感校准（**不可本轮硬做，避免改变既有可用音色**）。
  - 契约：保留孤儿登记（comp.ratio/comp.threshold），Part E 精确差集双向断言不变。
- **bass_shaping.enable vs shelf.enable**：`bass_shaping.enable` 的 setter 实为
  `setInt(shelfEnable, …)`（重定向到引擎真实参数 `shelf.enable`），且无 section →
  **删除 bass_shaping.enable spec**，保留 `shelf.enable`；bass_shaping 卡改用
  `shelf.enable` / model 方法驱动（组件核查后定）。

### 2.3 B4 · stereo 对账（规范固化）
- 现状核查：getParams 回读**已有** `stereoBands` 列表写回（state.dart L1567-1570）
  与 `stereoBandUsed`（L1360）；**缺口 = 逆换算**：下发时 `_pushStereoChain` 做了
  `(bands[i]*mix*2.0).clamp(0,1)*…` 换算，回读却把引擎 raw 值直接写回 UI 字段，
  无反向换算 → 引擎生效值 ≠ UI 滑块记忆值时可观漂移。补：回读分支按下发换算
  逆变换回 UI 刻度，带 `stereoOn` 守卫；补 ui_stereo_restore_test 用例。
- 规范 D-2 写进开发规范文档；B4 清单关闭。

### 2.4 B5 · 双声道效果器 → 声道对选择（引擎）
- 语义定案：arbmag/comp/eq 保持立体声实现（不升多声道），但在多声道（ch>2）下
  按 `*.channels` 掩码选择**完全选中的标准声道对**分别处理：
  | 掩码 | 声道对 | 含义 |
  |---|---|---|
  | `0x03` | FL/FR (0,1) | 前扬声器组 |
  | `0x0C` | C/LFE (2,3) | 中/低音组 |
  | `0x30` | SL/SR (4,5) | 后扬声器组 |
  允许多选（如 `0x33` = 前+后组都处理）；未选中任何完整对 → 全直通。
- 引擎改动：`engine_chain.cpp` 多声道路径中，arbmag/comp/eq 的立体声处理从
  "固定 0/1 对"改为"遍历掩码选中的标准对，各自过立体声链，其余直通"。
- UI：`ChannelRoutingSelector` 已是逐声道多选——用户同时勾 FL+FR 即选中前组、
  SL+SR 即后组，**无需改 UI**；引擎按"完整对"识别即对齐。
- **arbmag 升级多声道（每声道独立可选）**：产品认可有价值，**列入后续排期**
  （本文档标记，不随本批实现）。
- 契约：smoke_effects_allparams 的 3 个 stereo 探针升级为"选中对生效/未选对直通"断言。

### 2.5 B6 · 畸形输入边界判断

### 2.6 C1 · 关闭态隐藏延迟小框（全效果器）
