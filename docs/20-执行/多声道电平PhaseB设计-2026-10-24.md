## 2. 目标与非目标

**目标（Phase B in）**：

- G1 per-channel 最终输出电平（`channel_levels`）
- G2 per-stage per-channel 电平（`stage_ch_levels`）：自研效果器全声道 + gate 输入 + vendor 段（FL/FR 语义）
- G3 修复 MC 下 `stage_levels_l/r` 的 stale 失效（E1）
- G4 **ch<=2 行为逐位不变**（回归铁律：stereo 路径所有既有字段同源同值）
- G5 诚实性：作用域不含的声道显 -120，不把 FL/FR 值复制到全声道假装有效

**非目标（Phase C 候选，见 §10）**：插件链 per-channel 电平；3b 段 comp/eq per-stage 电平；输入增益后 per-channel 电平；vendor-src 真逐声道处理。

## 3. ABI 设计

### 3.1 追加式扩展

新增常量（与全引擎 clamp 一致，依据：`vst3_instance.cpp:1248`、`plugin_host_manager.cpp:409/477`、`clap_instance.cpp:534`、`plugin_chain_component.cpp:71`、`delay_line.h:77` 均 `channels > 8 → 8`）：

```c
#define AURADSP_CH_MAX 8
```

`auradsp_viz_frame` **尾部追加**（前 536 B 布局零变化）：

| 字段 | 类型 | 尺寸 | 说明 |
|---|---|---|---|
| channel_count | uint32_t | 4 | 本帧来源块的声道数（2/6/8）；0 = 无有效帧 |
| channel_levels | float[AURADSP_CH_MAX] | 32 | 最终输出 per-channel 峰值 dBFS；未用声道 -120 |
| stage_ch_levels | float[AURADSP_STAGE_MAX][AURADSP_CH_MAX] | 1024 | [stage][ch] dBFS；stage-major |
| **追加小计** | | **1060** | |
| **新 sizeof** | | **1600** | 1596 非 8 的倍数：struct 含 uint64/double，尾部须补 4B 对齐 → 1600 |

### 3.2 兼容性规则

- **老读者**（按旧 sizeof/前 536 B 读）：逐位兼容，零变化。
- **新读者**（Dart Struct 定长读取）：必须与引擎同 ABI 版本。`AURADSP_ABI` **1 → 2**，Dart 侧加载时强校验 `abi() == 2`，不匹配即明确报错——当前 Dart 只 `lookup` 未调用（`auradsp_ffi.dart` L459-460），本次补门禁。
- **python ctypes smoke**：`test/smoke/` 中镜像 `auradsp_viz_frame` 的脚本实施时逐個核对同步（结构体长度不一致会静默错位，属必须核对项）。

### 3.3 字段语义

- `channel_levels[c]`：`auradsp_process` 最终输出（out 缓冲）per-channel 峰值 dBFS。**[0]/[1] 恒等于 `level_l/r_dbfs`**（同源同一趟扫描，见 §4.5），保证 stereo 逐位一致。
- `stage_ch_levels[i][c]`：
  - i ∈ 0..11（vendor）：**[0]/[1] 有效**（= `stage_levels_l/r[i]`，MC 下 vendor 段只作用于 FL/FR 对——E5 设计语义），[2..7] 恒 -120。
  - i ∈ 12..20（自研效果器 + gate 输入）：MC 下 [0..ch-1] 有效；其中 16/17/20（bassmono/haas/spatial，Category B）仅 [0]/[1] 有效，[2..7] 恒 -120。
  - i ∈ 21..23、30..31：全 -120（预留槽）。
  - i ∈ 24..29（GR）：**全 -120**。GR 是全链单值计量，per-channel 无意义；GR 仍读 `stage_levels_l/r` 的 L 列（既有 getter `grLimiter` 等不变）。

```c

```

Dart 测试：`sizeOf<VizFrame>() == 1600`。

## 4. 引擎设计

### 4.1 handle 新增字段（`engine_internal.h`，RT 线程写）

```c
/* [Phase B 多声道电平] per-channel 峰值（线性；RT 每块记录，emit_viz 转 dBFS）。
 * 与 stage_peak_l/r 的关系：stereo 路径只写后者（逐位不变），MC 路径
 * 由 sample_stage_peak_mc 同时写两组（l/r 列取 ch0/ch1，修复 E1 stale）。 */
float stage_peak_ch[AURADSP_STAGE_MAX][AURADSP_CH_MAX] = {};
float ch_out_peak[AURADSP_CH_MAX] = {};   /* 最终输出 per-channel 线性峰值 */
int   last_block_ch = 0;                  /* RT 每块记录，emit_viz 填 channel_count */
```

### 4.2 采样函数（`engine_chain.cpp` 新增）

```c
static inline void sample_stage_peak_mc(auradsp_handle h, int stage_idx,
                                        const float* interleaved, int frames, int ch) {
    float pk[AURADSP_CH_MAX] = {};
    for (int i = 0; i < frames; ++i) {
        for (int c = 0; c < ch; ++c) {
            const float a = fabsf(interleaved[i * ch + c]);
            if (a > pk[c]) pk[c] = a;
        }
    }
    for (int c = 0; c < ch; ++c) h->stage_peak_ch[stage_idx][c] = pk[c];
    for (int c = ch; c < AURADSP_CH_MAX; ++c) h->stage_peak_ch[stage_idx][c] = 0.0f;
    h->stage_peak_l[stage_idx] = pk[0];   /* L/R 列 = ch0/ch1，修复 MC stale */
    h->stage_peak_r[stage_idx] = ch > 1 ? pk[1] : pk[0];
}
```

stereo 链不调用本函数（继续走 `sample_stage_peak`，stride 2，逐位不变）。

### 4.3 MC 链采样点表（`process_multichannel_chain` 内按现有顺序插入）

| # | 插入位置 | stage 槽 | per-channel 有效列 |
|---|---|---|---|
| 1 | `gate_process_mc` 后 | 13 | 0..ch-1 |
| 2 | `filter_process_mc` 后 | 15 | 0..ch-1 |
| 3 | `shelf_process_mc` 后 | —（stereo 链 shelf 亦无槽，保持一致） | — |
| 4 | `dyneq_process_mc` 后 | 14 | 0..ch-1 |
| 5 | `tube_process_mc` 后 | —（tube 在 vendor 内部，无独立槽） | — |
| 6 | vendor FL/FR 段出口 | 0..11 | 仅 0/1（`JamesDSPProcessMultiplexedStageSet` 的 `samplePeaks=1` 已写 `h->jdsp.stagePeakL/R`，emit_viz 直接复用，**零新增采样**） |
| 7 | `bassmono/basspsycho` 后（mx_stereo） | 16 | 仅 0/1 |
| 8 | `haas_process` 后 | 17 | 仅 0/1 |
| 9 | `spatial_process` 后 | 20 | 仅 0/1 |
| 10 | `exciter_process_mc` 后 | 18 | 0..ch-1 |
| 11 | `loudness_process_mc` 后 | 19 | 0..ch-1 |
| 12 | `limiter_process_mc` 后 | —（stereo 链 limiter 亦无电平槽） | — |
| 13 | 安全卫士后（链出口） | → `ch_out_peak[c]` | 0..ch-1 |

**输入级**（`auradsp_engine.cpp` MC 分支 L286-303）：`pk_in` 由 `pk_in_l/r` 扩为 `pk_in[AURADSP_CH_MAX]`（增益前），逐声道写入 `stage_peak_ch[12][c]`——与 stereo 的 `input_lvl_in`（stage 12）语义严格一致。现有 `input_lvl_in_l/r`、`input_lvl_out_l/r` L/R 字段不动（E3 的 per-channel 输出增益后电平列入 Phase C）。

**3b 段 comp/eq 对处理**（E6，`samplePeaks=0` 既存事实）：Phase B 不插采样、不改参数——避免行为变化；该段 per-stage 电平列入 Phase C。

### 4.4 emit_viz 填充规则（`engine_viz.cpp` L142-219 内扩展）

```c
f.channel_count = (uint32_t)h->last_block_ch;
for (int c = 0; c < AURADSP_CH_MAX; ++c)
    f.channel_levels[c] = h->ch_out_peak[c] > 1e-6f ? 20.0f * log10f(h->ch_out_peak[c]) : -120.0f;
for (int i = 0; i < AURADSP_STAGE_MAX; ++i) {
    for (int c = 0; c < AURADSP_CH_MAX; ++c) {
        if (i < AURADSP_VENDOR_STAGES) {
            /* vendor：仅 ch0/1 有效（E5 语义），其余 -120 */
            f.stage_ch_levels[i][c] = (c == 0) ? f.stage_levels_l[i]
                                    : (c == 1) ? f.stage_levels_r[i] : -120.0f;
        } else if (i >= 24 && i <= 29) {
            f.stage_ch_levels[i][c] = -120.0f;   /* GR 单值语义 */
        } else if (c < 2) {
            /* 自研效果器段 L/R 列与 stage_levels_l/r 同源（stereo 逐位不变） */
            f.stage_ch_levels[i][c] = (c == 0) ? f.stage_levels_l[i] : f.stage_levels_r[i];
        } else {
            const float p = h->stage_peak_ch[i][c];
            f.stage_ch_levels[i][c] = p > 1e-6f ? 20.0f * log10f(p) : -120.0f;
        }
    }
}
```

所有读写均在 RT 线程同一回调内完成（采样 → emit_viz → push），无跨线程竞争（与既有 `stage_peak_l/r` 同模型）。

### 4.5 viz_write 签名扩展（`engine_viz.cpp` L13-30）

`viz_write(h, out, frames)` → `viz_write(h, out, frames, ch)`：一趟遍历同时完成三件事——写 viz_hist（stride 2 取 ch0/ch1，**现状不变**）、`viz_lvl_l/r`（ch0/ch1）、`ch_out_peak[0..ch-1]`。合并单趟是为遵循该函数注释里已记录的教训（「两趟访问等于把 out 多读一遍」）。

四个调用点显式传 ch（`auradsp_engine.cpp`）：L320 shelf_scratch → 2；L327 MC out → ch；L337 mx_stereo → 2；L384 stereo out → 2。

**逐位不变保证**：stereo 路径 `ch_out_peak[0/1]` 与 `viz_lvl_l/r` 来自同一趟同一对 `fabsf` 结果 → `channel_levels[0]/[1]` 与 `level_l/r_dbfs` 逐位一致。

### 4.6 RT 成本与兜底

MC 新增 10 个采样点（§4.3 表中 1/2/4/7/8/9/10/11 + 链出口并入 viz_write 已有遍历）：每点一趟 O(frames×ch) 扫描。128 帧 × 8 声道 = 1024 样本/趟，约 10 趟 ≈ 10K 次 `fabsf`+比较 ≈ 个位数 µs；相对 Z17 后的 MC 链本体（≈ max(单组)）可忽略。**兜底**：若实测回调预算超标，将采样合并进各 `_mc` 效果器内部遍历（效果器本就逐声道循环，峰值顺带累计）——接口不变，作为 Phase B.1 优化，不提前做。

### 5.2 isolate 消息扩展（按 chCount 裁剪）

现有 'viz' 消息 ≈1 KB/帧 @100 fps。新增字段：

- `chCount`（int）
- `chLevels`（List\<double\>，chCount 个）
- `stageCh`（List\<double\>，**21 × chCount** 个，stage-major 扁平，只发 0..20 有效段——GR 与预留槽 per-channel 恒 -120 无信息量，由 UI 常量补齐）

裁剪后增量：stereo +672 B/帧；MC(8) +1.4 KB/帧（≈140 KB/s），isolate 消息可承受。若后续实测压力超标再裁，接口保持。

## 6. UI 设计

### 6.1 chain 页（`_SynthLedLadderMeter`）

MC 态（`channelCount > 2`）：`channelsDb` 由 `stage_ch_levels[*][0..chCount-1]`（stage 0..20 行）构成——组件已原生 N 列，仅换数据源。stereo 态：现路径（L/R 两列）逐位不变。GR 列不变。

### 6.2 home LevelMeter

N 柱：`channelLevels[0..chCount-1]`；`chCount <= 2` 时逐位不变（现有两柱）。

### 6.3 诚实性与降级

- `channelCount == 0`（无帧）→ 回退现有 L/R 行为，不显示空柱。
- vendor 段 / Category B 效果对 [2..7] 声道显 -120（该效果作用域不含这些声道）——不复制 FL/FR 值假装全声道（G5）。
- 不新增任何设置项/入口/图标；只在既有电平展示组件内扩柱（Z15 原则延续）。
