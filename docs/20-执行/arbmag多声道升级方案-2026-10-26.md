# arbmag 升级多声道方案（2026-10-26 · B5 后续排期启动）

> 目标：arbmag 从"多声道下仅处理选中**声道对**（B5 过渡语义）"升级为"**逐声道独立可选**"（产品裁决原文）。
> 约束：UI 零改动（逐声道 8 位掩码已存在）、双声道行为零回归。
> 状态：**✅ 已落地（2026-10-26）**——引擎逐声道池已实现并通过全部验证（见 §7 落地记录）。

## 1. 定案（与 B5 的关系）

- B5 把 comp/eq/arbmag 统一做成"对选择"，是为三者共用一套引擎入口的最小改动；
  arbmag 因是全频线性卷积，可独立升级为逐声道。comp/eq 保持对语义不变。
- 升级后 arbmag 掩码语义：**mask 第 c 位 = 声道 c 独立开关**，单个声道（如仅 C）可单独处理，
  (0,1) 不再捆绑。
- 备选 B（对语义保留一方）：(0,1) 保持整对同启同停，(2,3) 及以后才逐声道——
  已被用户否决（"我不需要对的区分，统一都是每个通道"）。
- 备选 C（IR 策略）：每声道独立 GraphicEQ 串 —— **不做**（用户明确"曲线用同一个"）。

## 3. 现状缺口（做什么）

多声道链 B5 段（`engine_chain.cpp` 3b）：额外对 `(2,3)/(4,5)/(6,7)` 以**整对**为单位判定
（`(mask & bits) == bits`），单个 C 声道（0x04）无法独立生效；且先 (0,1) 全链、后额外对
`stage_arbmag` 共用 `jdsp->arbMag.conv`（状态共享见 F3）。

## 4. 落点（实施方案：逐声道单声道卷积器池）

1. **池**（仅 arbmag）：`engine_chain.cpp` 或 jdsp 侧持 `FFTConvolver1x1` 池
   （N = 最大声道数 8），IR 与主 `arbMag.conv` **同源同一份**（同一 `eqFil` 系数，
   共享曲线——布局：系数共享、各池卷积器独立状态）；
   `blockSize` 变化时与主链同步 Refresh；曲线重解析时同步重载 8 池
   （沿 `set_arbmag_string` 控制线程路径直写）。
2. **门控改逐声道**：B5 段 arbmag 分支不再要求整对选中，改为按位：
   `for each c in pair: if (mask & (1<<c)) → 池[c] 处理声道 c`；
   (0,1) 的 arbmag 也从 `processFloatMultiplexd` 整链中按**逐声道**拆出
   （FL/FR 各自 mask 位决定是否进卷积器）。
3. **comp/eq 保持 B5 对语义**（实现不动）；`stage_arbmag` 在多声道链内**不再被调用**
   （由 per-ch 池替代），立体声链（ch==2）行为不变（bit-exact 回归）。

内存量级：每池 `FFTConvolver1x1` ≈ 卷积器输入/重叠/谱缓冲（同主卷积器同 IR 长度量级，
48k/512 块约每声道数十 KB×8）。
RT 安全：池在 control 线程（setParam/refresh）建/载，process 线程只读指针；
块长变化复用既有 `JamesDSPReallocateBlock` 后的 Refresh 钩子。
性能回归要求：额外 6 路单声道卷积 CPU 增量 ≤ B5 段现有开销的同量级（否则降级为"至多 N 对"）。

## 5. 门禁（落地验收）

- engine：`JamesDSPProcessMultiplexedStageSet(..., "comp,eq")` 子集断言
  （arbmag 已摘出，不再出现在多声道子集调用里）；
  arbmag 逐声道 8 位全排列 smoke（0x04 仅 C 生效、0x01 仅 FL、0xFF 全选，
  选中声道 diff>0.01、未选 1e-6）。
- 契约：`param_contract_test` 全绿（engine 表无新增 id，哨兵不触发；
  若动表则重生 fixture）。
- 回归：双声道（ch==2）arbmag 行为逐值一致（同一 IR 同一输入 → bit-exact）；
  `smoke_effects_allparams` ALL PASS。

## 6. 不做（明确排除）

- UI 掩码选择器：零改动（F4）。
- comp/eq 逐声道：保持 B5 对语义（本方案只动 arbmag）。
- 每声道独立 GraphicEQ 串：不做（曲线全声道共用已定案）。
- 卷积算法：不碰 vendor（只用现成 1x1 API 做实例管理）。

## 7. 落地记录（2026-10-26，✅ 已验证）

**实现（6 处）**
- `engine_internal.h`：句柄级 `ArbmagPool{ conv[8], loaded_block, loaded }` + 4 个 pool 函数声明。
- `engine_chain.cpp`：`arbmag_pool_alloc/free/reload/process_strided` 实现；
  `apply_arbmag` 启用时同步 reload 池；**Category B 拆链两段**（`tube,comp,bass,eq` → 池
  FL/FR 逐位 → `convolver…output`，samplePeaks=1 保持 viz 峰值语义，arbmag 级 stage 4
  峰值手动采样）；3b 段 arbmag 从对 ids 摘出，`comp,eq` 对处理后按声道位各自进池
  （samplePeaks=0，维持现有语义）。
- `engine_param_table.h`：`set_arbmag_string` 未 enable 分支也同步 reload 池。
- `jdspController.c` / `jdsp_header.h`：`JamesDSPProcessMultiplexedStageSet` 增加
  `samplePeaks` 参数（镜像 processInternal 逐 stage 峰值采样）。
- `auradsp_engine.cpp`：create 时 `arbmag_pool_alloc`，destroy 时 `arbmag_pool_free`。

**验证**
- 逐声道语义探针 **48/48 PASS**：0x01 仅 FL / 0x02 仅 FR / 0x04 仅 C（B5 对语义做不到）/
  0x0C / 0x30 / 0xFF 全选 / 0x00 全直通不变式——选中声道 diff>0.01、未选 <1e-6。
- **池(1x1) vs jdsp 链(2x2) bit-exact**：同 IR 同输入 FL 支 maxdiff=0.000000（F1 实证）。
- `smoke_effects_allparams.py` 升级为 `arbmag_persch_semantics`（7 档）+ comp/eq 对语义，**ALL PASS**。
- 立体声（ch==2）路径零回归（池不参与，jdsp 链原样）；param_contract 21/21 全绿（fixture 重生成）。

**说明**：范畴 A（FL/FR 拆链）使 arbmag 在 FL/FR 上同样按单声道位独立生效；
相邻的 conv/ddc 等仍在 (0,1) 上按原有对语义处理，未受影响。
