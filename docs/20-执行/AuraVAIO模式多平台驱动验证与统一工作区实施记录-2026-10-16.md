## 3. 关键架构修复与技术突破

### 3.1 修复内核适配器 COM 引用计数析构 Bug

- **问题现象**：驱动加载时，设备管理器报代码 10（`CM_PROB_FAILED_START`），系统事件显示 `STATUS_INVALID_PARAMETER` (`0xC000000D`)。
- **根因分析**：
  在 `core/desktop/windows-drivers/01_vaio_driver/src/AdapterCommon.cpp` 的 `InstallSubdevice` 函数中，局部变量 `portApi` 在将其赋给外部返回值指针 `*OutPortUnknown = portApi;` **之前**被错误地执行了 `portApi = NULL;`。导致 `StartDevice` 获得的 `m_WavePortUnknown` 与 `m_TopologyPortUnknown` 为空指针，进而导致调用 `PcRegisterPhysicalConnection` 物理桥接时报空指针无效参数。
- **修复方案**：
  在 `AdapterCommon.cpp` 中修正对象所有权转交逻辑：
  ```cpp
  if (OutPortUnknown) {
      *OutPortUnknown = portApi;
      (*OutPortUnknown)->AddRef();
  }
  ```
  保证微端口与端口驱动的 IUnknown 接口安全传递，驱动顺利完成 PnP `IRP_MN_START_DEVICE`。

### 3.2 针对 Windows 7 彻底解耦传统 INF 与引入 KMDF 1.11 CoInstaller

- **问题现象**：在 Windows 7 下通过 `devcon install` 安装驱动报 `0xE0000242` / `ERROR_BAD_SECTION_NAME_LINE`。
- **根因分析**：
  1. Win10 Universal INF 包含 `PnpLockDown = 1`，Windows 7 的 SetupAPI 不支持该声明并直接拒绝解析 INF。
  2. Windows 7 SP1 原生自带的 KMDF 版本仅为 1.09，而 `legacy` 工程基于 KMDF 1.11 编译。驱动加载必须依赖 `WdfCoinstaller01011.dll` 在设备安装期完成对系统 WDF 运行时的升级。
- **修复方案**：
  1. 建立独立的 `legacy/AuraVaioDriver.inf`：
     - 去除 `PnpLockDown = 1`；
     - 添加 `[AuraVAIO_Device.NT.CoInstallers]` 与 `[AuraVAIO_Device.NT.Wdf]` 安装段；
     - 添加 `[DestinationDirs]` 针对 System32（目录 11）拷贝 `WdfCoinstaller01011.dll`。
  2. 更新 `legacy/AuraVaioDriverLegacy.vcxproj`，将 INF 项指向 `AuraVaioDriver.inf`，构建时自动打包 `WdfCoinstaller01011.dll`。

### 3.3 替换规范的 Root 代码签名证书

- **问题现象**：PowerShell 的 `New-SelfSignedCertificate` 默认生成终端实体证书（`IsCA=False`），Windows 7 的 CryptoAPI 判定此类证书放入受信任根证书颁发机构后无效，仍报“Authenticode 签名的目录未建立受信任”。
- **修复方案**：
  使用 EWDK 的 `makecert.exe` 生成正规的自签名根测试证书（有效期至 2040 年）：
  ```cmd
  makecert.exe -r -pe -ss My -sr CurrentUser -n "CN=AuraDSP Test Signing" -eku 1.3.6.1.5.5.7.3.3
  ```
  传统轨采用 SHA-1 签名（Win7 原生支持），现代轨采用 SHA-256 签名，驱动均顺利通过两套操作系统的测试模式驱动签名检查。

### 3.4 探针与工具链的 EWDK 跨代静态编译及 CRT 标准输出刷新

- **问题现象**：通过 OpenSSH 在 Windows 7 Session 0 下运行 `tone_play.exe` 与 `apo_inspect.exe` 时无控制台输出。
- **根因分析**：
  1. 工具探针初版由 VS2026 C++20 现代编译器生成，其 UCRT 与异常处理模型依赖新版运行时；
  2. 管道与非交互式重定向终端下，C 运行时 stdout 处于块缓冲（Full Buffered）状态，在进程退出前若未调用 `fflush(stdout)`，输出不会实时推送给 SSH 会话。
  3. `WideToUtf8` 中使用 `s.data()` 在旧版 MSVC 下为 `const char*`，造成转换截断。
- **修复方案**：
  1. 将 `tone_play.cpp`、`ApoInspector.cpp`、`apo_inspect.cpp` 中的 `WideToUtf8` 统一规范为 `&s[0]`；
  2. 在所有 `printf` 关键打点后加入 `fflush(stdout)`；
  3. 使用挂载在 `E:\` 的 EWDK MSVC 19.27 重新编译生成 `tone_play.exe` 与 `apo_inspect.exe`。

## 5. Phase 4 内核跨环零拷贝环形缓冲区 IPC、采集端点与 7.1 声道实机落地

针对 SPEC-WIN-DRIVER-001 虚拟声卡模式 1（AuraVAIO）的 Phase 4 核心需求，已完成驱动核心扩展、独立控制设备暴露、双轨构建与双虚机实测验证：

### 5.1 跨环 IPC 控制设备与非分页共享环形缓冲区
1. **控制设备节点**：
   - 驱动在 `DriverEntry` 中通过 `IoCreateDevice` 创建 `\Device\AuraVaioControl`，并创建符号链接 `\DosDevices\AuraVaioControl`（用户态路径 `\\.\AuraVaioControl`）。
   - 在 `Driver.cpp` 中拦截 `IRP_MJ_CREATE`、`IRP_MJ_CLOSE`、`IRP_MJ_CLEANUP`、`IRP_MJ_DEVICE_CONTROL`，目标为控制对象时由 `ControlDevice.cpp` 独占分发，其它 PnP/音频流 IRP 安全透传至 PortCls `PcDispatchIrp`。
2. **零拷贝跨环共享内存**：
   - 内核分配 64KB+ 非分页物理连续缓冲区（`POOL_FLAG_NON_PAGED`），以 `AURA_VAIO_SHARED_HEADER`（Magic: `'AURB'`）为头结构，前置 128 字节元数据区，后置 64KB 环形数据负载区。
   - 用户态通过 `IOCTL_AURAVAIO_MAP_SHARED_RING` 请求映射，驱动使用 `MmMapLockedPagesSpecifyCache(UserMode, MmCached, NormalPagePriority | MdlMappingNoExecute)` 将内核页安全投影至调用进程地址空间，返回用户态虚拟地址（User VA），实现 100% 零拷贝交换。
   - 支持 `IOCTL_AURAVAIO_UNMAP_SHARED_RING` 显式解映射与进程异常退出时 `IRP_MJ_CLEANUP` 自动析构兜底。
3. **播放与采集双向数据通路**：
   - **渲染通路（Render）**：WaveRT 渲染流执行 `GetPosition` 时，将写入的音频帧同步追加至共享环形缓冲区，驱动自增 `WriteOffset` 与 `TotalBytesWritten`。
   - **采集通路（Capture）**：WaveRT 采集流执行 `GetPosition` 时，自共享环形缓冲区读取由用户态引擎灌入的数据帧；若发生欠载（Underrun）或未写入数据，自动补零（Silence）输出，杜绝内存回声与杂音。

### 5.2 采集端点（Capture Endpoint）与 7.1 声道矩阵
1. **新增采集引脚与拓扑桥接**：
   - 在 `AuraVaio.h` 与 `AuraVaoTables.h` 中引入 `KSPIN_WAVE_CAPTURE_BRIDGE` 与 `KSPIN_WAVE_CAPTURE_SINK`，拓扑引脚增加 `KSPIN_TOPO_MIC` 与 `KSPIN_TOPO_CAPTURE_BRIDGE`。
   - 物理桥接采用双向定向设计：渲染流为 Wave Filter Out -> Topology In；采集流为 Topology Out -> Wave Filter In。
   - 在现代轨与传统轨 INF 中注册 `KSCATEGORY_CAPTURE` 接口。
2. **7.1 声道与高规格音频矩阵**：
   - 数据范围表新增 8 声道环绕声格式（`KSAUDIO_SPEAKER_7POINT1_SURROUND` = 0x0000063F）。
   - 支持 44.1kHz、48kHz、96kHz、192kHz 采样率与 16-bit / 32-bit Float 格式协商。
