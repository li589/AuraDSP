# ASIO 双线开发规划（2026-10-15）

## 0. 一句话决策

- **Client 线**（已落地）：打开第三方 ASIO 驱动，处理其输入→输出。
  对应 `04_asio_client/`（宿主）+ `bridge/asio_bridge/`（FFI 桥）。
- **Driver 线**（推进中）：自身作为虚拟 ASIO 驱动（`AuraDSP Driver`）被 DAW 打开（FL Studio 设备列表里
  能选到我们），DAW 音频灌进来 → DSP → 选定后端出去。
  对应 `04_asio_driver/`（COM In-Proc Server，`auraasio_driver.dll`）。
- **定位**：两线均隶属于模式 4（ASIO 极低延迟领域），统一使用 `04_` 前缀；
  Client 线聚焦“向下接外部物理声卡/硬件驱动”，Driver 线聚焦“向上接外部专业宿主 DAW（FL Studio/Cubase/Reaper 等）”，
  形成完整的 ASIO 专业双向生态闭环。

## 1. Client 线现状（done，回归全绿）

- 宿主：枚举/load/init/channels/rate/buffer/start/stop（`04_asio_client/`）。
- 桥：detect/start/stop/status/set_param(+_str)/get_param(+_str)/viz/bypass/test，
  13 导出（含 `asio_start_ex` 多声道入口）；字符串通道 + LiveProg 回放已对齐 VB。
- App：驱动选择器 + 缓冲档 + 输出起始声道对（并显示设备 IN/OUT 与传输 ioCh）+ 热切换 + srMismatch 明示。
- Smoke：`smoke_asio_{probe,tone,bridge}.py`（FL Studio ASIO 实测 44.1k/512）+ `smoke_asio_multichannel.py`（B2c，VM 8ch）。
- 约束：ASIO 驱动独占，一次一家；占用优雅让路（NOTE 不判红）。

## 2. Driver 线设计

### 2.1 身份与注册

- COM 服务器 DLL：`DllGetClassObject` + `DllRegisterServer/Unregister`，
  注册 `HKLM\SOFTWARE\ASIO\AuraDSP Driver`（CLSID + DLL 路径），支持 64 位注册表视图。
- **商标合规定名**：严格遵守 Steinberg ASIO Usage Guidelines（严禁滥用 ASIO 作为主商标），
  驱动对外显示名及注册表 Description 定为 **`AuraDSP Driver`**（见 ADR-008）。
- IASIO 全方法：init/getDriverName/getChannels/get/setSampleRate/getBufferSize/
  createBuffers/start/stop/getLatencies/…；`bufferSwitch` 回调内调
  `auradsp_process`（复用引擎，不碰算法；RT 铁律沿用）。

### 2.2 后端路由（Driver 收到 DAW 音频后的去处）

Driver 本身只是"壳"，后端复用现有模式（App 侧新增"ASIO 驱动后端"选择器）：

| 后端 | 说明 | 状态 |
|---|---|---|
| WASAPI 渲染（默认输出） | 最先可用，高保真直通渲染汇，带自适应重采样 | ✅ 随 P2 落地 |
| VAIO 虚拟声卡 | VAIO 驱动，实现系统级音频闭环 | ⏳ 等待接线 |
| VB 总线 | 跟随 vbcallback 模式 | ✅ 逻辑已有 |
| ASIO-Client 驱动 | 抓外部物理驱动输出 | 可选 |

### 2.3 谈判与预算

- 采样率/缓冲：DAW 说了算（`setSampleRate/canSampleRate`），引擎按协商值建；
  只认驱动给的值（与 VB"只认有效 STARTING"同款思想）。
- 延迟预算：双份缓冲（DAW 侧 + 后端侧），如实展示，不承诺单份。
- 独占语义：Driver 被 DAW 独占期间，Client 线不得开同一底层设备
  （已有 busy 让路机制，复用）。

## 3. 分期与出口

- **P0**：名字/商标 ADR + 架构定型（已落地：ADR-008）。
- **P1**：COM 骨架——注册/反注册，DAW 能枚举到；init/getChannels 走通；
  smoke 做注册表对账。门：FL Studio 列表出现且可选中（已落地）。
- **P2**：bufferSwitch 直通（DAW→WASAPI 物理端点，无 DSP 也能响）+ 端到端延迟实测。
  门：440Hz 测试音走 Driver 通路可闻（已落地）。
- **P3**：DSP 接入 + 旁路/参数控制 + App 后端路由接合（复用引擎 FFI）。
  门：开 Bass/EQ 产生预期波形变化，bypass A/B 成立（进行中）。
- **P4**：DAW 矩阵（FL/Cubase/Live/Reaper）+ smoke（编译/回读/重建语义按
  Driver 重定）。门：主流 DAW 全绿。
- **P5**：安装器/免提权一键配置/卸载清理（注册表无残留）。

## 4. 目录布局

- Client 线：**`04_asio_client/`**（宿主封装 `AsioHost`，探测 `asio_probe`，发声 `asio_tone`）+ `bridge/asio_bridge/`。
- Driver 线：**`04_asio_driver/`**（虚拟驱动 `AuraAsioDriver`，COM 工厂 `AuraAsioClassFactory`，WASAPI 渲染汇 `AuraAsioWasapiSink`，注册脚本 `register_driver.ps1`）。
- 属性说明：桥是 FFI 薄适配，Driver 是 COM 服务器，职责清晰分离。两线均遵循 zero-DSP 分离原则。

## 5. 非目标（首版不做）

DSD、ASIO 2.x 特有扩展、多客户端并发、32 位构建。

## 6. 多声道扩展（B2c，2026-10-19）

两线同步由固定 2ch 升级为 2/4/6/8 档，通道数与引擎 `channels.count` 对齐（**桥/驱动为权威**，
在 `ApplyParamsString` 之后钉死，避免传输/处理步长错位）：

- **Client 线**：桥新增 `asio_start_ex(..., channels)`（`asio_start` 为 2ch 包装）；
  `AsioHost::create_io/process_io` 支持 N 声道；按驱动能力自动降级（`ioCh A->B` 记入 note）；
  `asio_status` 上报 `ioCh`。App 侧由文件源声道数决定 ioCh（4/6/8 raw 否则 2）。
- **Driver 线**：`AuraAsioDriver` 泛化到 N（`getChannels`/`createBuffers`/`bufferSwitch` 全链路），
  档位注册表 `Channels` 配置、**默认 2**；`kAuraAsioFutureSetChannels/GetChannels`（`createBuffers` 前）供测试；
  处理块 N 声道回录输入，并下混一份 N→立体声喂 `WasapiSink`。
- **输出映射**：binaural 时引擎写 FL/FR、其余置零（物理立体声端点取 ch0/1）；否则离散 N 直出。
