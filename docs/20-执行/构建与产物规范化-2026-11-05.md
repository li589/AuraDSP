# 构建与产物规范化（2026-11-05）

> 状态：**已实施**。范围：构建入口、产物目录、报告目录、发行包清单与陈旧
> 构建物清理。不改任何音频行为、不改 ABI、不改 CI 语义。

## 1. 背景

M3（2026-10-29）与 S2（2026-11-01）已经把引擎、桥、Linux 目标收进根
`CMakePresets.json`，但留下三处不一致：

1. `core/desktop/windows/build_engine.sh` 仍用子工程独立配置（`-B out`），
   `out/` 里同时躺着 vcxproj / CMakeCache / configure.log / build.log 和
   `Release/` 产物——产物目录不纯，日志与构建树会随产物一起被误拷。
2. `tools/probe/audio_quality_eval.py` 的报告 JSON 直接落在 `build/` 根，
   与构建树 `build/windows/` 混层；`build/` 根还堆积了调参期临时脚本与
   smoke/eval 日志。
3. `dist/AuraDSP-Windows-x64/` 没有构建标识：拿到 zip 无法判断它对应哪个
   提交、工作区是否干净、各二进制的哈希；zip 本身也可能落后于当前源码。

## 2. 变更

### 2.1 构建入口统一（Windows 引擎脚本）

`core/desktop/windows/build_engine.sh` 改为与 `tools/build_windows.ps1`、
CI J5 共用根 preset：

```bash
bash core/desktop/windows/build_engine.sh   # 内部：
# cmake --preset windows-x64
# cmake --build --preset windows-x64-release --target auradsp_engine [plugin_host_x64]
```

- 构建树固定 `build/windows/x64/`，`out/` 只保留 `Release/` 产物。
- 宿主 target 仍按 `AURADSP_PLUGIN_HOST_REMOTE` 缓存值条件追加；构建成功后
  自动调用 `tools/sync_artifacts.ps1`（→ `tools/sync_artifacts.py`）同步三处
  消费端。
- 子工程独立配置（`cmake -S . -B out`）保留为兼容入口，但不再是脚本默认路径。

### 2.2 报告目录统一

- `tools/probe/audio_quality_eval.py` 的默认输出改为
  **`build/reports/audio_quality_eval.json`**。
- 约定：`build/` 根只放构建树（`build/windows/`、`build/linux/`）与
  `reports/`；一次性日志、临时脚本不再落在根层。

### 2.3 发行包清单

新增 `tools/bin/dist_manifest.py`，在 `dist/<产品>-<平台>/` 写
`build-info.txt`：

- 产品版本（`app/auradsp_app/pubspec.yaml` 的 `version:`）
- git 提交 / 分支 / 工作区是否脏
- 本地与 UTC 生成时间
- 顶层二进制（exe / dll / so / plugin_host_*）的 SHA256 与字节数

接线：

| 触发点 | 行为 |
|---|---|
| `tools/build_windows.ps1` Step 5 | 归集到 `dist/AuraDSP-Windows-x64` 后写清单，随后 Step 6 打包 zip（清单随包） |
| `tools/sync_artifacts.py` | 每次同步后刷新 `dist/<平台>/build-info.txt`（`--what-if` 不写） |
| 打包/发布前 | `python tools/bin/dist_manifest.py --check` 校验清单与文件一致（退出码 2 = 不一致） |

### 2.4 垃圾清理（仅本机 gitignore 区域）

| 目标 | 处理 |
|---|---|
| `.tmp/`（10 月调试快照 / 日志 / 旧源码拷贝） | 清空 |
| `build/_tmp_*.py`、`build/_tmp_presets/`、`build/*.log` | 删除 |
| `build/audio_quality_eval.json` | 迁至 `build/reports/` |
| `core/desktop/windows/out/` 旧构建树（vcxproj / CMakeCache / 日志） | 删除，仅保留 `Release/` |
| `core/desktop/windows-drivers/out/` 旧构建树 | 删除，仅保留 `Release/` |

合计释放约 **750 MB**。可复用构建树（`build/windows/x64`、
`core/desktop/windows/build-x86`、Flutter `build/`）与所有产物目录未动。

## 3. 产物布局（规范化后）

| 类别 | 路径 | 说明 |
|---|---|---|
| 构建树 | `build/windows/x64/`、`build/linux/x64/` | 根 preset 的中间文件 |
| 构建树（32 位位桥） | `core/desktop/windows/build-x86/` | `plugin_host_x86` 专用树 |
| 引擎产物 | `core/desktop/windows/out/Release/` | `auradsp_engine.dll/.lib`、双宿主、测试 exe |
| 无插件裁剪 | `core/desktop/windows/out-noplugins/Release/` | CP-02 独立产物（不与 out 混用） |
| 桥/驱动产物 | `core/desktop/windows-drivers/out/Release/` | 三桥 + 驱动套件工具 |
| App 构建 | `app/auradsp_app/build/windows/x64/runner/Release/` | exe + data + resources |
| 报告 | `build/reports/` | 探针 JSON / bench 证据 |
| 发行包 | `dist/AuraDSP-Windows-x64/`、`AuraDSP-Linux-x64/` | 便携目录 + `build-info.txt` |
| 发行 zip | `dist/AuraDSP-Windows-x64.zip` | 由 `build_windows.ps1 -Package` 生成 |

## 4. 验证（2026-11-05）

- `bash core/desktop/windows/build_engine.sh`：preset 配置 + 增量构建 +
  产物同步 **19/19 OK**，`dist` 清单自动生成。
- `python tools/bin/dist_manifest.py --check`：13 个顶层二进制与清单一致。
- `tools/build_windows.ps1 -SkipEngine -SkipDrivers -SkipFlutter -Package`：
  从当前 Runner 归集 `dist/AuraDSP-Windows-x64` 并重打包，
  zip = **130.64 MB**（含资源）；DDC 450 / Liveprog 47 / 卷积 1056 文件。
- `python test/runner.py --smoke`：**PASS 136 | SKIP 7（Linux 用例）| FAIL 0**；
  `flutter analyze` 0 issues。全量 smoke 过程中发现并修复两处 HEAD 既存
  问题（与本轮规范化改动无关）：D4-b 遗留 `catch (_)`（
  `chain_spectrum_analyzer.dart` → 改走 `swallow`），以及 `6beafb7` 引入的
  VST3 `createView` 探测导致 ConvologyXT 重载崩溃（已回退探测，详见
  `.ai/memory/2026-11-05.md`）。
- Linux 侧：`core/desktop/linux/build_engine.sh` 未改；`dist/AuraDSP-Linux-x64`
  为 2026-11-03 真机构建产物，下一次 Linux 构建/同步会自动刷新清单。

## 5. 不再做的事

- 不把构建中间文件写回 `out/`（产物目录保持“只读产物”语义）。
- 不在 `build/` 根新增临时脚本/日志；一次性证据一律进 `build/reports/`。
- 不手工拷贝 DLL：一律 `sync_artifacts.py` 或 `build_engine.sh`。
