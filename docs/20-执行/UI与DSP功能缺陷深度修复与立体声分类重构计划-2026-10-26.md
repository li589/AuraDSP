# UI与DSP功能缺陷深度修复与立体声分类重构计划 (2026-10-26)

## 1. 目标与概述

针对用户深度测试中暴露的 12 项 UI 交互缺陷、DSP 状态同步冲突、多声道电平抖动、页面分类结构不合理及外部文件加载入口割裂等问题，制定本系统级修复与重构执行方案。

---

## 2. 问题清单与深度根因分析 (12项)

### 任务 1：高级声道路由展开动画与 UI 一致性
* **现象**：`ChannelRoutingSelector` 展开时硬切（直接 `if (_expanded)`），无缓动展开动画；预设按钮占用独立一行且带有“快速选择”字样，界面不够紧凑；与各效果器中的其他展开卡片视觉规范不统一。
* **根因**：未采用 `AnimatedCrossFade` 或 `AnimatedSize` 缓动容器；预设栏与声道点选栏未做同行右对齐压缩布局。
* **方案**：
  1. 重构 `ChannelRoutingSelector`，使用 `AnimatedCrossFade(duration: AuraDur.base, sizeCurve: AuraCurve.standard)` 实现平滑缓动展开；
  2. 统一旋转折叠箭头图标（`AnimatedRotation(turns: _expanded ? 0.25 : 0)`）；
  3. 声道选择栏与预设快捷按钮同行显示：左侧为当前拓扑实际存在的声道 Chips，右侧并排右对齐放置紧凑小字预设按钮（全选/前置/无LFE/环绕），不显示“快速选择”冗余文本；
  4. 可选声道数量严格跟随 `model.effectiveChannelCount`（2ch/4ch/6ch/8ch）。

### 任务 2：低音增强效果器 UI 异常与参数跳变
* **现象**：
  1. 卡片会自动打开；
  2. “低音增强强度”滑块自己跳变，复原按钮点击后偶发弹跳两次；
  3. 选择“低音增强模式”有概率导致效果器自动关闭。
* **根因**：
  1. 前端在 `setBassIntensity` 时试图通过 50ms 一次的 Timer（`_stepBassRamp`）向引擎按步长推 `bass.gain`；
  2. 但引擎后台的 `audio_isolate` 每 50ms 轮询一次参数，回读未爬完坡的中间临时增益，并通过 `params` 事件将前端的 `bassIntensity` 强行覆盖改写；
  3. C++ 引擎（`engine_chain.cpp`）底层本身已在音频线程实现了按块平滑 slew 渐变，前端的 Timer 渐变机制不仅画蛇添足，其延迟关断标记 `_bassDisableAfterRamp` 更在模式切换与开关点击时发生竞态冲突，误将 `bass.enable` 置为 0。
* **方案**：
  1. 移除 Dart 侧多余的 `_bassRampTimer` / `_stepBassRamp` 冗余爬坡，增益直接下发，交由 C++ 引擎音频线程的原生 slew 处理；
  2. 在 `state_events.dart` 中为 `bassIntensity` 和 `bassGain` 增加防回弹守护，避免回读在用户编辑或复位瞬间覆盖 UI；
  3. 彻底解耦 `setBassMode` 与 `bass.enable`，模式切换仅更新谐波配方，绝不触碰开关位。

### 任务 3：VDC / 脉冲响应无文件时按钮右对齐
* **现象**：移除文件或默认无文件加载时，“打开VDC文件”和“打开IR文件”按钮靠左显示，未按要求右对齐。
* **根因**：`_ResourceSlot` 容器内部布局中，标题右侧使用的是固定宽度的 `const SizedBox(width: AuraSpace.sm)`，丢失了 `Spacer()`。
* **方案**：在 `_ResourceSlot` 内部的文字信息区与操作按钮 `actions` 之间插入 `const Spacer()`，确保无论标题长短、无论是否有已加载文件，操作按钮恒定右对齐。

### 任务 4：动态压限器等滑块单位文字重复显示 (“dB dB”)
* **现象**：动态压限器阈值等滑块右侧显示了两次单位（如 `-18.0 dB dB`、`4.0:1 :1`、`95 Hz Hz`）。
* **根因**：`ValueSlider` 渲染右侧数值时硬拼接了 `'${fmt(displayed)} ${widget.unit}'`，而 `param_schema.dart` 中多个参数的 `formatter` 闭包又自行输出了单位字符（如 `formatter: (v) => '${v.toStringAsFixed(1)} dB'`），导致单位重复。
* **方案**：
  1. 改造 `ValueSlider`：智能检测若 `formattedStr` 已经以 `widget.unit` 结尾，则不再重复拼接；
  2. 全面清查 `param_schema.dart`，规范 `formatter` 闭包仅处理纯数字格式化，单位统一移交给 `unit:` 字段。

### 任务 5：多段图形均衡器预设丰富化与曲线平滑重构
* **现象**：高段数（如 15 段、31 段）下预设曲线粗糙，相邻频点出现硬跳阶跃，预设风格数量不足。
* **根因**：`state_eq.dart` 中的 `applyEqPreset` 采用硬编码的 `logF` 分段粗糙赋值，未采用声学多项式/对数正弦滤波目标函数。
* **方案**：
  1. 重写 `applyEqPreset` 声学计算曲线，基于对数频响采用连续平滑高阶数学模型，自适应任意段数（10/15/31 段）；
  2. 将预设种类从原有的 8 种扩充到 14 种，新增：电子/EDM、嘻哈/R&B、播客人声清晰、监听平直、影院电影、游戏听音辨位等。

### 任务 6：任意响度EQ (ArbMag) 清除曲线逻辑修复与描述重写
* **现象**：
  1. 点击清除曲线后，图像无变化（曲线未被清除）；
  2. 下方的预设仍处于选中状态；
  3. 触发系统报错提示：“arbmag.string:长度无效”；
  4. 标题上方的“8192点因果最小相位...”文案突兀且无头无尾。
* **根因**：
  1. `clearArbmag()` 向引擎下发空字符串 `''`，C++ 引擎校验 `bytes == 0` 时当成错误返回了 `invalid length (1..256KiB)` 并记录错误；
  2. 引擎报错导致状态回滚，回读又把旧曲线塞回前端；
  3. 清除时未将预设状态归位于“平直 (Flat)”。
* **方案**：
  1. C++ 引擎端增强容错：允许 `bytes == 0` 语义为“清空当前曲线并释放内存”，不报错；
  2. Dart 侧 `clearArbmag()` 将曲线重置为标准平直基线，`_codeCtrl.clear()`，并将预设选中状态高亮至“平直”；
  3. 移除界面上方裸露的副标题，改为在卡片标题旁放置问号信息气泡，完整重写为有头有尾的专业声学说明。

### 任务 7：串扰消除 (Crossfeed) 模式选择滑块自动变两次与预设变同参
* **现象**：点击串扰消除模式，下方滑块跳动两次，预设最终被覆盖成同一个参数。
* **根因**：`setCrossfeedMode` 仅在本地修改了 `xfeedFcut` 和 `xfeedFeed`，但只向下发了 `xfeed.mode`，未下发对应的数值；随后 `audio_isolate` 轮询读回引擎内未更新的旧 fcut/feed 并发回前端，前端无情覆盖本地变量。
* **方案**：在 `setCrossfeedMode` 切换模式时，同步将对应预设的数值通过 `setFloat` 下发至引擎，并在 C++ 引擎 `hook_crossfeed_mode` 中同步更新内部原子变量，阻断脏旧值回读。

### 任务 8：噪声门主开关关闭联动关闭齿音消除功能
* **现象**：噪声门主开关关闭后，高级区内的齿音消除 (De-esser) 仍然开启。
* **方案**：在 `setGateEnabled(false)` 及 `gate.enable` 置 0 时，联动下发关闭 `deesser.enable = false`，保证整体逻辑安全闭环。

### 任务 9：低音塑形下方冗余提示文案清理
* **现象**：低音单声道化下方常驻显示一行字：“100Hz.已选1对.每对...”，造成界面视觉杂乱。
* **方案**：直接删除 `_buildBassmonoSummary` 中第一行的 `summaryText` 渲染，仅在发生异常（如未选任何声道、选了中置/超低音）时渲染高优先级的警示气泡。

### 任务 10：输入门控电平表多声道自适应与抖动消除
* **现象**：
  1. 输入门控电平表只显示两声道 L/R；
  2. 放歌时分贝文字长度跳变（-∞ 到 -18.2dB）导致电平列水平晃动；
  3. 高级区滑动条只有左右平衡。
* **方案**：
  1. 将电平数字容器与条形柱封装为固定宽度（`width: 24`），使用等宽字体（mono），彻底消除水平晃动；
  2. 输入门控电平表根据 `model.effectiveChannelCount` 自适应扩展为 2/4/6/8 声道阵列；
  3. 高级展开区支持当前拓扑下的各声道平衡输入。

### 任务 11：界面分类体系重构 —— 新增“立体声专用”分类
* **规划**：
  - 将原 4 分类扩充调整为 5 个标准分类，标签字数规整：
    1. **前置整形** (`front`): `input`, `gate`, `filter`, `bass_shaping`
    2. **核心处理** (`core`): `comp`, `dyneq`, `loudness`, `bass`, `eq`, `arbmag`
    3. **空间效果** (`spatial`): `spatial`, `reverb`（字数对齐，原名“空间”改为“空间效果”）
    4. **激励与输出** (`late`): `exciter`, `tube`, `post`
    5. **立体声专用** (`stereo_only`): `stereo`, `crossfeed`, `haas`, `convolver`, `ddc`
  - 卡片物理移动至新分类；
  - `chain_page.dart` 中对应的卡片 Category 标签统一更新为 `立体声`（`categoryStereoOnly`）。

### 任务 12：统一的外部文件加载对话框与统一入口组件
* **规划**：
  - 提炼统一弹窗组件 `AuraPathPickerDialog`：
    - 输入框支持手动键入 / 粘贴绝对路径；
    - 弹窗左下角提供标准文件夹图标按钮，点击调用原生系统文件/文件夹管理器；
    - 集成通用底层文件扩展名校验、存在性安全检测与 `PathMemory` 记忆更新；
  - 全面替代 VDC、脉冲响应 (IR)、AutoEq 曲线导入、EEL2 脚本载入、预设导入与插件目录添加分散的原有实现，实现全平台架构统一。
