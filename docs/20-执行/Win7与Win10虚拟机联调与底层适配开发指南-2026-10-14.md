## 2. 虚拟机系统级配置基准（已完成与需保持）

底层音频驱动（APO 注入）要求操作系统允许加载第三方未签名/自签名 DLL，且具备必要的 C 运行时支持。

### 2.1 Audiodg 保护机制放宽（已自动注入完成）

两台虚拟机的注册表均已配置 `DisableProtectedAudioDG = 1`：
```cmd
reg add HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Audio /v DisableProtectedAudioDG /t REG_DWORD /d 1 /f
```
* **作用**：默认情况下 Windows `audiodg.exe`（音频引擎隔离进程）会拒绝加载非微软 WHQL 签名的 APO DLL。启用此项后，开发自研的 `AuraApo.dll` 才能被系统音频管线顺利装载。

### 2.2 Win7 关键补丁基线
* **KB4474419 (SHA-2 签名支持)**：已安装（镜像自带/独立安装包），确保系统识别现代 SHA-256 签名。
* **VC++ 2015–2022 Redistributable (x64)**：两台虚拟机系统目录均已具备 `msvcp140.dll`、`vcruntime140.dll`、`vcruntime140_1.dll` 与 `ucrtbase.dll`。

## 3. Windows 跨代底层适配关键技术规范

AuraDSP 底层驱动套件核心差异集中在 **Windows 7 (sAPO)** 与 **Windows 10/11 (APO 2.0)** 的架构代际断层：

```mermaid
graph TD
    subgraph Win10 [Windows 10 / 11 架构 (APO 2.0)]
        direction TB
        App10["音频播放应用"] --> Win10_SFX["SFX (Stream Effects)<br/>{d3993a3f...},5"]
        Win10_SFX --> Win10_MFX["MFX (Mode Effects)<br/>{d3993a3f...},6"]
        Win10_MFX --> Win10_Mix["系统音频混音器"]
        Win10_Mix --> Win10_EFX["EFX (Endpoint Effects)<br/>{d3993a3f...},7"]
        Win10_EFX --> HW10["声卡物理输出"]
    end

    subgraph Win7 [Windows 7 架构 (sAPO)]
        direction TB
        App7["音频播放应用"] --> Win7_LFX["LFX (Local Effects)<br/>{d04e05a5...},0"]
        Win7_LFX --> Win7_Mix["系统音频混音器"]
        Win7_Mix --> Win7_GFX["GFX (Global Effects)<br/>{d04e05a5...},1"]
        Win7_GFX --> HW7["声卡物理输出"]
    end
```

### 3.1 APO 挂载槽位与注册表差异

| 维度 | Windows 10 / 11 (现代模式) | Windows 7 (传统 sAPO 模式) | 适配代码要求 |
|---|---|---|---|
| **效果分层** | 3 级（SFX、MFX、EFX） | 2 级（LFX、GFX） | 配置器根据 OS 内核版本切换策略 |
| **FxProperties 注册表 GUID** | `{d3993a3f-99ac-42d4-a823-4903332c32f4}` | `{d04e05a5-593b-4d4c-b109-b16f219c795c}` | 写入注册表时严格匹配键名 |
| **槽位索引** | `,5` (SFX), `,6` (MFX), `,7` (EFX) | `,0` (LFX), `,1` (GFX) | 宏或枚举分离 |
| **COM 接口要求** | `IAudioSystemEffects2` (支持动态子效果列举) | `IAudioProcessingObject` + `IAudioProcessingObjectRT` + `IAudioProcessingObjectConfiguration` | 严禁在 Win7 下强制 Query `IAudioSystemEffects2` 失败时退出 |

### 3.2 驱动与引擎解耦原则（铁律）
1. **传输与算法绝对隔离**：
   * `AuraApo.dll` 和 `02_voicemeeter_client` 仅负责音频块抓取与泵送，通过 C ABI（`auradsp_process`）将数据传递给 `auradsp_engine.dll`。
   * 驱动工程（`core/desktop/windows-drivers/`）不内嵌任何具体音效算法数学代码。
2. **RT-Safe 零崩溃承诺**：
   * 在 `APOProcess` 回调中绝对禁止调用堆分配（`malloc/new`）、禁止加锁等待、禁止 I/O。
   * 当音频输入包含静音标记时，强制输出置零并透传 SILENT 标志，防止底层爆音。

## 4. 日常自动化联调与测试工作流

后续开发中，所有编译均在宿主机完成，通过 OpenSSH 实现远端静默测试与自检。

### 4.1 虚拟机生命周期命令（宿主机命令行直接管理）

使用 VMware 自带的 `vmrun.exe` 控制虚拟机（无需打开 VMware 图形界面）：

```powershell
$VMRUN = "D:\Program Files\VMware\VMware Workstation\vmrun.exe"
$VM_WIN10 = "C:\Users\likr\Documents\Virtual Machines\Windows 10 x64\Windows 10 x64.vmx"
$VM_WIN7  = "C:\Users\likr\Documents\Virtual Machines\Windows 7 x64\Windows 7 x64.vmx"

# 1. 查看运行状态
& $VMRUN list

# 2. 启动虚拟机 (后台静默启动 / 图形启动)
& $VMRUN -T ws start $VM_WIN10 nogui
& $VMRUN -T ws start $VM_WIN7 nogui

# 3. 挂起 / 保存状态
& $VMRUN -T ws suspend $VM_WIN10
& $VMRUN -T ws suspend $VM_WIN7

# 4. 创建基线快照 (在修改系统驱动前建议打快照)
& $VMRUN -T ws snapshot $VM_WIN10 "baseline_clean"
& $VMRUN -T ws snapshot $VM_WIN7 "baseline_clean"
```

### 4.2 一键部署与自动化测试流程

在宿主机编译完成后，通过以下流程向虚拟机同步产物并验证：

```powershell
# 步骤 1：宿主机编译驱动与探针
cmake --build core/desktop/windows-drivers/out --config Release

# 步骤 2：创建目标测试目录
ssh vm-win10 "if not exist C:\AuraDSP mkdir C:\AuraDSP"
ssh vm-win7 "if not exist C:\AuraDSP mkdir C:\AuraDSP"

# 步骤 3：推包至 Win10 / Win7
scp core/desktop/windows-drivers/out/Release/AuraApo.dll vm-win10:C:/AuraDSP/
scp core/desktop/windows-drivers/out/Release/apo_inspect.exe vm-win10:C:/AuraDSP/
scp core/desktop/windows-drivers/out/Release/tone_play.exe vm-win10:C:/AuraDSP/

# 步骤 4：在虚拟机运行只读端点探针
ssh vm-win10 "C:\AuraDSP\apo_inspect.exe"
```

### 4.3 端到端 APO 注入闭环验证

```powershell
# 1. 注册 AuraApo.dll
ssh vm-win10 "regsvr32 /s C:\AuraDSP\AuraApo.dll"

# 2. 注入指定音频端点 (通过 Python 脚本或未来 Configurator)
# 挂载后重启 Audiosrv
ssh vm-win10 "net stop Audiosrv & net start Audiosrv"

# 3. 触发 WASAPI 信号发声，验证心跳与无爆音
ssh vm-win10 "C:\AuraDSP\tone_play.exe 扬声器 2 440"
```
