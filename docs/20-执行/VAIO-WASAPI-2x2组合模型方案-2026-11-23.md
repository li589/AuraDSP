# VAIO/WASAPI 2×2 组合模型方案（2026-11-23）

user 提案（2026-11-23 13:09）+ 三点裁定（同日 13:15）+ 动工令（同日 16:42）。
本方案只覆盖普通管线范式内的 WASAPI/VAIO 两轴；附加（APO）与 ASIO
范式不在范围内，VB 模式不涉及。

## 一、模型（user 原义）

输入、输出各自独立二选一，可任意组合，功能严格按组合不越界：

| 输入＼输出 | WASAPI 输出 | VAIO 输出 |
|---|---|---|
| **WASAPI 输入** | 经典管线：采集（扬声器内录/麦克风）→ 处理 → 物理声卡 | 处理后音频送 VAIO 虚拟麦克风供他方录制；监听开时再镜像一路到选定的 WASAPI 设备 |
| **VAIO 输入** | 他方播入 VAIO 扬声器端点 → 处理 → 物理声卡（现行桥模式；录制端点静音，r64 S-A） | VAIO 扬声器进 → 处理 → VAIO 虚拟麦克风出（全虚拟环）；监听开时镜像到 WASAPI 设备 |

三点裁定（2026-11-23 13:15）：

1. 镜像目标 = WASAPI 输出选择器已选的设备，不设单独镜像选择器；
   该选择器依然排除 VAIO 设备。
2. 输出 = WASAPI 时监听开关**直接隐藏**（WASAPI 输出与监听同路，
   开关仅存在于 VAIO 输出时）。
3. WASAPI 输入的内录对象 = 输入选择器选中的扬声器设备，依然排除
   VAIO 设备。

## 二、现状盘点（四格里三格已有形态）

- **WASAPI 进 + WASAPI 出**：经典管线，已有，不动。
- **VAIO 进 + WASAPI 出**：现行桥模式，已有；r64 S-A 的
  `CaptureMuted`（桥映射环期间录制端点喂静音）正是此格口径，不动。
- **WASAPI 进 + VAIO 出**：今日靠「处理后渲染进 VAIO 扬声器端点 →
  驱动回环到录制端点」实现麦克风交付（r64 保留的管线回环），交付
  本身成立；**缺的是监听镜像**——今日此格没有任何物理声。
- **VAIO 进 + VAIO 出**：**不存在**。输入正占用渲染端点作接受点，
  处理结果无法再渲染回同一端点（回授）；驱动录制读端只读渲染环
  本身，没有「处理后回写」通道。此格是本轮唯一的驱动级新工程。

## 三、核心新工程：驱动处理后回写环（Processed Ring）

在现有渲染环之外新增第二条共享环，专供「处理后音频回写录制端点」：

- **IPC**：`AuraVaioIpc.h` 新增 `IOCTL_AURAVAIO_MAP_PROCESSED_RING`
  （0x805），响应结构同 MAP 响应口径；新环带同构
  `AURA_VAIO_SHARED_HEADER`（桥为生产者、驱动录制读端为消费者，
  读偏移在新环头内维护）。环格式跟随渲染流协商格式（采样率/声道/
  位深），桥写入前把引擎输出按 `channel_map.h` 适配到端点声道
  （与桥渲染物理设备的适配同口径）。
- **录制源三态**：现 `CaptureMuted`（0=回环 / 1=静音）泛化为录制源
  选择——0=渲染环回环（无桥的独立驱动行为，不变）、1=静音
  （r64 口径，桥在场且 VAIO 出未启用）、2=处理后环（VAIO 出启用）。
  实现上在共享头 `Reserved` 中再转正一字段 `CaptureSource`，
  `CaptureMuted` 保留兼容（源=1 时等价置位）；结构尺寸与 IPC
  版本号不变，旧桥/旧驱动组合按零值降级为现行行为。
- **流控**：复用渲染环既有的 snap/钳制丢弃纪律（帧格不变量、
  288 对齐）；生产者（桥）按渲染流时钟写入，消费者（录制流）
  拉取速率不一致时按同一纪律丢/补静音，不阻塞任一侧 RT 路径。
- **兜底**：处理后环映射的文件对象 Cleanup 时驱动清源标记回 0；
  桥拆映射前主动清零——与 `CaptureMuted` 的崩溃兜底同式。

## 四、桥与管线改造

- **VAIO 桥（auravaio_bridge）**：
  - VAIO 进 + VAIO 出：链路输出改写处理后环（不再渲染物理设备
    为主路）；置 `CaptureSource=2`；监听开时并行渲染一路到
    WASAPI 输出选择器选定的设备（镜像渲染复用 r64 S-B 的
    WASAPI 渲染客户端代码，静音帧技巧保留给镜像关闭态——
    关闭即不渲染，无需静音帧）。
  - VAIO 进 + WASAPI 出：现状不变；监听门在此格**失效**
    （见 §五对齐），主渲染恒发声。
- **管线（WASAPI 进 + VAIO 出）**：麦克风交付沿用渲染进 VAIO
  端点的既有回环（已验证，不迁处理后环，避免动已稳路径）；
  新增镜像渲染：输出级在写 VAIO 端点的同时，按监听开关把同一
  处理后音频渲染到 WASAPI 输出选择器选定的设备。镜像渲染的
  时钟跟随主管线输出，格式适配同主管线。

## 五、与 r64 S-B（本地监听总闸）的口径对齐

r64 把监听做成桥主路总闸（默认开、关 = 主路静音帧）。新模型下
监听的语义收敛为**「VAIO 输出时的 WASAPI 镜像开关」**：

- 参数 `routing.monitorMirroring` 与默认值（开）保留，作用域改
  为仅 VAIO 输出两格；桥内的主路静音门控随之退役（VAIO 进 +
  WASAPI 出格主路恒发声，开关隐藏，无门可守）。
- App 侧开关显隐由输出轴驱动：输出 = VAIO 才显示；输出 =
  WASAPI 时隐藏且不生效（值保留，切换回来恢复）。

## 六、App / UI / 配置

- 输入选择器：WASAPI 侧设备列表排除 VAIO 设备（内录对象与麦克风
  均为物理设备）；选 VAIO 即输入轴 = VAIO。
- 输出选择器：WASAPI 侧设备列表排除 VAIO 设备；选 VAIO 即输出
  轴 = VAIO。镜像目标不单独设选择器（裁定 1），即此选择器的
  当前值——输出 = VAIO 时该选择器改作镜像目标选择（文案随轴
  切换说明用途）。
- 监听开关：仅输出 = VAIO 时显示（裁定 2）。
- 配置：沿用 `pipelineInput` / `pipelineOutput` 两字段的
  wasapi/vaio 取值组合表达四格，不新增字段；存量「VAIO 模式」
  配置即 VAIO 进 + WASAPI 出格，天然迁移。提示文案
  （virtualSinkNotice 等）按四格重写，逐格说明音频去向。
- 引擎生效宽/声道口径与四格正交，沿用现行钳制，不在本轮动。

## 七、分段

| 段 | 内容 | 验证 |
|---|---|---|
| S1 | 驱动：处理后环 + 录制源三态 + 契约冒烟（源切换、回环/静音不回归） | 冒烟 + 驱动重编签名打包新鲜度门 |
| S2 | 桥：VAIO 进 + VAIO 出拓扑（写处理后环 + 镜像渲染 + 门退役） | 桥契约冒烟扩格；开发机门禁 |
| S3 | 管线：WASAPI 进 + VAIO 出镜像渲染 | 管线冒烟 + Dart 测试 |
| S4 | App：选择器/开关显隐/文案四格化 + 配置迁移核查 | Dart 全量 + analyze |
| S5 | 全量门禁 + 发行（r65）+ 宾机四格验收 | 见 §八 |

## 八、宾机验收口径（四格 × 关键判别）

1. WASAPI 进 + WASAPI 出：与今日一致（回归）。
2. VAIO 进 + WASAPI 出：他方播入有处理声、录制端点静音（r64
   回归）、监听开关不可见。
3. WASAPI 进 + VAIO 出：录制软件收到处理后音频；监听开 →
   选定物理设备同出处理声，关 → 物理静默；输入内录对象为
   选定扬声器（非 VAIO）。
4. VAIO 进 + VAIO 出：他方播入 VAIO 扬声器，录制软件收到
   **处理后**音频（逐声道测试判别处理痕迹，如 EQ 频响差）；
   无回授啸叫/原始流串入；监听镜像同第 3 格。

## 九、风险与开放点

- 双时钟域：处理后环的生产（渲染流时钟）与消费（录制应用
  时钟）漂移靠丢/补纪律吸收，长时录制（>1h）的漂移量级需在
  S1 冒烟里给量化口径。
- 录制端点格式协商：录制应用以端点格式开流，处理后环格式
  跟随渲染流；两者声道/采样率不一致时驱动沿用现有 snap 口径，
  S1 需覆盖 2ch 录制应用 × 8ch 渲染流的组合冒烟。
- 多录制客户端同时开录制端点：沿用现有环的单消费者假设，
  与今日回环行为一致，不在本轮扩围。
- 驱动改动需重装驱动包（DriverStore 旧包先卸载的既有纪律）。
