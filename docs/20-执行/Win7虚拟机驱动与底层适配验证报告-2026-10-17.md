## 2. 底层驱动套件 Win7 实测详情

### 2.1 模式 1: AuraVAIO 虚拟音频驱动

- **用户态桥接吞吐**：`vaio_bridge_test.exe`
  ```text

  underrun count: 0, overrun count: 0
  ```
- **结论**：KMDF 1.11 运行时兼容良好，音频流搬运稳定无抖动。

### 2.2 模式 3: System APO (sAPO)
- **代际差异**：Windows 7 采用传统 sAPO（Local Effects 与 Global Effects），不支持 Win10 的 SFX/MFX/EFX（5, 6, 7）和 Composite MULTI_SZ（13, 14）。
- **`apo_config.py` 增强**：
  - 自动识别 Windows 7（`sys.getwindowsversion().major == 6 and minor == 1`）。
  - 挂载模式切换为 `win7-sapo`：
    - `{d04e05a6-594b-4fb6-a80d-01af5eed7d1d},1` -> `OUR_CLSID` (LFX)
    - `{d04e05a6-594b-4fb6-a80d-01af5eed7d1d},2` -> `OUR_CLSID` (GFX)
    - 跳过 Win10 专用的 `PROC_MODES` 写入。
  - 双层备份与原子恢复：卸载时 100% 还原系统自带 Microsoft LFX/GFX GUID。
- **Audiodg 与实时心跳实测**：
  ```cmd
  tasklist /m AuraApo.dll
  audiodg.exe PID 3972 AuraApo.dll
  ```
  ```text
  心跳检测结果: {'alive': True, 'seq': 371, 'frames': 166208, 'sr': 44100, 'nbs': 448, 'pid': 3972}
  ```
- **结论**：Windows 7 下 `audiodg.exe` 成功载入 `AuraApo.dll`，RT 实时音频回调稳定运行。

### 2.3 模式 4: Virtual ASIO 驱动

## 3. Flutter APP 在 Win7 + VxKex 崩溃原因深度剖析

### 3.1 崩溃现象
```text
问题事件名称: APPCRASH
应用程序名: auradsp_app.exe
故障模块名称: flutter_windows.dll
异常代码: c0000005 (STATUS_ACCESS_VIOLATION)
异常偏移: 00000000007955c8
```

### 3.2 两层技术诱因

#### 第一层：静态导入表（Win8+ API 缺失）
现代 Flutter 3.x 官方构建的 `flutter_windows.dll` 默认链接了 Windows 8/10 的专属 API：
1. `api-ms-win-core-path-l1-1-0.dll`（`PathAllocCanonicalize` 等）
2. `KERNEL32.dll!GetCurrentThreadStackLimits`
3. `WS2_32.dll!GetHostNameW`
4. `ntdll.dll!RtlAddGrowableFunctionTable`
5. `api-ms-win-core-synch-l1-2-0.dll!WaitOnAddress`

在未安装 VxKex 的纯净 Win7 上，PE 加载器会因缺少上述 DLL/函数而直接弹出错误提示（错误代码 126/127）。

#### 第二层：渲染管线硬依赖（ANGLE + DXGI 1.2 + D3D11.1）
1. **安装 VxKex 但未装 KB2670838**：
   PE 加载器成功放行并执行到 `flutter_windows.dll` 初始化阶段，控制台输出直接暴露出 D3D 渲染器无法创建：
   ```text
   ERR: DisplayD3D.cpp:157 (rx::CreateRendererD3D): Failed to create D3D renderer: DXGI 1.2 required to present to HWNDs owned by another process.
   ERR: Display.cpp:1093 (egl::Display::initialize): ANGLE Display::initialize error 12289: No available renderers.
   [ERROR:flutter/shell/platform/windows/egl/egl.cc(57)] EGL Error: Not Initialized (12289) Failed to initialize EGL via ANGLE
   ```
2. **安装 VxKex + 官方平台更新补丁 KB2670838**：
   补全 DXGI 1.2 与 Direct3D 11.1 后，**D3D11 渲染器成功创建**（第一阶段错误解决）。但随后在分配交换链阶段遇到新的硬件/驱动级阻断：
   ```text
   [ERROR:flutter/shell/platform/windows/direct_manipulation.cc(182)] CoCreateInstance(CLSID_DirectManipulationManager, nullptr, CLSCTX_INPROC_SERVER, IID_IDirectManipulationManager, &manager_) failed
   ERR: SwapChain11.cpp:640 (virtual rx::SwapChain11::reset): Could not create additional swap chains or offscreen surfaces, HRESULT: 0x887A0022
   ERR: SwapChain11.cpp:647 (virtual rx::SwapChain11::reset): Device lost in SwapChain11::reset HRESULT: 0x887A0022, reason: HRESULT: 0x00000000
   [ERROR:flutter/shell/platform/windows/egl/egl.cc(57)] EGL Error: Context Lost (12302) Surface creation failed.
   ```
- **核心阻断点**：
  1. `HRESULT: 0x887A0022` 对应 `DXGI_ERROR_NOT_CURRENTLY_AVAILABLE`。现代 Flutter 桌面端采用 ANGLE 翻转模型交换链（`DXGI_SWAP_EFFECT_FLIP_DISCARD` 或 `DXGI_SWAP_EFFECT_FLIP_SEQUENTIAL`）。
  2. `FLIP_DISCARD` 为 Win10 独有；`FLIP_SEQUENTIAL` 在 Win7 上硬依赖 DWM（桌面窗口管理器）Aero 毛玻璃合成处于激活状态。
  3. 虚拟机 VMware SVGA 3D 虚拟显卡在 Win7（WDDM 1.1）驱动下未实现 Flip Model 呈现管线（仅支持传统的 Blt 拷贝交换链）。
  4. ANGLE 分配交换链失败导致 EGL 丢失后，Flutter C++ 嵌入器未进行防御性熔断，后续直接解引用空上下文指针（`mov rax, [rcx + 0x10]`，其中 `rcx = 0`），触发 `0xC0000005` 内存访问违规崩溃。

## 4. GitHub Issue 与后续路线图

已在代码仓库创建专项跟踪 Issue：**[#6 [app] Win7 下 Flutter UI (auradsp_app) 启动 APPCRASH (flutter_windows.dll 0xC0000005 与 ANGLE DXGI 1.2 SwapChain 限制)](https://github.com/li589/AuraDSP/issues/6)**。

### 4.1 Win7 前置基线三步法
1. **操作系统**：Windows 7 Ultimate SP1 x64 (Build 7601)。
2. **兼容层**：安装 **VxKex**（v1.2.1+），垫资 Win8+/Win10+ 静态 API。
3. **平台补丁**：安装微软官方更新 **KB2670838**（补充 DXGI 1.2 与 D3D11.1 运行时）。

### 4.2 物理机复测计划
- **测试环境**：Win7 物理机（Intel Core i7 7代 + AMD 独立显卡）。
- **验证目的**：真实 AMD 独立显卡驱动（具备完整 WDDM 驱动能力并原生支持 Aero DWM 毛玻璃合成），验证在物理 GPU 下是否能够正常分配 `FLIP_SEQUENTIAL` 交换链并成功渲染 Flutter UI，彻底排除虚拟机虚拟显卡驱动局限。

### 4.3 源码级适配方向（后续有余力推进）
若物理机同样受限于 Flutter 官方对 Flip Model 的硬性绑定，后续可从 Flutter 引擎源码层（`flutter/engine` -> `flutter/shell/platform/windows`）进行深度适配：
1. **交换链降级**：在检测到 OS 为 Win7 时，将 ANGLE 的交换链创建参数由 `FLIP` 降级为传统的拷贝模型（`DXGI_SWAP_EFFECT_DISCARD`）。
2. **纯软件渲染备选**：引入 SwiftShader 或 LLVMpipe 软件光栅化后端替换 ANGLE D3D11。
3. **空指针保护**：在 DirectManipulation 与 EGL 上下文初始化处加入防御性判断，避免 `0xC0000005` 崩溃。
