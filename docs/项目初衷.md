## 1. 为什么做这个项目

现有开源音效方案（JamesDSP 系、EqualizerAPO、PulseEffects、Element、ViPER 蝰蛇等）各自能解决一部分问题，但**在真实使用中都暴露了严重的稳定性、兼容性与体验缺陷**：

- **平台政策适配滞后**：Android 14+ 的音频会话/调用政策变化后，老方案大面积失效。
- **过度依赖第三方虚拟声卡**：链路脆弱，设备/驱动一变就崩。
- **进程与状态管理粗糙**：后台被杀、关窗即退、效果链丢失、切应用出问题。
- **UI/UX 陈旧、无本地化**：不直观、不舒服、没有中文。
- **插件生态兼容性差**：VST 加载崩溃、不支持 32 位、扫描即崩。

结论：**打补丁不如重做**。底层算法可以复用成熟实现，但**架构、进程模型、平台胶水、UI 必须从零重新设计**。

## 2. 现有方案痛点复盘（实测记录）

> 这一节是项目最原始的「初衷素材」，务必保留真实细节，用于后续设计时的对照与验收。

### 2.1 Android —— JamesDSP v6.1 (Magisk 模块) + RootlessJamesDSP

**JamesDSP v6.1（Magisk 模块）实测：**

| 系统 | 表现 |
|---|---|
| Android 12（MIUI） | 大部分情况正常运行，**少数时候找不到 `libjamesdsp.so`** |
| Android 13（MIUI） | 大部分正常，偶发 `libjamesdsp.so` 缺失 |
| Android 14（MIUI 14） | **几乎总是无法正常运行** |
| Android 15（HyperOS 2） | **几乎总是无法正常运行** |
| Android 16（OPPO ColorOS 16） | **几乎总是无法正常运行** |

失败形态：**找不到 `libjamesdsp.so`** 或 **无法初始化引擎**。

初步假设（待验证）：Android 14 起，**audio session（尤其 session 0）模型**与**音频调用策略 / audio policy** 发生了改变，导致老模块的 so 加载路径与引擎挂载方式不再被允许。

**RootlessJamesDSP 实测问题：**
- 挂后台经常被杀掉（进程保活失败）。
- 切换应用后**无声音**。
- **部分应用出现双重声音**（重复处理/双路叠加）。
- **部分应用完全不支持**。
- **偶发性闪退**。

### 2.2 Windows —— EqualizerAPO + Voicemeeter

- **开机后表面运行、实际音频未被处理**（静默失效，最难排查）。
- **更新 Voicemeeter 后必须重装** EqualizerAPO 才能恢复。
- 有时**找不到 Voicemeeter 的虚拟设备**。
- **加载 VST 经常崩溃 / 效果失效**。
- **DSP 不稳定**：重启前后声音完全不同（状态/系数未持久化或初始化时序问题）。
- **不支持 32 位 VST**。
- **界面极其古老**。

### 2.3 Linux —— PulseEffects / EasyEffects + JamesDSP for Linux

**PulseEffect（现 EasyEffects）：**
- 整体体验尚可，但**偶尔闪退**。
- 在 **Kali 上音频动效每几秒卡顿一下**（实时性/缓冲区调度问题）。
- **不支持 VST 插件接入**。

**JamesDSP for Linux：**
- **界面丑、不直观、不好用**。
- **没有汉化版**。

### 2.4 跨平台插件宿主 —— Element

- Windows 上配合 Voicemeeter 使用时**占用偏高**。
- **点窗口叉号直接退出**（必须去托盘隐藏），**操作反直觉**。
- **插件加载存在兼容性问题，VST 扫描经常崩溃**。
- **保存的音效链会丢失**（状态持久化不可靠）。

### 2.5 ViPER 蝰蛇音效（PC + 手机 Magisk）

- **PC 版效果一般**；**每换新耳机/设备都要重调驱动**。
- **手机版安装极其困难，经常找不到驱动**。
- **可调音效数量很少、过于傻瓜化，调不出满意效果**。

## 3. 痛点根因归纳（对应到设计约束）

| 根因类别 | 具体问题 | 新项目的设计要求 |
|---|---|---|
| 平台政策滞后 | Android 14+ session/audio policy 变化 | 建立**版本适配层**，按 API Level / ROM 分支处理；优先研究 14+ 稳定会话方案 |
| 第三方依赖脆弱 | 依赖 Voicemeeter 虚拟声卡 | **不依赖第三方虚拟声卡**；自研最小音频注入/虚拟设备 |
| 进程生命周期 | 后台被杀、关窗即退 | 前台服务 + 守护重启；**关窗最小化到托盘**，退出需显式确认 |
| 状态持久化 | 效果链丢失、重启后声音不同 | **原子化 + 版本化保存**，崩溃恢复，参数与系数一并持久化 |
| 设备热插拔 | 换设备/驱动即失效 | 监听默认设备变更，**自动重挂载音频图** |
| 插件兼容 | VST 崩溃、不支持 32 位 | 插件**独立进程/沙箱宿主**，32/64 位桥接，扫描隔离 |
| 静默失效 | 表面运行实则未处理 | **实时状态自检 + UI 明示处理中/旁路状态** |
| 体验/本地化 | 界面丑、无中文、不直观 | 全新 Flutter UI，**中文优先 + 国际化** |

## 4. 产品目标

1. **真·跨平台统一**：Windows / Linux / Android（macOS 列为后续，见第 5 节）。
2. **全新 UI**：基于 **Flutter** 重新设计，流畅、大气、直观、**中文优先**并支持多语言。
3. **多声道处理**：支持立体声到 5.1/7.1 的直通与处理，正确处理声道映射。
4. **多版本兼容**：显式覆盖 Android 12~16、Windows 7 及以上、主流 Linux 发行版（含 Kali 这类实时性敏感环境）。
5. **稳定可靠**：解决静默失效、后台被杀、状态丢失、热插拔失效等顽疾。
6. **插件与加速**：桌面端支持 VST（含 32 位），利用 SIMD 硬件加速。
7. **Linux 可 Root 运行**：面向类 Linux/多用户/嵌入式场景支持系统级运行。

## 5. 平台与版本支持矩阵（目标范围）

| 平台 | 最低/覆盖版本 | 音频接入方式（拟） | VST | 备注 |
|---|---|---|---|---|
| **Windows** | **Windows 7 起**（含 10/11） | APO 注入（自研，**不依赖 Voicemeeter**）/ WASAPI | VST2(32/64) + VST3 | Win7 无部分新 API，需分支降级 |
| **Linux** | 主流发行版（含 Debian/Kali 系） | PipeWire（优先）/ PulseAudio 模块 | VST3/LV2 | Kali 的实时调度卡顿需专项优化 |
| **Android** | **12 ~ 16**（重点 14+） | Root 守护进程（真全局）+ Rootless（受限） | 不支持 | 重点攻克 14+ session/audio policy |
| **macOS** | 待定（低优先级） | CoreAudio 虚拟设备 + AU | AU/VST | 用户未实测，列为后续 |

## 6. 技术选型（架构层面）

> 承接架构评审结论，并纳入本轮「UI 用 Flutter」的决策。

```
┌──────────────────────────────────────────────────────────┐
│  Flutter UI 层（跨平台统一）                                │
│  · 流畅大气界面、中文优先、i18n                            │
│  · 播放流可视化：CustomPaint / Texture + 引擎推送 FFT       │
├──────────────────────────────────────────────────────────┤
│  桥接层：dart:ffi（C ABI） 或 platform channel              │
├──────────────────────────────────────────────────────────┤
│  统一核心 core/（C++ / CMake）                              │
│  · EffectsGraph 效果链引擎（节点式机架）                    │
│  · 状态持久化（原子/版本化/崩溃恢复）                       │
│  · 插件宿主：JUCE 系（桌面 VST/AU/LV2）                     │
│  · 可视化数据源（FFT/电平，lock-free 环形缓冲）             │
├──────────────────────────────────────────────────────────┤
│  DSP 算法层：复用 libjamesdsp（C++）为核心 + 按需扩展        │
├──────────────────────────────────────────────────────────┤
│  平台音频 I/O 胶水层（按 OS 分化，本项目的核心难点）          │
│  · Windows：自研 APO / WASAPI（不依赖 Voicemeeter）         │
│  · Linux：PipeWire / PulseAudio 模块（可 Root）             │
│  · Android：Root 守护 + 版本适配层（12~16）                 │
│  · macOS：CoreAudio + AU（后续）                            │
└──────────────────────────────────────────────────────────┘
```

**关键决策与理由：**

| 决策点 | 选型 | 理由 |
|---|---|---|
| UI 框架 | **Flutter** | 用户拍板；一套代码多端、视觉现代、动画流畅 |
| 与 C++ 引擎通信 | **dart:ffi（首选）** | 零序列化开销，适合实时音频控制；复杂场景再退回 platform channel |
| DSP 算法 | **复用 libjamesdsp** | 成熟、免费、功能全；避免重复造轮子 |
| 效果机架 | 自研节点式 EffectsGraph | 参考 EqualizerAPO 配置式 + Element 节点式，但重做交互与持久化 |
| 插件宿主（桌面） | JUCE（参考 Element 实现） | 跨平台 VST/AU/LV2 宿主最成熟；但需解决其崩溃隔离与保存丢失问题 |
| 音频注入 | **自研，去第三方虚拟声卡** | 直击 Voicemeeter 依赖脆弱的核心痛点 |
| 硬件加速 | SIMD（NEON/AVX）+ 低延迟后端 | 音频块小，GPU 跑 DSP 得不偿失；GPU 仅用于可视化 |
| 构建 | CMake（C++）+ Gradle（Android） | 统一核心 + 原生端各用其构建 |

## 7. 功能清单（参考现有项目提炼）

**音效 / DSP（参考 libjamesdsp 与 EqualizerAPO）：**
- 图形 / 参数均衡（多段 PEQ、GEQ）
- 卷积混响（IR 加载）
- 动态处理（压缩、限幅、门限）
- Bass boost、立体声宽度/串扰（crossfeed）
- EEL 脚本自定义效果（JamesDSP 特色）
- 多声道直通 / 下混

**机架 / 系统（参考 Element 与 EqualizerAPO）：**
- 节点式效果链、配置式预设
- 预设导入导出、配置备份
- 设备热插拔自动重挂
- 处理状态可视化（处理中 / 旁路 / 失效明示）

**插件：**
- 桌面端 VST2(32/64) / VST3 / LV2 宿主
- 插件扫描与加载**进程隔离**（崩溃不拖垮主程序）

**界面 / 可视化：**
- 播放流 / 波形 / 频谱 / 声谱可视化
- 中文优先，多语言切换

## 8. 非目标（明确边界，避免范围蔓延）

- **不做 DAW / 音乐制作软件**：只做「系统级音效处理」。
- **Android 不承诺 VST**：Android 无 VST 运行时，仅在受限场景提供内置效果。
- **Windows 7 上的新特性可选**：依赖新 API 的特性在 Win7 上降级或禁用。
- **不做硬件 DSP 设备**：聚焦软件方案。

## 9. 主要风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| Android 14+ 音频政策未知 | Android 端可能长期难产 | 立项即启动专项调研（session/audio policy），先做 Rootless 有限版兜底 |
| Windows 驱动签名门槛 | Win 端 APO 分发受阻 | 开发期用测试签名；发布预留 EV 证书与签名预算 |
| Win7 支持成本 | 需维护旧 API 分支 | 抽象为「平台能力探测 + 特性降级」 |
| Flutter 桌面音频生态薄弱 | 需自建桥接 | 用 dart:ffi 直连 C++ 核心，UI 与引擎解耦 |
| 插件沙箱复杂度 | 开发量大 | 早期单进程内隔离，成熟后再上独立宿主进程 |
| 多端 UI 一致性 | 维护成本 | Flutter 单代码库，平台差异用响应式布局吸收 |

## 10. 里程碑规划（Roadmap）

1. **M0 立项与调研**：本文档定稿；Android 14+ 音频政策专项调研；确定 Flutter 与 C++ 核心的桥接方案。
2. **M1 桌面 MVP**：Linux(PipeWire) + Windows(自研注入) 打通 libjamesdsp 全局效果；Flutter UI 能实时调参与显示状态。
3. **M2 机架与持久化**：节点式效果链 + 原子化状态保存 + 设备热插拔重挂。
4. **M3 插件与可视化**：桌面 VST 宿主（进程隔离，含 32 位支持）；播放流/频谱可视化。
5. **M4 Android**：Rootless 有限版 → 攻克 14+ Root 守护真·全局（含 Magisk 集成）。
6. **M5 打磨与发布**：多声道、低延迟、SIMD 优化、i18n、各平台打包与签名。
