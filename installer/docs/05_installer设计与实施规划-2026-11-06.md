## 1. 现状与目标

- 现状（2026-11-05 深度审查 S1 确认）：`installer/` 此前只有规范与目录
  骨架，无可运行的打包实现；实际分发靠 `tools/windows/build_windows.ps1`
  的绿色包与驱动侧 `install_driver.ps1`。
- 目标：按发布总则实现「每平台三件齐备」的完整发行工具链——
  驱动包 + 便携包 + 正式安装包，产物统一进 `dist/`，带版本/提交/
  SHA256 清单（复用 `tools/bin/dist_manifest.py`），可从 `main` 分支
  一键复现。

## 2. 调研结论（工具链选型）

### 2.1 共享层

| 事项 | 选型 | 理由 |
| :--- | :--- | :--- |
| 版本真相源 | `pubspec.yaml` + `installer/shared/version_resolver.py` | 01 §2.1 已定；解析器向所有 pack 入口导出 `AURADSP_VERSION/BUILD/FULL_VERSION/TAG`，标签与 pubspec 不一致即中止 |
| 产物清单 | 复用 `tools/bin/dist_manifest.py` | 已落地（版本/提交/分支/SHA256 + `--check`），不再另造 |
| 校验和 | `dist/SHA256SUMS.txt` | 01 §3 既定 |

### 2.2 Linux

| 包 | 选型 | 调研要点 |
| :--- | :--- | :--- |
| 正式安装包 `.deb` | **手写 staging + `dpkg-deb --build`**（脚本在 `installer/linux/deb/`） | 零额外依赖、maintainer 脚本完全可控；nfpm 等多格式工具在需要 `.rpm` 时再引入，避免为单一格式背工具链 |
| 便携包 `.AppImage` | **appimagetool（AppImage/appimagetool 维护线，1.9.x）+ type2 runtime** | AppImageKit 旧线已停维且其 runtime 依赖 `libfuse.so.2`（新发行版已移除）；type2 runtime 为静态运行时，目标机只需 fusermount 助手。**供应链钉死**：appimagetool 本体按版本 + SHA256 钉死；runtime 必须用 `--runtime-file` 钉死日期版 + SHA256——appimagetool 默认从滚动 `continuous` 标签现下 runtime，不钉死则同一提交两次构建产物不同（业界复盘已多次点名此坑）。容器/CI 无 FUSE 时以 `APPIMAGE_EXTRACT_AND_RUN=1` 运行工具本体 |
| 便携包 `.tar.gz` | tar 打包 bundle + 启动脚本 | AppImage 的等价补充（无 FUSE 环境、服务器场景） |
| 驱动包 | **配置型 deb** `auradsp-driver-loopback`（03 §6） | Linux 无自研驱动；职责是固化 snd-aloop 自启与参数。纯配置、架构 `all` |
| Flatpak | manifest 已备（`installer/linux/flatpak/`） | 运行时 **`org.freedesktop.Platform // 25.08`**（当前稳定线；旧规格写的 23.08 已过时，本文更新）。当前 manifest 消费预构建 bundle，适用于 GitHub Release 直分发；**上架 Flathub 需另备 from-source 构建变体**，列为后续项 |
| Snap | snapcraft.yaml 已备（`installer/linux/snap/`） | 基础镜像 **`core24`**（core22 已旧）；先 strict + 03 §4.2 plugs，音频系统级能力是否需要 classic confinement 待真机评估。不进首发构成 |

AppImage 内容铁律（03 §1）：**绝不捆绑 `libpulse.so` / `libasound.so`**，
也不捆绑 GTK/GLib 家族——只装 Flutter bundle 自带库，音频与图形栈用
宿主机库，否则与宿主 PulseAudio/PipeWire 握手失败或与宿主 GLib 冲突。
glibc 基线：官方构建在 Ubuntu 22.04（glibc 2.35）环境产出。

### 2.3 Windows

| 包 | 选型 | 状态 |
| :--- | :--- | :--- |
| 便携包 zip | `tools/windows/build_windows.ps1`（Step5 清单 + Step6 zip） | 已落地 |
| 驱动包 zip | AuraVAIO 驱动文件 + `install_driver.ps1` 打成 `AuraDSP-Driver-x64-v{VERSION}.zip` | 打包脚本待补（小项） |
| 正式安装包 exe | 自研安装向导（02 号设计：载荷 = staging 目录 + 元数据尾块） | **未落地，首发前置条件** |
| 驱动签名 | **开放问题**：AuraVAIO 当前为测试签名；正式分发需微软 Attestation/EV 签名，否则目标机需开测试模式——必须在 Windows 阶段立项解决，见 §6 | 风险项 |

## 3. 总体架构

```text
输入（staging，每平台一目录，由各平台 build 脚本产出）
  Windows: dist/AuraDSP-Windows-x64/（build_windows.ps1 既有口径）
  Linux:   Flutter bundle（app/auradsp_app/build/linux/x64/release/bundle）
           ——引擎 .so 与 plugin_host_x64/x86 已由 sync 流程随 bundle 就位

共享: installer/shared/version_resolver.py → 版本 env；dist_manifest.py → 清单

打包入口（每平台一个 pack.*，可单独/组合产出）
  installer/windows/pack.py     → 驱动 zip / 便携 zip / Setup exe（向导就绪后）
  installer/linux/pack.sh       → deb / driver-loopback deb / AppImage / tar.gz
                                  （+ flatpak/snap 清单校验，不产出商店包）

输出: dist/ 全部产物 + SHA256SUMS.txt + 每包 build-info（dist_manifest --check 可验）
```

## 4. 发行流程衔接（与 01 §5 门禁对齐）

1. `dev` 合入 `main` 后，在 main 打标签 `v{VERSION}`（须与 pubspec 一致）。
2. CI 在标签上跑全门禁（八 job + 双平台冒烟 + Dart 单测），任一红灯中止。
3. 双平台 pack 入口在干净环境从该标签构建三件产物，`dist_manifest --check`
   与 SHA256 清单校验通过后汇集发布。
4. 发布演练（release drill）：干净虚拟机各一份做安装 → 运行 → 升级 →
   卸载全程验证，结果记入当次 RELEASE_NOTES。

## 6. 风险与开放问题

1. **Windows 驱动签名**（最大外部风险）：测试签名的驱动无法在默认
   Windows 上加载；Attestation 签名需要 EV 证书与微软合作伙伴中心
   流程，周期与成本需 owner 提前安排，否则 Windows「完整发行」只能
   附带测试模式说明降级发布。
2. **AppImage runtime 钉版维护**：钉死的 runtime 日期版需定期跟进
   安全更新，pack 脚本在 runtime 超过约定 age 时给出提示（先人工纪律）。
3. **Flatpak 上架形态**：Flathub 要求源码构建，与当前「预构建 bundle
   直分发」manifest 不同轨；上架时另立 from-source 变体，不改本轨。
4. **Linux 32 位宿主**：`plugin_host_x86` 随包分发，但在纯 64 位无
   multilib 的目标机上无法执行——属运行时能力降级（扫描侧已有
   isCompatible 口径），包内 README 需注明（已写入 deb 说明）。
5. **版本号进位规则**：修订号超过 9 进位次版本（01 §2.1 已定），
   version_resolver 做格式校验拦截非法版本。
