# 安装向导优化：覆盖升级、目录规范化与驱动签名告知（2026-11-06）

> 范围：`installer/windows/custom_installer/wizard/`、`installer/windows/pack.py`、
> `installer/windows/tests/test_pack_fixture.py`、随包 `driver/` 资产。
> 上位文档：02（向导设计）、05（子项目规划）、`docs/20-执行/Windows安装程序与打包脚本实施设计-2026-11-06.md`。

## 1. 依据（事实 / 已核实）

- 微软 Learn《Loading Test Signed Code - Windows drivers》：64 位 Windows 的内核模式代码签名策略要求驱动带数字签名，默认不加载测试签名驱动；`bcdedit /set TESTSIGNING ON` 需管理员并重启，Secure Boot 开启时可能报「受策略保护」，启用后有「测试模式」水印。自 Windows 10 1507 起，若开启内存完整性（HVCI），二进制必须以测试证书签名。
- 微软 Learn《Preparing a Computer for Manual Driver Deployment》：测试证书需导入受信任根与受信任发布者存储。
- 微软社区（启动设置 F7）：「禁用驱动程序签名强制」是**一次性**启动选项，下次重启自动失效。
- 因此「Win10 以下系统不受影响」**不成立**：Win7 / 8.1 / 10 / 11 的 64 位版本都受签名策略约束；只有 32 位系统基本不强制。Windows 11 的差别是额外门槛（Secure Boot、HVCI/VBS、较新版本对 bcdedit 写入的限制）。
- 代码事实：原 `install_driver.ps1` 的 `-Action` 默认 `status`，向导调用未传 `install`；该脚本按源码树 `modern/x64/<Config>/AuraVaioDriver` 找包且依赖 WDK signtool，随包平铺布局下不可用。
- 代码事实：原 `componentFilter(vaio: false)` 会把整个 `driver/` 从载荷解压中过滤掉，与「保留手动安装脚本」冲突。

## 2. 关键决策

1. **目录规范化**：新增纯函数 `normalizeInstallDir`，trim、统一分隔符、去尾部斜杠，末段非 `AuraDSP` 时自动补（大小写不敏感）。在输入框失焦 / 提交 / 开始安装时统一执行，不打断用户连续输入。覆盖升级与降级场景锁定为旧目录。
2. **更新语义**（一般软件的覆盖安装模型）：
   - 探测：`reg query HKCU|HKLM\Software\AuraDSP` 读 `Version` / `InstallDir`，再补 `install_manifest.json` 拿组件与文件台账；解析做成纯函数 `parseRegQuery` 可单测。
   - 判定：4 段数字版本比较 → `fresh` / `upgrade` / `repair` / `downgradeBlocked`。
   - 升级/修复：沿用旧目录与旧组件选择；解压前备份旧程序文件到会话临时目录；失败时删本次写入文件并恢复备份，成功时清理备份；`isUserPath` 保护 `user_data/`、`presets/`、`config.json`、`*.aurapreset.json` 等不被覆盖或删除。
   - 降级：拦截并提示先卸载（避免配置不兼容），不自动降级。
   - 静默模式：沿用旧目录与旧组件，完成注册表 `DisplayVersion` 与清单 `updateMode` / `previousFullVersion` 更新。
   - 不含在线检查更新 / 自动下载：需要版本清单服务与后端，超出本次最小可行范围，列为待确认项。
3. **双驱动可选、默认勾选**：`InstallOptions.asio` / `vaio` 默认 true，选项页分「驱动（可选，默认安装）」组并说明取消勾选仅跳过自动安装。`componentFilter` 不再按 `vaio` 过滤，`driver/` 恒写入安装目录。
4. **随包手动安装资产**：新增自包含 `driver/install_vaio.ps1`（平铺布局、`-Action status|install|uninstall`、检查 testsigning、导入测试证书、pnputil 入栈、devcon 建 root 设备节点、写 `%TEMP%\auradsp-vaio-install.log`、退出码 3 表示需开启测试签名），以及中英双语 `README.txt`。`pack.py` 用统一 `stage_driver_files` 把驱动产物、测试证书、devcon.exe、`install_driver.ps1`、`register_asio.ps1`、`install_vaio.ps1`、`README.txt`、ASIO DLL 副本组装进驱动 zip 与 Setup 载荷。向导 VAIO 步骤改调 `install_vaio.ps1 -Action install`。
5. **签名告知**：选项页 VAIO 勾选时显示警告卡片 + 完整教程弹窗（三语），完成页 warnings 给出提示与「打开驱动说明文件」入口；引擎按退出码 3 给出更明确指引；`driver/README.txt` 给出持久（testsigning）与一次性（F7）两套方案、适用系统矩阵、恢复方法与「无法开启时的影响」。明确区分 AuraASIO（用户态 COM，不受限）与 AuraVAIO（内核驱动，受限）。

## 5. 卸载缺陷修复（同日第三轮，用户实测反馈）

- 反馈：覆盖安装与卸载本身正常，但「不保留用户数据」「卸载残留严重」。
- 根因一（数据）：keepData 只控制 %APPDATA% / %LOCALAPPDATA% 两个数据根，收尾却用
  dir.delete(recursive: true) 把整个安装目录连同用户自建文件一起删除；UI 未说明保留范围。
- 根因二（残留）：卸载流程从未卸载 VAIO 驱动/设备节点/测试证书，未回收开始菜单空目录，
  只清一个 hive 的注册表与 Run 项，ASIO 反注册还被 components.contains('asio') 门控；
  整目录删除一旦遇到占用文件就整体失败，只留一句 warning。
- 根因三（升级遗留）：旧版专属文件不在新清单里，卸载时删不到。
- 修复：新增 classifyUninstallPath（清单内=随包程序文件删除；清单外=用户数据，keepData 时保留；
  uninstall.exe 与 install_manifest.json 总是删除），逐文件删除 + 自底向上回收空目录，
  不再整目录 delete；先卸驱动再删文件；两个 hive 注册表 + Run 全清；快捷方式幂等补删；
  临时日志清理；升级成功时按 staleUpgradePaths 清旧版遗留；随包脚本新增 -RemoveTestCert
  （按证书指纹精确删除 Root/TrustedPublisher/My）；完成页显式列出保留的用户数据路径。
- 验证：flutter analyze 0、flutter test 20/20；反向验证（临时还原「全删」行为）
  卸载分类断言转红 TEST_EXIT=1，恢复后全绿；fixture ALL PASS；真实重建 + --verify。
- 仍待真机验收：在测试机复跑「装 → 覆盖更新 → 卸载（保留/不保留两种）」，逐项核对
  %APPDATA%\AuraDSP、安装目录、设备管理器、DriverStore、证书存储、注册表与快捷方式。

## 6. UAC 提权、ASIO 占用与完成页快捷方式（第四轮，用户实测反馈）

- 反馈：UAC 点「否」后进度永远停滞；授权后还要再点一次「开始安装」；
  升级覆盖不丢预设与手动复制的 DDC（已验证通过）；Win 设置与开始菜单登记正常；
  卸载报 auraasio_driver.dll 被卸载程序自己占用；ASIO 在 FL Studio 中已消失；
  卸载应自动弹 UAC；完成页希望有「创建桌面快捷方式」选项；VAIO 因未开签名模式测不了。
- 根因一：提权用同步 ShellExecute FFI，UAC 弹窗期间阻塞 UI isolate；点「否」后又
  静默降级继续，界面观感即「卡在进度」。另外解压阶段 fraction 直接给到 1.0，
  后续步骤不再更新，进度条也像停滞。
- 根因二：ASIO 注册原用 DynamicLibrary.open 在向导进程内加载 DLL，dart:ffi 无 close，
  句柄一直被卸载程序持有 → 删除必报占用；同步调用还可能冻结 UI。
- 修复：
  - 提权协议加 --auto-start / --auto-uninstall / --keep-data / --no-keep-data；
    提权前先渲染「等待管理员授权」层再调用同步 ShellExecute；成功则退出当前进程让新进程
    自动继续（不再需要用户二次点击），失败弹三选一对话框（重新授权 / 仍要继续 / 返回），
    不再静默降级；autoStart/autoUninstall 进程未提权时直接降级，防止 UAC 循环。
  - 卸载一律请求管理员权限（清 HKLM / 设备 / 证书 / 公共快捷方式），与常见软件一致；
    静默或 autoUninstall 场景被拒绝时降级卸载并给警告。
  - ASIO 注册/反注册改用独立系统注册子进程（异步、退出即释放句柄），根除 DLL 占用。
  - 各阶段 fraction 映射为 0.02 → 0.05 → 0.05~0.75 → 0.80/0.86/0.90/0.94/0.97 → 1.0，全程单调推进。
  - 完成页新增「创建桌面快捷方式」勾选，点击完成时按最终状态补建或删除（幂等）。
- 验证：flutter analyze 0、flutter test 21/21、fixture ALL PASS、真实重建 + --verify。
- 仍待真机：UAC 点否/点是的完整交互、从「设置 → 应用 → 卸载」弹 UAC、
  VAIO（需先开启测试签名模式）。

## 7. 卸载占用与清理窗口（第五轮，用户实测反馈）

- 反馈：卸载报告 plugin_host_x64.exe 被占用（安装完后扫描过插件），但卸载程序退出后
  即可手动删除；UAC 正常、卸载完成后出现一个关不掉的 cmd「选择」窗口；
  其它前几轮问题均已解决，桌面快捷方式取消勾选后也正确消失。
- 根因一（卡住的窗口）：_closeWindow 用可见 cmd 执行延迟清理，GUI 父进程会创建
  控制台窗口；用户点选窗口文字即进入 QuickEdit「选择」模式，控制台挂起，
  ping 永不结束，窗口关不掉。
- 根因二（占用）：closeGuardedProcesses 只在卸载开始时跑一次，且无 /F 的
  taskkill 对无窗口宿主进程常无效；删除阶段既没有重试，也没有「进程退出后再删」
  的兜底，于是被占用文件直接进入 warnings。Windows 会在最后一个句柄（往往就在
  向导进程或其子进程里）释放后才允许删除，这正是「退出后就能删」的原因。
- 修复：
  - 清理改为 buildCleanupScript 生成 PowerShell 脚本（UTF-8 BOM，支持中文路径、
    单引号转义），由 ShellExecute(SW_HIDE) + -WindowStyle Hidden 隐藏启动，
    **不再出现任何可见控制台窗口**；脚本等待 2 秒后重试删除被占用文件（8 次 × 500ms）、
    清理会话目录、最后自删。
  - 进程守卫增加按镜像名 /F /IM /T 强杀兜底，并在删除文件前再执行一轮；
    逐文件删除改为 4 次重试（间隔 350ms）；仍失败的绝对路径记入
    EngineResult.leftoverPaths 交给退出后脚本，warnings 改为「已安排自动清理」。
- 验证：flutter analyze 0、flutter test 23/23（含清理脚本生成与转义）、
  清理脚本 PowerShell 语法解析、fixture ALL PASS、真实重建 + --verify。
- 待真机：卸载含正在运行的插件宿主时，确认不再出现占用警告、不再有可见黑窗口、
  且 leftover 在关窗后被清掉。

## 8. 同名进程误伤防护与渲染性能（第六轮）

- 反馈：① 进程守卫会不会误伤同名但不是我们的进程（网上有同名 AuraDSP，
  plugin_host 名称也很通用）；② 安装/卸载程序内存 1G+、GPU 最高 75%。
- 风险属实（第五轮引入）：原守卫用 tasklist 按 IMAGENAME 匹配，末尾还用
  taskkill /F /IM <name> /T 按镜像名全杀并连带子进程树——同名软件、别家宿主、
  甚至宿主里运行的 DAW 都可能被误杀。
- 防护：
  - 改用 Get-CimInstance Win32_Process 取 ExecutablePath，纯函数
    parseProcessPaths / ownedProcessPids 只认可执行文件确实位于安装目录下的 PID；
    排除系统 PID 与向导自身，防止 PID 复用或自杀。
  - 删除 /F /IM 与 /T；强杀只按复核过路径的 PID 发 /F /PID。
  - 查询失败或没有安装目录时返回空表（宁可漏杀，绝不按名全杀）；
    强杀前重新核对路径；轮询从最多 8 次 CIM 查询降到 2 次（也少启 PowerShell）。
  - 反向验证：临时去掉路径过滤，「只认安装目录」断言立即转红，恢复后全绿。
- 性能根因：
  - AuroraBackground 用 AnimationController.repeat() 按 vsync 60fps 全窗重绘，
    每帧新建 4 个大半径 RadialGradient Shader（3 光斑 + 暗角）；
  - 解压约 1600 个文件产生 1600 次 setState，整棵进度页随之重建，日志列表无限增长。
- 优化：
  - 极光改为 24 档量化 + 900ms Timer（约 1.1fps），CustomPaint 只在档位变化时重绘；
    RepaintBoundary 把内容层与背景层隔离。全屏渐变重绘由约 240 次/秒降到约 4.4 次/秒（约 2%）。
  - 进度事件 60ms 节流，done/restore 强制刷新；日志只保留最近 120 条。
  - 视觉上极光仍缓慢漂移，若嫌档位跳变可把 24 档 / 900ms 调成 48 档 / 450ms（约 2.2fps）。
- 验证：flutter analyze 0、flutter test 27/27、fixture ALL PASS、真实重建 + --verify。
  内存/GPU 的绝对值需在你的机器上复测，本轮给出的是代码级确定性热点的消除。
